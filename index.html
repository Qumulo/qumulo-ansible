The qumulo.cluster documentation

The pages are grouped by what you want from them:

  • To learn the collection by using it, start with a tutorial.

  • To get one task done, find its how-to guide.

  • To look up a variable, a module option or a message, go to the reference.

  • To understand why the collection works the way it does, read an explanation.

Tutorials

  • Your first cluster: adopt a cluster you already run and pass the zero-diff gate.

  • Your first fleet: adopt a hub and an edge you already run into one inventory.

How-to guides

Getting started:

  • Install and pin the collection: install it on a controller and pin the version.

  • Set up an inventory for your clusters: lay out hubs and edges, and connect to each.

  • Keep secrets out of the inventory: encrypt passwords with Ansible Vault, or look them up.

  • Adopt a cluster you already run: capture a formed cluster’s settings into host_vars.

  • Use a Terraform root’s output as the inventory: read hosts from the terraform plugin.

  • Respond to a refusal: what to read, and what lifts each kind of refusal.

Configuring clusters:

  • Declare common settings in the inventory: network, DNS, roles, users, directories, ACLs, quotas, FTP, cluster settings and audit logs.

  • Manage tenants: declare tenants, bind networks to them, give them settings, shares and exports, rename and delete them.

  • Join a cluster to Active Directory: the join, user mappings, home directories and SAML.

  • Manage the cluster’s TLS certificate: replace the factory certificate, renew it, and set the cipher suites.

  • Serve NFS with Kerberos from a standalone KDC: install the KDC’s keytab, turn on krb5, krb5i or krb5p, and require one on an export.

  • Serve a directory as an S3 bucket: S3 settings, a bucket, its policy and an access key.

  • Register a cluster with Nexus: monitoring, the Nexus connection and registration, and retiring a UUID.

  • Look up identities, DNS names and paths: check trustees before an ACL or a mapping names them, read an Active Directory user’s SID, NFS uid and groups, check a name with the cluster’s resolver before an export names it, and turn a path into a file id and back.

Edges, hubs and replication:

  • Pair an edge with its hub through a portal: declare, apply, check and remove a portal.

  • Replicate a directory to another cluster: declare a relationship and have the baseline make it.

  • License an edge: from no license to a license the cluster holds, with its clamp set.

  • Size and resize an edge’s cache: set the clamp, grow it, and shrink by rebuilding.

  • Clone an edge’s configuration onto a new edge: a fresh edge with an existing edge’s settings.

  • Rebuild an unprotected edge: drain, form again and replay the inventory.

  • Restore a rebuilt edge’s data from its replica: bring the data back from the target.

  • Fail over to a replica, and fail back: make the target writable when the source is lost, copy its writes back, and return to the source.

Upgrades and routine changes:

  • Upgrade a fleet: bring every cluster to its target release with the upgrade playbook.

  • Recover an upgrade that stopped: read the report, lift the cause and run again.

  • Rotate the admin password: change admin’s password and keep the play connected.

  • Rotate the access token a host connects with: replace the token, keep the play connected and put the new bearer in the vault.

  • Rotate the encryption key: rotate the master key for data at rest.

  • Take a snapshot before a change: a snapshot you can find again and lock.

  • Manage the keys that lock snapshots: register, inspect, replace, disable and remove a key in the file system key store, and lock a snapshot policy’s snapshots with one.

  • Run the playbooks from a pipeline: pin the collection, pass secrets, and split check from apply.
