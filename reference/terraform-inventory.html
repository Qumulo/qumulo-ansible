The Terraform inventory plugin

The inventory plugin qumulo.cluster.terraform adds one inventory host for each entry of a Terraform output named qumulo_ansible_inventory. This page lists the plugin’s source file and options, the output’s fields and formats, the values each Terraform resource gives, and the hosts, variables and groups the plugin produces. Use a Terraform root’s output as the inventory has the steps, and Terraform ownership says why the output is the only place the two meet.

ansible-doc -t inventory qumulo.cluster.terraform lists the plugin’s options and examples from the installed collection.

Summary

Plugin name

qumulo.cluster.terraform

Source file name

Ends in qumulo_terraform.yml or qumulo_terraform.yaml.

Output read

qumulo_ansible_inventory, a map from the Ansible host name to one entry per cluster.

Source of the output

terraform output -json qumulo_ansible_inventory run in project_path, or a saved copy of its result in output_file.

Hosts produced

One for each entry, in qumulo_clusters and in two child groups.

Connection variables set

None. The hosts have no ansible_connection.

Needs

Terraform on the controller with project_path; nothing with output_file.

Source file options

A source file is a YAML file that names the plugin and one source for the output.

# inventory/prod.qumulo_terraform.yml
plugin: qumulo.cluster.terraform
project_path: ../terraform/prod
workspace: prod

# inventory/ci.qumulo_terraform.yml
plugin: qumulo.cluster.terraform
output_file: ../terraform-output/qumulo_ansible_inventory.json

Rules for the source options:

  • Set exactly one of project_path and output_file. Setting both, or neither, fails the source.

  • workspace with output_file fails the source. timeout and binary_path with output_file have no effect.

  • A relative project_path or output_file is relative to the directory of the source file. A leading ~ and environment variables such as $HOME are expanded first. A binary_path without a directory separator is looked up on PATH as written, without expansion. One with a separator is expanded and made relative to the source file’s directory like the other two.

  • project_path must be a directory.

  • The plugin runs <binary_path> -chdir=<project_path> output -no-color -json qumulo_ansible_inventory with standard input from /dev/null. Every environment variable whose name starts with TF_LOG is removed from the command’s environment, so a failure message, which quotes terraform’s standard error, never carries a trace log.

  • With workspace, TF_WORKSPACE is set to it for that command, and the root’s selected workspace is not changed. Without it, a TF_WORKSPACE already in the environment applies, and otherwise the root’s selected workspace.

  • The command’s failure fails the source, whether terraform is missing or cannot be run, does not finish within timeout, exits non-zero (the message quotes its standard error), or prints text that is not JSON.

  • output_file fails the source when it cannot be read, is not JSON, or holds what terraform output -json prints without an output name. The plugin recognizes that listing by every top-level value being a map with value and type keys. The listing carries every output of the root, sensitive ones in plain text.

  • Given a directory with -i, Ansible’s ansible.builtin.yaml inventory plugin reads every .json file in it as an inventory of its own, so a saved output kept in that directory is parsed twice.

  • A source file that fails is skipped with a warning, and the run continues without its hosts. ANSIBLE_INVENTORY_ANY_UNPARSED_IS_FAILED=true makes the run fail instead.

Cache

With cache: true and a persistent cache plugin such as ansible.builtin.jsonfile, the plugin keeps the hosts it has read. The default cache_plugin, memory, keeps nothing between runs, so with cache: true alone the plugin reads the output on every run and records no addresses for the subset check.

  • What is cached is the checked hosts, never the raw output. A cached read checks them again.

  • The cache key covers the source file’s path, project_path, output_file, and the workspace, from workspace or from TF_WORKSPACE. A cached source is read again when any of them changes. A workspace switched with terraform workspace select is read once cache_timeout passes or the cache is refreshed.

  • A second entry, under another key with the same parts, records the addresses each load_balancer_name last resolved to (Load balancer names).

  • --flush-cache reads the source again and writes the cache, and ignores the recorded addresses.

Without cache, the plugin reads the output on every run.

The output

The output is a map from the Ansible host name to an entry. A host name is a string with no whitespace and no /. terraform output -json qumulo_ansible_inventory prints it as JSON:

{
  "cnq01": {
    "api_host": "10.0.1.20",
    "cluster_uuid": "7c1e0d4a-77c1-4b8e-9a51-2f0e6c3d9e02",
    "cluster_kind": "cnq",
    "managed_by": "terraform_provider",
    "owned_areas": ["network.floating_ips"],
    "password_ref": {"type": "aws_ssm_parameter", "id": "/qumulo/cnq01/admin-password"},
    "portal_hosts": ["10.0.1.20", "10.0.1.21", "10.0.1.22"],
    "replication_address": "10.0.1.20"
  }
}

The output carries no secret, so it need not be marked sensitive.

Strictness

The plugin checks every entry before it adds any host, and one bad entry fails the whole source. The message names each bad entry and each bad field, and quotes no value from the output. The exceptions are a load_balancer_name that has already passed the fully qualified DNS check, and the addresses the cache recorded for it that it no longer resolves to.

The plugin fails the source for:

  • an output that is not a map;

  • an entry that is not a map;

  • a missing required field;

  • a field outside the nine above, and in password_ref outside type and id;

  • a field whose name matches pass, secret, token, credential, private, key or value, in any case, as a substring, and is not one of the nine fields. The message calls it a secret, and the plugin never reads its value, puts it in a variable or the cache, or shows it. Names such as password, admin_password, api_token and join_key are refused this way;

  • two entries with the same cluster_uuid, compared without regard to case, since that would make one cluster two hosts;

  • an entry name with whitespace or / in it;

  • a value in the formats below that the plugin refuses.

Constructed groups and variables

compose, groups and keyed_groups work as they do for any constructed inventory. The plugin evaluates them for each host after it has set the variables above, so their expressions can read those variables and the host name. strict makes an expression that fails an error instead of a skipped entry.

Load balancer names

An entry may give load_balancer_name instead of portal_hosts and replication_address. The plugin resolves the name on the controller, with the system resolver, each time it reads the output. That includes a read from the cache, which keeps the name and not the addresses.

Rule

Detail

When it resolves

The entry has load_balancer_name and leaves out portal_hosts or replication_address. An entry that gives both fields is not resolved.

What it fills

portal_hosts gets every address the name resolves to. replication_address gets the first of them. Each field is filled only where the entry leaves it out; an address the entry gives wins.

Address form

IPv4 and IPv6 addresses, canonical, without repeats, IPv4 first, then IPv6, each in ascending numeric order.

The name itself

Never published as an address. Portals and replication take IP addresses only.

Failure

The source fails, naming the entry, when the name resolves to no address on the controller, or to any loopback, unspecified, multicast or zoned address.

Failure with the cache

With cache on and a persistent cache plugin, and addresses recorded for the name on an earlier run, the source fails when the name now resolves to a proper subset of them, naming the addresses missing.

Ways out of that failure

Give the addresses in portal_hosts and replication_address, or run once with --flush-cache to take the shorter list.

Recorded addresses

After a run that resolved a name with cache on, the cache holds the name’s addresses from that run. A name that resolves to other addresses, not to a subset of the recorded ones, is accepted and recorded. The record expires cache_timeout seconds after it was last written. A run after that records whatever the name resolves to, a shorter list included. cache_timeout: 0 keeps the record until --flush-cache.

A load balancer with cross-zone load balancing off leaves a zone with no healthy target out of its name’s answers. Edges, hubs and portals explains what that does to the addresses a run publishes.

Failure summary

Every failure below fails the source, and Ansible by default only warns and goes on without the source’s hosts.

Condition

Where it is checked

Both or neither of project_path and output_file; workspace with output_file

Source options.

project_path is not a directory; terraform cannot be run, times out or exits non-zero; its output is not JSON

Running terraform.

output_file cannot be read, is not JSON, or lists every output of the root

Reading the file.

An output that is not a map; a field or value outside The output; two entries with one cluster_uuid

Checking the entries, before any host is added.

A load_balancer_name that resolves to nothing, to a loopback, unspecified, multicast or zoned address, or to fewer addresses than the cache recorded

Resolving the names, after the entries pass.
