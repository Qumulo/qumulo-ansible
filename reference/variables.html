Inventory variables

The variables the collection’s playbooks and roles read from an inventory: the groups, the connection, the variable for each area of a cluster, ownership, the variables passed for one run, and the variables of the other roles.

The keys, types and defaults of each variable are in the role’s argument specification, which ansible-doc -t role qumulo.cluster.cluster_baseline prints and the doc site renders from roles/cluster_baseline/meta/argument_specs.yml. This page does not copy them. It gives what the specification does not: which group reads what, which step applies which variable, and the rules that cut across variables. A key that the specification does not list for a variable, such as a misspelt one, is refused before the baseline’s first task, with a message that names the path to the key; a tenant’s smb_settings and nfs_settings, which the specification cannot list, are checked at step 2. examples/inventory/ is a complete inventory with a comment on every variable it sets; it does not show tenants yet, which Manage tenants does. Set up an inventory for your clusters builds one, and Declare common settings in the inventory has recipes for most areas.

Ids such as G-TOKEN and QUIRK-060 are entries of the gap register and the quirk register.

The example inventory makes qumulo_edges and qumulo_hubs children of qumulo_clusters. The playbooks are in playbooks/; Playbooks and roles lists what each does.

The qumulo.cluster.terraform inventory plugin puts each host in one group for its kind (qumulo_edges, qumulo_cnq or qumulo_baremetal) and one qumulo_managed_by_<value> group, all under qumulo_clusters. It never puts a host in qumulo_hubs. No playbook or role reads the qumulo_cnq, qumulo_baremetal or qumulo_managed_by_* groups; they select group_vars.

Areas

cluster_baseline applies the areas in this order. An area whose variable is unset is left alone. The step numbers are those of the role’s documentation.

Step 1 is cluster_guard, unless cluster_baseline_guard is false. Step 2 holds five checks that fail before anything is written: the ownership check, no quota, snapshot policy or S3 bucket under a spoke root (G-SPOKE-PATHS), no path with both a mode and an ACL (G-FS-ACL-MODE), every lock_key in qumulo_snapshot_policies held by the file system key store unless -e qumulo_allow_deferred_policy_lock_keys=true is given, and no keytab to install beside a domain join (G-KRB-AD). Whenever the inventory declares qumulo_tenants, qumulo_network, qumulo_smb_shares, qumulo_nfs_exports, qumulo_nfs_settings or qumulo_factory_defaults, step 2 also reads the cluster’s tenants and plans steps 3a to 20a (Tenants). Step 8 is the license Qumulo issues outside the role (G-LICENSE), and step 12, the encryption key store, is not in this release.

Notes by variable

Network

Variable: qumulo_network. Step 3.

  • frontend_networks is the whole set: a network the cluster has and the list leaves out is removed.

  • A change that drops qumulo_api_host from the cluster’s addresses fails unless qumulo_allow_management_disruption is true and qumulo_api_host_after names the address to use afterwards.

  • On a cluster whose network the host manages, such as a host-managed cloud cluster, every network has type HOST, and only its name, tenant, netmask and floating ranges can change.

  • A flat network names its tenant with tenant, a tenant’s name. tenant_id is deprecated: the role accepts it for one release, with a warning, and translates it to the tenant’s name, and a network entry that sets both tenant and tenant_id is refused. A network of the backend bond takes no tenant, and a tenant_id there is dropped with a warning.

  • With more than one tenant, a new network that is not on the backend bond needs a tenant.

  • At most one STATIC network, across frontend_networks and the tenants’ networks, carries an IPv4 default_gateway, and at most one an IPv6 one. Step 2 refuses a second on every cluster, before any write. Networks the cluster already gives a gateway of that version warn and pass.

Tenants

Qumulo marks the multitenancy REST API as preview in Qumulo Core 7.10.3 and 7.11.0. The collection manages tenants through it on those releases, and a later Qumulo Core release may change it.

Variables: qumulo_tenants, qumulo_management_network, qumulo_cluster_port, qumulo_cluster_kind. Steps 2, 3a, 3, 3b and 20a, and the tenant keys of steps 18 and 19.

qumulo_tenants is a list of tenants, each found by its name, compared exactly. A tenant the list leaves out stays as it is. ansible-doc -t role qumulo.cluster.cluster_baseline lists the keys.

  • previous_name is ignored when state is absent.

  • A service flag (web_ui_enabled, rest_api_enabled, ssh_enabled, replication_enabled, nfs_enabled, smb_enabled) that is unset is off on a new tenant and unchanged on an existing one.

  • smb_settings and nfs_settings set only the keys given, or inherit removes the override. Leaving the key out leaves the override as it is.

  • identity is reserved for per-tenant identity, which is not supported yet. Step 2 refuses it.

  • A tenant’s networks is in the area network and its floating_ip_ranges in network.floating_ips. Its overrides and its shares and exports are in smb or nfs as well, and the tenants are in tenants (Ownership).

  • qumulo_management_network is the id of the network the play reaches the cluster on, or a list of ids, such as two for a name with an IPv4 and an IPv6 network. It is used when two or more tenants remain after a write. Declare it for a play behind NAT or a load balancer, or when the cluster’s network status is unavailable. 0 is a network id.

  • qumulo_cluster_port is the port the cluster listens on for the play, when a load balancer or tunnel maps the port the play connects to onto another. Unset, the rule takes qumulo_api_port, and at port 443 it needs both rest_api_enabled and web_ui_enabled on the tenant that holds the play’s network. Declare 443 when your port is mapped onto 443.

  • qumulo_cluster_kind is cnq, edge or baremetal. Step 2 refuses every tenant write to a cloud cluster: cnq, or, with the kind unset, a cluster whose protection type is object-backed. An on-premises cluster whose storage is object-backed declares baremetal. Null counts as unset. An unset kind falls back to the protection type for tenancy, and counts as cnq for the areas Terraform owns by default on a provider-formed cluster (Ownership), so declaring the kind of an on-premises cluster settles both.

  • qumulo_allow_management_disruption skips the continuity rule for the whole run.

  • The baseline, in a check run too, reads the cluster at step 2 whenever the inventory declares qumulo_tenants, qumulo_network, qumulo_smb_shares, qumulo_nfs_exports, qumulo_nfs_settings or qumulo_factory_defaults: the tenant list, which needs PRIVILEGE_TENANT_READ, the network document, the shares and the exports, the NFS settings and each tenant’s. A failure to read the tenant list stops the run.

  • A flat entry of qumulo_smb_shares or qumulo_nfs_exports takes tenants, a list of tenant names or all. It is needed once the inventory or the cluster, with the tenants the run creates, has more than one tenant; which pairs it claims is under Lists add, unless they purge. A flat entry’s tenant_id is deprecated, counts as tenants: [<that tenant's name>] with a warning, and cannot be given beside tenants.

  • The factory Files share and / export are tenant 1’s. qumulo_factory_defaults applies there, and does nothing, saying so, when tenant 1 is gone.

Manage tenants has the procedures, and Tenants and the continuity rule the reasons. Troubleshooting has the messages.

DNS

Variable: qumulo_dns. Step 4.

  • servers and search_domains are in the order the cluster asks. Each is the whole list.

  • lookup_overrides is the cluster’s lookup table, its /etc/hosts: names the cluster resolves without asking DNS. Each entry gives an ip_address and its aliases, the first of which is the name a lookup of the address returns. The table is the whole set: an address the cluster has and the table leaves out is removed.

  • The role applies DNS before the domain join, so an entry can name a domain controller that the site’s DNS does not.

  • When the role changes the servers, it clears the cluster’s DNS cache afterwards. It also clears it when the DNS step changed something and then failed. A change of lookup_overrides needs no clear.

Authoritative DNS

Variable: qumulo_authoritative_dns. Step 4.

  • The cluster answers DNS queries for its own name with its floating addresses, one node’s per answer. A cluster without floating addresses has no address to answer with.

  • Clients reach the answers only once the site’s DNS delegates the name to the floating addresses. The collection does not set that up.

  • host_restrictions: [] lets any client query the server.

  • Once a name is set, the cluster cannot clear it (G-DNS-FQDN-CLEAR). enabled: false stops the answers.

  • When qumulo_terraform_owned_areas lists dns.fqdn, declaring enabled or fqdn fails at the ownership check (Ownership). host_restrictions and record_ttl_seconds still apply.

Time

Variable: qumulo_time. Steps 4 and 14.

Step 4 applies the source, the NTP servers and use_ad_for_primary: false, which the hypervisor source needs. use_ad_for_primary: true is applied at step 14, after the join.

Name

Variable: qumulo_cluster_name. Step 5.

The name is also the cluster’s computer account in Active Directory. The server refuses a rename while the cluster is joined. The reason the role sets it first is in Identity.

File system settings

Variable: qumulo_filesystem_settings. Step 5.

A new permissions_mode applies to later operations only; the cluster rewrites no ACL it already holds. The role sets it before the directories and ACLs of step 17.

Web UI

Variable: qumulo_web_ui_settings. Step 5.

inactivity_timeout is in minutes, from 2 to 600; 0 turns the timeout off. An empty login_banner removes the banner.

Certificate

Variable: qumulo_ssl. Step 6.

  • certificate and private_key are PEM. probe lists the addresses to compare, as host or host:port; a host alone uses qumulo_api_port, and an empty list compares qumulo_api_host only. The cluster offers no way to read the installed certificate back (G-SSL-READBACK), so the step installs when any probed address serves a certificate other than the first of certificate. An address that is not probed is not compared, and keys are never compared.

  • ca_path_after is the CA to verify the cluster with once the certificate is installed. Declaring it also lets the role install a chain that does not verify against the current qumulo_ca_path.

  • A newly formed edge serves a factory certificate that cannot be verified (G-FACTORY-TLS), and a run that connects to it with qumulo_validate_certs: false sends the admin password unverified. Manage certificates installs the certificate in a run of its own that changes nothing else; the baseline that follows runs with verification on, and its certificate step reports ok.

Cipher suites

Variable: qumulo_ssl_ciphers. Step 6.

  • tls_1_2 and tls_1_3 are lists of suites in the order the cluster prefers them. The order is part of the setting.

  • The cluster adds ECDHE-RSA-AES128-SHA256 to the end of a tls_1_2 list and TLS_AES_128_GCM_SHA256 to the end of a tls_1_3 list that leaves it out. ssl_ciphers adds the same suite before it compares, so a second run changes nothing (QUIRK-060).

  • An empty list fails (QUIRK-061).

  • The cluster keeps a TLS 1.2 name it does not know and never uses it (QUIRK-061). The role cannot tell such a name from a valid one.

Monitoring and Nexus

Variables: qumulo_monitoring, qumulo_nexus_api_token, qumulo_nexus_api_url. Step 7.

Whether the cluster connects to Nexus, where, how often, and which capabilities it allows

The cluster’s registration

  • A key left unset keeps the cluster’s value. Turning enabled off also turns the Nexus connection off.

  • The role registers the cluster only when qumulo_monitoring.nexus.nexus_enabled is true and there is a join key or qumulo_nexus_api_token. With the token, nexus_registration mints its own single-use key for each cluster. nexus_account_id names the organization the minted key registers to. qumulo_nexus_api_url names a Nexus API other than the modules’ default.

  • A join key registers one cluster only (G-NEXUS-KEY).

  • A registered cluster is left alone.

  • The license step never uses the token. The collection never reads licenses in Nexus (Licensing and capacity).

Register a cluster with Nexus has the procedure.

Audit logs

Variable: qumulo_audit_destinations. Step 7.

  • Destinations are listed by name. A destination the list leaves out is left alone, and state: absent deletes one.

  • When qumulo_terraform_owned_areas lists audit.cloudwatch, the ownership check at step 2 refuses every declared entry whose type is CLOUDWATCH before anything is written, unless qumulo_take_over_from_terraform is true. An entry that would change nothing is refused too.

Capacity

Variable: qumulo_capacity. Steps 9 to 11.

  • The license step runs whenever qumulo_capacity is declared, and nothing in it waits for a license.

  • A host’s qumulo_capacity replaces the group’s whole (Precedence). The example inventory keeps the license document in a variable of its own, vault_qumulo_license_document, which the group’s qumulo_capacity refers to.

  • A clamp below the stored one fails. playbooks/edge_cache_resize.yml chooses the route to a smaller cache (G-CLAMP-SHRINK).

license

Missing license

Clamp

pending (default)

Handed off, naming the cluster’s UUID

Waits for the license

required

As pending, and the role sets cluster_baseline_license_missing while the cluster has no active license

Waits for the license

none

Nothing is handed off; the role says the edge runs without a license

  • none goes with a clamp and never with license_document; the license step refuses the pair.

  • With a license active, none runs as pending and warns that none is stale.

  • An edge with none provisions nothing above 1 TB until a license arrives (G-EDGE-FLOOR).

License an edge has the procedure for the two passes.

Local users and groups

Variables: qumulo_local_groups, qumulo_local_users. Step 13.

  • The role creates the groups without members, then the users, then sets the groups’ members. A primary group must exist before its users.

  • A local password cannot be read back (G-PASSWORD). update_password: on_create, the default, sends it only when the user is created. always sends it on every run and reports a change each time.

  • Changing the password of admin needs allow_admin_password_change, because the server applies it to every node’s console and SSH password too (G-ADMIN-OS).

  • qumulo_api_password_after is not a key of these variables (Connection); Rotate the admin password has the procedure.

Active Directory

Variable: qumulo_ad. Step 14.

On an edge, join_user and join_password are what let the rebuild’s predestroy phase delete the computer account and record that the old edge left the domain. A replay with qumulo_ad refuses to join under the old name without that record, unless edge_rebuild_old_edge_destroyed is true.

Kerberos

Variable: qumulo_kerberos. Step 14: the keytab before the join, and the setting after it and after the domain-time step.

The keys, their types and which are no_log are in ansible-doc -t role qumulo.cluster.cluster_baseline.

  • keytab is base64, and whitespace in it is ignored. keytab_state: absent deletes the cluster’s keytab, and the role then ignores keytab and keytab_path.

  • The keytab step runs when keytab, keytab_path or keytab_state is defined, with kerberos_keytab. The settings step runs when use_alt_security_identities_mapping is defined, with kerberos_settings. Each receives the keys of qumulo_kerberos, never the variable whole.

  • A keytab to install, with keytab or keytab_path and no keytab_state: absent, fails the role before its first write when qumulo_ad is also declared (G-KRB-AD). keytab_state: absent beside qumulo_ad deletes the keytab, then joins.

  • The role never leaves a domain. A cluster that is already joined, with no qumulo_ad declared, passes the opening check, and the keytab step then fails in kerberos_keytab (G-KRB-AD). To move a joined cluster to a standalone KDC, run ad_domain with state: absent, then the baseline with the keytab.

  • capture_info writes use_alt_security_identities_mapping and never a key (Capture areas).

Keep secrets out of the inventory shows how to keep the keytab encrypted, and Join a cluster to Active Directory has the order of a keytab and a join.

Mappings, home directories and SAML

Variables: qumulo_user_defined_mappings, qumulo_identity_attributes, qumulo_saml. Step 14, after the join.

Join a cluster to Active Directory has the procedures.

Roles

Variables: qumulo_roles, qumulo_role_members. Step 15.

  • Members are trustees in the collection’s grammar: local:svc-backup, ad:CORP\Qumulo-Admins, ldap_group:admins, sid:S-1-5-21-..., uid:1000 or Everyone. A bare name is refused. ad: trustees resolve only after the join, except ad:NT AUTHORITY\Authenticated Users.

  • The role creates custom roles, then applies qumulo_role_members, then deletes the roles declared state: absent. The cluster refuses to delete a role that still has members, so qumulo_role_members removes them first, with purge: true or state: absent.

  • privileges is the role’s whole set. The privileges differ between Qumulo Core versions, and a name the cluster does not know fails before anything is written.

  • The built-in roles Administrators, Observers, Data-Administrators and Qumulo-Support cannot be changed. Name them in qumulo_role_members only.

Portal

Variables: qumulo_portal, qumulo_portal_hosts. Step 16.

  • qumulo_portal is declared on the spoke. hub names an inventory host with a qumulo_cluster_uuid; the edge rebuild also requires it to be in qumulo_hubs.

  • Step 16 checks that both clusters run one Qumulo Core version, proposes the spoke portal and its roots, accepts and authorizes them on the hub, and waits until the portal is ACTIVE.

  • A spoke_root must not exist on the spoke yet, and its parent directory must. A hub_root must exist on the hub.

Pair an edge with its hub has the procedure.

Directories and ACLs

Variables: qumulo_directories, qumulo_file_acls. Step 17.

  • A path may have a mode in qumulo_directories or an ACL in qumulo_file_acls, not both. Setting a mode rewrites the ACL, and the role refuses a path with both before it writes anything (G-FS-ACL-MODE).

  • qumulo_file_acls gives a path its whole ACL, entries in order, with the trustees in the grammar shares take.

  • The cluster applies a new ACL to the path alone. Entries with inheritance flags reach what is created beneath it afterwards.

  • On an edge, a path inside a spoke root is the hub’s data. The role refuses to change its ACL unless the entry sets allow_data_loss: true, because the write replaces the hub’s ACL whole.

Replication

Variables: qumulo_replication_relationships, qumulo_replication_address, qumulo_replication_port, qumulo_previous_cluster_uuids. Step 21.

qumulo_replication_relationships is declared on the source host. Each entry has a source_path there, a target that is an inventory host, and a target_path on it. A relationship is the two paths and the target’s UUID; the address and the port are settings of the target host.

The step makes these checks once, before it touches any relationship, and fails when one is unmet:

  • The target is an inventory host with a qumulo_cluster_uuid and a qumulo_replication_address.

  • The target host declares the target path in its qumulo_directories, path only, with no entry inside it. The source host’s run creates the directory when the play does not include the target.

  • No target path is /, declared twice or nested on one target host, or inside a portal root on it.

  • No two hosts declare one replication address and port.

  • No host’s qumulo_previous_cluster_uuids holds its own UUID.

qumulo_replication_address is required on every target; qumulo_replication_port defaults to 3712. Step 21 also checks the tenant that serves the address, on every run, an established relationship included. With one tenant, that tenant must have replication_enabled. With two or more, the address must lie on a network, in the target’s network document, whose tenant has it on; an address that no network’s ranges hold, or that lies on a network no tenant holds, is not judged and gets a warning. The user the play connects to the target as needs PRIVILEGE_TENANT_READ, and with two or more tenants PRIVILEGE_NETWORK_READ. Status is never read for this. While qumulo_previous_cluster_uuids is set on a source, a relationship whose replica may be the only copy of the source’s data is held.

Entry keys with a rule:

  • allow_non_empty_target: true lets the source’s content replace a target directory that already holds entries; the first job deletes whatever the source lacks. Without it, such a directory is refused.

  • state: absent deletes the relationship on the source, then on the target, and the target directory keeps its data. Setting the entry back to present later with allow_non_empty_target replaces that data.

A relationship into an edge that declares qumulo_capacity is not created or authorized until the edge’s license and clamp apply. The run reports a hand-off naming ansible-playbook qumulo.cluster.edge_license_complete, which creates the relationship once they do, and does not fail.

The grammar of a release entry is <target host>:<target path>@<record id>:<rows>, for example dr01:/replicas/edge01-projects@<record id>:O2,O4. The rows are those of the overwrite table. A refusal prints each entry that would lift it. A release is passed with -e for one run (Run-level variables). A release that lifts nothing in a run fails it, and so does one that is malformed or that names a target host the run reaches but no relationship of the run. An entry for a host the run does not reach is left alone, so --limit still works.

Replicate a directory and Restore a replica have the procedures.

Factory share and export

Variable: qumulo_factory_defaults. Steps 18 and 19.

Every formation creates the SMB share Files and the NFS export / (G-FACTORY). smb_files_share and nfs_root_export each say what becomes of one: absent removes it and present leaves it. A rebuild needs both keys. NFSv4 cannot be turned on while the / export exists.

Quotas and snapshot policies

Variables: qumulo_quotas, qumulo_snapshot_policies. Step 20.

The cluster refuses both under a spoke root (G-SPOKE-PATHS), so step 2 fails before it writes anything when one is declared there. A hub’s roots may carry both.

A policy entry takes the options of snapshot_policy, among them lock_key: the name or id of a key in the cluster’s file system key store, which locks each snapshot the policy takes. Declare it by the key’s name: the name holds on a rebuilt or cloned cluster, where the key gets a new id. An entry without it keeps the policy’s key, and "" takes the key off. Step 2 refuses the run, before anything is written, when a lock_key names a key the key store does not hold, unless -e qumulo_allow_deferred_policy_lock_keys=true is given. A null lock_key is read as unset. The check names each policy, its key and the two ways on. An entry with state: absent is not checked. The user the play connects as needs PRIVILEGE_FS_KEY_MANAGEMENT_READ to read the key store.

S3

Variables: qumulo_s3_settings, qumulo_s3_buckets, qumulo_s3_bucket_policies, qumulo_s3_access_keys. Steps 19 and 22.

  • Buckets and the base path need the directories of step 17. Policies need the users and the domain join of steps 13 to 15.

  • A bucket under a spoke root fails at step 2, before anything is written.

  • The cluster shows a key’s secret only when it makes the key (G-S3-KEY). Step 22, the role’s last, writes the secret at once to <cluster_baseline_artifact_dir>/<inventory host>/secrets/s3-<user>-<access_key_id>.yml, a directory and a file readable only by their owner. The role names each new key and its file in cluster_baseline_s3_access_keys, never the secret.

  • An entry of qumulo_s3_access_keys that would make a key fails when the host has no artifact directory.

Serve a directory as an S3 bucket has the procedure.

FTP

Variable: qumulo_ftp_settings. Step 19, after the S3 tasks.

  • The keys are the options of ftp_settings. A key the variable leaves out keeps the cluster’s value.

  • The cluster has one FTP server for every network, so the variable has no tenant.

  • anonymous_user is local:<name>, the name of a local user, or "" for no anonymous logins. The cluster takes no other identity. Step 13 applies qumulo_local_users first, so the anonymous user may be one the same run creates. The name is compared in any case, and the result shows it as the cluster spells it; a check run notes a user the cluster does not hold yet.

  • A local user that is deleted leaves the setting as a local user with an empty name, which the modules read as local:. A declared "" replaces it, and capture leaves anonymous_user out.

  • greeting takes 1 to 1024 bytes of UTF-8, compared exactly, trailing newline included. The cluster cannot set the factory greeting back (G-FTP-GREETING), so a capture taken before the change holds the text to go back to.

  • The FTP settings are applied after the directories and ACLs of step 17.

Serve FTP over TLS with an anonymous user has the procedure.

Precedence

Ansible’s usual precedence applies, from lowest to highest:

  1. group_vars/qumulo_clusters.yml, then the more specific group_vars/qumulo_edges.yml or qumulo_hubs.yml.

  2. Variables on the host in the hosts file, or from the Terraform plugin.

  3. host_vars/<host>.yml.

  4. Facts the roles set during a run, such as a new address or password.

  5. -e on the command line.

  • A dict is replaced whole, never merged. A host that sets qumulo_capacity gives every key it needs.

  • A host_vars file outranks the Terraform plugin’s variables.

  • A variable given with -e applies to every host of the run, a portal’s hub included, and outranks the facts of level 4. This holds for the connection variables such as qumulo_validate_certs.

Playbooks and roles lists the roles and the playbooks that run them.

Upgrade variables

The upgrade playbook reads qumulo_upgrade_* variables of its own, such as qumulo_upgrade_target and qumulo_upgrade_images, and the qumulo_cluster_kind the Terraform plugin sets. The upgrade lists them.
