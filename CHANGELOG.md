## v0\.1\.0

<a id="release-summary"></a>
### Release Summary

0\.1\.0 is the first release of qumulo\.cluster\, an Ansible collection for day\-2 configuration of Qumulo Core clusters\. You declare shares\, exports\, identity\, portals\, quotas\, snapshot policies\, licensing and monitoring in an inventory\, and the collection applies them through the Qumulo REST API\. Its roles also rebuild an unprotected edge\, upgrade a fleet hop by hop\, and pair\, fail over and fail back replication\. Every module supports check mode\, and every module that changes a cluster supports diff mode\, so you see each change before you make it\. 0\.1\.0 was tested on Qumulo Core 7\.10\.3 build 385145\.1\.82\, on single\-node Qumulo Core containers\, a single\-node Cloud Native Qumulo \(CNQ\) cluster in AWS\, and a four\-node cluster on lab hardware\. The collection needs Qumulo Core 7\.10\.3 or later and ansible\-core 2\.20 or later\. It is a pre\-release\: interfaces may change before 1\.0\.0\, and it is not supported for production use yet\. The documentation index is <code>docs/README\.md</code> in the installed collection and in the public repository Qumulo/qumulo\-ansible on GitHub\.

<a id="minor-changes"></a>
### Minor Changes

* Documentation \- docs/how\-to/nfs\-kerberos\.md serves NFS with Kerberos from a standalone KDC\.
* Documentation \- the pages under docs/ are split by what the reader wants\: docs/tutorials/ for learning on a cluster you already run\, docs/how\-to/ for one task each\, docs/reference/ for facts to look up\, and docs/explanation/ for why the collection works the way it does\. docs/README\.md lists every page\. The gap and quirk registers and the troubleshooting page are in docs/reference/\.
* The Nexus modules take an optional Nexus user\'s API token \(<code>nexus\_api\_token</code>\) to mint join keys and retire clusters\.
* The collection is MIT apart from these GPL\-3\.0\-or\-later files\: the inventory plugin <code>qumulo\.cluster\.terraform</code>\, the action plugin of <code>qumulo\.cluster\.replication\_restore\_lock</code> and the filter plugins in <code>plugins/filter/</code>\, with the unit tests of the inventory and action plugins\; <code>LICENSES/GPL\-3\.0\-or\-later\.txt</code> holds the license text\.
* The tenant and tenant\_info modules\, and the tenant options of the existing modules\, use the multitenancy REST API\, which Qumulo marks as preview in Qumulo Core 7\.10\.3 and 7\.11\.0\; a later release may change it\.
* access\_token \- new module that makes sure a user holds an access token\, rotates the user\'s tokens\, making the new one before it deletes the old\, or revokes them\, and sets <code>enabled</code> and <code>expiration\_time</code>\. The cluster stores no name for a token\, so a user\'s tokens are managed as one set\. It writes a new token\'s bearer at once to a file of its own in <code>secret\_destination</code>\, readable only by its owner\, returns it in that run only\, and refuses to make a token unless the task sets <code>no\_log</code> and a destination\. It refuses to delete\, disable or expire the token the task connects with unless <code>allow\_management\_disruption</code> is set\.
* artifact\_dir \- new filter that gives the cluster\_baseline and edge\_rebuild roles their artifact directory\, beside the inventory source on disk that defines the host\, and none for a host list such as <code>\-i edge01\,</code>\.
* audit\_destination \- new module that creates\, changes or deletes an audit log destination by name\, writing its whole configuration with PUT\. It refuses any write while its terraform\_owned\_areas option lists audit\, and a write to a CloudWatch destination while it lists audit\.cloudwatch\, unless take\_over\_from\_terraform is true\.
* auth\_cache\_clear \- new action module that clears the cluster\'s cache of identities and group memberships\, always reporting a change \(G\-ACTIONS\) and in check mode clearing nothing\. The <code>cluster\_baseline</code> role runs it after a user\-defined mapping or an identity\'s home directory changed\, even when a later step of the two fails\.
* authoritative\_dns \- new module that turns the cluster\'s authoritative DNS server on or off and sets its name\, the clients that may query it and how long answers may be cached\, comparing client ranges as sets of addresses and refusing enabled and fqdn where Terraform owns them\.
* capacity\_clamp \- the default <code>rounding\_tolerance</code> is the larger of 1\% of the request and 8 GiB\. On a small edge the server rounds the clamp up to a whole 8 GiB unit\, so a smaller tolerance would refuse a second run of the same request as a decrease\.
* capacity\_clamp\, portal\_eviction\_settings and edge\_cache\_route \- new modules\, and the edge\_cache\_resize role and playbooks\, to resize an unprotected edge\'s cache without a rebuild where the server allows it\.
* capture\.yml \- <code>qumulo\_capture\_dir</code> defaults to a <code>captures</code> directory beside the inventory source\, so Ansible does not read the capture files as inventories\.
* capture\.yml \- adoption leaves out of the host\_vars file each SMB share or NFS export entry that the inventory already declares with the same values\, compared as the modules compare them\, or removes\, with a comment naming the inventory\'s entry and any key the cluster keeps that no entry declares\. Before it writes the host\_vars file\, it refuses a network the inventory declares too and an entry the inventory declares with other values\. Leaving out only the variables the inventory defines would not be enough\: a flat <code>qumulo\_smb\_shares</code>\, <code>qumulo\_nfs\_exports</code> or <code>qumulo\_network</code>\, or a <code>qumulo\_factory\_defaults</code> removal\, in group\_vars stays in force beside the <code>qumulo\_tenants</code> that adoption writes\, and the baseline would refuse what is declared twice\. The <code>host\_vars\_duplicates</code> filter makes the per\-entry comparison\.
* capture\.yml \- captures everything the collection configures through <code>capture\_info</code>\: identity\, DNS\, time\, local users and groups and role members\, the network document\, cloud monitoring and the Nexus connection\, the eviction threshold and an active license\, the AD membership\, the spoke portal\, directories\, the SMB and NFS settings\, shares and exports and whether the factory share and export are present\, quotas\, snapshot policies and the replication relationships the cluster is the source of\, and <code>qumulo\_portal\_hosts</code> and <code>qumulo\_replication\_address</code> from the peers captured in the same run when their records agree\. The file is sorted\, so a second capture of an unchanged cluster writes the same file\, and ends with comments naming each secret to supply and what was left out\. Areas Terraform owns are not written to the capture file\. With <code>qumulo\_adopt\=true</code> it writes the host\'s host\_vars beside the inventory source that defines it\, with what the inventory does not already define\, never rewriting an existing file\.
* capture\.yml \- the capture and adopted host\_vars files tag each string they are written with <code>\!unsafe</code>\, and only those strings\, so a template added to the file by hand is still evaluated\. Ansible templates the strings it reads from an inventory file\, so without the tag a share description or other value holding a Jinja expression would run on the controller at the next play that read the file\. The comments that end the files wrap every line\, so a newline in a captured path cannot end a comment\.
* capture\.yml \- when the inventory defines <code>qumulo\_tenants</code>\, adoption keeps what the capture holds under each tenant\, entry by entry\. Each share and export of a captured tenant that the inventory does not declare is written in the flat <code>qumulo\_smb\_shares</code> or <code>qumulo\_nfs\_exports</code> with <code>tenants</code> naming its tenant\, one the inventory declares the same way is left out with a comment\, and a captured tenant the inventory does not declare or removes gets a comment\. Adoption refuses\, and writes no host\_vars file\, when the inventory declares a captured share or export with other values\, declares a captured tenant\'s switches or settings otherwise\, or does not list a captured tenant network for that tenant\, or lists it with other values\, since the baseline\'s network document would leave it out or rewrite it\. A captured <code>tenants\: all</code> entry is written as the list of the captured tenants when the inventory declares other tenants\, a tenant the inventory renames is matched by its <code>previous\_name</code>\, and the capture\'s <code>Default</code> with <code>state\: absent</code> is not written and gets a comment\.
* capture\_info \- <code>qumulo\_factory\_defaults</code> reports the factory <code>Files</code> share and <code>/</code> export of tenant 1 only\; a share or export of that name in another tenant does not count\.
* capture\_info \- a capture with the <code>tenants</code> area\, as the default <code>gather\_subset\: \[all\]</code> reads\, writes <code>qumulo\_tenants</code> and puts each share and export\, and each network a tenant holds off the backend bond\, under its tenant\'s entry\. <code>qumulo\_smb\_shares</code> and <code>qumulo\_nfs\_exports</code> hold only the shares and exports identical in two or more tenants\, with <code>tenants</code>\, and no network\, share or export carries <code>tenant\_id</code>\. On a cluster with one tenant\, leaving the <code>tenants</code> area out keeps the shares\, exports and networks in the flat lists\.
* capture\_info \- a cluster without tenant 1 is captured with <code>\{name\: Default\, state\: absent\}</code> in <code>qumulo\_tenants</code>\, and with the factory share and export <code>absent</code> in <code>qumulo\_factory\_defaults</code>\, so a rebuild from the inventory drops the <code>Default</code> tenant\, <code>Files</code> share and <code>/</code> export that a newly formed edge has and the old one lacked\. No such entry is written when another tenant is named <code>Default</code>\, or when a replay of the capture could not delete <code>Default</code>\: a network on the backend bond stays in <code>qumulo\_network\.frontend\_networks</code>\, or <code>leave\_out</code> names <code>network</code>\, <code>smb</code> or <code>nfs</code>\. A network no tenant holds always gets the entry\. The <code>tenant 1</code> note in <code>left\_out</code> says which case applies and what to do\. Qumulo marks the multitenancy REST API\, which capture reads the tenants through\, as preview\; a later Qumulo Core release may change it\.
* capture\_info \- a cluster without tenant 1 whose networking the host manages \(no managed interfaces\, only HOST networks\) is captured with <code>previous\_name\: Default</code> on the one tenant that holds a network\, and no <code>Default</code> entry\, when every network has a tenant\, the <code>network</code>\, <code>smb</code> and <code>nfs</code> areas are read and no tenant is named <code>Default</code>\. A rebuild from the capture renames the <code>Default</code> the new edge forms with to that tenant\, which keeps the HOST network\, the one the play reaches REST on\, in tenant 1 throughout\. <code>smb\_files\_share</code> is <code>present</code> when the capture writes a share named <code>Files</code>\, in any letter case\, for that tenant\, and <code>nfs\_root\_export</code> when it writes that tenant\'s export at <code>/</code>\, since the rebuilt edge\'s tenant 1 is that tenant\. A <code>/</code> export of that tenant\'s that the capture leaves out\, as for a deleted mapped user\, keeps <code>Default</code> absent\, since a rebuild that waives the export\'s drift would otherwise leave the factory <code>/</code> export in its place\. In the other cases the capture writes <code>Default</code> absent\. The <code>tenant 1</code> note in <code>left\_out</code> says which\. <code>clone\_host\_vars</code> keeps the <code>previous\_name</code>\, so a fresh target\'s <code>Default</code> is renamed to that tenant\.
* capture\_info \- also returns <code>spoke\_roots</code>\, the directories of the cluster\'s spoke portals\' roots\, and <code>replication\_targets</code>\, the directories it receives replication into\, which a clone of it leaves out\.
* capture\_info \- an NFS export restriction whose <code>require\_tls</code> is false is captured without it\, which declares the same restriction\, since Qumulo Core stores false when it is unset\, and <code>nfs\_export</code> refuses <code>require\_tls\: false</code> on a release before 7\.11\.0\. A restriction that requires TLS is captured with <code>require\_tls\: true</code>\.
* capture\_info \- new area <code>tenants</code> in <code>gather\_subset</code> and <code>leave\_out</code>\, which writes <code>qumulo\_tenants</code>\, sorted by name\. Each entry holds the tenant\'s six services\, its networks \(<code>\[\]</code> for none\)\, its SMB and NFS settings \(<code>inherit</code> without settings of its own\, else the full record\)\, and its shares and exports\, each list left out when it has none\. Tenant 1 renamed is written with <code>previous\_name\: Default</code>\. Qumulo marks the multitenancy REST API\, which the area reads\, as preview\; a later Qumulo Core release may change it\.
* capture\_info \- new audit area\, which captures the audit log destinations as qumulo\_audit\_destinations\, and leave\_out takes audit\.cloudwatch\, which leaves out the CloudWatch destinations\.
* capture\_info \- new module that reads every setting the collection\'s modules write and the cluster reads back\, and returns it as the cluster\_baseline role\'s variables in the shape the role passes to those modules\, with the secrets to supply and what it left out named apart\.
* capture\_info \- on a cluster with two or more tenants\, the <code>smb</code> and <code>nfs</code> areas without the <code>tenants</code> area write <code>qumulo\_smb\_shares</code> and <code>qumulo\_nfs\_exports</code> empty and note each tenant\'s shares\, exports and SMB and NFS settings in <code>left\_out</code>\. To write them\, add <code>tenants</code> to <code>gather\_subset</code>\, which puts them under their tenants\.
* capture\_info \- reading the <code>network</code>\, <code>smb</code>\, <code>nfs</code> or <code>tenants</code> area reads the tenant list\, and the <code>smb</code> and <code>nfs</code> areas each tenant\'s SMB or NFS settings\, so the user the play connects as needs <code>PRIVILEGE\_TENANT\_READ</code>\, without which the capture fails\. The <code>tenants</code> area also reads the protection type\. Remedy\: give the user read access to the tenants\.
* capture\_info \- reads the FTP server settings back as the new <code>ftp</code> area\, which writes <code>qumulo\_ftp\_settings</code>\. An anonymous user that names a deleted local user\, or is anything but a local user\, is left out with a note\. A capture of every area reads the FTP settings\, which needs <code>PRIVILEGE\_FTP\_READ</code>\.
* capture\_info \- the <code>s3</code> area captures each S3 access key by its owner and id as <code>qumulo\_s3\_access\_keys</code>\, and names each key\'s secret\, which the cluster never returns\, under <code>supply</code>\.
* capture\_info \- the <code>s3</code> area captures each bucket\'s policy as <code>qumulo\_s3\_bucket\_policies</code>\, each principal as a trustee\, leaving out\, with the reason\, a policy with a principal /v1/identity/find cannot resolve\.
* capture\_info \- the <code>s3</code> area captures the buckets outside the spoke roots as <code>qumulo\_s3\_buckets</code>\, and the <code>directories</code> area declares each bucket\'s directory\.
* capture\_info \- the <code>snapshots</code> area lists each key of the file system key store in <code>left\_out</code> by name and id\, since a key is registered only with its private key or a signature of its name\.
* capture\_info \- the dns area also reads the authoritative DNS settings\, as qumulo\_authoritative\_dns\, and leave\_out takes dns\.fqdn\, which leaves out enabled and fqdn\.
* capture\_info \- the dns area also reads the lookup overrides\, as qumulo\_dns\.lookup\_overrides\.
* capture\_info \- the following are noted in <code>left\_out</code>\: a cloud cluster\'s tenant services\, which are not written since no cloud cluster accepts a tenant write \(G\-TENANT\-CLOUD\)\; a missing tenant 1\; a tenant on its own identity configuration\, written in full except its identity\; with the <code>tenants</code> area\, or on a cluster with two or more tenants\, a VLAN that carries two tenants\' networks\, or a tenant\'s and an unbound one\; and\, on a cluster with two or more tenants\, a backend network a tenant holds \(G\-TENANT\-BACKEND\)\, and an unbound network\.
* capture\_info \- the new <code>kerberos</code> area writes <code>qumulo\_kerberos</code> on every capture\, and names a held keytab\'s principals in a supply line\, without the keytab\. Naming them reads the keytab\, which needs <code>PRIVILEGE\_KERBEROS\_KEYTAB\_READ</code>\; a user without it\, such as a member of the built\-in Observers role\, gets the setting and a <code>left\_out</code> entry in place of the supply line\, and the capture goes on\.
* capture\_info \- the new <code>s3</code> area captures the S3 server settings as <code>qumulo\_s3\_settings</code>\, and the <code>directories</code> area declares the base path\'s directory\, which <code>s3\_settings</code> requires to exist\.
* capture\_info \- the ssl area also captures the cipher suites\, as qumulo\_ssl\_ciphers\.
* capture\_info \- with the <code>tenants</code> area\, a VLAN that carries a tenant\'s network and a network no tenant holds stays in <code>managed\_interfaces</code>\, and the tenant network carries its <code>vlan\_id</code> too\, so the baseline\'s step 2 refuses it as declared in two places rather than take the other network off the VLAN\. The refusal says to list that network under the VLAN\'s tenant with its <code>vlan\_id</code> and remove the VLAN from <code>frontend\_vlans</code>\, or to give each network a VLAN of its own\.
* capture\_info \- with the <code>tenants</code> area\, a tenant network\'s VLAN is written on the network as <code>vlan\_id</code>\, with <code>mtu</code> when the VLAN sets one\. <code>managed\_interfaces</code> then lists neither the VLANs that carry only tenant networks nor tenant networks on the frontend bond\. A backend\-bond network and a network no tenant holds stay in <code>qumulo\_network\.frontend\_networks</code>\.
* capture\_info \- without the <code>tenants</code> area \(left out of <code>gather\_subset</code>\, named in <code>leave\_out</code>\, or not offered by the cluster\)\, every network is written in <code>qumulo\_network\.frontend\_networks</code>\. On a multi\-tenant cluster each network a tenant holds off the backend bond carries <code>tenant</code> by name\.
* capture\_info \- writes <code>qumulo\_capacity\.license\: none</code> for an unprotected edge that holds no license\.
* capture\_info \- writes each snapshot policy\'s <code>lock\_key</code> by the key\'s name\, so a replay sets it again\; when the key store cannot be read\, or when the key has no name \(QUIRK\-120\)\, it leaves the key out with a <code>left\_out</code> note\.
* client \- an error that quotes a URL\, from the server\'s description or a redirect\'s location\, quotes it without its query string or user information\.
* clone\_edge\.yml \- new playbook that gives a fresh cluster another cluster\'s configuration\: it captures the source\, changing nothing on it\, writes the target\'s host\_vars file with clone\_host\_vars\, and runs the baseline on the target\, the first pass\, with the secrets <code>clone\_edge\_supply</code> gives for that run only\. Configuration only\, no data\. A second run writes the same file and changes nothing\, and a run that would write a different file refuses\.
* clone\_edge\.yml \- the clone leaves out of the target\'s host\_vars file each share or export entry that the target\'s inventory already declares or removes\, with a note\, for the same reason as adoption\. Since the target creates the share or export from the inventory\'s entry alone\, the clone refuses\, before it writes anything\, an entry the inventory declares with other values or without a key the source\'s entry sets to other than what a create gives\.
* clone\_host\_vars \- a <code>qumulo\_tenants</code> entry with <code>state\: absent</code> is left out of the clone with a note\, since the target\'s <code>Default</code> holds the target\'s own networks\; declare it absent on the target once its networks are under a tenant that stays\. A target whose capture notes a missing tenant 1 has no tenant from formation\, so the fresh\-target check counts each tenant it holds\, and a clone onto such a target fails unless <code>allow\_configured\_target</code> is set\. The rule copies tenants that Qumulo\'s multitenancy REST API\, marked as preview\, defines\; a later Qumulo Core release may change them\.
* clone\_host\_vars \- a target whose capture holds a tenant beyond the one formation creates\, or a share or export in any tenant other than the factory <code>Files</code> and <code>/</code> in the tenant formation creates\, is refused as not fresh unless <code>allow\_configured\_target</code> is set\. The clone\_edge playbook\'s target capture reads the <code>tenants</code> area\, so its fresh\-target check sees them\. Remedy\: clone onto a newly formed cluster\, or set <code>allow\_configured\_target</code> \(<code>clone\_edge\_allow\_configured\_target</code>\) for a second run of the same clone\.
* clone\_host\_vars \- copies <code>qumulo\_ftp\_settings</code>\.
* clone\_host\_vars \- copies the S3 settings\, buckets and bucket policies\, leaving out a bucket\, its policy and the base path in the source\'s spoke roots or on what it receives replication into\, and the source\'s access keys\, each with a note\; a target that holds an S3 bucket or access key is not fresh\.
* clone\_host\_vars \- copies the TLS cipher suites and the audit log destinations\, except the CloudWatch destinations\, whose log group and region are the source\'s\, which it leaves out with a note\.
* clone\_host\_vars \- new module that derives a fresh cluster\'s host\_vars from another cluster\'s capture\, with a rule for every variable a capture holds\: the clone\'s own UUID and a new name\; AD settings copied for a fresh join\, with supply lines for the join credentials\, the clone\'s own Nexus join key and a license for its UUID\; and no portal\, replication relationship\, network document\, or share\, export or directory in the source\'s spoke roots or receiving its replication\, each left out with a note\. It refuses a target that is the source or holds configuration of its own\, and a name another cluster has\.
* clone\_host\_vars \- new rule for <code>qumulo\_tenants</code>\. Each tenant keeps its name\, <code>previous\_name</code>\, services and SMB and NFS settings\, and its networks are dropped with a note per tenant\, since they hold the source\'s addresses\. Its shares and exports are filtered as the flat lists are\: one in a spoke root of the source\'s portal\, or in a directory the source receives replication into\, is left out with a note that names its tenant\.
* cluster\_baseline \- <code>cluster\_baseline\_replication\_on\_held</code> set to <code>report</code> keeps a held relationship as a result instead of failing step 21\, as the rebuild\'s replay does\.
* cluster\_baseline \- <code>qumulo\_capacity\.license\: none</code> declares an edge that runs without a license\, within the capacity its formation gives it\. The license step hands nothing off for it and writes its clamp with no license\, in the first pass and the second\; a <code>pending</code> or <code>required</code> edge\'s clamp still waits for its license\. The step refuses <code>none</code> beside a license document\, before anything applies the document\. While a clamp waits\, the step reads the stored one\, and the hand\-off says when the license\'s cap will apply at the next quorum formation without a clamp write\. On an edge with a declared clamp\, it warns when a held license\'s cap still waits for a quorum formation\, and on a <code>none</code> edge that holds a license after all\, that <code>none</code> is stale\.
* cluster\_baseline \- <code>tenant\_id</code> on an entry of <code>qumulo\_smb\_shares</code> or <code>qumulo\_nfs\_exports</code> is deprecated\; the plan translates it to <code>tenants</code> with a warning\, and skips an entry whose id no tenant has\, with a warning\. A flat entry of <code>qumulo\_network\.frontend\_networks</code> names its tenant with <code>tenant</code>\, and its <code>tenant\_id</code> is translated with a warning too\. Remedy\: write <code>tenants</code> on a share or export\, and <code>tenant</code> on a network\.
* cluster\_baseline \- a <code>qumulo\_terraform\_owned\_areas</code> the inventory gives is all that Terraform owns\, an empty list included\, so a list that leaves out <code>network\.floating\_ips</code> gives the floating addresses to the role\. A host with <code>qumulo\_cluster\_kind\: cnq</code> and <code>qumulo\_managed\_by\: terraform\_provider</code> whose list leaves the area out is refused before any write\, as the Terraform inventory plugin refuses such an output\. Add <code>network\.floating\_ips</code> to the list when Terraform sets the floating addresses\, or set <code>qumulo\_managed\_by\: none</code> when the provider did not form the cluster\.
* cluster\_baseline \- applies the keytab of <code>qumulo\_kerberos</code> with <code>kerberos\_keytab</code> before the domain join\, and its setting with <code>kerberos\_settings</code> after it\, and refuses a keytab to install beside <code>qumulo\_ad</code> before its first write\.
* cluster\_baseline \- before its first write\, the role reads the cluster\'s tenants\, network document\, SMB shares\, NFS exports\, NFS settings and each tenant\'s NFS settings whenever the inventory declares any of <code>qumulo\_tenants</code>\, <code>qumulo\_network</code>\, <code>qumulo\_smb\_shares</code>\, <code>qumulo\_nfs\_exports</code>\, <code>qumulo\_nfs\_settings</code> and <code>qumulo\_factory\_defaults</code>\, so the user the play connects as needs read access to each\, <code>PRIVILEGE\_TENANT\_READ</code> for the tenant list included\. Remedy\: give the user read access to the tenants\, the network\, the SMB shares and the NFS exports and settings\.
* cluster\_baseline \- floating ranges in <code>qumulo\_network\.frontend\_networks</code> that Terraform owns are refused before step 2 reads the cluster\, in the role\'s words\, with where each is declared and the owner\: <code>qumulo\_terraform\_owned\_areas</code> when the inventory gives the list\, or <code>qumulo\_managed\_by\: terraform\_provider</code>\, since the provider applies its own floating addresses\, when it does not\. A tenant\'s floating ranges are refused by the area refusal\, which says the same of the provider\. With no list and no <code>qumulo\_cluster\_kind</code>\, both messages also offer declaring an edge or bare\-metal cluster\'s kind\. Remedy\: remove the ranges\, or <code>network\.floating\_ips</code> from <code>qumulo\_terraform\_owned\_areas</code> when there is one\, or set <code>qumulo\_take\_over\_from\_terraform\: true</code>\, which hands the role the audit destinations\, <code>dns\.fqdn</code> and the floating addresses together\.
* cluster\_baseline \- new area <code>tenants</code> in <code>qumulo\_terraform\_owned\_areas</code>\. It covers <code>qumulo\_tenants</code> and the entries of <code>qumulo\_smb\_shares</code> and <code>qumulo\_nfs\_exports</code> that name their tenants with <code>tenants</code> or <code>tenant\_id</code>\.
* cluster\_baseline \- new role\, with playbooks/baseline\.yml\, that brings a cluster\'s system and identity settings to the baseline its inventory declares\, in the order the server\'s rules need\; a second run changes nothing\.
* cluster\_baseline \- new variables <code>qumulo\_tenants</code>\, the tenants by name with their services\, networks\, SMB and NFS settings\, shares and exports\, and <code>qumulo\_management\_network</code>\, <code>qumulo\_cluster\_port</code> and <code>qumulo\_cluster\_kind</code>\, which tell the continuity rule which network the play reaches the cluster on\, which port the cluster listens on for it and whether the cluster is a cloud cluster\. With the inventory cache\, a name that resolves to fewer addresses than the cache recorded fails the source\, naming the missing ones\. docs/how\-to/terraform\.md shows how a root reads the load balancer\'s IPs from its network interfaces instead\.
* terraform inventory plugin \- an entry of <code>qumulo\_ansible\_inventory</code> may give <code>portal\_hosts</code>\, a list of IP addresses\, and <code>replication\_address</code>\, one IP address\, which become <code>qumulo\_portal\_hosts</code> and <code>qumulo\_replication\_address</code>\, each in canonical form\. These are the addresses Terraform outputs\, the floating IPs or\, for a multi\-AZ cluster in AWS\, the load balancer\'s IPs\, and the plugin never derives or translates one\; a host name\, a port\, brackets\, a zone id\, a URL\, an unspecified\, loopback or multicast address\, an empty list and an address given twice are refused\.
* terraform inventory plugin \- new plugin that reads the <code>qumulo\_ansible\_inventory</code> output of a Terraform root\, from <code>terraform output \-json</code> or a saved file\, into hosts with their UUID and ownership\; docs/reference/terraform\-inventory\.md describes the output\.
* terraform inventory plugin \- the rule that <code>owned\_areas</code> must list <code>network\.floating\_ips</code> with <code>managed\_by\: terraform\_provider</code> holds only for <code>cluster\_kind\: cnq</code>\. An <code>edge</code> or <code>baremetal</code> entry may leave the area out\, which hands the cluster\'s floating addresses to the baseline\.
* terraform inventory plugin \- two entries of <code>qumulo\_ansible\_inventory</code> with the same <code>cluster\_uuid</code> fail the source\, naming both entries\.
* trustees \- Authenticated Users is named <code>ad\:NT AUTHORITY\\Authenticated Users</code> by every module that reads a trustee back\, <code>capture\_info</code> and <code>identity\_info</code> among them\, and <code>sid\:S\-1\-5\-11</code> is looked up by that name\, since a node refuses the find of <code>S\-1\-5\-11</code> until it has looked up a name in <code>S\-1\-5</code> since it started\. A file ACL\, SMB share\, directory or role membership that names the group by its SID works on a freshly started node too\.
* trustees \- File Owner and File Group Owner\, which Qumulo Core returns with a name and no SID\, uid or gid\, are the trustees <code>internal\:File Owner</code> and <code>internal\:File Group Owner</code>\, accepted in any letter case\. <code>file\_acl</code> accepts an ACL that holds either\, and <code>capture\_info</code> captures a directory or bucket policy whose ACL or principals hold either\.
* unprotected\_edge\_create\, network\_config\, cluster\_settings\, dns\_settings\, time\_settings\, ssl\_certificate\, local\_group\, local\_user\, role\_member\, ad\_domain and identity\_info \- new modules for a cluster\'s system and identity baseline\.
* upgrade \- new module that upgrades one cluster by one hop through Qumulo Core\'s own upgrade routes\, as far as <code>state</code> asks\: verify\, prepare\, commit or the commit\'s reboots\. Each phase reads back before it writes\, so a rerun picks up where the cluster is\, and a lost answer is read back rather than sent again\. It refuses a downgrade\, a limited\-release source without <code>allow\_upgrade\_from\_limited\_release</code>\, a degraded cluster and an upgrade started outside the run before any write\, decides the commit from the running build\, and with <code>commit\_record</code> keeps a record on the controller of a commit that did not finish\. A secret part of the image\'s URL goes in <code>image\_secret</code> and never shows in the result\.
* upgrade and cluster\_upgrade \- the message for a reboot that another run paused says to follow \"Resume a paused reboot\" in the collection\'s docs/how\-to/resume\-an\-upgrade\.md\, then run the upgrade again\.
* upgrade\.yml \- new playbook that upgrades each cluster in <code>qumulo\_clusters</code> to its <code>qumulo\_upgrade\_target</code>\, hop by hop through every quarterly release on the way\, with the <code>cluster\_upgrade</code> role\. It plans the whole fleet from every inventory host\'s reads and <code>qumulo\_upgrade\_\*</code> variables before it sends anything but reads\, and fails with every refusal at once\; before the plan\, lists the restore records and locks under each <code>edge\_rebuild\_artifact\_dir</code> and warns \(W1\) of each open record\, and each live lock on a host it does not lock\, that names a host it moves or reboots\, and goes on\; takes each moved host\'s restore lock\, and each source\'s that replicates to one\, for the whole run and releases them at every end the run reaches\, a run stopped with Ctrl\-C or killed excepted\; and fails at its end when a hop stopped the run\. <code>qumulo\_upgrade\_api\_host</code> gives the address it connects to in place of <code>qumulo\_api\_host</code>\, for a cluster behind a load balancer that closes idle connections\. In check mode it predicts each host\'s first hop and each lock\, and changes nothing on the clusters\. It refuses <code>qumulo\_upgrade\_aggressive\=true</code>\.
* upgrade\_plan \- new module that plans a fleet\'s Qumulo Core upgrade from every inventory host\'s reads and upgrade variables before anything is sent\: the hops\, one release at a time in lock\-step\, each host\'s image and reboot mode\, the order of each hop\'s commits\, a portal component\'s spokes before their hub and a replication target before its source\, the hosts a failure holds\, the restore locks the run takes\, and from <code>restore\_files</code> the W1 warnings for the open restore records and live restore locks that name a host it moves\. Any refusal stops the whole plan\. With <code>window</code>\, it answers only whether a hop\'s commits may begin now by the hosts\' maintenance windows\.
* upgrade\_report \- new module that turns one hop of the plan and each host\'s registered upgrade results into the hop\'s report\: each host\'s releases\, phase times\, outage\, reboot and outcome\, the host whose failure held a held one\, each portal component\'s mismatch window and whether the hop left it on two releases\, and the peer readings\. It reads only the results\' return fields\, and redacts every URL\'s query string and user information\.
* user\_defined\_mappings \- new module that sets the cluster\'s whole list of mappings from Active Directory users to LDAP users with PUT and If\-Match\, compared without regard to order\. It refuses a list the cluster would refuse before any request\, and outside a domain refuses a list that is not empty before the PUT\, which the cluster would answer with 500 \(QUIRK\-031\)\. The <code>cluster\_baseline</code> role applies <code>qumulo\_user\_defined\_mappings</code> after the domain join\, and <code>capture\_info</code> reads it back in the new <code>identity\_mappings</code> area\.
* version \- a version gate on a cluster that serves no OpenAPI document is decided by the cluster\'s release\, with a warning\.
* version parsing \- a respin letter in the version a cluster reports\, such as <code>Qumulo Core 7\.10\.3A</code>\, is accepted by every version fact\, gate and floor check\.
* web\_ui\_settings \- new module that sets the Web UI\'s login banner and inactivity timeout\, in minutes\, with If\-Match\. An empty banner removes it and a timeout of 0 turns it off\. cluster\_baseline applies <code>qumulo\_web\_ui\_settings</code> after the file system settings\, and capture\_info reads it back as the new <code>web\_ui</code> area\, which clone\_host\_vars copies\.

<a id="deprecated-features"></a>
### Deprecated Features

* network\_config \- the <code>tenant\_id</code> suboption of <code>frontend\_networks</code> is deprecated and will be removed in 0\.3\.0\. It is still accepted beside <code>tenant</code> when both name one tenant\, so a document read with <code>network\_info</code> can be given back\, and refused when they differ\. An id that no tenant has is dropped with a warning\, and the network keeps the tenant the cluster reports\. Remedy\: name the tenant with <code>tenant</code>\.
* smb\_share\, nfs\_export \- the <code>tenant\_id</code> option is deprecated and will be removed in 0\.3\.0\. It is still accepted beside <code>tenant</code> when both name one tenant\, so a share or export read with <code>smb\_info</code> or <code>nfs\_info</code> can be given back\, and refused when they differ\, naming both\. Alone\, it is used as given\, and refused when the tenant list can be read and no tenant holds it\, except with <code>state\: absent</code>\, which then changes nothing\. Remedy\: name the tenant with <code>tenant</code>\, or with <code>tenants</code> for several\.
