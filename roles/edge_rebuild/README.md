# edge_rebuild

Rebuilds a Qumulo unprotected edge: drains the old edge into its hub, records that it is safe to destroy, and after the edge is reinstalled forms it again, deletes the hub's record of the old UUID, brings the new edge back to its baseline, pairs it with its hub again, and writes a report of what is left to hands. A rebuilt edge always has a new UUID (G-UUID), so everything keyed on the old one is cleaned up or replayed. The role replays the inventory, never the state of the edge it destroys. `docs/how-to/edge-rebuild.md` is the guide.

## Phases

`edge_rebuild_phase` picks one. Whichever it is, the role first checks the inventory against the argument specification of `cluster_baseline`, which refuses a key a variable's options do not list, such as a misspelt one, with `Validation of arguments failed:`; a rebuild in one run is refused before it drains anything, and a replay run on its own before it contacts the new edge.

- `predestroy`, on the old edge:
  1. `cluster_guard` checks that the edge is the inventory's.
  2. The info modules' facts go to `captured-<UTC>.yml`, a record for people that nothing replays. SMB sessions are left out, since they name the clients and users connected at the time.
  3. Before the preflight, predestroy runs the baseline's ownership check, so an area Terraform owns that the inventory declares is refused before the drain, with the baseline's own message. Then `edge_rebuild_preflight` fails on drift: tenants, tenant networks, shares, exports, quotas, policies, users, groups or portal roots the inventory does not declare, or declares absent, unless `edge_rebuild_ignore_drift`. The role passes `qumulo_tenants`, `qumulo_smb_shares`, `qumulo_nfs_exports`, `qumulo_factory_defaults` and `qumulo_network` as they are, with the parts of the network document the baseline owns (`cluster_baseline_owned_parts`), and the preflight reads them as the baseline's tenancy step reads them on a newly formed edge, so it judges the old edge against what the replay will build:
     - Each share and export is matched within its tenant, by name or by path. A tenant's nested entries are in that tenant, and absent with it when it is declared absent.
     - A flat entry is in each tenant its `tenants` lists, or every tenant `qumulo_tenants` declares present, for `all`. One with neither `tenants` nor `tenant_id` is in the rebuilt edge's only tenant, and fails the preflight once the replay has more than one tenant, tenant 1 and the tenants the inventory creates. Its deprecated `tenant_id` is read only for tenant 1; another id is skipped with a warning, so its share or export on the old edge is drift.
     - A tenant that an entry's `previous_name` renames is read by its new name.
     - A tenant the inventory declares absent and the edge holds is drift. Tenant 1 is otherwise replayed only under the name the replay gives it, `Default` or the name of the entry with `previous_name: Default`, so tenant 1 renamed by hand is drift unless an entry says so.
     - Tenant 1's `Files` share and `/` export are never drift, whatever tenant 1's name; those of another tenant are. When `qumulo_factory_defaults` says `absent` for either, the preflight reads that as the baseline does, as tenant 1's share or export to remove, so an entry that also declares that share or export in tenant 1 is refused.
     - A network the old edge binds to a tenant the replay builds again, that the replay would not bind to it, is drift in the `tenant_networks` area; a tenant that is itself drift is reported without its networks. A network listed under a `qumulo_tenants` entry's `networks` is that tenant's; one in `qumulo_network.frontend_networks` is its `tenant`'s, tenant 1's for `tenant_id: 1`. A listed network sent with no tenant (a flat network with no `tenant`, or a `tenant_id` the newly formed edge lacks) stays in tenant 1, or the preflight refuses it (see below); one the old edge holds in no tenant is `tenant_networks` drift with `added: true`, which `edge_rebuild_ignore_drift` waives. When the inventory sets neither `qumulo_network.frontend_networks` nor `networks` on any present `qumulo_tenants` entry, not even as an empty list, the replay keeps the newly formed edge's networks, which are all tenant 1's, and does not replay a network the formed edge lacks, and network 1 that the old edge holds in no tenant is `tenant_networks` drift with `added: true` on managed networking. Once any network is listed, the replay keeps only the listed networks and removes the rest: list each network the edge holds, under its tenant, or in `qumulo_network.frontend_networks` for a network no tenant holds or on the backend bond, and give every present tenant `networks`, `[]` for none.
     - On an edge whose network document has no managed interfaces and only HOST networks, which forms again with no frontend network, an inventory that creates a tenant in the replay but lists no network for a tenant that stays fails, after any drift and whatever `edge_rebuild_ignore_drift` says: the baseline's step 2 would refuse the create after the destroy. The replay's tenant 1 pass writes tenant 1's own networks, or every listed network that stays when tenant 1 holds none, in tenant 1 before the create, and tenant 1 declared `state: absent` takes part as `Default`, so it needs no rename. The preflight decides with the replay's own filter, `tenancy_first_pass`, on the newly formed edge. List the edge's HOST network under a tenant's entry, or in `qumulo_network.frontend_networks`. The role gives the preflight the areas Terraform owns (`cluster_baseline_owned`); with `network` among them the refusal also says how to take the area back for the rebuild ([Troubleshooting](../../docs/reference/troubleshooting.md#rebuilds)).
     - On the same kind of edge, when the tenant 1 pass would write two or more networks into tenant 1, which it does only when tenant 1 holds two or more, or holds none while the inventory lists two or more, and the replay creates a tenant, the baseline's step 2 needs to know which HOST network the play reaches the edge on. On an old edge with two HOST networks reached on the host's own address, set `qumulo_management_network` to the id of the network `qumulo_api_host` is on; keep it if the inventory already sets it. The preflight infers it only for an old edge with one HOST network whose network status answers, as when the inventory adds a network: it takes the network that carries the play's address there, placed by the continuity rule, by a network's ranges or from the network status, on the document's one HOST network. The role passes the preflight `cluster_baseline_management_network`, which comes from `qumulo_management_network`, and a null value counts as unset; the variable overrides the inference; when they disagree the preflight warns and the replay uses the variable. The preflight returns the ids the replay will use as `management_network`. It fails, after any drift and whatever `edge_rebuild_ignore_drift` says, when it has neither, since step 2 would refuse the create after the destroy. The message starts "the replay's tenant 1 pass would write networks" and ends with the remedy, and its reason is one of these: the old edge does not answer its network status; its network status read failed ("this edge's network status read failed: <error>"); it holds two HOST networks and the play reaches it on the host's own address ("this edge holds HOST networks 0 and 1 and the play reaches it on the host's own address, A, which the network status does not place on any one of them"); the status does not show the address ("this edge's network status places the play's address on no one network"); the status shows the HOST network it would name served on no device; or `qumulo_api_host` resolves to no address. When the play reaches the old edge on a network the replay's tenant 1 pass does not write, the message instead starts "the play reaches this edge on network N, which the replay's tenant 1 pass does not write before it creates tenant X, so the baseline's step 2 would refuse the create after the destroy", and says to set `qumulo_api_host` to an address on one of the networks the pass writes for the rebuild and `qumulo_management_network` to that network's id, or, if the inventory lists network N under another id, to set `qumulo_management_network` to that id. Whenever the pass runs and the replay creates a tenant, a `qumulo_management_network` that names a network the pass does not write fails too, however many networks the pass writes, since the baseline's step 2 judges the first create against the document the pass leaves, and step 3 adds the other networks only after that create. An id that no tenant lists gets a message that starts "qumulo_management_network names network<s> <ids>, which the inventory lists for no tenant that stays", and says to set it to the id of the network `qumulo_api_host` is on. An id that step 3 adds later, such as a second tenant's own network, gets one that starts "qumulo_management_network names network<s> <ids>, but the replay's tenant 1 pass writes only", and says to name the network of tenant 1 that `qumulo_api_host` is on or, if the play reaches the edge on that network, to set `qumulo_api_host` to an address on a network the pass writes for the rebuild. So does one declared with no network ("qumulo_management_network is declared with no network"), which step 2 would refuse at the create after the destroy: set it to the id of the network `qumulo_api_host` is on, or leave it unset.
     - On an edge that forms host-managed, a network under a `qumulo_tenants` entry's `networks` with `vlan_id` or `type: STATIC` fails the preflight once it has read the edge's network document, before drift and whatever `edge_rebuild_ignore_drift` says, with the baseline's own host-managed message after "the replay onto the rebuilt edge would refuse the inventory", where the baseline's step 2 would refuse it after the destroy. Remove `vlan_id`, or give the network `type: HOST`. The check waits for the replay when `qumulo_network` declares `managed_interfaces` and the tenant 1 pass runs, which writes them first.
     - An old edge without tenant 1 is rebuilt with one, since a newly formed edge has tenant 1, `Default`, with the `Files` share and `/` export, and the replay keeps it unless the inventory declares it `state: absent`. A capture of such an edge declares `Default` absent, with the factory share and export, unless another tenant is named `Default` or a replay could not delete it. On host-managed networking it can write the rename instead, `previous_name: Default` on the one tenant that holds a network and no `Default` entry; the `capture_info` module's `tenants` area gives the cases, and its `tenant 1` note says which it wrote. For an inventory without that entry, the preflight reports the gained tenant as drift, with `added: true`, which `edge_rebuild_ignore_drift` accepts. To clear it, declare `Default` with `state: absent` in `qumulo_tenants` (or drop the entry for the renamed tenant, or its `previous_name`) and claim the factory share and export for removal, either with `qumulo_factory_defaults` `smb_files_share` and `nfs_root_export` set to `absent` or by declaring `Files` and `/` under the absent `Default` entry, and list each network under a tenant that stays.
     - An inventory that the inventory rules of the baseline's tenancy step would refuse (renames, entries and tenant references, claims, and the network rules that need no read), such as a flat entry with neither `tenants` nor `tenant_id` once the replay has a second tenant, two `qumulo_tenants` entries of one name, an inventory that leaves no tenant, three inventory network rules (once a present tenant declares `networks` every present tenant must, a network is listed once, and an absent tenant's network is neither kept flat nor named by a flat `tenant_id`), tenant 1 declared `state: absent` while no network is listed, or a network listed with no tenant while tenant 1 is declared `state: absent`, fails here before the preflight reads the edge, and `edge_rebuild_ignore_drift` does not waive it. A listed network with no integer `id` also fails before any read, with its own message. One more refusal comes after the preflight reads the edge's network document, but before any other read and before drift: a network sent with no tenant that the newly formed edge does not hold, once the replay has more than one tenant, which on host-managed networking cannot happen, since the tenant 1 pass writes every network sent with no tenant first. `edge_rebuild_ignore_drift` does not waive it. `docs/explanation/rebuilds.md` ("A network sent with no tenant") says which networks the formed edge holds. The network document's own checks (its validation, the backend checks, and the interfaces) and the NFS and continuity checks need the new edge and run only at the replay, as do its host-managed checks apart from the one on tenant networks above.
  4. It also fails on state the replay cannot create again, unless `edge_rebuild_acknowledge` lists its area: a STATIC network or VLAN without `qumulo_network`, a key store other than the local one, `replication`, a relationship the inventory does not declare present, S3 keys, access tokens, or `local_data`, files outside the portal's spoke roots and snapshots, which no drain moves to the hub. `edge_rebuild_ignore_drift` never waives these. Each replication peer's record of a declared relationship is read through the peer's inventory host, and a record matches the peer by its current UUID or one of its `qumulo_previous_cluster_uuids`. A relationship into the edge is replayable while the edge's record is ESTABLISHED and read-only and the source holds it ESTABLISHED, and its target directory and replication snapshots are then not local data; in any other state its directory is local data, named with both records' states. One whose record names a previous UUID of the source is `only_copy`: its replica may be the only copy of the data the source had, and its record is the hold on the source's side, so it needs both `local_data` and `replication` acknowledged, and the report's second-pass hand-off says the second pass creates the relationship from the source directory as it is. When its record allows the source's own restore, ESTABLISHED, read-only and with a recovery point, and the source host has an IP-literal `qumulo_replication_address`, the detail names that restore first: the source's second pass for a source in `qumulo_edges`, `playbooks/replication_restore.yml` for any other. A declared relationship whose record names a UUID the peer's inventory does not hold needs `replication`, and the detail says to apply that peer's `host_vars` patch. A relationship out of the edge whose record is live will be held at the replay, its replication snapshots not local data only while the target holds a live replica; one whose record is ENDED or pending needs `replication`. The record lists each relationship and what the rebuild does with it.
  5. The `portal_pair` role drains every portal the edge holds, declared or not, through the inventory host in `qumulo_hubs` whose `qumulo_cluster_uuid` is its hub's: the hub makes it read-only until both sides settle, then it is deleted on both sides. A portal whose hub no inventory host names fails the phase before any change. When a drain fails, the role stops and says what it had done, unless `edge_rebuild_allow_data_loss` lets it force the deletes. A rerun that finds the hub's record of a deleted spoke still DELETING waits for it, or with `edge_rebuild_allow_data_loss` forces it at once; a portal any earlier record of the UUID shows drained counts as drained. A declared hub that does not answer blocks the phase only when the edge holds a portal to it.
  6. `ad_domain` leaves the domain; with `qumulo_ad.join_user` and `join_password` the leave deletes the computer account.
  7. `nexus_registration` removes the Nexus registration, and with `qumulo_nexus_api_token`, `nexus_cluster` retires the UUID in Nexus.
  8. `predestroy-<UTC>.yml` records the old UUID, each portal and whether it was drained, deleted or forced, whether the leave deleted the computer account, Nexus, the drift and the acknowledged areas, the `management_network` the preflight returned and the `management_api_host` it was found by (`qumulo_api_host`), and says the edge is safe to destroy. It is written as each portal finishes, with `safe_to_destroy: false` until the phase ends, so a run that fails later still records a drain that finished.
- `replay`, on the reinstalled edge:
  1. Refuses `qumulo_replication_release` and `qumulo_replication_restore`, which belong to later runs, naming the second pass's restore as the way out of a held relationship where the report names it. Checks what it needs from the inventory, among it that no snapshot policy declares a `lock_key`, unless `-e qumulo_allow_deferred_policy_lock_keys=true` is given, since the new edge's key store is empty (the predestroy phase runs this check too, before it changes anything): the declaration `-e qumulo_rebuild=true`, `edge_rebuild_eula_accepted`, the `admin` password, `qumulo_cluster_uuid` of the old edge, `qumulo_cluster_name`, both keys of `qumulo_factory_defaults`, a `qumulo_portal.hub` in the `qumulo_hubs` group with its `qumulo_cluster_uuid`, `qumulo_portal_hosts` on the edge and on the hub, a `qumulo_capacity.license` of `pending`, `required` or `none`, and no quota or snapshot policy under a spoke root, and no path with both a mode in `qumulo_directories` and an ACL in `qumulo_file_acls` (G-FS-ACL-MODE). It refuses `license: none` beside a license document, as the license step does, and, on every rebuilt edge whatever its license, a declared clamp more than its rounding tolerance below min(1 TB, `edge_cache_resize_floor_bytes`): the new edge forms unlicensed with the smaller of its platform and 1 TB, and provisioning never shrinks, so the baseline could not write it (G-EDGE-FLOOR, G-CLAMP-SHRINK). The refusal has a form for a `none` edge and one for any other, and names the bound, "1 TB" or its bytes. Lower `edge_cache_resize_floor_bytes` only to describe a smaller platform. These checks come before the drain in a rebuild in one run, and before the formation in the replay phase of one in two runs. Step 3 runs here too, since it reads only the records.
  2. Connects as `admin` with `edge_rebuild_admin_password`, which defaults to `qumulo_api_password`, never with `qumulo_api_token` or another user, which belong to the old edge. In phase `all` it then reads the inventory again (`meta: refresh_inventory`). It takes the edge's `qumulo_cluster_uuid` as the new UUID when it is not the old one, as when the reinstall tasks replace a Terraform edge resource that the `qumulo.cluster.terraform` inventory plugin reads. A replay on its own without `qumulo_new_cluster_uuid`, whose inventory UUID no predestroy record names, takes the old UUID from the newest predestroy record that says it was safe to destroy, of a UUID no rebuild report has replaced, and the report names that record. `cluster_guard` in mode `rebuilt` passes only an UNCONFIGURED node, or an ACTIVE cluster with the new UUID, typed in `qumulo_new_cluster_uuid` or read from the inventory, the inventory's name, no portals and only the factory share and export; and the replay fails when that cluster is the one `qumulo_cluster_uuid` names, as when `host_vars` already holds the new UUID. A wrong host fails here, and a factory certificate that does not verify fails naming `edge_rebuild_validate_factory_certs`.
  3. With `qumulo_ad`, refuses to join again unless a predestroy record of the old UUID shows the old edge left the domain with credentials, or `edge_rebuild_old_edge_destroyed` says it is gone: a join under the same name resets the computer account a live old edge still uses. In a rebuild in one run, `edge_rebuild_ad_leave` with the credentials stands in for the record.
  4. Deletes the hub's record of the old UUID. A PENDING record is deleted at once, and so is a DELETING one that any predestroy record of the old UUID shows drained; a DISCONNECTED one, an old edge that was never drained, needs `edge_rebuild_allow_data_loss`; one the hub still reaches fails. This runs before the edge forms, so a refusal leaves the node UNCONFIGURED. With `qumulo_nexus_api_token`, step 7 runs here too, before formation.
  5. `unprotected_edge_create` forms the edge when it is UNCONFIGURED. When the formation fails after the edge formed, the role reads the new UUID from the node and writes the report before it stops.
  6. The role switches `qumulo_cluster_uuid` to the new UUID, which the per-request guard checks from then on, adds the old one to `qumulo_previous_cluster_uuids`, and writes `rebuild-<UTC>.yml` with it, so a replay that fails later still leaves it behind.
  7. With `qumulo_nexus_api_token`, `nexus_cluster` retires the old UUID in Nexus, with step 4, so a formation that fails leaves no old UUID behind.
  8. When the new edge has no frontend network and no managed interfaces, as an edge on host-managed networking forms, and the inventory creates a tenant, the baseline's ownership check and tenancy step run first with tenant 1 alone, holding tenant 1's own networks. Tenant 1 is its entry's `name` and `previous_name`, or, when no present entry declares it, as when it is declared `state: absent`, the `Default` the edge formed with. Its own networks are those under its entry's `networks` and the `qumulo_network.frontend_networks` that step 2 resolves to tenant 1 or to no tenant, each sent with no tenant, with no shares, no exports and no factory defaults. Only when tenant 1 holds none, as when it is declared absent, undeclared or given `networks: []`, does the pass send every network the inventory lists for a tenant that stays: the `qumulo_network.frontend_networks` that the tenancy step does not leave to an absent tenant and each present tenant's own `networks`. That writes the networks, in tenant 1, before the baseline creates tenants at step 3a, which step 2 would otherwise refuse ("The cluster's networking is host-managed and it has no frontend network yet ..."), since the baseline writes its network document only at step 3; step 3 then binds each network to its tenant and adds a second tenant's own networks, which the pass left out, and step 2 places the play on the one HOST network the pass leaves, tenant 1's, so tenant 1 on HOST 0 beside a second tenant on its own HOST 1 rebuilds without `qumulo_management_network` when the play reaches the edge on tenant 1's network and the newly formed edge answers its network status; a play on the second tenant's network sets `qumulo_api_host` to an address on a network the pass writes for the rebuild. The pass runs inside the block that writes the report, so a failure there reports the baseline failed. The `tenancy_first_pass` filter decides the pass. The pass and the baseline take `qumulo_management_network` from the inventory when it sets one, a null not counting, else the predestroy record's `management_network`, but only while `qumulo_api_host` is still the record's `management_api_host`, since a changed address may be on another network; with another address, or a record without either, it is null and step 2 decides. A check run stops after the pass, since the baseline's prediction needs the networks the pass writes.
  9. The `cluster_baseline` role, without its guard, brings the edge to its baseline and pairs it with its hub again. Its replication step holds each relationship out of the edge whose replica may be the only copy of the destroyed data, and writes nothing for it, whatever `edge_rebuild_allow_data_loss` says; no relationship into the edge is created. This is the first pass: the new UUID has no license yet, so the role leaves the capacity clamp for the license, and nothing waits. The second pass, `playbooks/edge_license_complete.yml`, applies the license document once Qumulo has issued it for the new UUID, then sets the clamp, creates the relationships into the edge, and restores the held ones from their replicas. An edge that declares `qumulo_capacity.license: none` runs without a license: its clamp is written in this pass, with no license, and the report says it runs without a license in place of a license hand-off.
  10. Writes `rebuild-<UTC>.yml` again with the `host_vars` patch, which holds the whole `qumulo_previous_cluster_uuids` list, and the new UUID unless the inventory already names it, and the hand-offs.
- `all` checks what the replay needs from the inventory, the AD leave with credentials and the reinstall tasks file among it, then runs predestroy, the tasks file in `edge_rebuild_reinstall_tasks`, and the replay.

Under `--check`, predestroy predicts its changes, drains nothing and writes no record, `all` stops before the reinstall, a replay onto an UNCONFIGURED node stops after predicting the formation, and a replay onto a formed edge that needs the tenant 1 pass stops after predicting it.

The rebuild destroys everything on the edge outside its portal's spoke roots: local directories, the files in them and their snapshots. Only the spoke roots' data reaches the hub. The predestroy phase refuses while such data exists, until `edge_rebuild_acknowledge` lists `local_data`.

## Variables

`meta/argument_specs.yml` is the reference. The role also reads the inventory the `cluster_baseline` role reads.

| Variable | Default | Meaning |
|---|---|---|
| `edge_rebuild_phase` | required | `predestroy`, `replay` or `all` |
| `edge_rebuild_reinstall_tasks` | unset | the absolute path of the tasks file that reinstalls the edge; needed for `all` |
| `edge_rebuild_eula_accepted` | unset | accepts Qumulo's end user license agreement, which forming the edge needs; required for the replay |
| `edge_rebuild_admin_password` | `qumulo_api_password` | the new edge's `admin` password, which the replay forms the edge with and connects as |
| `edge_rebuild_allow_data_loss` | `false` | force the portal's deletion when the drain fails, delete without a drain a portal whose hub is not in the inventory, and delete the hub's DISCONNECTED record of an old edge that was not drained |
| `edge_rebuild_ad_leave` | `qumulo_ad is defined` | leave the domain in predestroy |
| `edge_rebuild_nexus_deregister` | `true` | remove the Nexus registration in predestroy |
| `edge_rebuild_drain_timeout` | `3600` | seconds to wait for the drain and for each portal record to go |
| `edge_rebuild_artifact_dir` | `artifacts` beside the inventory source | records go under a directory named after the inventory host; never inside an inventory directory, whose `.yml` files Ansible reads as inventories |
| `edge_rebuild_ignore_drift` | `false` | rebuild although the edge holds state the inventory does not declare, or declares absent, which is lost. It also accepts a tenant 1 that the rebuilt edge gains, and a network the old edge holds in no tenant that the rebuilt edge puts in tenant 1 |
| `edge_rebuild_acknowledge` | `[]` | areas of unreplayable state to rebuild without: `network`, `kmip`, `replication` (relationships the inventory does not declare), `s3_keys`, `access_tokens`, `local_data` |
| `edge_rebuild_old_edge_destroyed` | `false` | the old edge is gone, for a replay with `qumulo_ad` and no record of a domain leave |
| `edge_rebuild_validate_factory_certs` | `true` | with `false`, connect to the new edge without verifying its factory certificate until the baseline installs `qumulo_ssl` and verifies it with `qumulo_ssl.ca_path_after` (G-FACTORY-TLS); set it in `host_vars`, not as `-e qumulo_validate_certs=false`, which would leave the hub and the rest of the run unverified |
| `edge_cache_resize_floor_bytes` | `1000000000000` | the capacity a rebuilt edge provisions at formation, if its platform is larger; it bounds the refusal of a clamp below the floor, at most 1 TB. Lower it only to describe a platform smaller than 1 TB |
| `qumulo_new_cluster_uuid` | unset | the UUID of an edge formed by hand or by Qumulo's installer, which the replay adopts; without it, the replay takes a new UUID from the inventory, as a Terraform output gives once the edge's resource is replaced |

## The report

`rebuild-<UTC>.yml` holds the old and new UUID, whether the replay formed the edge or adopted it, `previous_record` when the old UUID came from a predestroy record, `host_vars_patch` to apply to the edge's `host_vars`, with the whole `qumulo_previous_cluster_uuids` list, the new UUID unless the inventory already names it, and `qumulo_management_network` when the replay took the management network from the predestroy record (`qumulo_api_host` unchanged) and the inventory lacked it, and the hand-offs: the license the new UUID needs, where its document goes, and `ansible-playbook qumulo.cluster.edge_license_complete -i <inventory> -l <edge>` after the patch, each replication relationship into the edge, which that second pass creates again, the source hosts whose replication step fails at the edge's guard until the patch is applied, each held relationship with its way out, the second pass's restore when its holder allows one and otherwise the copy back and the release, each relationship into the edge nested with a held source path, which waits for that restore, a raised cap waiting for a quorum formation, a spent Nexus join key, the old UUID in Nexus without a token, DNS records, Terraform state that still names the old UUID (G-TF-STALE) unless the inventory already names the new one, the domain's computer account, each lock key the old edge held, to register again with `security_key` (or, when its key store could not be read, that it names none), each snapshot policy the baseline applied without its lock key, a hub record the predestroy phase could not reach, and each acknowledged area, such as access tokens to issue again to their consumers, S3 keys, which the replay's baseline makes again for each declared entry, with each new secret in a file under `<edge_rebuild_artifact_dir>/<host>/secrets/` for its consumers and the entry's `access_key_id` to change, and local data to restore. Once the patch is applied, `playbooks/baseline.yml` manages the edge. A replay that failed after the edge formed is finished that way too. Until the baseline's identity steps have run, the new edge has only `admin`, with `edge_rebuild_admin_password` (or `qumulo_api_password`) and no token, so for that run put `qumulo_api_username: admin`, that password and no `qumulo_api_token` in the edge's `host_vars`, and, if it failed before the certificate step, `qumulo_validate_certs: false` too: the certificate step turns verification back on with `qumulo_ssl.ca_path_after`. Take them out again afterwards, and never pass them with `-e`, which would reach the hub's connection too. The report also says when `admin`'s new password differs from the inventory's.

## Example

```yaml
- name: Rebuild the edge in one run
  hosts: edge01
  serial: 1
  gather_facts: false
  module_defaults:
    group/qumulo.cluster.qumulo:
      api_host: "{{ qumulo_api_host }}"
      api_password: "{{ qumulo_api_password }}"
```
