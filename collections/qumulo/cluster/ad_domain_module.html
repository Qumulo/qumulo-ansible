qumulo.cluster.ad_domain module – Join a Qumulo cluster to an Active Directory domain, or leave it

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.ad_domain.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • With state=joined, joins the cluster to domain when it is not joined to any domain, and otherwise changes the settings that can change in place. With state=absent, leaves domain.

  • The cluster is in the desired state when it is joined to domain, compared without regard to case. It is joined under its own name, which is its computer account (NAME$) and cannot change while joined.

  • Joining and leaving are explicit. The module never leaves a domain in order to join another, or to change a setting that only a join sets; it fails and names the step to run instead.

  • The join and leave credentials cannot be read back, and the computer account itself lives in Active Directory, where the module cannot see it (G-AD-JOIN). A join under a name whose computer account already exists takes that account over and resets its password, which breaks any other cluster still using that account.

  • Every operation runs in the background on the cluster. With wait=true, the module waits for it to finish and fails with the cluster’s reason when it fails. With wait=false, the result is the membership the operation is expected to leave, not one read back.

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

base_dn

string

The distinguished names to search for users and groups, separated by ;. Changes in place.

An empty value means the cluster’s default, CN=Users under the domain, and compares equal to it.

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

domain

string / required

The domain’s DNS name, such as corp.example.com. Compared without regard to case.

domain_controllers

list / elements=string

The domain controllers to use, by name or address; empty lets the cluster find them. Changes in place.

The cluster reports the configured domain controllers only in the record of its last AD operation, which a later operation replaces. When that record is not for domain, the list cannot be compared and is sent only with a join. On a joined cluster the result then carries a note (G-AD-DCS).

domain_netbios

string

The domain’s NetBIOS name. Unset lets the cluster derive it from the first label of domain.

Set only by a join. A different value on a joined cluster fails the task.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

join_password

string

The password of join_user. It cannot be read back, and it is sent only to join or leave.

join_user

string

The domain user that joins the cluster, and that deletes its computer account when it leaves. Needed to join.

Without it, leaving still succeeds, with a warning, but leaves the computer account in Active Directory.

ou

string

The organizational unit the computer account is created in, as a distinguished name. Unset uses the domain’s default container.

Set only by a join. A different value on a joined cluster fails the task.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

search_trusted_domains

boolean

Also look identities up in domains this one trusts. Changes in place. A join that leaves it unset turns it on.

Choices:

  • false

  • true

state

string

joined joins or keeps the cluster joined; absent leaves the domain.

Choices:

  • "joined" ← (default)

  • "absent"

use_ad_posix_attributes

boolean

Read POSIX user and group ids from Active Directory. Changes in place.

Choices:

  • false

  • true

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

wait

boolean

Wait for the join, leave or change to finish.

Choices:

  • false

  • true ← (default)

wait_timeout

integer

Seconds to wait for it.

Default: 600

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Predicts a join or leave from the cluster’s state; whether Active Directory accepts it is known only by doing it.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

Idempotent as far as the cluster can tell, which is that it is joined to domain under its own name.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v1/ad/status and /v1/ad/monitor; POST /v1/ad/join, /v1/ad/reconfigure and /v1/ad/leave.

  • A join needs the cluster to resolve the domain’s names (qumulo.cluster.dns_settings) and its time to be within Kerberos’s tolerance of the domain’s (qumulo.cluster.time_settings).

  • The cluster’s name (qumulo.cluster.cluster_settings) is the name of its computer account.

  • Registers: G-AD-JOIN, G-AD-DCS.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# The cluster's name becomes its computer account, which cannot be renamed while joined. A join under a name whose
# computer account already exists takes that account over and resets its password, which breaks another cluster
# that still uses it. Name the cluster, and give it the domain's DNS and a time source the domain agrees with, first.
- name: Prepare the edge to join the domain
  block:
    - name: Name the edge
      qumulo.cluster.cluster_settings:
        cluster_name: edge01

    - name: Resolve names through the domain's DNS servers
      qumulo.cluster.dns_settings:
        servers: [10.0.0.2, 10.0.0.3]
        search_domains: [corp.example.com]

    - name: Take time from the domain's time servers
      qumulo.cluster.time_settings:
        source: API_TIME_SOURCE_NTP
        ntp_servers: [ntp1.corp.example.com, ntp2.corp.example.com]

- name: Join the edge to the domain under its own name
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    ou: OU=Edges,DC=corp,DC=example,DC=com
    join_user: svc-qjoin
    join_password: "{{ vault_ad_join_password }}"

- name: Join the edge with the domain's NetBIOS name, POSIX attributes from Active Directory and a search base
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    domain_netbios: CORP
    use_ad_posix_attributes: true
    base_dn: "CN=Users,DC=corp,DC=example,DC=com;OU=Staff,DC=corp,DC=example,DC=com"
    join_user: svc-qjoin
    join_password: "{{ vault_ad_join_password }}"

- name: Allow a slow domain to take half an hour to join
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    join_user: svc-qjoin
    join_password: "{{ vault_ad_join_password }}"
    wait_timeout: 1800

# With wait: false the result is the membership the join is expected to leave. Read the cluster later with
# qumulo.cluster.identity_info to see whether the cluster has joined.
- name: Start the join and carry on without waiting for it
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    join_user: svc-qjoin
    join_password: "{{ vault_ad_join_password }}"
    wait: false

- name: Preview joining the domain
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    join_user: svc-qjoin
    join_password: "{{ vault_ad_join_password }}"
  check_mode: true
  diff: true
  register: join_preview

- name: Preview a change to the domain controllers
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    domain_controllers: [dc1.corp.example.com, dc2.corp.example.com]
  check_mode: true
  diff: true
  register: ad_preview

- name: Show the membership the change would leave
  ansible.builtin.debug:
    var: ad_preview.ad_domain

# On a joined cluster these settings change in place, with no join credentials. ou and domain_netbios are set only
# by a join, so a different value fails the task. When the cluster's last AD operation was for another domain, the
# domain controllers cannot be compared and are not sent (G-AD-DCS).
- name: Use two domain controllers and stop searching trusted domains
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    domain_controllers: [dc1.corp.example.com, dc2.corp.example.com]
    search_trusted_domains: false

# A cluster joined to one domain is never moved to another: leave it first, then join the other.
- name: Move the edge from the old domain to the new one
  block:
    - name: Leave the old domain, deleting the computer account
      qumulo.cluster.ad_domain:
        domain: old.example.com
        state: absent
        join_user: svc-qjoin-old
        join_password: "{{ vault_old_ad_join_password }}"

    - name: Join the new domain
      qumulo.cluster.ad_domain:
        domain: corp.example.com
        join_user: svc-qjoin
        join_password: "{{ vault_ad_join_password }}"

- name: Leave the domain before the edge is destroyed, deleting its computer account
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    state: absent
    join_user: svc-qjoin
    join_password: "{{ vault_ad_join_password }}"

# Without credentials the cluster leaves, warns, and the computer account stays in Active Directory.
- name: Leave the domain without credentials
  qumulo.cluster.ad_domain:
    domain: corp.example.com
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

ad_domain

dictionary

The cluster’s AD membership after the task. In check mode, or with wait=false, it is the membership the task is expected to leave, not one read back.

Returned: always

Sample: {"base_dn": "CN=Users,DC=corp,DC=example,DC=com", "domain": "corp.example.com", "domain_controllers": [], "domain_netbios": "CORP", "ou": null, "search_trusted_domains": false, "status": "JOINED_TO_DOMAIN", "use_ad_posix_attributes": false}

base_dn

string

The search base distinguished names, or null.

Returned: success

domain

string

The joined domain, or null.

Returned: success

domain_controllers

list / elements=string

The configured domain controllers, or null when they cannot be read for this domain.

Returned: success

domain_netbios

string

The domain’s NetBIOS name, or null.

Returned: success

ou

string

The organizational unit given at the join, or null.

Returned: success

search_trusted_domains

boolean

Whether trusted domains are searched.

Returned: success

status

string

The join status, such as JOINED_TO_DOMAIN or NOT_IN_DOMAIN.

Returned: success

use_ad_posix_attributes

boolean

Whether POSIX ids come from Active Directory.

Returned: success

maybe_applied

boolean

true when the join, change or leave request was sent and the connection was lost before the cluster answered.

Sample: true

Returned: when there is something to note
