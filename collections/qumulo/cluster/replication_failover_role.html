qumulo.cluster.replication_failover role – Fail a replication relationship over to its target, copy the target’s writes back, or fail it back

Note

This role is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_failover.

Entry point main – Fail a replication relationship over to its target, copy the target’s writes back, or fail it back

New in qumulo.cluster 0.1.0

Synopsis

  • Runs from the source host’s context, for the relationships replication_failover_relationships names among the host’s present entries of qumulo_replication_relationships. The source and the target are the declared ones, whatever direction the records run in.

  • failover makes the target’s copy writable, from its recovery point, and sends nothing to the source, so it works with the source gone. resync reverses the relationship on the target and reconnects it on the source, so the target replicates the failover’s writes to the source while clients still use the target. failback resyncs when the relationship has not been resynced, waits until the target’s recovery point has moved twice, makes the source writable, reverses the relationship on the source, reconnects it on the target, and applies the declared settings.

  • Before each step it reads both clusters with qumulo.cluster.replication_info and asks qumulo.cluster.replication_failover_plan for the next step, then runs only that step. A run that stops anywhere resumes from what the records show.

  • It reads and plans every named relationship, and prints each one’s state and every step left, before the first write of any. A refusal of any relationship fails the run before any write.

  • A real run fails before its first write without replication_failover_allow_data_loss. Check mode needs no replication_failover_allow_data_loss, prints the plan and writes nothing; it is the dry run. In check mode too, a failover is refused without replication_failover_allow_partial_job while the source is running a job of the relationship.

  • Each reconnect is sent without qumulo.cluster.replication_reverse‘s allow_data_loss unless replication_failover_allow_newer_writes names the host it is sent to. The module then compares the directory with the recovery point first and refuses when anything was written there since.

  • A failback runs each relationship up to its wait for a current recovery point, then waits for the waiting relationships, those on one target host together and the target hosts one after another, then makes each source writable, reverses it and reconnects the target.

  • Sets the fact replication_failover_results, one entry per relationship with name, id, state_before, state_after, steps, the names of the steps run, plan, the lines of the steps listed, and notes.

Parameters

Parameter

Comments

replication_failover_action

string / required

The action to run, failover, resync or failback.

Choices:

  • "failover"

  • "resync"

  • "failback"

replication_failover_allow_data_loss

boolean

The run’s consent, which every real run with a step left needs. For failover it accepts that the target’s copy starts from the recovery point, that writes on the source after it stay behind, and that a job the source was running when it stopped answering is discarded. For resync it accepts that the source’s directory becomes read-only under its clients. For failback it accepts that the target’s directory becomes read-only under its clients and that the source’s copy starts from the last recovery point.

The role sets it in its own vars/main.yml, so a value in group_vars, host_vars, a play’s vars or vars_files is ignored. Anything a playbook sets closer to the role or during the run lifts it: -e, the include’s vars, a block’s vars, role parameters, set_fact and include_vars.

Choices:

  • false ← (default)

  • true

replication_failover_allow_newer_writes

list / elements=string

The inventory hosts whose directory a reconnect may send back to the recovery point although the comparison found writes there after it, discarding them. A reconnect is sent to the source host in a resync and to the target host in a failback. Without its host here, a reconnect that finds writes fails, naming them.

A host named here makes every reconnect sent to it skip the comparison, a failback’s last one included.

A string, as -e replication_failover_allow_newer_writes=edge01 gives it, is split at commas into host names, and a name matches a whole host name only.

The role sets it in its own vars/main.yml, so a value in group_vars, host_vars, a play’s vars or vars_files is ignored. Anything a playbook sets closer to the role or during the run lifts it: -e, the include’s vars, a block’s vars, role parameters, set_fact and include_vars.

Default: []

replication_failover_allow_partial_job

boolean

Let a failover discard the changes of a job that the source, which answers, is running. Without it, such a failover fails, saying to run again once the job ends. A source that does not answer is never refused for a job.

The role sets it in its own vars/main.yml, so a value in group_vars, host_vars, a play’s vars or vars_files is ignored. Anything a playbook sets closer to the role or during the run lifts it: -e, the include’s vars, a block’s vars, role parameters, set_fact and include_vars.

Choices:

  • false ← (default)

  • true

replication_failover_artifact_dir

string

Where a rebuilt source’s restore keeps its records, <dir>/<source host>/restore/. A resync or failback of a relationship whose restore record is there is refused, naming playbooks/replication_restore.yml. A failover notes the record and goes on.

Defaults to edge_rebuild_artifact_dir, else the edge_rebuild role’s default.

replication_failover_connections

dictionary / required

The connection options of the source host and of each target host of its relationships, by inventory host, as the cluster_baseline role’s connections.yml records them in cluster_baseline_connections.

replication_failover_relationships

list / elements=string / required

The relationships to act on, each <target host>:<target path> of a present entry of the source host’s qumulo_replication_relationships, compared without the target path’s trailing slash.

replication_failover_source_timeout

integer

Seconds a failover’s read of the source waits for an answer, as both retry_timeout and request_timeout, before it goes on without the source. A source that does not answer is not read again in the run, whatever the action.

Default: 30

replication_failover_sync_timeout

integer

Seconds the failback’s wait for the target’s recovery point to move twice may take, for every named relationship together, from when the waits begin. The relationships on one target host are polled together, the target hosts one after another.

Default: 86400

replication_failover_wait_timeout

integer

Seconds the polls of one step may take, all of its records together. A verb’s polls and a wait step each have this long. A wait that runs out sends nothing.

Default: 1800
