qumulo.cluster.access_token module – Manage the access tokens of a user on a Qumulo cluster

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.access_token.

New in qumulo.cluster 0.1.0

Synopsis

  • Makes sure a user holds an access token, rotates the user’s tokens, or removes them.

  • Tokens are matched by user alone. The cluster stores no name or description for a token, so the module manages the tokens of a user as one set (G-TOKEN).

  • The cluster returns a token’s bearer only in its answer to the request that makes the token. The module writes it at once to a file of its own in secret_destination, readable only by its owner, and returns it in bearer_token of that run only. No other key, diff, note, warning or message holds it.

  • The module refuses to make a token in a task that does not set no_log, or that has no secret_destination. It refuses before any write, in check mode too.

Parameters

Parameter

Comments

allow_management_disruption

boolean

Allow the task to remove, disable or expire the token it connects with. Later tasks must then connect with a password, or with the new token in bearer_token. An expiration at most an hour after the controller’s clock counts as expiring the token.

The module sends the write that removes, disables or expires the token it connects with after its other writes, and nothing after it. It reports connection_token_changed when it removed that token; a token that it disabled or expired is not reported. A write that fails after another succeeded fails the task with changed true.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

enabled

boolean

Whether the user’s tokens can log in. Unset leaves each token as it is; a token the task makes is enabled.

Ignored with state=absent.

Choices:

  • false

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

expiration_time

string

When the user’s tokens stop working, as an RFC 3339 time with a time zone offset or Z, such as 2027-06-01T00:00:00Z, or never for no expiration. Unset leaves each token as it is; a token the task makes then has none.

The cluster reads a time back in UTC, so times are compared as instants, not as text.

A time at or before now is refused for a token the task would make.

An unquoted time in YAML reaches the module in ISO 8601 form, with +00:00 for Z and a fraction cut to microseconds, which the module accepts.

The module sends the instant in UTC with Z, whatever form the task gave.

Ignored with state=absent.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

secret_destination

path

The directory on the controller where the module writes the bearer of a token it makes, in access-token-<user>-<id>.yml, readable only by its owner, where <user> is the user as access_tokens names it, with each run of characters other than letters, digits, ., _ and - replaced by one _. The file holds user, access_token_id and bearer_token. It is flushed to disk before its name appears, and never replaces another file.

The module removes no bearer’s file except the one it wrote in the same run for a token that the listing after the create did not show, which it deletes with the token. The file of a token that a later task deletes stays, and its bearer no longer works; the newest file of a user holds the bearer of the token the user was last given.

Before a token is made, the module makes the directory, or makes the one there readable only by its owner, and writes a file in it and removes it; if it cannot, the task fails before any write.

Required to make a token; a task that would make one without it fails before any write, in check mode too.

Check mode does not look at the directory, so one the module cannot use passes check mode and fails the real run before any write.

state

string

present makes a token when the user holds none, and otherwise makes none. enabled and expiration_time apply to each token the user holds, and to a token the task makes.

rotated makes a new token, writes its bearer to its file, confirms the token in a listing, and then removes every token the user held before. It reports a change on every run. enabled and expiration_time apply to the new token. A user holds at most two tokens, so a user who holds two is refused before any write.

rotated removes the old tokens at the end of the task, so every other holder of the user’s token loses access until it holds the new bearer (G-TOKEN).

absent removes every token of the user. A removed token stops working at once.

Choices:

  • "present" ← (default)

  • "absent"

  • "rotated"

user

string / required

The user that holds the tokens, as a trustee such as local:svc-backup or ad:CORP\svc-backup. A bare name is refused, and the cluster refuses a group.

The user must exist. In check mode, a user that does not exist yet because an earlier task creates it is reported as a new token. With state=absent, a user that does not exist holds no token, and the task changes nothing.

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

A token that would be made is reported as a change, without a bearer.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

The diff lists the user’s tokens before and after, each with its id, enabled and expiration_time. In check mode, a token the run would make appears with the id (a new token).

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

A run that makes a token returns its bearer, which no later run can return; a second run with state=present finds the token and changes nothing.

state=rotated makes a new token on every run.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v1/auth/access-tokens/ with the user, POST /v1/auth/access-tokens/, PATCH and DELETE /v1/auth/access-tokens/{id}; POST /v1/identity/find; GET /v1/session/who-am-i when the task connects with an access token.

  • A task that would make a token fails before any write unless it sets no_log and secret_destination (G-TOKEN). On ansible-core 2.22 and later the module also registers the bearer with Ansible’s masking of secret values.

  • A task with no_log hides its result, notes and the diff included, and keeps warnings; when the task fails, ansible-core still prints its msg. The module reports a token that is expired, and stays so, as a warning, because the no_log such a task needs hides notes.

  • A user holds at most two tokens, and an expired token counts (G-TOKEN).

  • A token holds the roles of its user, so the token of a member of Administrators is a full administrator’s credential.

  • A token is bound to the cluster that made it, and a rebuilt cluster has none of the old tokens.

  • When the connection is lost after a token is made, or the module cannot store its bearer, or the listing after the make does not show the token, the module removes that token and fails, and a rotation keeps the old tokens; the message says to run the task again. When removing that token fails too, the token stays, and the message names it. When the connection to a create is lost and the listing after it fails too, the module fails with changed and maybe_applied true, and the message says that a token whose bearer is lost may be left, and gives state=rotated when the user held no token, and state=absent, then state=present, when it held one. A later state=rotated for a user who then holds two tokens is refused before any write, and the refusal marks the token the task connects with (G-TOKEN).

  • When a step after the bearer is stored fails, the module fails with changed true, and the message names the new token, the file that holds its bearer and the old tokens it kept; the module gives the same words as a warning. The user may then hold two tokens, and the module has no way to remove only the old one. The message names the old token’s id and the way to delete it outside the module, qq auth_delete_access_token or DELETE /v1/auth/access-tokens/{id} (G-TOKEN). When a delete of an old token lost its connection, the message says that token may have been deleted and says to list the user’s tokens before deleting it.

  • A user who holds two tokens is refused a rotation before any write. The message names each token, marks the one the task connects with and any that expired, and says to delete the one to drop by its id, or to run state=absent and then state=present to replace both (G-TOKEN).

  • A rotation with enabled=false is refused when the token the task connects with is among the old ones, since the play would be left no token to connect with.

Examples

# These tasks take api_host and a credential from module_defaults for group/qumulo.cluster.qumulo.
# A task that makes a token needs no_log and secret_destination, since the cluster shows the bearer only once.
# Give each consumer a user of its own: a user's tokens are one set, so two consumers of one user cannot tell whose
# token is whose, and a rotation for one cuts off the other.
- name: Give the backup service an access token, writing a new token's bearer to a file
  qumulo.cluster.access_token:
    user: local:svc-backup
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  register: backup_token
  no_log: true

# The bearer is in the file only after the task made a token; a second run finds the token and changes nothing.
- name: Say where a new token's bearer is
  ansible.builtin.debug:
    msg: "made access token {{ backup_token.access_token_id }}; its bearer is in {{ backup_token.secret_file }}"
  when: backup_token.secret_file is defined

# Quote the time. A user who holds no token is given one, so the task carries no_log and secret_destination.
- name: Make the backup service's tokens expire at the end of June
  qumulo.cluster.access_token:
    user: local:svc-backup
    expiration_time: "2027-06-30T23:59:59Z"
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  no_log: true

- name: Stop the backup service's tokens from logging in, keeping them
  qumulo.cluster.access_token:
    user: local:svc-backup
    enabled: false
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  no_log: true

# no_log hides the diff from the output; a check run makes no token, so its diff holds no bearer.
- name: Preview a rotation of the backup service's token
  qumulo.cluster.access_token:
    user: local:svc-backup
    state: rotated
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  check_mode: true
  diff: true
  register: preview
  no_log: true

- name: Show the rotation's preview
  ansible.builtin.debug:
    var: preview.diff

# The new token works before the old one is removed, but the old one is removed at the end of the task: every consumer
# of the user's token loses access until it holds the new bearer. A user who holds two tokens is refused before any write;
# delete the one to drop by its id outside the collection, as the message says, or replace both with state: absent, then
# state: present, from a play that connects with a password.
- name: Rotate the backup service's token
  qumulo.cluster.access_token:
    user: local:svc-backup
    state: rotated
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  register: rotated
  no_log: true

# When the play connects with the token it rotates, later tasks must connect with the new one. The old token is removed
# last, so this task's own connection lasts until it ends. The token of a member of Administrators is a full
# administrator's credential: keep the file private.
- name: Rotate the token this play connects with
  qumulo.cluster.access_token:
    user: local:svc-ansible
    state: rotated
    allow_management_disruption: true
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  register: own_token
  no_log: true

- name: Connect with the new token from here on
  ansible.builtin.set_fact:
    qumulo_api_token: "{{ own_token.bearer_token }}"
  when: own_token.connection_token_changed | default(false)
  no_log: true

- name: Revoke every token of a retired service
  qumulo.cluster.access_token:
    user: local:svc-old
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

access_token_id

string

The id of the token the run made.

Returned: when the run made a token, outside check mode; and on the same failures as bearer_token

Sample: "1000000000000000000001"

access_tokens

list / elements=dictionary

The user’s tokens after the task, oldest first, without their bearers; empty after state=absent.

In check mode a token the run would make has no id, creator or creation time yet, and each is null.

Returned: when the task succeeds

Sample: [{"creation_time": "2026-06-01T09:30:00.000000000Z", "creator": "local:admin", "enabled": true, "expiration_time": null, "id": "1000000000000000000001", "user": "local:svc-backup"}]

creation_time

string

When the cluster made the token.

Returned: success

creator

string

The user who made the token, as a trustee.

Returned: success

enabled

boolean

Whether the token can log in.

Returned: success

expiration_time

string

When the token stops working, as the cluster reads it back, in UTC; null for never.

In check mode, a time the task would set is shown in UTC with Z, as the module would send it.

Returned: success

id

string

The token’s id.

Returned: success

user

string

The token’s user, as a trustee.

Returned: success

bearer_token

string

The new token’s bearer, the only time the cluster returns it. Hide it with no_log.

After a failure it is the bearer of the token the module made, which is also in the file secret_file names.

Returned: when the run made a token, outside check mode; and on a failure after the bearer was stored in its file, when the confirming listing, the disabling of the new token or the removal of an old token failed

Sample: "access-v1:example-not-a-real-bearer"

connection_token_changed

boolean

true when the task removed the token it connected with; later tasks must connect with another credential.

Returned: when the task removed the token it connected with

Sample: true

maybe_applied

boolean

true when a create, change or removal of a token was sent and its answer was lost, by a lost connection or a gateway’s HTTP 502 or 504, so it may have been applied. After a lost create it is set only when the listing that looks for the new token failed too; the message then says a token whose bearer is lost may be left, and what to run. The module fails with changed true.

Returned: on such a failure; with bearer_token, access_token_id and secret_file when the lost write came after the new bearer was stored

Sample: true

notes

list / elements=string

What the module noticed, which is a user that does not exist yet in check mode.

Returned: when there is something to note

Sample: ["user local:svc-backup does not exist yet; an earlier task must create it, and this task then makes its token"]

secret_file

string

The file in secret_destination that holds the new token’s bearer.

Returned: when the run made a token, outside check mode; and on the same failures as bearer_token

Sample: "/srv/artifacts/edge01/secrets/access-token-local_svc-backup-1000000000000000000001.yml"
