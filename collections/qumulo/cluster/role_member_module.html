qumulo.cluster.role_member module – Manage the members of a Qumulo role

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.role_member.

New in qumulo.cluster 0.1.0

Synopsis

  • Assigns trustees, such as local users and groups or Active Directory users and groups, to the role role, or removes them.

  • Trustees are named, never given by id, and resolved on every run. A member is the same trustee when it resolves to the same identity, so ad:CORP\alice and ad:alice@corp.example.com are one member.

  • An ad: trustee resolves only once the cluster has joined the domain, except ad:NT AUTHORITY\Authenticated Users, which resolves joined to a domain or not.

  • The role must exist, as qumulo.cluster.role creates a custom one, unless the task only removes members, with state=absent or with purge and no members, since a role that does not exist has none to remove; the task then reports no change, with a note, and looks up no member. In check mode a role that does not exist yet has no members, with a note, because an earlier task may create it.

  • A name the cluster could not find stays unresolvable for about a minute after it is created (QUIRK-017). A run that creates a local user and assigns it a role soon after a check run looked the user up can therefore fail to resolve it.

Parameters

Parameter

Comments

allow_management_disruption

boolean

Allow removing the user this task connects as from the role, which can take away the privileges later tasks need. Only a direct assignment of that user is detected, not one through a group.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

members

list / elements=string / required

Trustees in the collection’s grammar, such as local:svc-backup, ad:CORP\Qumulo-Admins, ldap_group:admins, sid:S-1-5-21-..., uid:1000 or Everyone. A bare name is refused, because it is ambiguous once the cluster uses AD or LDAP.

qumulo_support:qumulosupport:everyone is the member a cluster registered with Nexus has in the Qumulo-Support role.

With state=present, a trustee that does not exist fails the task; in check mode it is reported as a change, with a note, because an earlier task may create it or join its domain.

With state=absent, a trustee that does not exist is no member, with a note, in check mode and in a real run alike, as after its account is deleted.

purge

boolean

With state=present, also remove members not listed in members.

The local admin and system users always stay in Administrators, as the server requires. purge is refused for the Qumulo-Support role, which holds the assignment Qumulo’s support access relies on.

Choices:

  • false ← (default)

  • true

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

role

string / required

The role’s name, such as Administrators, Observers or a custom role.

state

string

present assigns the members; absent removes them.

Choices:

  • "present" ← (default)

  • "absent"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET (paginated) and POST /v1/auth/roles/{role}/members, DELETE /v1/auth/roles/{role}/members/{auth_id}, POST /v1/identity/find; GET /v1/session/who-am-i when the task connects with an access token.

  • Registers: QUIRK-017.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# An ad: trustee resolves only after the cluster has joined the domain with qumulo.cluster.ad_domain, and a local
# trustee only after qumulo.cluster.local_user created it. Deleting a local user drops its role assignments, so assign
# roles after the users are final.
- name: Make the AD group of storage administrators the cluster's administrators
  qumulo.cluster.role_member:
    role: Administrators
    members: ['ad:CORP\Qumulo-Admins']

- name: Give a local service user the Observers role
  qumulo.cluster.role_member:
    role: Observers
    members: ['local:svc-monitor']

- name: Preview which observers purging would remove
  qumulo.cluster.role_member:
    role: Observers
    members: ['local:svc-monitor']
    purge: true
  check_mode: true
  diff: true
  register: observers_preview

- name: Show the observers that would remain
  ansible.builtin.debug:
    var: observers_preview.role_member.members

- name: Let only the monitoring service user observe
  qumulo.cluster.role_member:
    role: Observers
    members: ['local:svc-monitor']
    purge: true

- name: Add the storage operators to the administrators, keeping the other members
  qumulo.cluster.role_member:
    role: Administrators
    members: ['ad:CORP\Storage-Operators']

- name: Take the storage operators out of the administrators
  qumulo.cluster.role_member:
    role: Administrators
    members: ['ad:CORP\Storage-Operators']
    state: absent

# A role with members cannot be deleted. This removes every member of a custom role, so that qumulo.cluster.role can
# delete it.
- name: Remove every member of the Backup-Operators role
  qumulo.cluster.role_member:
    role: Backup-Operators
    members: []
    purge: true

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

maybe_applied

boolean

true when a membership write was sent and the connection was lost before the cluster answered. The module does not send it again.

Returned: on a failure after such a write

Sample: true

notes

list / elements=string

What the module noticed, such as a role that does not exist yet in check mode, or a trustee that does not exist and so is no member.

Returned: when there is something to note

Sample: ["role 'Backup-Operators' does not exist yet; an earlier task is expected to create it"]

role_member

dictionary

The role’s members after the task, or in check mode the members the task would leave.

Returned: always

Sample: {"members": ["ad:CORP\\Qumulo-Admins", "local:admin"], "role": "Administrators"}

members

list / elements=string

Every member as a trustee string, sorted.

Returned: success

role

string

The role’s name.

Returned: success
