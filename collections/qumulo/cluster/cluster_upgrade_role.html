qumulo.cluster.cluster_upgrade role – Upgrade a fleet of Qumulo clusters hop by hop, in the order the upgrade plan gives

Note

This role is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.cluster_upgrade.

Entry point main – Upgrade a fleet of Qumulo clusters hop by hop, in the order the upgrade plan gives

New in qumulo.cluster 0.1.0

Synopsis

  • Runs each hop of cluster_upgrade_plan, the plan qumulo.cluster.upgrade_plan returns, on every host of the play at once, and finishes each hop on every host before the next starts. A hop is nine steps, keyed by facts on each host. 1. waits out a reboot under way, with qumulo.cluster.cluster_info‘s upgrade subset, and then the upgrade’s preflight, with its upgrade_blocked subset; 2. prepares every host the hop moves, every prepare before any commit; 3. prepares again each host whose first prepare failed, and asks qumulo.cluster.upgrade whether each host may commit; 4. asks the plan module whether the hop’s commits may begin inside the maintenance window; 5. commits the schedule’s steps in order, the spokes of a portal component together and then their hub, each step’s readiness checked again just before its commit; 6. waits on each moved component’s portals and reads each replication relationship that touches a moved host; 7. waits for the reboots; 8. reads the peers again; 9. writes the report.

  • A host that fails a step leaves the play, and holds its unit, its whole portal component, and every unit that follows it by qumulo_upgrade_after or a kept replication edge, as the plan’s holds give them. The rest of the hop goes on, and the run stops before the next hop, with upgrade_stop set.

  • Runs only in a linear play without serial; its first task refuses a play run in batches. Every qumulo.cluster.upgrade call writes its commit record on the controller through commit_record, so the play’s hosts use the local connection.

  • Under --check, makes one qumulo.cluster.upgrade call per host, for its first hop, which predicts every phase; asks the maintenance window once; skips the other steps up to the report; renews no lock; and writes the report, marked as a check run’s.

  • Sets the facts upgrade_moves, upgrade_reboots_only, upgrade_prepare_failed, upgrade_ready and upgrade_committed on each host, reset at each hop’s start; upgrade_held, the hop’s held hosts, upgrade_stop, true once the run must stop, and upgrade_stop_reason, why a failed lock renewal stopped it, on every host.

Parameters

Parameter

Comments

cluster_upgrade_artifact_dir

string

The directory, on the controller, of the commit records, <host>/upgrade/commit.yml, and of the report, upgrade-<UTC>.yml. Refused empty.

Defaults to the edge_rebuild role’s own expression, beside the inventory source that defines the host.

cluster_upgrade_peer_timeout

integer

Seconds steps 6 and 8 wait for a component’s portals to read ACTIVE. A timeout is reported, not failed.

Default: 1800

cluster_upgrade_plan

dictionary / required

The plan, the qumulo.cluster.upgrade_plan module’s output. Its hops are run in order.

cluster_upgrade_poll_delay

integer

Seconds between the reads of step 1, which waits out a reboot and the preflight, and between the portal reads of steps 6 and 8.

Each read of the reboot status in step 1 asks every node for its boot identity; a value below 30 is for tests.

Default: 30

cluster_upgrade_prepare_throttle

integer

How many prepares, and so how many clusters’ image downloads, run at once. It bounds step 2 and step 3’s prepare again, never the commits.

Unset, they run as wide as forks.

cluster_upgrade_reboot_timeout

integer

Seconds a reboot may take, passed to every upgrade call as its reboot_timeout, and step 1’s bound.

Default: 43200

cluster_upgrade_unblock_timeout

integer

Seconds step 1 waits for the upgrade’s preflight to clear, such as the background work after a reboot.

Default: 14400

cluster_upgrade_wait_timeout

integer

Seconds each phase of an upgrade call waits, passed to every call as its wait_timeout.

Default: 3600

edge_rebuild_artifact_dir

string

The directory of the restore locks, <host>/restore/lock, the edge_rebuild role’s own variable.

qumulo_portal

dictionary

The host’s portal, whose hub names the hub whose portals a spoke reads when the hub is outside the play.

qumulo_replication_relationships

list / elements=dictionary

The host’s replication relationships, whose last job the peer steps read when one touches a moved host.

qumulo_upgrade_allow_limited_release

boolean

A support-directed action; Qumulo Care directs when to set it.

Sends Qumulo Core’s waiver of the rule that refuses a limited (letter) release as the source.

Choices:

  • false ← (default)

  • true

qumulo_upgrade_images

list / elements=any

The host’s images, each a URL or a path, or a mapping with image and build. The plan’s image_index picks the hop’s entry; its URL’s query string and user information are passed as the call’s image_secret, read once per hop.

qumulo_upgrade_reboot_set_size

integer

How many nodes a rolling reboot takes at once, at least 1. Unset, Qumulo Core chooses.

qumulo_upgrade_verify_in_check_mode

boolean

In check mode, also run verify, which downloads the whole image on every node.

Choices:

  • false ← (default)

  • true

upgrade_lock_held

list / elements=string

The hosts a lock the lock step refused protects. Each hop holds, for each of them it moves, its holds in that hop.

Default: []

upgrade_lock_hosts

list / elements=string

The hosts that hold one of the run’s restore locks, the plan’s lock_hosts the lock step took. Each renews its lock to the hop’s lease at each hop’s start, outside check mode; a renewal that fails stops the run before the hop.

Default: []

upgrade_lock_token

string

On each of upgrade_lock_hosts, the token its take of the lock returned, which each renewal passes back.

upgrade_stop

boolean

True to run no hop. The role sets it once a hop ends with a host held or out of the play.

Choices:

  • false ← (default)

  • true
