qumulo.cluster.upgrade_report module – Turn one hop’s upgrade results into the hop’s report

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.upgrade_report.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

  • See Also

  • Examples

  • Return Values

Synopsis

  • Takes one hop of qumulo.cluster.upgrade_plan‘s plan and each host’s registered qumulo.cluster.upgrade results for the hop, and returns the hop’s report, which the qumulo.cluster.cluster_upgrade role writes after each hop.

  • A pure computation. It sends no request, takes no connection options, and is not in the qumulo.cluster.qumulo action group, so module_defaults for that group do not reach it.

  • Each host’s entry gives the release and build it ran and ends on, the upgrade type, each phase’s start and end, the prepare’s duration, the commit’s start, the seconds the REST API did not answer during the commit’s restart, the reboot, the outcome and its lines.

  • Each portal component the hop moves gets its mismatch window, from its first member’s commit start to its last member’s commit done, and whether the hop left it on two releases.

  • Only the results’ return fields are read, never their invocation, and every text passes through the same URL redaction as the modules’ own messages.

Parameters

Parameter

Comments

check_mode_run

boolean

Whether the run was a check run, whose results predict and change nothing.

Choices:

  • false ← (default)

  • true

held

list / elements=string

The hosts the run held out of this hop’s commits.

Default: []

hop

dictionary / required

The hop, one of qumulo.cluster.upgrade_plan‘s plan.hops.

lines

list / elements=string

The caller’s own lines for the hop, such as why the run stopped before it. They come first among the hop’s lines.

Default: []

lock_held

list / elements=string

The hosts a restore lock the run could not take holds out of every hop.

Default: []

peers

dictionary

The peer steps’ readings, before the reboots and after them.

Default: {}

commits

list / elements=dictionary

The readings after the commits. A portal’s is {component, host, active, seconds, line}, with active null when the step skipped the component; a replication relationship’s is {source, target, error, line}.

Default: []

reboots

list / elements=dictionary

The readings after the reboots, in the same shape.

Default: []

prepare_failed

list / elements=string

The hosts whose first prepare failed with a refusal a second prepare may lift, which the run kept for its second prepare.

Such a host whose failed first prepare is its last result, its second prepare skipped because its unit was held, is reported as held, with the host whose failure held it.

Default: []

results

dictionary

A mapping of host name to that host’s registered qumulo.cluster.upgrade results for this hop, a list in the order the tasks ran, or one result.

A failure is its registered result, with failed and msg. The module leaves out skipped results.

Default: {}

window

dictionary

The window form’s answer for the hop, as qumulo.cluster.upgrade_plan returns it in window.

Attributes

Attribute

Support

Description

check_mode

Support: full

This action does not modify the cluster.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: none

This action does not modify the cluster.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

This action does not modify the cluster.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Examples

# upgrade_report takes no connection options. In a play over many hosts every host computes the same report, so run_once
# keeps it to one run, and delegate_to: localhost puts that run on the controller.
- name: Report a hop from every host's results
  # upgrade_plan_result is the registered result of qumulo.cluster.upgrade_plan, and edge01_prepare and edge01_commit
  # are the registered results of two qumulo.cluster.upgrade tasks run against edge01.
  qumulo.cluster.upgrade_report:
    hop: "{{ upgrade_plan_result.plan.hops[0] }}"
    results:
      edge01:
        - "{{ edge01_prepare }}"
        - "{{ edge01_commit }}"
  run_once: true
  register: upgrade_report_result

- name: Report a hop of a check run
  # upgrade_plan_result is the registered result of qumulo.cluster.upgrade_plan, and upgrade_prediction is the registered
  # result of a qumulo.cluster.upgrade task run against edge01 in check mode.
  qumulo.cluster.upgrade_report:
    hop: "{{ upgrade_plan_result.plan.hops[0] }}"
    results:
      edge01:
        - "{{ upgrade_prediction }}"
    check_mode_run: true
  run_once: true
  register: upgrade_report_check

- name: Report a hop that held a host out of its commits
  # upgrade_hop_results maps each host to its registered qumulo.cluster.upgrade results; upgrade_held lists the hosts the
  # run held; upgrade_plan_window is the registered result of qumulo.cluster.upgrade_plan with its window option.
  qumulo.cluster.upgrade_report:
    hop: "{{ upgrade_plan_result.plan.hops[0] }}"
    results: "{{ upgrade_hop_results }}"
    held: "{{ upgrade_held }}"
    window: "{{ upgrade_plan_window.window | default(omit) }}"
    lines:
      - The run stopped before the second wave.
  run_once: true
  register: upgrade_report_held

- name: Show the lines of the hop's report
  ansible.builtin.debug:
    var: upgrade_report_held.report.lines

Key

Description

report

dictionary

The hop’s report.

Returned: always

check_mode_run

boolean

Whether the results are a check run’s predictions.

Returned: success

components

dictionary

Each portal component the hop moves, with its members, its moving members, split, its mismatch window, {started, ended, seconds, open, uncommitted} or null when no member’s commit started, and two_releases, whether the hop left it on two releases.

Returned: success

hop

dictionary

The hop’s number, release, lease and the hosts it moves.

Returned: success

hosts

dictionary

Each host of the hop, with from and to, each {version, build}, upgrade_type, phases, each {started, ended} in UTC, prepare_seconds, commit_started, downtime_seconds, reboot, {mode, set_size, seconds}, commit_sent, committed and lines.

outcome is committed, rebooted once a platform upgrade’s reboots are done, failed with its message, maybe_applied and unfinished_commit, held with held_by, the host whose failure held it, and lock_held, at target, predicted in a check run, with the module’s prediction, or not committed.

Returned: success

lines

list / elements=string

The hop’s own lines, lines first, then the window’s, the peer steps’ and each component left on two releases.

Returned: success

notes

list / elements=string

The hop’s notes from the plan.

Returned: success

peers

dictionary

The peer steps’ readings, peers as given, as commits and reboots lists.

Returned: success

warnings

list / elements=dictionary

Each warning the hop’s results gave, {host, message}.

Returned: success

window

dictionary

The window form’s answer, window as given, or null.

Returned: success
