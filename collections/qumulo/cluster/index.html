Qumulo.Cluster

Collection version 0.1.0

  • Description

  • Plugin Index

  • Role Index

Description

Declarative, idempotent day-2 configuration of Qumulo Core clusters through the Qumulo REST API.

Authors:

  • Qumulo, Inc.

  • Mark McCallister

Supported ansible-core versions:

  • 2.20.0 or newer

  • Issue Tracker
  • Repository (Sources)

Plugin Index

These are the plugins in the qumulo.cluster collection:

Modules

  • access_token module – Manage the access tokens of a user on a Qumulo cluster

  • ad_domain module – Join a Qumulo cluster to an Active Directory domain, or leave it

  • audit_destination module – Manage a Qumulo cluster’s audit log destination

  • auth_cache_clear module – Clear a Qumulo cluster’s cache of identities and group memberships

  • authoritative_dns module – Manage the DNS server a Qumulo cluster runs for its own name

  • capacity_clamp module – Set a Qumulo cluster’s capacity clamp, writing only when it must change

  • capture_info module – Read a Qumulo cluster’s configuration as the inventory variables that declare it

  • clone_host_vars module – Derive a fresh Qumulo cluster’s host_vars from another cluster’s capture

  • cluster_guard module – Check that a Qumulo cluster is the one a play expects, and wait until it is ready

  • cluster_info module – Read a Qumulo cluster’s identity, version, license, capacity and product type

  • cluster_settings module – Manage a Qumulo cluster’s name

  • directory module – Make sure a directory exists on a Qumulo cluster, with its mode, owner and group

  • directory_quota module – Manage the hard capacity quota of a directory on a Qumulo cluster

  • dns_cache_clear module – Clear a Qumulo cluster’s DNS cache

  • dns_lookup_overrides module – Manage the names a Qumulo cluster resolves without asking DNS

  • dns_settings module – Manage the DNS servers and search domains a Qumulo cluster resolves names with

  • edge_cache_route module – Choose how to bring a Qumulo edge’s cache to a target size

  • edge_rebuild_preflight module – Check that a Qumulo edge’s live state can be replayed from its inventory before a rebuild destroys it

  • encryption_key_rotation module – Rotate a Qumulo cluster’s at-rest encryption key once it is older than a given age

  • file_acl module – Declare the access control list of a file or directory on a Qumulo cluster

  • filesystem_info module – Read a Qumulo cluster’s file system capacity, root directory and quotas

  • filesystem_settings module – Manage a Qumulo cluster’s file system settings

  • ftp_info module – Read a Qumulo cluster’s FTP settings and each node’s FTP server status

  • ftp_settings module – Manage a Qumulo cluster’s FTP server settings

  • host_vars_text module – Write variables read from a Qumulo cluster as a host_vars file Ansible never templates

  • identity_attributes module – Manage the home directory a Qumulo cluster gives an Active Directory, LDAP or POSIX identity

  • identity_info module – Read a Qumulo cluster’s local users and groups, roles, directory services and sign-in settings

  • kerberos_keytab module – Install, replace or delete a Qumulo cluster’s Kerberos keytab

  • kerberos_settings module – Manage a Qumulo cluster’s Kerberos settings

  • license module – Make sure a Qumulo cluster holds a license for its current UUID

  • local_group module – Manage a Qumulo cluster’s local group and its members

  • local_user module – Manage a Qumulo cluster’s local user

  • monitoring_info module – Read a Qumulo cluster’s monitoring, Nexus, audit and encryption settings and status

  • monitoring_settings module – Manage a Qumulo cluster’s cloud monitoring settings

  • network_config module – Manage a Qumulo cluster’s network document

  • network_info module – Read a Qumulo cluster’s network and name resolution settings

  • nexus_cluster module – Retire a cluster in Qumulo’s Nexus service

  • nexus_connection module – Manage a Qumulo cluster’s connection to Qumulo’s Nexus service

  • nexus_registration module – Register a Qumulo cluster with Qumulo’s Nexus service

  • nfs_export module – Manage an NFS export on a Qumulo cluster

  • nfs_info module – Read a Qumulo cluster’s NFS exports and NFS server settings

  • nfs_settings module – Manage a Qumulo cluster’s NFS server settings

  • portal_eviction_settings module – Manage the free-capacity threshold at which a cluster evicts cached spoke data

  • portal_hub module – Accept a spoke’s portal proposal on the hub, set its type and roots, or delete it

  • portal_info module – Read a Qumulo cluster’s spoke and hub portals, its eviction threshold and its cache size

  • portal_spoke module – Propose a spoke portal to a hub cluster, or delete it

  • replication_failover_plan module – Choose the next step of a replication failover, resync or failback, from fresh reads of both clusters

  • replication_info module – Read a Qumulo cluster’s replication relationships, as source, as target and to object storage

  • replication_pair_plan module – Join the source’s and the target’s check passes of a replication relationship into one decision

  • replication_relationship module – Declare a replication relationship on its source cluster, or delete the source’s records of it

  • replication_restore_info module – List the restore records and restore locks left on the controller, with their age

  • replication_restore_lock module – Hold the controller’s lock on an edge’s restore, so one restore runs per edge at a time

  • replication_restore_step module – Choose the next step of a rebuilt source’s restore from its replica, from fresh reads of both clusters

  • replication_reverse module – Make a replication target writable, reverse a relationship, or reconnect it, by its id

  • replication_target module – Authorize a replication relationship on its target cluster, or delete the target’s records of it

  • role module – Manage a custom Qumulo role and its privileges

  • role_member module – Manage the members of a Qumulo role

  • s3_access_key module – Manage the S3 access keys of a user on a Qumulo cluster

  • s3_bucket module – Manage an S3 bucket on a Qumulo cluster

  • s3_bucket_policy module – Manage the policy of an S3 bucket on a Qumulo cluster

  • s3_info module – Read a Qumulo cluster’s S3 settings, buckets, bucket policies and access keys

  • s3_settings module – Manage a Qumulo cluster’s S3 server settings

  • saml_settings module – Manage a Qumulo cluster’s SAML single sign-on settings

  • security_key module – Manage a key that locks snapshots in a Qumulo cluster’s file system key store

  • smb_info module – Read a Qumulo cluster’s SMB shares, SMB server settings and open SMB sessions

  • smb_settings module – Manage a Qumulo cluster’s SMB server settings

  • smb_share module – Manage an SMB share on a Qumulo cluster

  • snapshot module – Take a snapshot of a directory on a Qumulo cluster

  • snapshot_info module – Read a Qumulo cluster’s snapshots, snapshot policies, snapshot capacity and lock keys

  • snapshot_lock module – Lock or unlock a snapshot on a Qumulo cluster with a key from its key store

  • snapshot_policy module – Manage a snapshot policy on a Qumulo cluster

  • ssl_certificate module – Install the TLS certificate a Qumulo cluster serves

  • ssl_ciphers module – Manage the TLS cipher suites a Qumulo cluster accepts

  • tenancy_plan module – Check a cluster’s tenants, networks, shares and exports before the baseline writes any of them

  • tenant module – Manage a Qumulo cluster’s network tenant

  • tenant_info module – Read a Qumulo cluster’s network tenants

  • time_settings module – Manage where a Qumulo cluster gets its time

  • unprotected_edge_create module – Form a single-node unprotected edge from an unconfigured Qumulo node

  • upgrade module – Upgrade a Qumulo cluster by one hop, from verify to its reboots

  • upgrade_plan module – Plan a fleet’s Qumulo Core upgrade, hop by hop, before anything is sent

  • upgrade_report module – Turn one hop’s upgrade results into the hop’s report

  • user_defined_mappings module – Manage which Active Directory users a Qumulo cluster maps to which LDAP users

  • web_ui_settings module – Manage a Qumulo cluster’s Web UI login banner and inactivity timeout

Filter Plugins

  • artifact_dir filter – Where the collection’s roles keep a host’s records and secrets

  • host_vars_duplicates filter – A host_vars file’s variables without the shares and exports the inventory already declares

  • item_areas filter – The keys inside list items that put a declared variable in an area

  • policy_lock_keys filter – What the cluster_baseline role applies of the snapshot policies, given the key store

  • redact_images filter – An upgrade images list without the secret parts of its URLs

  • restore_key_hash filter – The digest that names a relationship’s restore record and restore stamp

  • restore_report_claims filter – The rebuild report’s claim on a host’s relationships, read on the controller

  • tenancy_first_pass filter – What the edge_rebuild replay declares in its tenant 1 pass, before the baseline

  • tenancy_status_due filter – Whether the cluster_baseline role’s step 2 reads the cluster’s network status

  • url_secret filter – The secret parts of an upgrade image’s URL

  • warn filter – Show a text as a warning of the task that renders it

Inventory Plugins

  • terraform inventory – Qumulo clusters from a Terraform root’s qumulo_ansible_inventory output

Role Index

These are the roles in the qumulo.cluster collection:

  • cluster_baseline role – Bring a Qumulo cluster to the baseline its inventory declares

  • cluster_upgrade role – Upgrade a fleet of Qumulo clusters hop by hop, in the order the upgrade plan gives

  • edge_cache_resize role – Bring a Qumulo edge’s cache to a target size, by the least disruptive route

  • edge_rebuild role – Rebuild a Qumulo unprotected edge, draining it first, and bring the new edge back to its baseline

  • portal_pair role – Pair a spoke cluster with a hub cluster through a portal, or drain and decommission the pairing

  • replication_failover role – Fail a replication relationship over to its target, copy the target’s writes back, or fail it back

  • replication_pair role – Declare a replication relationship between two clusters, or remove it, refusing before any write
