qumulo.cluster.replication_failover_plan module – Choose the next step of a replication failover, resync or failback, from fresh reads of both clusters

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_failover_plan.

New in qumulo.cluster 0.1.0

Synopsis

  • The qumulo.cluster.replication_failover role calls this module before every step, with fresh reads of both clusters, and runs only the step it returns. Its first answer lists every step left, which is the role’s dry run.

  • A pure computation. It sends no request, takes no connection options, and is not in the qumulo.cluster.qumulo action group, so module_defaults for that group do not reach it.

  • The source and the target are the relationship’s declared ones, whatever direction the records run in. In the declared direction the target holds a target record from the source’s UUID with the two paths; after a reverse it holds a source record of the target path to the source’s UUID. The module matches both clusters’ records against both forms.

  • It names the relationship’s state, state, and lists the steps action has left from it, steps.

  • Each verb moves the record of the cluster it is sent to first, and the peer’s record follows seconds later. The module reads the state from the record a verb moves first, and the other record may lag.

  • Two pairs of states read the same. The source’s target record DISCONNECTED after a reverse reads as the resync’s state before its reconnect, unless last_verb is the failback’s make-writable on the source. The target’s record DISCONNECTED in the declared direction reads as failed over, unless last_verb is the failback’s reverse.

  • It fails, before any step, when no record of the relationship is on the target, when records run in both directions or two run in one, when a live record on the target is from a previous UUID of the source, when the state is one action does not start from, when a make-writable has no recovery point or the source answers with a job running and allow_partial_job is false, when a resync or failback has no answer from the source or no record on it, when a reverse is toward an address that is not an IP literal, and when a new target’s tenant has replication off. The message says what would lift it, where something does.

Parameters

Parameter

Comments

action

string / required

failover makes the target’s copy writable. resync reverses the relationship and reconnects it, so the target replicates its writes to the source. failback resyncs when needed, then waits for a current recovery point, makes the source writable, reverses it back and reconnects the target, and applies the declared settings.

Choices:

  • "failover"

  • "resync"

  • "failback"

allow_partial_job

boolean

Let a failover discard the changes of a job the source, which answers, is running.

Choices:

  • false ← (default)

  • true

last_verb

string

The name of the last verb step this run sent, the name of that answer’s step, or unset before the run sends one.

It decides the two states that read the same. A finished wait for the source’s record to read DISCONNECTED counts as make_writable_source.

newer_writes_hosts

list / elements=string

The inventory hosts that the role’s replication_failover_allow_newer_writes names, whose reconnects skip the comparison.

The text of a reconnect step sent to one of them says that it does not compare first. Nothing else in the answer depends on it.

Default: []

relationship

dictionary / required

The declared relationship, one entry of the source host’s qumulo_replication_relationships, with source_path and target_path, and the settings a failback applies at its end.

source_cluster_uuid

string / required

The source’s qumulo_cluster_uuid.

source_error

string

Why the source did not answer, when it did not. A resync or failback names it in its refusal.

source_host

string / required

The source’s inventory host name.

source_previous_cluster_uuids

list / elements=string

The source host’s qumulo_previous_cluster_uuids. A live record on the target from one of them holds the replica a rebuilt source’s restore brings back, and the module refuses, naming the restore.

Default: []

source_relationships

dictionary

The source’s replication facts from qumulo.cluster.replication_info.

Leave it out when the source did not answer.

source_replication_address

string

The source’s qumulo_replication_address, which a resync’s reverse sends.

Required, as an IP literal, when the steps left hold the resync’s reverse.

source_replication_port

integer

The source’s qumulo_replication_port.

Default: 3712

source_tenancy

dictionary

The source’s tenants, tenants, as qumulo.cluster.tenant_info gives them, and its network document, document, as qumulo.cluster.network_info gives it, for the check that the tenant serving its replication address has replication on. Required when the steps left hold a resync’s reverse.

synced

boolean

Whether this run’s wait for a current recovery point, the step await_sync, has finished, which drops that step.

Choices:

  • false ← (default)

  • true

target_cluster_uuid

string / required

The target’s qumulo_cluster_uuid.

target_host

string / required

The target’s inventory host name.

target_relationships

dictionary / required

The target’s replication facts from qumulo.cluster.replication_info.

target_replication_address

string

The target’s qumulo_replication_address, which a failback’s reverse sends.

Required, as an IP literal, when the steps left hold the failback’s reverse.

target_replication_port

integer

The target’s qumulo_replication_port.

Default: 3712

target_tenancy

dictionary

The target’s tenants and network document, as source_tenancy. Required when the steps left hold a failback’s reverse.

Attributes

Attribute

Support

Description

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: none

This action does not modify the cluster.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

This action does not modify the cluster.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • While the source does not answer, the target’s record of a job the source was running reads REPLICATION_RUNNING for as long as it was watched (QUIRK-125), so the module refuses a make-writable for a running job only when the source answers, and otherwise notes the partial job the make-writable discards.

  • docs/explanation/replication.md says why the module reads the states as it does.

Examples

# The qumulo.cluster.replication_failover role does these reads and calls before every step. Use the module directly
# to read what a failover would do without the role. The role goes on without the source only when its read gave up or
# ended in a 502, 503 or 504; this recipe treats every failure of the read as the source not answering.
- name: Record how to connect to edge01 and dr01
  # The reads below take their connections from cluster_baseline_connections, which this include records first.
  ansible.builtin.include_role:
    name: qumulo.cluster.cluster_baseline
    tasks_from: connections.yml
  vars:
    cluster_baseline_connection_hosts: [edge01, dr01]

- name: Read the source's relationships, which may not answer
  qumulo.cluster.replication_info:
    gather_subset: [source, target]
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ cluster_baseline_connections['edge01'] }}"
  register: edge01_replication
  failed_when: false

- name: Read the target's relationships
  qumulo.cluster.replication_info:
    gather_subset: [source, target]
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ cluster_baseline_connections['dr01'] }}"
  register: dr01_replication

- name: Plan the failover of edge01's projects to dr01
  qumulo.cluster.replication_failover_plan:
    action: failover
    relationship: {source_path: /projects, target: dr01, target_path: /replicas/edge01-projects}
    source_host: edge01
    target_host: dr01
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    source_relationships: "{{ edge01_replication.replication | default(omit) }}"
    source_error: "{{ edge01_replication.msg | default(omit) }}"
    target_relationships: "{{ dr01_replication.replication }}"
  register: failover_plan

- name: Show every step left
  # A second run, once dr01 is writable, lists no step, and done is true.
  ansible.builtin.debug:
    msg: "{{ failover_plan.steps | map(attribute='text') | list }}"

- name: Read edge01's tenants
  qumulo.cluster.tenant_info:
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ cluster_baseline_connections['edge01'] }}"
  register: edge01_tenants

- name: Read edge01's network document
  qumulo.cluster.network_info:
    gather_subset: [document]
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ cluster_baseline_connections['edge01'] }}"
  register: edge01_networks

- name: Read dr01's tenants
  qumulo.cluster.tenant_info:
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ cluster_baseline_connections['dr01'] }}"
  register: dr01_tenants

- name: Read dr01's network document
  qumulo.cluster.network_info:
    gather_subset: [document]
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ cluster_baseline_connections['dr01'] }}"
  register: dr01_networks

- name: Plan the failback of edge01's projects with both addresses and both clusters' tenants
  # A resync's reverse needs the source's address, and a failback's the target's, as an IP literal, and each reverse
  # needs the tenants and the network document of the cluster that becomes the target. A failback takes both clusters'
  # when it runs the resync's steps first. The source's relationships come from the reads at the top of these examples.
  qumulo.cluster.replication_failover_plan:
    action: failback
    relationship: {source_path: /projects, target: dr01, target_path: /replicas/edge01-projects}
    source_host: edge01
    target_host: dr01
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    source_replication_address: 203.0.113.10
    target_replication_address: 203.0.113.40
    source_relationships: "{{ edge01_replication.replication }}"
    target_relationships: "{{ dr01_replication.replication }}"
    source_tenancy: {tenants: "{{ edge01_tenants.tenants }}", document: "{{ edge01_networks.network.document }}"}
    target_tenancy: {tenants: "{{ dr01_tenants.tenants }}", document: "{{ dr01_networks.network.document }}"}
  register: failback_plan

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

direction

string

declared when the target holds the target record, reversed when it holds a source record.

Returned: success

Sample: "declared"

done

boolean

Whether the action has nothing left to do.

Returned: success

Sample: false

notes

list / elements=string

What the module noticed, such as a source that did not answer.

Returned: success

Sample: ["edge01 did not answer (the cluster did not answer); the plan goes on from dr01's record alone"]

recovery_point

string

The target’s record’s recovery point, or null before the first job.

Returned: success

Sample: "2026-11-08T06:26:34.190479565Z"

relationship_id

string

The relationship’s id, which both records share and a reverse keeps.

Returned: success

Sample: "9465828e-7dcf-466e-a550-78ed0bd6b79b"

state

string

The relationship’s state, one of replicating, failing over, failed over, reconnecting, reversed, resyncing, resynced, failing back, source disconnecting, failing back, source writable and failing back, reversed.

Returned: success

Sample: "failed over"

step

dictionary

The next step, the first of steps, or null when done.

Returned: success

Sample: {"cluster": "target", "host": "dr01", "kind": "verb", "name": "make_writable_target", "polls": [{"cluster": "target", "side": "target", "until": ["DISCONNECTED"]}], "relationship_id": "9465828e-7dcf-466e-a550-78ed0bd6b79b", "text": "dr01: make /replicas/edge01-projects writable. It goes back to the recovery point 2026-11-08T06:26:34.190479565Z; writes on edge01 after it stay behind on edge01", "verb": "make_writable"}

steps

list / elements=dictionary

Every step left, in order. Each has name, cluster, source or target, the inventory role of the cluster it runs on, host, that cluster’s inventory host, kind, verb, poll, sync or settings, relationship_id and text, its line in the plan.

A verb step has verb, the qumulo.cluster.replication_reverse verb, polls, the records to wait for after it, and for reverse source_address and source_port. A poll step has polls, each cluster, side and until, the states that end it. A sync step has recovery_point, the value the wait counts moves past. A settings step has options, for qumulo.cluster.replication_relationship.

Returned: success

Sample: [{"cluster": "target", "host": "dr01", "kind": "verb", "name": "make_writable_target", "polls": [{"cluster": "target", "side": "target", "until": ["DISCONNECTED"]}], "relationship_id": "9465828e-7dcf-466e-a550-78ed0bd6b79b", "text": "dr01: make /replicas/edge01-projects writable. It goes back to the recovery point 2026-11-08T06:26:34.190479565Z; writes on edge01 after it stay behind on edge01", "verb": "make_writable"}]
