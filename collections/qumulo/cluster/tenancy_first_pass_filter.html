qumulo.cluster.tenancy_first_pass filter – What the edge_rebuild replay declares in its tenant 1 pass, before the baseline

Note

This filter plugin is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.tenancy_first_pass.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Input

  • Keyword parameters

  • Examples

  • Return Value

Synopsis

  • On a cluster whose network document has no managed interfaces and no frontend network, as a newly formed edge on host-managed networking has, the cluster_baseline role’s step 2 refuses a second tenant’s create, because the creates at step 3a come before the network document at step 3.

  • When the inventory’s tenants create a tenant on such a cluster, the filter gives what the edge_rebuild role’s replay passes the baseline’s tenancy step first. That is tenants, tenant 1 alone, found by its name after the entries’ renames, with its entry’s name and previous_name and nothing else, or its name alone when no present entry declares it, as when it is declared absent, where it is the Default the edge forms with. It is also network, the given qumulo_network with frontend_networks replaced by tenant 1’s own networks, which are the networks under its entry, which go without vlan_id or mtu, and each network in frontend_networks that the baseline’s step 2 resolves to tenant 1 or to no tenant, as a tenant_id the newly formed edge lacks does. Each is sent with no tenant or tenant_id, which in a run of one tenant is tenant 1. The baseline’s step 3 then adds the other tenants’ networks, and, where the newly formed edge answers its network status, its step 2 places the play’s address on the one HOST network the pass leaves, which is not the play’s when it reaches the edge on another tenant’s network.

  • Only when tenant 1 holds no network, as when it is declared absent, left undeclared or given networks [], does network hold every network the inventory lists for a tenant that stays, that is, each network in frontend_networks whose tenant is not an absent one, and each present tenant’s own networks. So every network exists before any create and the baseline’s step 3 only binds them.

  • It gives an empty dict when the document has a frontend network or managed interfaces, when the entries create no tenant, when the cluster has no tenant 1, or when the inventory lists no network for a tenant that stays, since that pass would write nothing. The edge_rebuild_preflight module calls the same rule on the newly formed edge it models, and refuses an inventory that gets no pass while it creates a tenant.

  • Each entry and each cluster tenant needs a name, and each cluster tenant an id; one without fails the filter, naming qumulo_tenants. A listed network without an id fails it too, naming the networks.

  • The tenants are defined by Qumulo’s multitenancy REST API, which Qumulo marks as preview; a later Qumulo Core release may change it.

Input

This describes the input of the filter, the value before | qumulo.cluster.tenancy_first_pass.

Parameter

Comments

Input

list / elements=dictionary / required

The entries of qumulo_tenants, or null or an empty list when it is unset.

Keyword parameters

This describes keyword parameters of the filter. These are the values key1=value1, key2=value2 and so on in the following example: input | qumulo.cluster.tenancy_first_pass(key1=value1, key2=value2, ...)

Parameter

Comments

cluster_tenants

list / elements=dictionary / required

The cluster’s tenants, as qumulo.cluster.tenant_info returns them in tenants.

document

dictionary / required

The cluster’s network document, as qumulo.cluster.network_info returns it in network.document.

network

dictionary

qumulo_network, or null when it is unset.

Examples

# The read tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Read the cluster's tenants
  qumulo.cluster.tenant_info:
  register: tenants_read

- name: Read the cluster's network document
  qumulo.cluster.network_info:
    gather_subset: [document]
  register: network_read

- name: Plan the tenant 1 pass
  ansible.builtin.set_fact:
    first_pass: >-
      {{ qumulo_tenants | default([]) | qumulo.cluster.tenancy_first_pass(tenants_read.tenants, network_read.network.document,
                                                                          qumulo_network | default(none)) }}

Return Value

Key

Description

Return value

dictionary

The pass’s tenants and network, or an empty dict when there is no pass.

Returned: always

Sample: {"network": {"frontend_networks": [{"id": 0, "name": "Default", "type": "HOST"}]}, "tenants": [{"name": "accounts", "previous_name": "Default"}]}
