qumulo.cluster.upgrade module – Upgrade a Qumulo cluster by one hop, from verify to its reboots

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.upgrade.

Synopsis

  • Upgrades one cluster to the release of one image, through Qumulo Core’s own upgrade routes. state sets how far the task goes, through verify, prepare, commit or the commit’s reboots. Each phase reads back before it writes, so a rerun after a failure picks up where the cluster is.

  • An upgrade is an action, not a setting (G-ACTIONS). A cluster that already runs the target release, and the declared build when one is given, with no reboot under way, is left alone. A cluster PREPARED with the same image, reboot settings and waivers is not prepared again; with other settings or another image it is prepared again, which replaces the earlier prepare.

  • Before any write the module reads the cluster’s UUID, its version, the upgrade status, the preflight, the protection status, the reboot status and the nodes. A reboot under way is waited out first, up to reboot_timeout. A reboot paused outside this run, or stopped on an error, fails at once.

  • The commit’s outcome is decided from the running build, not from an IDLE status (G-UPGRADE-RECORD). A commit that did not finish fails at once with unfinished_commit, and the module sends nothing more.

  • With commit_record, the module writes a record on the controller just before the commit request, and decides any record it finds there before any write, as qumulo.cluster.upgrade_plan does.

  • Check mode sends only reads, and verify when verify_in_check_mode is set, and waits for nothing. It reports the phases the task would run and the waits it would make. In check mode changed is true whenever a phase would run, even a readiness check of a cluster already PREPARED, whose real run changes nothing.

  • This module runs one hop of one cluster. The qumulo.cluster.cluster_upgrade role runs a fleet.

Parameters

Parameter

Comments

allow_upgrade_from_limited_release

boolean

On a cluster that runs a limited (letter) release, such as 7.10.3A, send Qumulo Core’s waiver of the rule that refuses such a source (G-UPGRADE-LETTER). From 7.11.0 that is the named rule allow_upgrade_from_limited_release; below 7.11.0 it is override_compatibility_check, which lifts every compatibility rule, so it is sent only with build and only after a verify, sent with it, reads version.

On a cluster that runs no letter release, nothing is sent.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

build

string

The build the cluster must end on, as Qumulo Care names it. Once the cluster runs a new build of version, another build fails at once.

Needed for allow_upgrade_from_limited_release on a source below 7.11.0.

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

commit

boolean

With state=rebooted, false refuses a cluster that does not already run the target release, so the task only waits for the reboots and never commits.

Choices:

  • false

  • true ← (default)

commit_record

path

The path, on the controller, of this cluster’s commit record. The qumulo.cluster.cluster_upgrade role passes <cluster_upgrade_artifact_dir>/<host>/upgrade/commit.yml.

The module writes it as pending just before the commit request, and flushes it to disk first. It removes it once the commit is done or refused, and marks it unfinished when the commit did not finish.

A record already there is decided before any write. One this cluster’s state shows done, or that belongs to another cluster, is removed, with a warning. One the cluster’s state shows was never committed is removed too. One of a commit still under way, or one that did not finish, is refused. A file that is not a commit record is refused.

Unset, no record is written, and the failure messages say so.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

host_name

string

The name this module’s messages and returns give the cluster. Defaults to api_host.

The qumulo.cluster.cluster_upgrade role always sets it, to the inventory host’s name. When it is set, the refusals name the role’s and the inventory’s settings, such as cluster_upgrade_wait_timeout and qumulo_upgrade_reboot_set_size, in place of wait_timeout and reboot_set_size.

When it is set, the module does not warn that a reboot declaration is ignored; qumulo.cluster.upgrade_plan gives that warning instead.

image

string

The image, as an http:// or https:// URL every node can reach without its query string and user information, or an absolute path, which each node reads from its own disk or else from the cluster’s file system.

A URL that carries a query string or user information is refused before any request; pass those parts in image_secret.

A plain URL or a path reads in full in the result and in every message.

Required, except with state=rebooted and commit=false, which only waits for the reboots and needs version instead.

image_secret

dictionary

The parts of the image’s URL that are secret, joined back to image inside the module.

The filter qumulo.cluster.url_secret produces it from the full URL, and qumulo.cluster.redact_images produces image from the same URL.

query

string

The URL’s query string, without its ?, as a presigned URL’s signature.

userinfo

string

The URL’s user information, as user:password.

maintenance_windows

list / elements=dictionary

Time ranges inside which the commit may begin, in window_timezone. Outside them the module still prepares, then refuses the commit, naming when the window next opens; the cluster stays prepared.

A range whose end is at or before its start runs past midnight, and its maintenance_windows[].on_days names the day it starts. Unset, the commit may begin at any time.

A timezone that is no IANA name, an hour outside 0 to 23, a minute outside 0 to 59 or a day name outside the week is refused before any request.

The qumulo.cluster.cluster_upgrade role checks the window itself, once per hop, and never passes this option.

end_hour

integer / required

The hour the range ends, 0 to 23.

end_minute

integer / required

The minute the range ends, 0 to 59.

on_days

list / elements=string / required

The days the range starts on, as MON to SUN, or EVERY_DAY.

start_hour

integer / required

The hour the range starts, 0 to 23.

start_minute

integer / required

The minute the range starts, 0 to 59.

prepare

boolean

With state=prepared or state=committed, prepare a cluster that is not PREPARED with the image, the reboot settings and the waivers. false refuses such a cluster instead, and sends only reads before the commit.

Choices:

  • false

  • true ← (default)

ready_to_commit

boolean

With state=prepared, also check that the cluster may commit now. The preflight must clear, and the image must hold version. On a platform upgrade, the current node fault tolerance must reach reboot_set_size, and with reboot=all it must be back at the configured tolerance. Each of those is waited for up to wait_timeout.

Choices:

  • false ← (default)

  • true

reboot

string

How a platform upgrade reboots its hosts. rolling reboots them in groups, each once the cluster has reprotected; all reboots every host at once.

Unset, the reboots are rolling.

A cluster whose configured node fault tolerance is 0 reboots every host at once whatever this says, with a warning when a declaration is ignored.

Choices:

  • "rolling"

  • "all"

reboot_set_size

integer

How many nodes a rolling reboot takes at once, at least 1. Unset, Qumulo Core uses its own, the current tolerance minus one, at least one (G-UPGRADE-COUNT).

The prepare waits up to wait_timeout for the current node fault tolerance to reach it.

Ignored, with a warning, when the reboot is not rolling.

reboot_timeout

integer

Seconds a wait for a reboot may take, before the prepare and at state=rebooted.

Default: 43200

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

state

string

verified runs verify, which every node runs on the image and which installs nothing.

prepared leaves the cluster PREPARED with the image, the reboot settings and the waivers. With ready_to_commit, it then decides with reads and waits only whether the cluster may commit now.

committed prepares first when needed, then commits, and returns once the commit is done. On a rolling platform upgrade, the commit is done once the new build forms a quorum and the status reads REBOOTING; state=rebooted waits for the rest.

rebooted is committed, and then waits for the platform upgrade’s reboots to finish.

Choices:

  • "verified"

  • "prepared"

  • "committed" ← (default)

  • "rebooted"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

verify_in_check_mode

boolean

In check mode, also run verify, which downloads the whole image on every node and installs nothing.

Choices:

  • false ← (default)

  • true

version

string

The release the image holds, such as 7.11.0 or 7.10.0.3, as a string.

Unset, it is read from an image file named qumulo_core_<version>.qimg or cloud_qumulo_core_<version>.qimg, and otherwise learned from verify.

The prepare compares it with the release Qumulo Core reads in the image, and refuses a commit when they differ (G-UPGRADE-PATH).

wait_timeout

integer

Seconds each phase waits, in turn, for the preflight, the tolerance, the prepare and the commit.

Default: 3600

window_timezone

string

The IANA timezone of maintenance_windows, such as America/Los_Angeles. Required with them.

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

A cluster at the target, or PREPARED with the same image and settings, is left alone. A commit is an action that cannot be undone or sent twice (G-UPGRADE-ONESHOT).

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v1/node/state and /v1/version, which need no login; GET /v3/upgrade/status, never the deprecated v2 status, /v2/upgrade/blocked, /v1/cluster/protection/status, /v1/shutdown/reboot/status and /v1/cluster/nodes/; POST /v2/upgrade/verify-image, /v2/upgrade/prepare and /v2/upgrade/commit.

  • Verify and prepare are sent with a request timeout of their own, 2700 seconds on a source of 7.10.3 or later and 4500 below. The API host, and any load balancer or NAT gateway in front of it, must hold an idle connection that long; one closed sooner loses the answer, which the module reads back.

  • None of verify, prepare and commit is sent again after a lost answer; the module reads back instead. The one exception is a commit found still PREPARED, with the REST API answering throughout, which is sent once more.

  • While a reboot is under way, the preflight reads degraded for the nodes the reboot has taken, and that is waited out as the reboot (G-UPGRADE-BLOCKED). A degraded preflight outside a reboot fails at once.

  • Qumulo Core’s own refusals, such as an unlicensed edge’s (G-UPGRADE-LICENSE), are passed on with its words, and with a line saying every node must reach a URL image when the refusal could come from an unreachable URL.

  • Registers: G-ACTIONS, G-UPGRADE-ONESHOT, G-UPGRADE-RECORD, G-UPGRADE-LETTER, G-UPGRADE-PATH, G-UPGRADE-COUNT, G-UPGRADE-BLOCKED, G-UPGRADE-LICENSE.

Examples

# edge01_connection holds the connection options, such as {api_host: edge01.example.com, api_username: admin,
# api_password: "{{ vault_edge01_password }}"}. image_url is the image's full URL, presigned query string included.
- name: Upgrade one cluster to 7.11.0 and wait for its reboots
  qumulo.cluster.upgrade:
    image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
    state: rebooted
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Preview the upgrade without sending anything but reads
  qumulo.cluster.upgrade:
    image: /upgrades/qumulo_core_7.11.0.qimg
    version: "7.11.0"
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"
  check_mode: true
  diff: true
  register: upgrade_prediction

- name: Preview the upgrade and run verify on every node
  qumulo.cluster.upgrade:
    image: /upgrades/qumulo_core_7.11.0.qimg
    version: "7.11.0"
    verify_in_check_mode: true
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"
  check_mode: true

- name: Verify the image on every node, installing nothing
  qumulo.cluster.upgrade:
    image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
    state: verified
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Prepare from a presigned URL, and check the cluster may commit now
  qumulo.cluster.upgrade:
    image: "{{ [image_url] | qumulo.cluster.redact_images | first }}"
    image_secret: "{{ image_url | qumulo.cluster.url_secret }}"
    version: "7.11.0"
    state: prepared
    ready_to_commit: true
    commit_record: "{{ playbook_dir }}/artifacts/{{ inventory_hostname }}/upgrade/commit.yml"
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Commit a cluster that an earlier task prepared, and refuse to prepare it again
  # image, image_secret, version, commit_record, reboot, reboot_set_size and allow_upgrade_from_limited_release must be the
  # ones the prepare sent, or the commit is refused. This task repeats the prepare example above.
  qumulo.cluster.upgrade:
    image: "{{ [image_url] | qumulo.cluster.redact_images | first }}"
    image_secret: "{{ image_url | qumulo.cluster.url_secret }}"
    version: "7.11.0"
    state: committed
    prepare: false
    commit_record: "{{ playbook_dir }}/artifacts/{{ inventory_hostname }}/upgrade/commit.yml"
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Reboot every node at once, in one outage, instead of in groups
  qumulo.cluster.upgrade:
    image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
    state: rebooted
    reboot: all
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Reboot two nodes at a time and give the reboots a day
  # Leave reboot_set_size unset to take Qumulo Core's own size, which suits most clusters.
  qumulo.cluster.upgrade:
    image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
    state: rebooted
    reboot: rolling
    reboot_set_size: 2
    reboot_timeout: 86400
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Commit only inside a weekend maintenance window
  # Outside the window the task still prepares, then refuses the commit and leaves the cluster prepared.
  qumulo.cluster.upgrade:
    image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
    maintenance_windows:
      - start_hour: 22
        start_minute: 0
        end_hour: 4
        end_minute: 0
        on_days: [SAT, SUN]
    window_timezone: America/Los_Angeles
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Wait for the reboots of an upgrade that was already committed
  qumulo.cluster.upgrade:
    version: "7.11.0"
    state: rebooted
    commit: false
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Upgrade a cluster that runs a limited release, at the direction of Qumulo Care
  # Set this only when Qumulo Care directs it. Below 7.11.0 the waiver needs the build Qumulo Care names.
  qumulo.cluster.upgrade:
    image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
    version: "7.11.0"
    build: "393623.1.1"
    allow_upgrade_from_limited_release: true
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"

- name: Upgrade, and on a failure say whether a write may have been applied
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ edge01_connection }}"
  block:
    - name: Upgrade edge01 to 7.11.0
      qumulo.cluster.upgrade:
        image: https://images.example.com/qumulo/qumulo_core_7.11.0.qimg
  rescue:
    - name: Fail with the module's message and whether its write may have been applied
      ansible.builtin.fail:
        msg: "{{ ansible_failed_result.msg }} Maybe applied: {{ ansible_failed_result.maybe_applied | default(false) }}."
