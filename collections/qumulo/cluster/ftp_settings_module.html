qumulo.cluster.ftp_settings module – Manage a Qumulo cluster’s FTP server settings

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.ftp_settings.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Sets the cluster’s FTP server settings. Options left unset keep the cluster’s values.

  • Only the settings that differ are written, in one PATCH, with the If-Match of the read.

  • The cluster has one FTP server, which answers on every network, so the module has no tenant option.

Parameters

Parameter

Comments

allow_unencrypted_connections

boolean

Whether the cluster accepts FTP connections that are not encrypted.

With false it accepts only encrypted connections.

Choices:

  • false

  • true

anonymous_user

string

The local user that anonymous logins act as, written local:<name>, or "" for no anonymous logins.

The cluster takes only a local user. Any other form, a bare name, Everyone, or an AD, SMB or NFS identity included, fails before any request, naming the form the option takes. The name of a local group, written local:<name>, reaches the cluster, which refuses it.

The name is compared in any case, as the cluster finds a local user, and the result and the diff show it as the cluster holds it. In check mode a changed user is looked up in the cluster’s user list, so the result shows the cluster’s spelling there too.

A name the cluster has no local user for fails, naming qumulo.cluster.local_user. In check mode no write is sent, so such a name is reported as a change with a note in notes, as a user an earlier task creates.

After the local user is deleted, the cluster keeps the setting with an empty name, which the module returns as local:. Declaring local: fails.

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

check_remote_host

boolean

Whether all the connections of one FTP session must come from the same host.

Turning it off allows FXP, a transfer between two servers that a third host directs.

Choices:

  • false

  • true

chroot_users

boolean

Whether the cluster confines FTP users with chroot.

Choices:

  • false

  • true

enabled

boolean

Whether the cluster allows FTP connections.

Choices:

  • false

  • true

expand_wildcards

boolean

Whether LIST and NLST take POSIX-like shell wildcards in the final path component.

Choices:

  • false

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

greeting

string

The text sent with the 220 reply to a new connection.

It takes 1 to 1024 bytes of UTF-8, compared exactly, a trailing newline included. An empty greeting, or one over 1024 bytes, fails before any request, in check mode too.

The cluster cannot set the factory greeting back once it is changed (G-FTP-GREETING).

log_operations

boolean

Whether the cluster logs FTP operations.

Choices:

  • false

  • true

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET and PATCH /v0/ftp/settings, the PATCH with the If-Match of the read; GET /v1/users/ in check mode when anonymous_user changes, so a check run then needs the privilege to read local users.

  • The cluster accepts no empty greeting and has no reset, so the factory greeting cannot be set back once changed (G-FTP-GREETING).

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Serve FTP over TLS only, with users confined by chroot
  # A second run changes nothing.
  qumulo.cluster.ftp_settings:
    enabled: true
    allow_unencrypted_connections: false
    chroot_users: true

- name: Let anonymous logins act as the local user ftp-guest
  # The cluster_baseline role makes the users of qumulo_local_users before it applies the FTP settings. The cluster
  # finds the name in any case and returns its own spelling, so local:FTP-GUEST is no change against ftp-guest.
  block:
    - name: Create the local user ftp-guest
      qumulo.cluster.local_user:
        name: ftp-guest
        primary_group: Guests
        password: "{{ vault_ftp_guest_pw }}"

    - name: Let anonymous logins act as ftp-guest
      qumulo.cluster.ftp_settings:
        anonymous_user: local:ftp-guest

- name: Turn anonymous logins off
  # Also use this when the local user was deleted: the cluster then names a user with an empty name, which the module
  # reads as local:, and "" replaces it.
  qumulo.cluster.ftp_settings:
    anonymous_user: ""

- name: Greet clients with the site's notice
  # The greeting is compared exactly, so the newline a block scalar ends with is part of it. The cluster cannot set the
  # factory greeting back once this runs; take a capture of the cluster first, whose qumulo_ftp_settings.greeting
  # holds the text to go back to.
  qumulo.cluster.ftp_settings:
    greeting: |
      Authorized use only.

- name: Put back the greeting a capture of the cluster recorded
  # A capture taken before the greeting changed holds the factory text in qumulo_ftp_settings.greeting; sending it back
  # is the only way to restore it.
  qumulo.cluster.ftp_settings:
    greeting: "{{ qumulo_ftp_settings.greeting }}"

- name: Let clients use wildcards in listings and run FXP transfers
  qumulo.cluster.ftp_settings:
    expand_wildcards: true
    check_remote_host: false

- name: Preview turning the FTP server off
  qumulo.cluster.ftp_settings:
    enabled: false
  check_mode: true
  diff: true
  register: ftp_preview

- name: Show whether the FTP server would change
  ansible.builtin.debug:
    msg: "enabled would go from {{ ftp_preview.diff.before.enabled }} to {{ ftp_preview.diff.after.enabled }}"
  when: ftp_preview.changed

- name: Turn the FTP server off
  qumulo.cluster.ftp_settings:
    enabled: false
