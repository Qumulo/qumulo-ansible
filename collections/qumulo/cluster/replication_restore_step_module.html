qumulo.cluster.replication_restore_step module – Choose the next step of a rebuilt source’s restore from its replica, from fresh reads of both clusters

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_restore_step.

Synopsis

  • The restore of a rebuilt edge from the replica its old UUID left on a target runs in steps. The qumulo.cluster.replication_pair role’s restore calls this module before every step, with fresh reads, and runs only the step it returns.

  • A pure computation. It sends no request, takes no connection options, and is not in the qumulo.cluster.qumulo action group, so module_defaults for that group do not reach it.

  • X is the old record on the target that holds the replica, a live record at the target path from one of previous_cluster_uuids. R is the restore relationship, from the target’s replica directory to the edge’s declared source path; the reverse turns it into the declared relationship’s orientation. The restore record, on the controller under artifact_dir, is written after X’s delete and marked before the reconnect.

  • With relationship, the selection rule’s answer for that relationship, decided in this order, the first that applies.

  • A record of an unknown format fails the module, naming the file, with stops_run set, since it stops the edge’s whole run.

  • A record whose R is ENDED, or missing on a cluster in both orientations, is removed first. An unmarked record whose R reconnected is marked first.

  • With a marked record, step 9 once R is ESTABLISHED on both sides, step 8’s read-only wait while one side lags, and otherwise a refusal with its note.

  • done for the declared relationship ESTABLISHED with no record. The next step while R’s pair exists, or a stop when that step’s precondition no longer holds. Step 1 or step 2 when X exists and R has no pair, or the refusals of step 1’s preconditions. Otherwise the relationship is not applicable, with its note.

  • When an answer needs inputs only a later read gives, such as step 1’s check passes, decision is read and reads names them. Call the module again with them.

  • With relationships and no relationship, the run’s choice of the edge’s relationships, picked, and what the run refuses or reports before any step.

  • With waiting, one round’s check of step 4’s wait. With after_delete, step 7’s restore record from the read after X’s delete.

  • In check mode sequence holds the remaining steps the module predicts, since nothing changes between steps.

Attributes

Attribute

Support

Description

check_mode

Support: full

This action does not modify the cluster.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: none

This action does not modify the cluster.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

This action does not modify the cluster.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: none.

  • Registers: G-REPL-ONESHOT, the restore’s verbs are one-shot and its leftovers named; G-REPL-PEER, a rebuilt source’s old record holds its replica until the restore; G-REPL-SNAPSHOT, step 9 names the snapshots X left in snapshots_left; G-REPL-IDMAP, the last step applies the declared map_local_ids_to_nfs_ids.

Examples

- name: Choose the next step of the restore of /projects
  # Run on the controller, with fresh reads of both clusters (edge_read and target_read are the registers of
  # qumulo.cluster.replication_info on the edge and on the target).
  qumulo.cluster.replication_restore_step:
    edge: edge01
    edge_cluster_uuid: "{{ qumulo_cluster_uuid }}"
    previous_cluster_uuids: "{{ qumulo_previous_cluster_uuids }}"
    entry_point: playbook
    artifact_dir: "{{ edge_rebuild_artifact_dir }}"
    relationship: "{{ qumulo_replication_relationships[0] }}"
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    edge_relationships: "{{ edge_read.replication }}"
    target_relationships: "{{ target_read.replication }}"
    record_text: "{{ record_file.content | default(none) }}"
    replication_address: "{{ qumulo_replication_address }}"
    target_replication_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
  register: restore_step

- name: Preview the steps the restore of /projects would run from here
  qumulo.cluster.replication_restore_step:
    edge: edge01
    edge_cluster_uuid: "{{ qumulo_cluster_uuid }}"
    previous_cluster_uuids: "{{ qumulo_previous_cluster_uuids }}"
    entry_point: playbook
    artifact_dir: "{{ edge_rebuild_artifact_dir }}"
    relationship: "{{ qumulo_replication_relationships[0] }}"
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    edge_relationships: "{{ edge_read.replication }}"
    target_relationships: "{{ target_read.replication }}"
    replication_address: "{{ qumulo_replication_address }}"
    target_replication_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
  check_mode: true
  register: restore_preview

- name: Show the steps the preview predicts
  ansible.builtin.debug:
    msg: "{{ restore_preview.sequence }}"

- name: Choose the relationships the restore run picks, and what it refuses before any step
  qumulo.cluster.replication_restore_step:
    edge: edge01
    previous_cluster_uuids: "{{ qumulo_previous_cluster_uuids }}"
    inventory_cluster_uuids: "{{ dict(groups['qumulo_clusters'] | zip(groups['qumulo_clusters'] | map('extract', hostvars, 'qumulo_cluster_uuid'))) }}"
    entry_point: playbook
    relationships: "{{ qumulo_replication_relationships }}"
    names: "{{ qumulo_replication_restore | default(none) }}"
    targets: "{{ target_reads }}"
    restore_files: "{{ restore_directory_files }}"
  register: restore_run

- name: Stop the run when the playbook refused it as a whole
  ansible.builtin.fail:
    msg: "{{ restore_run.refusal }}"
  when: restore_run.refusal != ''

- name: Check one round of the wait for the full sync of the restore relationship
  qumulo.cluster.replication_restore_step:
    edge: edge01
    edge_cluster_uuid: "{{ qumulo_cluster_uuid }}"
    entry_point: playbook
    relationship:
      source_path: /projects
      target: dr01
      target_path: /replicas/edge01-projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    edge_relationships: "{{ round_read.replication }}"
    waiting:
      relationship_id: "{{ restore_id }}"
      wait_started: "{{ wait_started }}"
    wait_timeout: 86400
  register: round

- name: Compose the restore record from the read of R after X's delete
  qumulo.cluster.replication_restore_step:
    edge: edge01
    entry_point: playbook
    after_delete:
      record: "{{ restore_step.actions | selectattr('action', 'equalto', 'write_record') | map(attribute='record') | first }}"
      relationship: "{{ after_delete_read.replication.relationship | default(none) }}"
  register: composed

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

actions

list / elements=dictionary

The step’s actions, in the order the role runs them, each with action and its parameters. A removal or a mark of the record that comes first is listed before them.

create_directory, ensure_record_directory, create_relationship, authorize, wait_for_recovery_point, make_writable, poll, reverse, delete_x, read_after_delete, write_record, mark_record, reconnect, apply_settings, write_stamp and remove_record.
