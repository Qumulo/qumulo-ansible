qumulo.cluster.edge_rebuild_preflight module – Check that a Qumulo edge’s live state can be replayed from its inventory before a rebuild destroys it

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.edge_rebuild_preflight.

Synopsis

  • Reads only, and never reports a change. The qumulo.cluster.edge_rebuild role runs it on the old edge before it drains anything.

  • Drift. Fails when the edge has tenants, tenant networks, SMB shares, NFS exports, quotas, snapshot policies, local users, local groups or portal spoke roots that the inventory does not declare, or that the inventory declares absent, unless ignore_drift is set. The inventory declares a tenant, share or export absent with state absent in its own entry, and the other areas in declared_absent. A share or export is matched within its tenant, so a share of the same name in another tenant is a different share. Tenant 1’s factory Files share and / export, whatever tenant 1’s name, the built-in users admin and guest, and the built-in groups Users and Guests are never drift; a Files share or a / export in any other tenant is drift like any other.

  • Tenants. The module judges the old edge against what the replay will build. It reads tenants, smb_shares, nfs_exports, factory_defaults and network as the baseline reads them on a newly formed edge, which holds tenant 1 named Default, the factory share and export, and nothing else. It reads the old edge’s tenants by their names after the renames the inventory declares, that is, an entry whose previous_name the edge holds while the edge lacks its name. A tenant the inventory declares absent and the edge holds is drift, tenant 1 included. Otherwise tenant 1 is replayed only under the name the replay gives the new tenant 1, Default or the name of the entry with previous_name Default, so tenant 1 renamed by hand to another name is drift unless an entry names it with a previous_name of Default. Another tenant is replayed when the replay ends with a tenant of its name.

  • A tenant gained. A newly formed edge has tenant 1, Default, with the factory Files share and / export, and the replay keeps it unless tenants declares it absent. When the edge has no tenant 1 and the replay ends with tenant 1 under a name the edge does not hold, that tenant is drift with added true, which ignore_drift waives; its message begins “the rebuilt edge would gain tenant”. An edge that holds a tenant of that name gains nothing. An entry that declares that tenant absent is refused, as below, unless the factory share and export are claimed for its removal, by both keys of factory_defaults set to absent or by declaring them under that entry. docs/explanation/rebuilds.md says why the gain is drift.

  • Tenant networks. The module works out which tenant the replay binds each network to. A network listed in the networks of an entry of tenants is that tenant’s. A network in the frontend_networks of network is the tenant’s named by its tenant, and tenant 1’s for tenant_id 1. A listed network sent with no tenant, that is, a flat network with no tenant, or a tenant_id the newly formed edge lacks, stays in tenant 1, the formed edge’s tenant after any rename by previous_name of Default, unless the module refuses it, as below. When the edge holds that network in no tenant, and on neither backend bond, it is drift in the tenant_networks area with added true, which ignore_drift waives; its message begins “the rebuilt edge would put network”. When network has no frontend_networks and no present entry of tenants has networks, not even an empty list, the replay keeps the newly formed edge’s networks, which are all tenant 1’s, and does not replay a network the formed edge lacks. On managed networking that is network 1, so network 1 that the edge holds in no tenant is that drift too. Once any network is listed, the replay keeps only the listed networks and removes the rest, so each network the edge holds must be listed, under its tenant or in frontend_networks for a network no tenant holds or on the backend bond, and every present tenant must have networks, [] for none. For each tenant the replay builds again, each network the edge binds to it that the replay would not is drift in the tenant_networks area; a tenant that is itself drift is reported without its networks.

  • On an edge whose network document has no managed interfaces and only HOST networks, which forms again with no frontend network, fails when the replay creates a tenant but the inventory lists no network for a tenant that stays. The replay’s tenant 1 pass writes tenant 1’s own networks, or every listed network that stays when tenant 1 holds none, in tenant 1 before the baseline creates the other tenants; with none to write, the replay would fail after the destroy, and docs/explanation/rebuilds.md says why. Tenant 1’s own networks are those under its entry and the flat ones that step 2 resolves to tenant 1 or to no tenant, and the baseline’s step 3 adds the other tenants’ networks. The module decides with the replay’s own rule, the qumulo.cluster.tenancy_first_pass filter on the newly formed edge, so a network listed under any present tenant or in frontend_networks of network, for a tenant that stays or for none, is enough. Tenant 1 declared absent takes part as the Default the edge forms with, so it needs no rename. The message starts “the replay would create tenant”, comes after any drift, and ignore_drift does not waive it. With network in terraform_owned_areas, the message ends with the remedy that option describes.

  • On the same kind of edge, when the replay creates a tenant and the tenant 1 pass would write two or more networks into tenant 1, which it does only when tenant 1 holds two or more, or holds none while the inventory lists two or more, the baseline’s step 2 needs to know which HOST network the play reaches the edge on. Where tenant 1 holds a network, a second tenant’s own network is not in the pass; the baseline’s step 3 adds it. With management_network unset, the module infers it from this edge, as the network that carries the play’s address there, and returns it as management_network; management_network says when it can. It fails when it cannot place the address. The message starts “the replay’s tenant 1 pass would write networks”, names them, says why the module cannot tell, and says to set qumulo_management_network to the id of the network qumulo_api_host is on. The reasons are that this edge does not answer its network status, that its network status read failed (the reason is “this edge’s network status read failed”, then the error), that it holds two HOST networks and the play reaches it on the host’s own address (“this edge holds HOST networks 0 and 1 and the play reaches it on the host’s own address, A, which the network status does not place on any one of them”), that the status does not show the address (“this edge’s network status places the play’s address on no one network”), that the status shows the HOST network it would name served on no device (“this edge’s network status shows network N served on no device”), and that qumulo_api_host resolves to no address.

  • On the same kind of edge, when the tenant 1 pass would write two or more networks, fails when the play reaches this edge on a network the pass does not write, which is one the inventory lists for no tenant that stays or lists under a second tenant. The message starts “the play reaches this edge on network N, which the replay’s tenant 1 pass does not write before it creates tenant X, so the baseline’s step 2 would refuse the create after the destroy”, and says to set qumulo_api_host to an address on one of the networks the pass writes for the rebuild and qumulo_management_network to that network’s id, or, when the inventory lists network N under another id, to set qumulo_management_network to that id.

  • Each of those two messages comes after any drift, in the place of the “the replay would create tenant” message, and ignore_drift does not waive either.

  • On the same kind of edge, when the replay creates a tenant and the tenant 1 pass writes a network, fails when management_network names a network the pass does not write, however many networks the pass writes, whether the inventory lists it for no tenant that stays or for a tenant whose network the baseline’s step 3 adds only after that create, and when it is declared with no network, as management_network describes.

  • On the same kind of edge, fails when a network listed in the networks of an entry of tenants has vlan_id or is type STATIC, which step 2’s host-managed check refuses of a tenant network. The module makes this check once it has read the edge’s network document, before drift, and ignore_drift does not waive it. The message starts “the replay onto the rebuilt edge would refuse the inventory” and goes on with the baseline’s own, such as “network 0 of tenant it-one has vlan_id 10, but the host manages this cluster’s networking, so a tenant network takes no VLAN. Remove vlan_id.” A network in frontend_networks of network is not checked here. The check waits for the replay when network declares managed_interfaces and the tenant 1 pass runs, which writes them first.

  • Fails before it reads the edge when the inventory rules of the baseline’s tenancy step would refuse the inventory, that is, its renames, its entries and tenant references, its claims, and its network rules that need no read. Examples are a flat share or export with neither tenants nor tenant_id once the replay has more than one tenant, counting the tenants the inventory creates, two entries of tenants with one name, a key in a tenant’s smb_settings or nfs_settings dict that the global settings do not take, an inventory that leaves no tenant, and two entries, or an entry and factory_defaults, that claim one share or export in one tenant. The network rules are that once a present tenant declares networks every present tenant must, that a network is listed once, and that an absent tenant’s network is neither kept flat nor named by a flat tenant_id. Tenant 1 declared absent while no network is listed is refused too, since it holds the newly formed edge’s networks, which the run keeps, and so is a network listed with no tenant while tenant 1 is declared absent. The network document’s own checks (its validation, the backend checks, and the interfaces) and the NFS and continuity checks need the new edge and run only at the replay, as do its host-managed checks apart from the one of a tenant network above. The message starts “the replay onto the rebuilt edge would refuse the inventory”, and ignore_drift does not waive it. The warnings of that step come back as module warnings prefixed “the replay onto the rebuilt edge”. An entry of tenants with no name, or with a state other than present or absent, also fails before any read, with a message that names the entry, such as qumulo_tenants[0] gives no name. So does a listed network with no integer id, such as qumulo_network.frontend_networks[0] gives no id; these messages do not carry the replay prefix. A flat entry’s deprecated tenant_id is read only for tenant 1; any other id is skipped with a warning, so the entry’s share or export on the old edge is drift.

  • Fails after it reads the edge’s network document, before any other read and before drift, on a listed network sent with no tenant that the newly formed edge does not hold, when the replay has more than one tenant at the baseline’s step 3, counting the tenants it creates and those it deletes only at the end. The message starts “the replay onto the rebuilt edge would refuse the inventory” and is the baseline’s step 2 refusal; ignore_drift does not waive it. The newly formed edge holds network 1 on managed networking, and on host-managed networking the networks the replay’s tenant 1 pass writes. A network that the managed_interfaces of network puts on the backend bond is not refused, unless owned_parts leaves out interfaces. docs/explanation/rebuilds.md says which networks the newly formed edge holds.

  • Unreplayable state. Fails when the edge has state that the replay cannot create again, unless acknowledge lists its area. network is a STATIC frontend network or a VLAN while network_declared is false. kmip is a key store other than the local one (G-KMS). replication is a source or target relationship that replication_declared does not declare, and any object relationship, each listed by its id, its peer’s UUID and both paths (G-REPL-PEER). s3_keys is any S3 access key and access_tokens any access token (G-S3-KEY, G-TOKEN). local_data is any file, link or other object outside the portal’s spoke roots, and any snapshot. The files are counted from the cluster’s aggregates, and a directory they count empty, as they may for some seconds after a write, is listed instead. Its details say files: or snapshots:, and acknowledging the area gives up both.

  • Declared relationships. A record matches an entry of replication_declared by its side, its paths, and the peer’s UUID, the current one or one of its previous ones. A relationship it declares with the edge as its target is replayable only while the edge’s record is ESTABLISHED with its directory read-only and the source host’s record of the same id is ESTABLISHED; its target directory is then not local data. In any other state, its directory is local data, listed whatever it holds, with a detail naming both records’ states. A relationship it declares with the edge as its source, whose record is live, is held at the replay while the target holds a replica; its source directory is local data as any other, and the detail says whether the target host still holds a live replica. One whose record is ENDED or pending needs replication acknowledged, since a declaration explains only a live record.

  • A rebuilt peer. A record that names a previous UUID of its peer was made before the peer was rebuilt, and the detail says which previous UUID it names. With the edge as its source it is held. With the edge as its target, its outcome is only_copy. Its directory is local data, listed whatever it holds, and it is listed under replication too, so both areas must be acknowledged. When the edge’s record allows the source’s restore (ESTABLISHED, read-only, with a recovery point) and the entry’s peer_replication_address is an IP literal, the detail names that restore first, the source’s second pass for a source in qumulo_edges, playbooks/replication_restore.yml for any other.

  • A record of a declared relationship whose peer UUID the peer host’s inventory does not hold, current or previous, as before a rebuilt peer’s host_vars_patch is applied, needs replication, and the detail says to apply that patch.

  • A snapshot whose owners are all replayable relationships, or held relationships out of the edge whose target holds a live replica, is not local data.

  • ignore_drift never waives an area. Each acknowledged area that holds such state is returned in acknowledged.

  • Names compare as the server compares them. Share names ignore case, and export paths the edge reports ignore a trailing slash, each within its tenant. Quota and portal root paths ignore a trailing slash. Tenant names compare exactly.

management_network

list / elements=integer

The ids of the networks this play reaches the edge on, as the baseline reads qumulo_management_network. The qumulo.cluster.edge_rebuild role passes cluster_baseline_management_network, null when the variable is unset. A null value counts as unset.

On an edge that forms host-managed again, when the tenant 1 pass writes two or more networks, which it does only when tenant 1 holds two or more, or holds none while the inventory lists two or more, and the replay creates a tenant, this overrides the network the module infers from the old edge, which management_network returns when this is unset. The module infers it only for an old edge with one HOST network whose network status answers, as when the inventory adds a network. When the two disagree, the module warns “qumulo_management_network names network 1, but the play reaches the old edge on network 0; the replay uses qumulo_management_network”. An id that the inventory lists for no tenant that stays gets a message that starts “qumulo_management_network names” and goes on “which the inventory lists for no tenant that stays”. An id that step 3 adds later, such as a second tenant’s own network, gets one that starts “qumulo_management_network names” and goes on “but the replay’s tenant 1 pass writes only”. A value declared with no network, [], fails as well, with a message that starts “qumulo_management_network is declared with no network”, since step 2 would refuse it at the create after the destroy. Like the one above, each comes after any drift and ignore_drift does not waive it.

list / elements=dictionary

The inventory’s qumulo_smb_shares, as it is, present or absent. The entries are those of qumulo.cluster.smb_share, plus tenants as the baseline reads it. The shares nested in an entry of tenants are read with it, and are not passed here.

A flat entry is in each tenant its tenants lists, in every tenant the inventory declares present for all, and absent in each tenant declared absent. One with neither tenants nor tenant_id is in the rebuilt edge’s only tenant; once the replay has more than one tenant, counting the tenants the inventory creates, the module refuses it, as the baseline does. Its deprecated tenant_id is read only for tenant 1; any other id is skipped with a warning.

Default: []

snapshot_policies

list / elements=string

The snapshot policy names the inventory declares, present or absent.

Default: []

tenants

list / elements=dictionary

The inventory’s qumulo_tenants, as it is, present or absent. The entries are as the variables of qumulo.cluster.cluster_baseline describe them, and the baseline’s tenancy step reads them the same way.

A tenant the edge holds that the replay does not build again as the edge holds it is drift. An entry whose previous_name the edge holds, while the edge does not hold its name, is a rename the inventory declares, so the edge’s tenant of the old name is read by the new name, and so are its shares and exports. An entry whose name the edge already holds records a rename already done, and its previous name is ignored. An entry with state of absent renames nothing.

Default: []

terraform_owned_areas

list / elements=string

The areas Terraform owns, as the baseline’s ownership step records them from qumulo_terraform_owned_areas, or, without it, from qumulo_managed_by. The qumulo.cluster.edge_rebuild role passes them as cluster_baseline_owned.

Only network is read. With it listed, the refusal of an inventory that lists no network for a tenant that stays, on an edge whose networking the host manages, ends by saying to take network out of qumulo_terraform_owned_areas for the rebuild, to list the edge’s HOST network under a tenant in tenants or in qumulo_network.frontend_networks, and to put network back in qumulo_terraform_owned_areas and remove the listing in the same change. The baseline’s ownership step refuses qumulo_network and a networks key under a tenant while Terraform owns the area. Without network, the refusal says to list the HOST network.

Default: []

Choices:

  • false

  • true ← (default)

Notes

Note

  • API: GET /v1/multitenancy/tenants/, /v3/smb/shares/, /v3/nfs/exports/, /v1/files/quotas/status/, /v3/snapshots/policies/status/, /v1/users/, /v1/groups/, /v2/portal/spokes/ with the attributes of each spoke root, /v3/network, /v2/encryption/key-store/status, /v2/replication/source-relationships/status/, /v2/replication/target-relationships/status/, /v3/replication/object-relationships/, /v1/s3/access-keys/, /v1/auth/access-tokens/, /v1/files/%2F/aggregates/ and those of each directory above a spoke root, /v1/files/{ref}/entries/ of a directory the aggregates count empty, and /v4/snapshots/status/.

  • Needs the tenant list, which needs PRIVILEGE_TENANT_READ; a failure to read it fails the task.

  • The tenants drift area, and the tenant each share and export is in, resolve through the multitenancy REST API, which Qumulo marks as preview; a later Qumulo Core release may change it.

  • Registers: G-KMS, G-REPL-PEER, G-S3-KEY, G-TOKEN.

Examples

# These tasks carry no connection options, except where a task names another cluster. Set them once for the play
# with module_defaults for group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Check that the edge holds nothing its inventory does not declare
  # The edge_rebuild role passes the inventory's tenants, shares, exports, factory defaults and network as they are, so
  # the preflight reads them as the replay's baseline will. Nested shares and exports stay inside their tenant's entry.
  qumulo.cluster.edge_rebuild_preflight:
    tenants: "{{ qumulo_tenants | default([]) }}"
    smb_shares: "{{ qumulo_smb_shares | default([]) }}"
    nfs_exports: "{{ qumulo_nfs_exports | default([]) }}"
    factory_defaults: "{{ qumulo_factory_defaults | default({}) }}"
    network: "{{ qumulo_network | default(none) }}"
    quotas: "{{ qumulo_quotas | default([]) | map(attribute='path') }}"
    snapshot_policies: "{{ qumulo_snapshot_policies | default([]) | map(attribute='policy_name') }}"
    local_users: "{{ qumulo_local_users | default([]) | map(attribute='name') }}"
    local_groups: "{{ qumulo_local_groups | default([]) | map(attribute='name') }}"
    declared_absent:
      quotas: >-
        {{ qumulo_quotas | default([]) | selectattr('state', 'defined') | selectattr('state', 'equalto', 'absent')
           | map(attribute='path') }}
      snapshot_policies: >-
        {{ qumulo_snapshot_policies | default([]) | selectattr('state', 'defined') | selectattr('state', 'equalto', 'absent')
           | map(attribute='policy_name') }}
      local_users: >-
        {{ qumulo_local_users | default([]) | selectattr('state', 'defined') | selectattr('state', 'equalto', 'absent')
           | map(attribute='name') }}
      local_groups: >-
        {{ qumulo_local_groups | default([]) | selectattr('state', 'defined') | selectattr('state', 'equalto', 'absent')
           | map(attribute='name') }}
    portal_roots: "{{ qumulo_portal.roots | default([]) | map(attribute='spoke_root') }}"
    network_declared: "{{ qumulo_network is defined }}"
    acknowledge: [access_tokens]

- name: Check an edge of two tenants whose inventory declares a shared share and removes one
  # Each entry is as qumulo_tenants, qumulo_smb_shares and qumulo_nfs_exports hold it. projects is nested in
  # engineering, backups is in both tenants, and scratch is declared absent there. The edge's engineering tenant may
  # still be named eng; the preflight reads it as engineering, since the entry renames it. A tenant the edge holds and
  # these entries do not declare is drift.
  qumulo.cluster.edge_rebuild_preflight:
    tenants:
      - name: Default
      - name: engineering
        previous_name: eng
        smb_shares:
          - {share_name: projects, fs_path: /engineering/projects}
        nfs_exports:
          - {export_path: /builds, fs_path: /engineering/builds}
    smb_shares:
      - {share_name: backups, fs_path: /backups, tenants: [Default, engineering]}
      - {share_name: scratch, fs_path: /scratch, tenants: [engineering], state: absent}

- name: Check an edge of one tenant whose inventory removes the scratch share and an old user
  # A name declared absent is still listed with the others; the edge still holding it is drift. A flat share or export
  # with no tenants is in the rebuilt edge's only tenant; once the replay has a second tenant the baseline refuses
  # it, and so does the preflight, so name the tenants there.
  qumulo.cluster.edge_rebuild_preflight:
    smb_shares:
      - {share_name: projects, fs_path: /projects}
      - {share_name: scratch, fs_path: /scratch, state: absent}
    local_users: [svc_backup, build_old]
    portal_roots: [/hub-data]
    declared_absent:
      local_users: [build_old]

- name: Rebuild without the edge's snapshots and its files outside the spoke roots
  # Acknowledging local_data gives up both the files and the snapshots.
  qumulo.cluster.edge_rebuild_preflight:
    smb_shares:
      - {share_name: projects, fs_path: /projects}
    portal_roots: [/hub-data]
    acknowledge: [local_data]
  register: preflight

- name: List what the rebuild gives up, for the hand-off
  ansible.builtin.debug:
    msg: "{{ preflight.unreplayable | selectattr('area', 'in', preflight.acknowledged) | list }}"

- name: Read the peer's replication records, through the peer's own connection
  qumulo.cluster.replication_info:
    gather_subset: [source, target]
    api_host: hq01.example.com
    api_password: "{{ vault_hq01_admin_password }}"
    expected_cluster_uuid: 4b3c802f-8201-42b7-bb41-28f562cd8dfd
  register: hq01_replication

- name: Check an edge that is the target of a replication relationship the inventory declares
  qumulo.cluster.edge_rebuild_preflight:
    smb_shares:
      - {share_name: projects, fs_path: /projects}
    portal_roots: [/hub-data]
    replication_declared:
      - side: target
        peer_host: hq01
        peer_cluster_uuid: 4b3c802f-8201-42b7-bb41-28f562cd8dfd
        source_path: /projects
        target_path: /replicas/projects
        peer_replication_address: 10.0.0.10
        peer_in_edges: false
        peer_relationships: "{{ hq01_replication.replication.source_relationships }}"
  register: replication_preflight

- name: Show what the rebuild does with each replication relationship
  ansible.builtin.debug:
    msg: "{{ item.side }} {{ item.id }}: {{ item.outcome }}"
  loop: "{{ replication_preflight.replication }}"

- name: List what the inventory misses, without failing on it
  # Unreplayable state still fails unless acknowledge lists its area. This survey only reads, so it acknowledges
  # every area.
  qumulo.cluster.edge_rebuild_preflight:
    ignore_drift: true
    acknowledge: [network, kmip, replication, s3_keys, access_tokens, local_data]
  register: drift_survey

- name: Show each item the inventory misses
  ansible.builtin.debug:
    msg: "{{ item.area }}: {{ item.name }}{{ (' in tenant ' ~ item.tenant) if item.tenant is defined else '' }}"
  loop: "{{ drift_survey.drift }}"

- name: Collect what blocks a rebuild without stopping the play
  # A failure on drift, unreplayable state, the tenant 1 pass or the management network still returns drift,
  # unreplayable, acknowledged and replication; a failure on an inventory the replay would refuse returns none of them.
  qumulo.cluster.edge_rebuild_preflight:
    smb_shares:
      - {share_name: projects, fs_path: /projects}
  register: blockers
  ignore_errors: true

- name: Show the areas that would block the rebuild
  ansible.builtin.debug:
    msg: "{{ blockers.unreplayable | map(attribute='area') | unique | list }}"
  when: blockers is failed and blockers.unreplayable is defined

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

acknowledged

list / elements=string

The areas in unreplayable that acknowledge lists, sorted.

Returned: success, and when the module fails on drift, unacknowledged unreplayable state, the tenant 1 pass or the management network

Sample: ["access_tokens"]

drift

list / elements=dictionary

What the edge has that the inventory does not declare, or declares absent, each with its area, its name and declared_absent. An entry of the smb_shares or nfs_exports area also has tenant, the name of the tenant the share or export is in, and its name is the share’s name or the export’s path. An entry of the tenants area has the tenant’s name in name, and added true when it is a tenant the rebuilt edge would gain and the edge lacks. An entry of the tenant_networks area has tenant, the tenant’s name, and name, the network’s id and its name, as in 2 (eng-net). It also has added true when the edge holds the network in no tenant and the rebuilt edge would put it in that tenant, whether the inventory lists it or lists no network. A tenant that the inventory’s previous_name renames, and its shares and exports, are named by the new name.

Returned: success, and when the module fails on drift, unacknowledged unreplayable state, the tenant 1 pass or the management network

Sample: [{"area": "tenants", "declared_absent": false, "name": "Corp"}, {"added": true, "area": "tenants", "declared_absent": false, "name": "Default"}, {"area": "tenant_networks", "declared_absent": false, "name": "2 (eng-net)", "tenant": "eng"}, {"added": true, "area": "tenant_networks", "declared_absent": false, "name": "1 (Default)", "tenant": "Default"}, {"area": "smb_shares", "declared_absent": false, "name": "scratch", "tenant": "Default"}]

management_network

list / elements=integer

The ids of the networks the replay uses as qumulo_management_network for its tenant 1 pass and its baseline. They are management_network when set, else the ids inferred from this edge, else null.

The inferred ids are the networks that carry the address of qumulo_api_host on this edge. management_network says when the module infers them. Null means it did not infer one.

With management_network unset, it is null when the module fails on the tenant 1 pass, as when the inventory lists no network for a tenant that stays, and when it fails on the management network without having found one. With management_network set, it is that value whenever it is returned.

The qumulo.cluster.edge_rebuild role records it in the predestroy record as management_network, with the qumulo_api_host the module found it by as management_api_host.

Returned: success, and when the module fails on drift, unacknowledged unreplayable state, the tenant 1 pass or the management network

Sample: [1]

replication

list / elements=dictionary

Each replication relationship the edge holds and what the rebuild does with it. Its outcome is replayable, local_data, held, only_copy or unreplayable; detail says why.

Each has id, side, outcome and detail. A source or target record also has peer_cluster_uuid, source_path, target_path and state. An object relationship has side object and no more.

A declared one also has peer, the peer’s record of the same id (state, recovery_point, error_from_last_job), when the peer holds one and the record names the peer’s current UUID.

Returned: success, and when the module fails on drift, unacknowledged unreplayable state, the tenant 1 pass or the management network

Sample: [{"detail": "...", "id": "4", "outcome": "replayable", "peer": {"error_from_last_job": null, "recovery_point": "2026-11-01T10:00:00Z", "state": "ESTABLISHED"}, "peer_cluster_uuid": "4b3c802f-8201-42b7-bb41-28f562cd8dfd", "side": "target", "source_path": "/projects", "state": "ESTABLISHED", "target_path": "/replicas/projects"}]

unreplayable

list / elements=dictionary

State the replay cannot create again, each with its area and a detail, acknowledged or not.

Returned: success, and when the module fails on drift, unacknowledged unreplayable state, the tenant 1 pass or the management network

Sample: [{"area": "access_tokens", "detail": "2 access tokens"}]
