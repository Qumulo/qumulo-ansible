qumulo.cluster.license module – Make sure a Qumulo cluster holds a license for its current UUID

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.license.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

  • Examples

  • Return Values

Synopsis

  • A license is bound to a cluster UUID. This module talks only to the cluster and makes no Nexus call. It reads the license the cluster holds, applies a license document when given one, and reports what it found.

  • The module never creates a license, reads one from Nexus, or waits for one. document takes the license file Nexus issued for the cluster’s UUID; once applied, the license is active at once.

  • With document, the module applies the document to the cluster, unless the cluster already holds it, and reads the license back. Licenses are told apart by their key, which the module never returns.

  • Without a document, the module reports whether the cluster holds an active license for its UUID, and the UUID a license must be issued for, and changes nothing. Only applying a document reports a change.

  • A license that raises the usable capacity takes effect at the cluster’s next quorum formation, which the module reports as needs_quorum_bounce and does not cause. With check_waiting_cap, it also reports a held license’s cap that still waits for one on an edge formed without a license, as cap_waits_for_formation.

check_waiting_cap

boolean

added in qumulo.cluster 0.1.0

For an active license the cluster already held, one this run did not apply, also read the file system’s size, returned as file_system_size_bytes, and tell whether the license’s cap still waits for a quorum formation, as cap_waits_for_formation.

Meant for an edge whose capacity clamp is declared.

Choices:

  • false ← (default)

  • true

document

aliases: license

dictionary

The license document Nexus issued for this cluster, the license file. JSON text is accepted, as from lookup('ansible.builtin.file', 'license.json').

The key signs every other field, so the document must have exactly the fields below; one Nexus adds later is refused rather than dropped.

The module validates the document on the cluster before it activates it, and fails without a change when the cluster refuses it, for example when it is for another cluster or has been altered.

The UUID of the cluster the license is for.

details

any / required

When the license expires, as Nexus issued it.

license_key

string / required

The signature over the other fields. It is kept out of logs and results.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Check mode applies nothing; it predicts whether a document would be applied. It does ask the cluster to validate the document, which changes nothing, so a document the cluster would refuse fails in check mode too.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

A document the cluster already holds, by its key, cap and expiry, is not applied again.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v1/license/status and /v1/license/enforcement; POST /v1/debug/license/validate and /v1/debug/license/activate to apply a document; GET /v1/file-system once one is applied, and then GET /v1/capacity/clamp when the cap is more than 10^11 bytes above the file system. With check_waiting_cap, for a license the cluster already held, GET /v1/file-system, and then GET /v1/capacity/clamp when the file system is inside the window cap_waits_for_formation describes and the cap more than 10^11 bytes above 10^12 bytes. The module makes no Nexus call.

  • The server rounds the file system, the cap and the clamp to whole units of a size the module cannot read, so the module compares them through a margin of 10^11 bytes.

  • Applying a document uses the cluster’s debug license routes, which need the PRIVILEGE_DEBUG privilege; the built-in admin user holds it (G-LICENSE).

  • The license facts are the ones qumulo.cluster.cluster_info reports in its license subset.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Report whether the edge holds a license for its UUID
  # Without a document the module changes nothing.
  qumulo.cluster.license:
  register: license_check

- name: Name the UUID Nexus must issue the license for
  # A rebuilt edge always has a new UUID, and so needs a new license.
  ansible.builtin.debug:
    msg: "No license yet; ask for one for cluster {{ license_check.cluster_uuid }}"
  when: license_check.license_status == 'absent'

- name: Apply the license file Nexus issued for the edge, kept encrypted with ansible-vault
  qumulo.cluster.license:
    document: "{{ lookup('ansible.builtin.file', 'licenses/edge01.json') }}"
  register: licensed

# edge01_license holds the license file's JSON, as a mapping or as text.
- name: Apply a license document kept in a variable
  qumulo.cluster.license:
    document: "{{ edge01_license }}"

- name: Say that the larger capacity waits for the next quorum formation
  ansible.builtin.debug:
    msg: The larger capacity applies at the next quorum formation; qumulo.cluster.capacity_clamp causes one.
  when: licensed.needs_quorum_bounce

- name: Preview whether the license file would be applied
  qumulo.cluster.license:
    document: "{{ lookup('ansible.builtin.file', 'licenses/edge01.json') }}"
  check_mode: true
  diff: true
  register: license_preview

- name: Show what the preview found
  ansible.builtin.debug:
    msg: "status: {{ license_preview.license_status }}, would apply: {{ license_preview.activated }}"

- name: Tell whether the held license's cap still waits for a quorum formation
  # Meant for an edge whose capacity clamp is declared and that was formed without a license.
  qumulo.cluster.license:
    check_waiting_cap: true
  register: cap_check

- name: Say that the held license's cap applies at the next quorum formation
  ansible.builtin.debug:
    msg: >-
      The file system holds {{ cap_check.file_system_size_bytes }} bytes; the license's cap applies at the next quorum
      formation, which qumulo.cluster.capacity_clamp causes when it changes the clamp.
  when: cap_check.cap_waits_for_formation

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

activated

boolean

True when the module applied a license document, or would in check mode.

Returned: success

Sample: false

cap_waits_for_formation

boolean

True when check_waiting_cap is true, the cluster holds an active license that this run did not apply, the file system is at most 10^12 bytes and more than 10^12 less the margin of 10^11 bytes, the size an edge formed without a license has, and the smaller of the license’s cap and the stored capacity clamp, an unset clamp limiting nothing, is more than that margin above 10^12 bytes. That cap applies at the next quorum formation, unless the platform’s disks already limit the file system.

False otherwise.

Returned: success

Sample: false

cluster_uuid

string

The cluster’s current UUID, the one a license must be issued for.

Returned: success, and when the cluster accepted the document but does not report it held

Sample: "6f1c2c1e-5c3a-4c56-9d2e-3f8c1b0a7e11"

file_system_size_bytes

integer

The file system’s size in bytes, as read for check_waiting_cap, whether or not the license has a cap.

Returned: when check_waiting_cap is true and the cluster holds an active license that this run did not apply

Sample: 996432412672

license

dictionary

The cluster’s license after the task, as qumulo.cluster.cluster_info reports it.

Returned: success, and when the cluster accepted the document but does not report it held

Sample: {"cluster_uuid": "6f1c2c1e-5c3a-4c56-9d2e-3f8c1b0a7e11", "enforced": true, "expiration_date": "2027-10-31T23:59:59Z", "state": "LICENSE_STATE_ACTIVE", "usable_capacity_cap": 4000000000000}

license_pending

boolean

True when license_status is not active.

Returned: success, and when the cluster accepted the document but does not report it held

Sample: false

license_status

string

active when the cluster holds an active license for its UUID, and, when document is given, that document’s.

absent when it does not, as when an activation fails.

Returned: success, and when the cluster accepted the document but does not report it held

Can only return:

  • "active"

  • "absent"

Sample: "active"

maybe_applied

boolean

True when the activation was sent over a connection that was lost and the license read back is not the document.

Returned: on such a failure

Sample: true

needs_quorum_bounce

boolean

True when the license this run applied, or in check mode would apply, allows more usable capacity than the file system has by more than that margin, 10^11 bytes, and the capacity clamp, when set, allows more by more than it too. The cap applies at the next quorum formation, which qumulo.cluster.capacity_clamp causes when it changes the clamp.

A run that applies nothing reports false. With check_waiting_cap, such a run reports cap_waits_for_formation true for a cap that waits on an edge formed without a license, whose file system is inside the floor’s margin; elsewhere the module cannot tell a cap that waits for a quorum formation from a file system the platform keeps smaller.

Returned: success

Sample: true
