qumulo.cluster.local_user module – Manage a Qumulo cluster’s local user

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.local_user.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

  • Examples

  • Return Values

Synopsis

  • Creates, changes or deletes the cluster-local user named name.

  • The user is found by name, never by its id.

  • A password cannot be read back (G-PASSWORD). It is sent when the user is created, and on later runs only with update_password=always, which then reports a change on every run.

  • Membership of groups other than the primary group is qumulo.cluster.local_group‘s to manage. Changing the primary group adds the user to the new group; the server keeps the user in the old one too.

Parameters

Parameter

Comments

allow_admin_password_change

boolean

Allow a change to the password of admin. The server applies it to the operating system’s console and SSH password of every node too (G-ADMIN-OS). Without this option the module refuses the change.

Choices:

  • false ← (default)

  • true

allow_management_disruption

boolean

Allow a change to the password of the user this task connects as. Later tasks must then connect with the new password. The module reports connection_password_changed when it made such a change.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

home_directory

string

The user’s home directory path. Unset keeps the current value; an empty string clears it.

name

string / required

The user’s name. Users and groups share one set of names on a cluster.

password

string

The user’s password. Needed to create a user.

Sent on create, and on later runs only with update_password=always.

primary_group

string

Name of the local group that is the user’s primary group. Unset keeps the current one; a new user gets Users.

A group that does not exist fails the task. In check mode it is reported as a change, with a note, because an earlier task may create it.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

state

string

Whether the user exists. admin and guest cannot be deleted; asking to fails before any request is sent.

Choices:

  • "present" ← (default)

  • "absent"

uid

integer

The user’s NFS user id. Unset keeps the current value; a new user then has none.

update_password

string

on_create sends password only when the user is created, so later runs report no change for it.

always sends it on every run, and so always reports a change.

Choices:

  • "on_create" ← (default)

  • "always"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

The password cannot be read back, so update_password=always reports a change on every run.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET and POST /v1/users/; GET, PUT (with If-Match) and DELETE /v1/users/{id}; GET /v1/groups/; GET /v1/session/who-am-i when the task connects with an access token.

  • The PUT that changes a user sends its uid and home directory again, as the server replaces the whole user.

  • Registers: G-PASSWORD, G-ADMIN-OS.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# A user's primary group must exist first: create it with qumulo.cluster.local_group, or use a built-in one.
- name: Create a service user, setting its password only when it is created
  qumulo.cluster.local_user:
    name: svc-backup
    primary_group: Users
    uid: 5001
    password: "{{ vault_svc_backup_pw }}"

- name: Create a user with a home directory in an existing group
  qumulo.cluster.local_user:
    name: svc-monitor
    primary_group: edge-admins
    uid: 5002
    home_directory: /home/svc-monitor
    password: "{{ vault_svc_monitor_pw }}"

- name: Preview moving svc-backup to the edge-admins group
  qumulo.cluster.local_user:
    name: svc-backup
    primary_group: edge-admins
  check_mode: true
  diff: true
  register: user_preview

- name: Show the user the change would leave
  ansible.builtin.debug:
    var: user_preview.local_user

# The cluster keeps the user in its old primary group too.
- name: Make edge-admins svc-backup's primary group and give it a home directory
  qumulo.cluster.local_user:
    name: svc-backup
    primary_group: edge-admins
    home_directory: /home/svc-backup

- name: Clear svc-backup's home directory
  qumulo.cluster.local_user:
    name: svc-backup
    home_directory: ""

# The password cannot be read back, so this task reports a change on every run.
- name: Set svc-backup's password from the vault
  qumulo.cluster.local_user:
    name: svc-backup
    password: "{{ vault_svc_backup_pw }}"
    update_password: always

# The password of admin is also every node's console and SSH password (G-ADMIN-OS). When the play connects as
# admin, later tasks must connect with the new password; connection_password_changed says when. The collection's
# playbooks/admin_password_rotate.yml does this from the inventory.
- name: Rotate the admin password
  qumulo.cluster.local_user:
    name: admin
    password: "{{ vault_admin_password_next }}"
    update_password: always
    allow_admin_password_change: true
    allow_management_disruption: true
  register: admin_rotated

# The playbooks' module_defaults read qumulo_api_password, so later tasks connect with the new password.
- name: Connect with the new admin password from here on
  ansible.builtin.set_fact:
    qumulo_api_password: "{{ vault_admin_password_next }}"
  when: admin_rotated.connection_password_changed | default(false)

- name: Delete the service user
  qumulo.cluster.local_user:
    name: svc-backup
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

connection_password_changed

boolean

true when the task changed the password of the user it connects as.

Returned: when the password of the connecting user changed

Sample: true

expected

dictionary

The values the task wrote, for the keys that did not converge. The password is left out.

Returned: when the user did not converge

Sample: {"uid": 5001}

local_user

dictionary

The user after the task, or in check mode the user the task would leave; empty after a delete. The password is never returned.

Returned: always

Sample: {"home_directory": null, "name": "svc-backup", "primary_group": "Users", "uid": 5001}

home_directory

string

The home directory, or null.

Returned: success

name

string

The user’s name.

Returned: success

primary_group

string

The primary group’s name.

Returned: success

uid

integer

The NFS user id, or null.

Returned: success

maybe_applied

boolean

true when a write was sent and the connection was lost before the cluster answered, and reading the user back did not confirm it. A lost change of an existing user’s password, with update_password=always, cannot be confirmed by reading back, so that task then always fails with this set.

Returned: on a failure after such a write

Sample: true

notes

list / elements=string

What the module noticed, such as a primary group that does not exist yet in check mode, or a write it confirmed by reading back after the connection was lost.

Returned: when there is something to note

Sample: ["local group 'edge-admins' does not exist yet; an earlier task is expected to create it"]

observed

dictionary

What the cluster read back for the keys of expected.

Returned: when the user did not converge

Sample: {"uid": 5002}
