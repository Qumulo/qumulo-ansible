qumulo.cluster.ssl_ciphers module – Manage the TLS cipher suites a Qumulo cluster accepts

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.ssl_ciphers.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Sets the TLS 1.2 and TLS 1.3 cipher suites the cluster accepts, as two lists in the cluster’s order of preference. The order is part of the setting, so the lists are compared in order.

  • The cluster always accepts ECDHE-RSA-AES128-SHA256 for TLS 1.2 and TLS_AES_128_GCM_SHA256 for TLS 1.3, and adds each to the end of a list that leaves it out (QUIRK-060). The module adds them the same way before it compares, so a second run changes nothing.

  • Since TLS 1.3 always keeps its suite, no list cuts the controller off from the cluster.

  • A list left unset keeps the cluster’s.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

tls_1_2

list / elements=string

The TLS 1.2 cipher suites, by their OpenSSL names, such as ECDHE-RSA-AES256-GCM-SHA384.

An empty list, or one that names a suite twice, fails before any request is sent.

tls_1_3

list / elements=string

The TLS 1.3 cipher suites, by their standard names, such as TLS_AES_256_GCM_SHA384.

An empty list, or one that names a suite twice, fails before any request is sent.

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

  • true ← (default)

Notes

Note

  • API: GET and PUT /v2/cluster/settings/ssl/ciphers, with If-Match.

  • The cluster refuses a TLS 1.3 name it does not know, and a TLS 1.2 name, such as ALL, that would let in RC4 or anonymous suites; the module fails with the cluster’s message.

  • The cluster stores a TLS 1.2 name it does not know, so a misspelt name is kept as written and never used.

  • The cluster takes an empty list as the one suite it adds, so the module refuses an empty list itself (QUIRK-061).

  • The certificate the cluster serves is set by qumulo.cluster.ssl_certificate.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Accept AES-GCM suites, AES-256 first
  qumulo.cluster.ssl_ciphers:
    tls_1_2:
      - ECDHE-RSA-AES256-GCM-SHA384
      - ECDHE-RSA-AES128-GCM-SHA256
    tls_1_3:
      - TLS_AES_256_GCM_SHA384
      - TLS_AES_128_GCM_SHA256

- name: Preview a change to the TLS 1.3 suites, leaving TLS 1.2 as it is
  qumulo.cluster.ssl_ciphers:
    tls_1_3: [TLS_AES_256_GCM_SHA384]
  check_mode: true
  diff: true
  register: ciphers_preview

# The TLS 1.3 list ends with TLS_AES_128_GCM_SHA256, which the module adds because the task left it out.
- name: Show the suites the change would leave
  ansible.builtin.debug:
    var: ciphers_preview.ssl_ciphers

- name: Accept only AES-256 GCM for TLS 1.3, and the suite the cluster requires
  qumulo.cluster.ssl_ciphers:
    tls_1_3: [TLS_AES_256_GCM_SHA384]

- name: Accept only AES-256 GCM for TLS 1.2, and the suite the cluster requires
  qumulo.cluster.ssl_ciphers:
    tls_1_2: [ECDHE-RSA-AES256-GCM-SHA384]

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

expected

dictionary

The values the task wrote, for the options that did not converge.

Returned: when the read-back after a write differs from what was written; after a lost connection the task returns maybe_applied instead

Sample: {"tls_1_3": ["TLS_AES_256_GCM_SHA384", "TLS_AES_128_GCM_SHA256"]}

maybe_applied

boolean

true when a write was sent and the connection was lost before the cluster answered, and reading the settings back did not confirm it. The task fails with changed true.

Returned: on a failure after such a write

Sample: true

notes

list / elements=string

What the module noticed, such as a write it confirmed by reading back after the connection was lost.

Returned: when there is something to note

observed

dictionary

What the cluster read back for the keys of expected.

Returned: when the read-back after a write differs from what was written; after a lost connection the task returns maybe_applied instead

Sample: {"tls_1_3": ["TLS_AES_128_GCM_SHA256"]}

ssl_ciphers

dictionary

The cipher suites after the task, or in check mode the suites the task would leave, each list with the suite the cluster adds.

Returned: always

Sample: {"tls_1_2": ["ECDHE-RSA-AES256-GCM-SHA384", "ECDHE-RSA-AES128-GCM-SHA256", "ECDHE-RSA-AES128-SHA256"], "tls_1_3": ["TLS_AES_256_GCM_SHA384", "TLS_AES_128_GCM_SHA256"]}

tls_1_2

list / elements=string

The TLS 1.2 cipher suites, in order of preference.

Returned: success

tls_1_3

list / elements=string

The TLS 1.3 cipher suites, in order of preference.

Returned: success
