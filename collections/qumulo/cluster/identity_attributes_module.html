qumulo.cluster.identity_attributes module – Manage the home directory a Qumulo cluster gives an Active Directory, LDAP or POSIX identity

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.identity_attributes.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

  • Examples

  • Return Values

Synopsis

  • Sets or removes the attributes the cluster keeps for one identity it does not own, such as an Active Directory user. The only attribute is the home directory.

  • The identity is named by trustee, never given by id, and resolved on every run.

  • A local user’s home directory is qumulo.cluster.local_user‘s home_directory, and the cluster stores both in one place, so a trustee that resolves to a local identity is refused.

  • The cluster lists no identity’s attributes, so qumulo.cluster.capture_info cannot read them back (G-ID-ATTRIBUTES).

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

home_directory

string

The identity’s home directory, as the path the cluster shows, such as /home/alice.

Required with state=present.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

state

string

present sets the attributes; absent removes them, so the cluster keeps none for the identity.

Choices:

  • "present" ← (default)

  • "absent"

trustee

string / required

The identity, in the collection’s trustee grammar, such as ad:CORP\alice, ldap_user:alice, uid:1000, gid:1000 or sid:S-1-5-21-.... A bare name is refused, because it is ambiguous once the cluster uses AD or LDAP.

An ad: trustee resolves only once the cluster has joined the domain, except ad:NT AUTHORITY\Authenticated Users, which resolves joined to a domain or not.

With state=present, a trustee that does not exist fails the task; in check mode it is reported as a change, with a note, because an earlier task may join its domain.

With state=absent, a trustee that does not exist has no attributes to remove, so the task reports no change, with a note, in check mode and in a real run alike, as after the identity’s account is deleted.

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: POST /v1/identity/find; GET, PUT and DELETE /v1/auth/identities/{auth_id}/attributes, which take no If-Match, so the last writer wins.

  • Registers: G-ID-ATTRIBUTES.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# An ad: trustee resolves only after the cluster has joined the domain with qumulo.cluster.ad_domain.
- name: Give an AD user a home directory
  qumulo.cluster.identity_attributes:
    trustee: 'ad:CORP\alice'
    home_directory: /home/alice

- name: Give an AD user a home directory, named by its user principal name
  qumulo.cluster.identity_attributes:
    trustee: 'ad:alice@corp.example.com'
    home_directory: /home/alice

- name: Give an LDAP user a home directory
  qumulo.cluster.identity_attributes:
    trustee: ldap_user:alice
    home_directory: /home/alice

- name: Give an NFS user, known only by its uid, a home directory
  qumulo.cluster.identity_attributes:
    trustee: uid:1000
    home_directory: /home/u1000

- name: Preview moving an AD user's home directory
  qumulo.cluster.identity_attributes:
    trustee: 'ad:CORP\alice'
    home_directory: /home2/alice
  check_mode: true
  diff: true
  register: home_preview

- name: Show the attributes the move would leave
  ansible.builtin.debug:
    var: home_preview.identity_attributes

# The cluster caches identities; a changed home directory reaches one it has already seen once the cache is cleared.
- name: Move an AD user's home directory
  qumulo.cluster.identity_attributes:
    trustee: 'ad:CORP\alice'
    home_directory: /home2/alice
  register: home_moved

- name: Clear the authentication cache after the home directory moved
  qumulo.cluster.auth_cache_clear:
  when: home_moved is changed

- name: Remove an AD user's attributes
  qumulo.cluster.identity_attributes:
    trustee: 'ad:CORP\alice'
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

expected

dictionary

The attributes the task wrote, on a failure where the cluster read back something else.

Returned: when the attributes did not converge

Sample: {"home_directory": "/home/alice"}

identity_attributes

dictionary

The identity’s attributes after the task, or in check mode those the task would leave; {} when it has none.

Returned: always

Sample: {"home_directory": "/home/alice", "trustee": "ad:CORP\\alice"}

home_directory

string

The identity’s home directory.

Returned: success

trustee

string

The identity as a trustee string, as the cluster names it.

Returned: success

maybe_applied

boolean

true when the write was sent and the connection was lost before the cluster answered, and reading the attributes back did not confirm it.

Returned: on a failure after such a write

Sample: true

notes

list / elements=string

What the module noticed, such as a trustee that does not exist yet in check mode, or a write it confirmed by reading back after the connection was lost.

Returned: when there is something to note

Sample: ["trustee 'ad:CORP\\alice' does not exist yet; an earlier task is expected to create it or join its domain"]

observed

dictionary

What the cluster read back for the keys of expected.

Returned: when the attributes did not converge

Sample: {"home_directory": "/home/alice2"}
