qumulo.cluster.kerberos_keytab module – Install, replace or delete a Qumulo cluster’s Kerberos keytab

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.kerberos_keytab.

New in qumulo.cluster 0.1.0

Synopsis

  • With state=present, installs the keytab given in keytab or keytab_path as the cluster’s keytab, replacing any other. With state=absent, deletes the cluster’s keytab.

  • The keytab is a standalone KDC’s (MIT Kerberos, FreeIPA, or a domain controller used only as a KDC), for a cluster outside Active Directory. A cluster joined to a domain takes no keytab, and one that holds a keytab cannot join (G-KRB-AD); the module fails before any keytab write, in check mode too, on a joined cluster.

  • The cluster holds one keytab. It is in the desired state when it holds the same entries as the given keytab, each compared by principal, key version and encryption type, and the keys of all of them through one SHA-256 digest.

  • The module reads the keytab before it sends it, and fails before any request on a keytab the cluster would refuse or one with no entries.

  • No key is returned, shown in a diff, or put in a message; each entry’s principal, key version and encryption type are.

  • The cluster checks neither the principals nor the keys against the domain (G-KRB-KEYTAB).

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

keytab

string

The keytab file, in base64. Whitespace in it is ignored.

Exactly one of keytab and keytab_path is needed with state=present. With state=absent both are ignored, and the keytab is not read.

keytab_path

path

The absolute path of a plain keytab file, read unchanged. The module reads it on the host it runs on, which is the controller with ansible_connection set to local, as the collection’s inventory sets it; there, a relative path resolves against the directory ansible-playbook was started in, not the playbook’s or a role’s.

A file encrypted with Ansible Vault fails, because the module reads its bytes and decrypts nothing.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

state

string

present installs the keytab, or keeps it; absent deletes the cluster’s keytab.

With absent, keytab and keytab_path are ignored and not read, so a task may keep the keytab declared.

Choices:

  • "present" ← (default)

  • "absent"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

The diff shows the entries without their keys. When the task installs or replaces the keytab, its after_header says that the keys changed, without showing them.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET, PUT and DELETE /v1/auth/kerberos-keytab, the PUT with the file as application/octet-stream and no If-Match (QUIRK-160); GET /v1/ad/status before a PUT; with state=absent, GET and PUT /v1/auth/kerberos-settings around the DELETE (QUIRK-161).

  • Privileges: PRIVILEGE_KERBEROS_KEYTAB_READ and PRIVILEGE_KERBEROS_KEYTAB_WRITE. A write of the keytab, which in check mode is only a keytab that would change, also needs PRIVILEGE_AD_READ for GET /v1/ad/status. With state=absent, the task also needs PRIVILEGE_KERBEROS_SETTINGS_READ and PRIVILEGE_KERBEROS_SETTINGS_WRITE.

  • The cluster keeps the low 8 bits of a key version (QUIRK-162). The module compares by them, and warns about an entry whose version is above 255.

  • A failed PUT is reported by its HTTP status and error class only (QUIRK-163).

  • NFS’s Kerberos flavours (qumulo.cluster.nfs_settings) work only once the keytab holds the cluster’s NFS service principal, and the cluster’s name and clock agree with the KDC’s.

  • Registers: G-KRB-AD, G-KRB-KEYTAB, QUIRK-160, QUIRK-161, QUIRK-162, QUIRK-163.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# The keytab is a standalone KDC's, for a cluster outside Active Directory; a cluster joined to a domain takes none.
# The file lookup decrypts a file encrypted with ansible-vault. Make one with
#   mkdir -p files
#   base64 -w0 edge01.keytab | ansible-vault encrypt --output files/edge01.keytab.b64
# The lookup finds a relative name under the playbook's or the role's files/ directory.
# A second run with the same keytab changes nothing.
- name: Install the edge's keytab for NFS with Kerberos
  qumulo.cluster.kerberos_keytab:
    keytab: "{{ lookup('ansible.builtin.file', 'edge01.keytab.b64') }}"

# A pipeline that writes the keytab to a file on the controller from its secret store can give the path instead.
# Give an absolute path. The module reads the file as it is, so the file must not be vaulted.
- name: Install the keytab a pipeline step wrote
  qumulo.cluster.kerberos_keytab:
    keytab_path: /run/secrets/edge01.keytab

# The cluster stores the keytab without asking the KDC, so a keytab for the wrong host installs and NFS with Kerberos
# then fails (G-KRB-KEYTAB); the entries below show the principals the cluster would hold.
- name: Preview replacing the keytab after the KDC rotated the service principal's keys
  qumulo.cluster.kerberos_keytab:
    keytab: "{{ lookup('ansible.builtin.file', 'edge01-rotated.keytab.b64') }}"
  check_mode: true
  diff: true
  register: keytab_preview

- name: Show the principals and key versions the keytab would hold
  ansible.builtin.debug:
    var: keytab_preview.kerberos_keytab.entries

# With state: absent the keytab options are ignored, so a play may keep the keytab declared. Deleting the keytab turns
# use_alt_security_identities_mapping off on the cluster (QUIRK-161); the module turns it back on when it was on. If
# turning it back on fails, a rerun finds no keytab and does not try again, so declare kerberos_settings after a
# keytab's absent, as the second task does.
- name: Delete the cluster's keytab and keep the altSecurityIdentities mapping on
  qumulo.cluster.kerberos_keytab:
    state: absent

- name: Declare the altSecurityIdentities mapping after the keytab is gone
  qumulo.cluster.kerberos_settings:
    use_alt_security_identities_mapping: true

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

diff

dictionary

The entries before and after the task, without their keys.

Returned: when the task runs with diff mode on

after

dictionary

The keytab after the task.

Returned: success

after_header

string

changed, not shown: keys when the task installs or replaces the keytab.

Returned: when the task installs or replaces the keytab

Sample: "changed, not shown: keys"

before

dictionary

The keytab before the task.

Returned: success

error_class

string

The error class of a request the cluster answered with an error, such as a refused keytab PUT.

Returned: on a failure the cluster answered with an HTTP error, except when turning use_alt_security_identities_mapping back on failed

Sample: "keytab_parse_error"

expected

dictionary

The entries the module wrote, when the read-back after the write held others. Both this and observed are empty when only the keys differ.

Returned: on a failure when the read-back after a write differs from what was written, except after a lost connection, which returns maybe_applied instead

Sample: {"entries": [{"enctype": "KERBEROS_ENCRYPTION_TYPE_AES256_CTS_HMAC_SHA1_96", "principal": "nfs/edge01.corp.example.com@CORP.EXAMPLE.COM", "version": 3}]}

kerberos_keytab

dictionary

The keytab after the task, without its keys. In check mode, the keytab the task would leave.

Returned: always

Sample: {"entries": [{"enctype": "KERBEROS_ENCRYPTION_TYPE_AES256_CTS_HMAC_SHA1_96", "principal": "nfs/edge01.corp.example.com@CORP.EXAMPLE.COM", "version": 3}]}

entries

list / elements=dictionary

The keytab’s entries, sorted, each with principal, version, the key version the cluster keeps, and enctype. Empty when the cluster holds no keytab, and after state=absent.

Returned: success

maybe_applied

boolean

True when a write was sent and the connection was lost, and the read-back did not confirm it. The writes are the keytab’s PUT or DELETE, and the settings PUT that turns use_alt_security_identities_mapping back on; nothing is read back after that PUT. The module fails with changed true.

Returned: on such a failure

Sample: true

notes

list / elements=string

What the module noticed, such as the setting it turned back on after the DELETE, or a write it confirmed by reading back after the connection was lost.

Returned: when there is something to note

Sample: ["the keytab's DELETE turned use_alt_security_identities_mapping off (QUIRK-161); turned it back on"]

observed

dictionary

The entries the cluster returned on that read-back.

Returned: on a failure when the read-back after a write differs from what was written, except after a lost connection, which returns maybe_applied instead

Sample: {"entries": [{"enctype": "KERBEROS_ENCRYPTION_TYPE_AES256_CTS_HMAC_SHA1_96", "principal": "nfs/edge01.corp.example.com@CORP.EXAMPLE.COM", "version": 2}]}

status

integer

The HTTP status of a request the cluster answered with an error, such as a refused keytab PUT.

Returned: on a failure the cluster answered with an HTTP error, except when turning use_alt_security_identities_mapping back on failed

Sample: 400
