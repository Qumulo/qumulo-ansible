qumulo.cluster.smb_share module – Manage an SMB share on a Qumulo cluster

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.smb_share.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Creates, changes or removes one SMB share. The share is found by its name, and by its tenant when tenant or tenant_id is set, never by its id. With tenants the module does this once for each tenant named.

  • Options left unset are not managed, so an existing share keeps the values it has.

  • Share names are matched without regard to case, as the cluster matches them.

  • A newly formed cluster has a share named Files on /.

Comments

access_based_enumeration_enabled

boolean

Hide files and directories from users who cannot read them.

Choices:

  • false

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

create_fs_path

boolean

Create fs_path when it does not exist.

The cluster makes the new directories readable by everyone, and the last one writable by everyone.

Sent with every create and every change (QUIRK-007).

Choices:

  • false ← (default)

  • true

default_directory_create_mode

any

POSIX mode of the directories SMB clients create, as an octal string such as '0755'.

Quote it. YAML reads an unquoted octal as a decimal number, so a number is refused.

default_file_create_mode

any

POSIX mode of the files SMB clients create, as an octal string such as '0644'.

Quote it. YAML reads an unquoted octal as a decimal number, so a number is refused.

description

string

A description of the share.

expand_fs_path_variables

boolean

Expand %U in fs_path to the connecting user’s name.

Choices:

  • false

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

fs_path

string

Absolute path of the directory the share serves. A trailing slash is ignored.

Required to create a share.

network_permissions

list / elements=dictionary

Which client addresses may use the share, and with which rights, in order. For each right, the first entry whose network_permissions[].address_ranges match the client’s address and that names the right decides it, as in permissions, so a DENIED entry overrides only the ALLOWED entries after it.

A right no matching entry allows is denied, and a client allowed no right at all cannot connect to the share, including an address that matches no entry.

The list replaces the share’s network permissions.

A share created without it allows every address. An empty list denies every address.

address_ranges

list / elements=string

Addresses, CIDR blocks or ranges, compared as written and in order. An empty list matches every address.

Default: []

rights

list / elements=string / required

The rights, as for permissions[].rights.

Choices:

  • "READ"

  • "WRITE"

  • "CHANGE_PERMISSIONS"

  • "ALL"

  • "NONE"

type

string

Whether the entry allows or denies its rights.

Choices:

  • "ALLOWED" ← (default)

  • "DENIED"

offline_files_caching_mode

string

The offline-files caching the share offers Windows clients.

Choices:

  • "NO_CACHING"

  • "MANUAL_CACHING"

  • "AUTOMATIC_CACHING"

permissions

list / elements=dictionary

The share’s access control list, in order. For each right, the first entry that matches the user and names the right decides it, so a DENIED entry overrides only the ALLOWED entries after it, and a later entry can allow a right the earlier ones did not name. A right no matching entry allows is denied.

A user gets a right only when network_permissions allows it too.

Required to create a share. An empty list denies everyone.

The list replaces the share’s whole access control list.

rights

list / elements=string / required

The rights, compared as a set. ALL is READ, WRITE and CHANGE_PERMISSIONS; NONE is no rights.

An ALLOWED entry with WRITE needs READ too, because the cluster refuses write-only access.

Choices:

  • "READ"

  • "WRITE"

  • "CHANGE_PERMISSIONS"

  • "ALL"

  • "NONE"

trustee

string / required

Whom the entry applies to, as a trustee such as Everyone, local:admin, ad:CORP\alice, uid:1000 or sid:S-1-5-21-1-2-3-1001. A bare name is refused.

Authenticated Users is ad:NT AUTHORITY\Authenticated Users, which the cluster resolves joined to a domain or not.

Compared by the identity it resolves to. An entry the cluster reads back compares by the identity it gives with the entry.

type

string

Whether the entry allows or denies its rights.

Choices:

  • "ALLOWED" ← (default)

  • "DENIED"

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

require_encryption

boolean

Require clients to encrypt their traffic to this share.

Choices:

  • false

  • true

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

share_name

string / required

The share’s name. It is the key, so a different case names the same share and does not rename it.

state

string

Whether the share exists. Removing a share leaves its directory and data in place.

Choices:

  • "present" ← (default)

  • "absent"

tenant

string

The tenant the share belongs to, by name, compared exactly. The share is matched within this tenant only, and its tenant never changes.

Needed only when a share of this name exists in more than one tenant. Without it the task then fails, and the message names the tenants and says to set tenant.

A create makes the share in this tenant. Without a tenant, the create names none, and the cluster chooses one.

Outside check mode, a name that no tenant has fails, and the message lists the tenants. In check mode such a name is taken as a tenant an earlier task creates, so a create is reported as a change with a note in notes, and the result shows the share with that name and a null tenant_id. With state=absent such a name is satisfied, and the task changes nothing.

Needs the tenant list, which needs PRIVILEGE_TENANT_READ; a failure to read it fails the task.

tenant_id

integer

Deprecated, and removed in release 0.3.0 of this collection; use tenant. The id of the tenant the share belongs to.

Accepted beside tenant when both name one tenant, so a share read with qumulo.cluster.smb_info can be given back, and refused when they differ, naming both.

With state=absent, when no tenant has the name in tenant and none has this id, the task changes nothing; when this id belongs to a tenant, the task is refused.

Used alone, it chooses the share and goes in the body of a create. It is refused when the tenant list can be read and no tenant holds the id, with the message tenant_id <n> is no tenant on the cluster; name its tenant with tenant, and with state=absent the task then changes nothing. Where the list is not offered, or the user may not read it (HTTP 403), the id is used without that check.

Mutually exclusive with tenants.

tenants

list / elements=string

Tenants, by name and compared exactly. The module runs once for each name, as it would with tenant set to that name, and reads the list of shares once for all of them, again after each write. It writes only to a tenant whose share differs from the one the task describes.

smb_share and the diff are keyed by tenant name. A side where the share is missing, or where the tenant is not on the cluster and state=absent, is {}. A name the cluster lacks is handled as for tenant.

Names only. all, an empty list and a name that appears twice are refused.

The names are taken in the order given. Before the first write every name is looked up, and outside check mode a name the cluster lacks fails the task. In check mode too, a tenant that does not hold the share fails it then while fs_path or permissions is unset, a tenant an earlier task creates included.

Apart from that lookup, whose message lists the cluster’s tenants, a failure for one tenant starts its message with the tenant’s name in quotes, as in tenant 'eng':. Outside check mode, when earlier tenants were already changed, the message ends with ; the task had already changed tenant 'eng', or tenants 'a' and 'b', and the result has changed true.

Mutually exclusive with tenant and with tenant_id.

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

A trustee that does not exist yet, because an earlier task creates it or joins its domain, is reported as a change.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET and POST /v3/smb/shares/; GET, PATCH (If-Match) and DELETE /v3/smb/shares/{id}; POST /v1/identity/find; GET /v1/multitenancy/tenants/ on every run, before the write in a run without tenant or tenants. With tenant or tenants that read needs PRIVILEGE_TENANT_READ and any failure of it fails the task; without them, a cluster that does not offer the list and a user who may not read it (HTTP 403) get null for tenant in the results. The PATCH never carries the tenant.

  • Qumulo marks the /v3/smb/shares/ routes this module uses as preview in Qumulo Core 7.10.3 and 7.11.0; a later Qumulo Core release may change them.

  • tenant and tenants resolve through the multitenancy REST API, which Qumulo marks as preview; a later Qumulo Core release may change it.

  • Rights the cluster stores in a finer form than READ, WRITE and CHANGE_PERMISSIONS, written by another tool, read back as those finer rights, and the module replaces them.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Share the project tree, read-only for everyone and full access for the engineers
  qumulo.cluster.smb_share:
    share_name: projects
    fs_path: /data/projects
    description: Project data
    permissions:
      - trustee: ad:CORP\Engineering
        rights: [ALL]
      - trustee: Everyone
        rights: [READ]

- name: Share a directory that does not exist yet, with the mode and owner it should have
  # A directory the cluster creates for create_fs_path is readable by everyone and its last level is writable by
  # everyone, so make the directory first, with a mode and an owner, and share it afterwards.
  block:
    - name: Make the shared scratch directory
      qumulo.cluster.directory:
        path: /data/scratch
        mode: "0770"
        owner: local:svc_build
        group: ad:CORP\Engineering

    - name: Share the scratch directory with the engineers
      qumulo.cluster.smb_share:
        share_name: scratch
        fs_path: /data/scratch
        permissions:
          - trustee: ad:CORP\Engineering
            rights: [ALL]

- name: Share a directory and let the cluster create it, readable by everyone and writable by everyone at its last level
  qumulo.cluster.smb_share:
    share_name: incoming
    fs_path: /data/incoming
    create_fs_path: true
    permissions:
      - trustee: Everyone
        rights: [READ, WRITE]

- name: Share each user's home directory at /home/<user name>
  # Each user's directory must already exist, with that user as its owner and a mode such as "0700" (make it with
  # qumulo.cluster.directory). The share's ACL does not restrict who reads it; access_based_enumeration_enabled only
  # hides what a user cannot read.
  qumulo.cluster.smb_share:
    share_name: home
    fs_path: /home/%U
    expand_fs_path_variables: true
    access_based_enumeration_enabled: true
    permissions:
      - trustee: Everyone
        rights: [ALL]

- name: Let only the engineers and the contractors into the project share
  # The list replaces the share's whole ACL, so it repeats the entries that stay.
  qumulo.cluster.smb_share:
    share_name: projects
    permissions:
      - trustee: ad:CORP\Engineering
        rights: [ALL]
      - trustee: ad:CORP\Contractors
        rights: [READ]

- name: Deny the interns write access before the broader entry would allow it
  # The first matching entry decides each right, so the DENIED entry comes before the ALLOWED one.
  qumulo.cluster.smb_share:
    share_name: projects
    permissions:
      - type: DENIED
        trustee: ad:CORP\Interns
        rights: [WRITE, CHANGE_PERMISSIONS]
      - trustee: ad:CORP\Engineering
        rights: [ALL]
      - trustee: Everyone
        rights: [READ]

- name: Allow the project share only from the office and VPN networks
  qumulo.cluster.smb_share:
    share_name: projects
    network_permissions:
      - address_ranges: [10.20.0.0/16, 10.99.0.0/24]
        rights: [ALL]

- name: Set the modes of the files and directories SMB clients create in the project share
  qumulo.cluster.smb_share:
    share_name: projects
    default_file_create_mode: "0664"
    default_directory_create_mode: "0775"

- name: Let laptops keep the field-reports share for offline use
  qumulo.cluster.smb_share:
    share_name: field-reports
    offline_files_caching_mode: MANUAL_CACHING

- name: Describe the project share in the eng tenant
  # The share is found by its name within the tenant, so a share of the same name in another tenant is left alone. A
  # tenant the cluster lacks fails the task, in check mode too, since the task does not set fs_path and permissions to
  # create the share there.
  qumulo.cluster.smb_share:
    share_name: projects
    tenant: eng
    description: Project data of the eng tenant

- name: Share the project tree in the eng and finance tenants
  # One run for both tenants. A tenant that already holds the share is written only when it differs, and the result is
  # keyed by tenant name. A tenant that holds no share of this name needs fs_path and permissions, as here.
  qumulo.cluster.smb_share:
    share_name: projects
    tenants: [eng, finance]
    fs_path: /data/projects
    permissions:
      - trustee: Everyone
        rights: [READ]

- name: Preview giving the project share one description in two tenants
  # Both tenants must already hold the share: a tenant without it needs fs_path and permissions to create it. Each side
  # of the diff maps a tenant name to that tenant's share.
  qumulo.cluster.smb_share:
    share_name: projects
    tenants: [eng, finance]
    description: Project data
  check_mode: true
  diff: true
  register: projects_by_tenant

- name: Show the description each tenant's share would change from
  ansible.builtin.debug:
    msg: "{{ item.key }}: {{ item.value.description | default('no share') }}"
  loop: "{{ projects_by_tenant.diff.before | dict2items }}"
  loop_control:
    label: "{{ item.key }}"

- name: Remove the scratch share from the eng and finance tenants
  # A tenant the cluster lacks, or one without the share, is already as the task asks and is left alone.
  qumulo.cluster.smb_share:
    share_name: scratch
    tenants: [eng, finance]
    state: absent

- name: Preview requiring encryption on the project share
  qumulo.cluster.smb_share:
    share_name: projects
    require_encryption: true
  check_mode: true
  diff: true
  register: projects_preview

- name: Show what the share would change from
  ansible.builtin.debug:
    msg: "require_encryption is {{ projects_preview.diff.before.require_encryption }} and would become true"
  when: projects_preview.changed

- name: Remove the scratch share, keeping the directory and its data
  qumulo.cluster.smb_share:
    share_name: scratch
    state: absent

- name: Remove the factory share
  # Every newly formed cluster has a share named Files on /. Its directory and data stay.
  qumulo.cluster.smb_share:
    share_name: Files
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

diff

dictionary

The share before and after the task, with the option names above, and tenant before tenant_id.

With tenants, before and after each map a tenant’s name to the share, {} where it is missing.

Returned: when the task runs with diff mode on

after

dictionary

The share after the task; an empty dict after state=absent.

With tenants, a dict keyed by tenant name.

Returned: success

before

dictionary

The share before the task; an empty dict when it did not exist.

With tenants, a dict keyed by tenant name.

Returned: success

expected

dictionary

The values the module wrote, for the options the read-back after the write did not return as written.

Returned: on a failure when the read-back after a write differs from what was written, except after a lost connection, which returns maybe_applied instead

maybe_applied

boolean

True when a write was sent and the read-back did not confirm it. The module fails with changed true.

Returned: on such a failure

Sample: true

notes

list / elements=string

What the module noticed, such as a tenant that does not exist yet in check mode, or a write it confirmed by reading back after the connection was lost.

With tenants, each note starts with the name of the tenant it is about, as in eng: write reconciled after a lost connection.

Returned: when there is something to note

Sample: ["tenant 'finance' does not exist yet; an earlier task is expected to create it"]

observed

dictionary

The values the cluster returned on that read-back, for the options in expected.

Returned: on a failure when the read-back after a write differs from what was written, except after a lost connection, which returns maybe_applied instead

smb_share

dictionary

The share after the task, with the option names above; an empty dict after state=absent.

In check mode, and when nothing is written, it is the share as read with the task’s options laid over it. A create in check mode returns only the options the task set.

Each share carries tenant, its tenant’s name, before tenant_id, which is deprecated with tenant_id. tenant is null when the tenant list does not name the id, and, in a task without tenant or tenants, when the cluster does not offer the list or the user may not read it (HTTP 403). In check mode a tenant that an earlier task creates shows its name there, with a null tenant_id.

With tenants it is a dict keyed by tenant name, each value the share of that tenant as above, and {} for a tenant that has none.

A permission’s trustee that no trustee form names is shown by the name the cluster gives, or failing that its domain.

Returned: always
