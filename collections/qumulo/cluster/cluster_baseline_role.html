qumulo.cluster.cluster_baseline role – Bring a Qumulo cluster to the baseline its inventory declares

Note

This role is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.cluster_baseline.

Entry point main – Bring a Qumulo cluster to the baseline its inventory declares

New in qumulo.cluster 0.1.0

Synopsis

  • Applies each area the inventory declares, in the order the server’s own rules need, and leaves an area whose variable is unset alone.

  • Before step 1, Ansible refuses each key that a variable’s options do not list, a misspelt one among them, with Validation of arguments failed:, then the dotted path to the key, and the keys taken where the key sits; with keys in more than one place, the list is for one of them. The message does not say which entry of a list holds the key. A variable that lists the keys of a module takes that module’s options, apart from the connection options, which the play’s module_defaults set, and the options the role sets itself, which are tenant and state of the SMB and NFS settings, whose tenant overrides go in the entry of qumulo_tenants, and declared_access_key_ids of qumulo_s3_access_keys. It refuses both kinds, such as request_timeout or state in an entry. A dict whose options are left open takes any key. These are qumulo_network.managed_interfaces, which qumulo.cluster.network_config sends to the cluster as the document’s interfaces, qumulo_s3_bucket_policies[].policy, qumulo_capacity.license_document, and qumulo_tenants[].identity, which step 2 refuses.

    1. qumulo.cluster.cluster_guard, unless cluster_baseline_guard=false.

    1. An ownership check, which fails when a provider-formed cnq cluster’s qumulo_terraform_owned_areas leaves out network.floating_ips, as the Terraform inventory plugin does; when a declared area belongs to Terraform by qumulo_terraform_owned_areas, or, with no list, by qumulo_managed_by=terraform_provider on a cluster of kind cnq or unset, which gives the provider the floating addresses; owning them covers every floating_ip_ranges in qumulo_network and in a tenant’s networks; or when a declared CloudWatch entry of qumulo_audit_destinations does while the list names audit.cloudwatch, unless qumulo_take_over_from_terraform hands the area back; a check that no declared quota, snapshot policy or S3 bucket lies under a spoke root of qumulo_portal (G-SPOKE-PATHS); and a check that no path has both a mode in qumulo_directories and an ACL in qumulo_file_acls (G-FS-ACL-MODE); and a check that the file system key store holds each lock_key that qumulo_snapshot_policies declares, unless -e qumulo_allow_deferred_policy_lock_keys=true is given. It reads the key store once, and refuses the whole run, not only the policies it names, so that the run writes nothing it would have to finish later. It also checks that no keytab is declared to install beside a domain join (G-KRB-AD), which qumulo_kerberos.keytab_state=absent satisfies. All five fail before anything is written. The ownership check also finds a tenant’s networks in network, its networks’ floating_ip_ranges in network.floating_ips, its smb_settings and smb_shares in smb, and its nfs_settings and nfs_exports in nfs. tenants covers qumulo_tenants, and each entry of qumulo_smb_shares and qumulo_nfs_exports that names its tenants with tenants or tenant_id.

  • 2, continued. Whenever the inventory declares qumulo_tenants, qumulo_network, qumulo_smb_shares, qumulo_nfs_exports, qumulo_nfs_settings or qumulo_factory_defaults, the role reads the tenants with qumulo.cluster.tenant_info, the network document with qumulo.cluster.network_info, and its status only when the cluster has two or more tenants or the run creates one, the shares with qumulo.cluster.smb_info, the exports, NFS settings and each tenant’s NFS settings with qumulo.cluster.nfs_info, and the protection type with qumulo.cluster.cluster_info when qumulo_tenants is declared and qumulo_cluster_kind is not. Every such run makes these reads, so the user the play connects as needs read access to each, PRIVILEGE_TENANT_READ for the tenant list included, even for an inventory written before tenants. Then qumulo.cluster.tenancy_plan plans steps 3a to 20a, and refuses before any write what the inventory breaks and any write that would cut the play off from the cluster. When step 3a will write and step 3’s document differs from the cluster’s, qumulo.cluster.network_config checks that document in check mode first. With two or more tenants once the run is done, while Terraform owns network or network.floating_ips, by qumulo_terraform_owned_areas, or by default on a provider-formed cluster of kind cnq or unset, the role warns that a Terraform apply that sends the networks without their tenants unbinds them.

  • 3a. qumulo_tenants with qumulo.cluster.tenant, the renames, then the services turned on, then the creates.

    1. The network document the plan built from the tenants’ networks and qumulo_network, with qumulo.cluster.network_config, when the plan has one to apply.

  • 3b. qumulo_tenants with qumulo.cluster.tenant, the services turned off, after every network is bound.

    1. qumulo_dns with qumulo.cluster.dns_settings, clearing the DNS cache with qumulo.cluster.dns_cache_clear when the servers changed, and its lookup_overrides with qumulo.cluster.dns_lookup_overrides; then qumulo_authoritative_dns with qumulo.cluster.authoritative_dns; then the source and NTP servers of qumulo_time with qumulo.cluster.time_settings.

    1. qumulo_cluster_name with qumulo.cluster.cluster_settings; the server refuses a rename while the cluster is joined to a domain. Then qumulo_filesystem_settings with qumulo.cluster.filesystem_settings, and qumulo_web_ui_settings with qumulo.cluster.web_ui_settings.

    1. qumulo_ssl with qumulo.cluster.ssl_certificate, then qumulo_ssl_ciphers with qumulo.cluster.ssl_ciphers.

    1. qumulo_monitoring with qumulo.cluster.monitoring_settings, its nexus with qumulo.cluster.nexus_connection, then qumulo.cluster.nexus_registration when the Nexus connection is on and there is a join key or qumulo_nexus_api_token to mint one. No other monitoring write runs between the registration and its result. Then qumulo_audit_destinations with qumulo.cluster.audit_destination.

    1. Qumulo issues the license for the cluster’s UUID in Nexus, outside the role, once the cluster is registered. The document goes in qumulo_capacity.license_document (G-LICENSE).

    1. qumulo.cluster.license, whenever qumulo_capacity is declared. It first refuses qumulo_capacity.license=none beside a license document. It applies qumulo_capacity.license_document when the document is for the cluster’s UUID, and otherwise reads the license. Nothing waits for a license. Without an active license the role hands it off, naming the UUID, and sets cluster_baseline_license_missing when qumulo_capacity.license=required; with qumulo_capacity.license=none it says the edge runs without a license instead.

    1. qumulo_capacity.clamp with qumulo.cluster.capacity_clamp. While a license is expected and not active the clamp waits for it, and the role only reads the stored clamp to word the hand-off. With qumulo_capacity.license=none the clamp is written with no license. It then limits a license that arrives later, and a clamp above 1 TB provisions nothing more until a license arrives. With a license, a clamp that would change and that the license’s cap is below fails before the write. The second pass, which is this role again or, on an edge, playbooks/edge_license_complete.yml, runs the same step. It applies the document, or finds the license the cluster holds, and then sets the clamp. A clamp below the stored one fails; the edge_cache_resize role chooses the route to a smaller cache.

    1. qumulo_capacity.free_threshold with qumulo.cluster.portal_eviction_settings.

    1. The encryption key store (encryption_key_store), which is not in this release.

    1. qumulo_local_groups without members, then qumulo_local_users, then the groups’ members, with qumulo.cluster.local_group and qumulo.cluster.local_user; a primary group must exist before its users.

    1. The keytab of qumulo_kerberos with qumulo.cluster.kerberos_keytab, before the join, which the cluster refuses while it holds a keytab (G-KRB-AD); a keytab to install beside qumulo_ad fails the role before its first write, and qumulo_kerberos.keytab_state=absent deletes the keytab before the join. Then qumulo_ad with qumulo.cluster.ad_domain, then qumulo_time.use_ad_for_primary, then the setting of qumulo_kerberos with qumulo.cluster.kerberos_settings, then qumulo_user_defined_mappings with qumulo.cluster.user_defined_mappings, which the cluster takes only once joined, then qumulo_identity_attributes with qumulo.cluster.identity_attributes, whose ad: trustees resolve only once joined, except ad:NT AUTHORITY\Authenticated Users, which resolves joined to a domain or not, with qumulo.cluster.auth_cache_clear after either changed, even when a later step of the two fails; then qumulo_saml with qumulo.cluster.saml_settings. A failed clear fails the run, and a later run does not clear the cache again, since neither step then changes; qumulo.cluster.auth_cache_clear clears it.

    1. qumulo_roles with qumulo.cluster.role, then qumulo_role_members with qumulo.cluster.role_member, then the roles qumulo_roles declares absent. The cluster refuses to delete a role that still has members, so the inventory removes those members in qumulo_role_members first, with qumulo_role_members[].purge or qumulo_role_members[].state=absent. ad: trustees resolve only after the join, except ad:NT AUTHORITY\Authenticated Users, which resolves joined to a domain or not, and deleting a user drops its role assignments.

    1. qumulo_portal with the portal_pair role, the cluster as the spoke and qumulo_portal.hub as the hub. It checks that both run one Qumulo Core version, proposes the spoke portal and its roots, accepts and authorizes them on the hub, and waits until the portal is ACTIVE.

    1. qumulo_directories with qumulo.cluster.directory, then qumulo_file_acls with qumulo.cluster.file_acl; paths may lie under the portal’s authorized roots.

    1. From the plan, the SMB shares the run removes first, those declared absent, a deleted tenant’s and the factory Files share when qumulo_factory_defaults.smb_files_share=absent; then qumulo_smb_settings with qumulo.cluster.smb_settings; then each tenant’s smb_settings; then the shares, each in the tenants its entry names, with qumulo.cluster.smb_share.

    1. From the plan, the NFS exports the run removes first, the factory / export when qumulo_factory_defaults.nfs_root_export=absent among them; then qumulo_nfs_settings with qumulo.cluster.nfs_settings; then each tenant’s nfs_settings; then the exports with qumulo.cluster.nfs_export. NFSv4.1 cannot be on for a tenant while two of its export paths nest, so the removals go first. Then S3, qumulo_s3_settings with qumulo.cluster.s3_settings, qumulo_s3_buckets with qumulo.cluster.s3_bucket, and qumulo_s3_bucket_policies with qumulo.cluster.s3_bucket_policy; buckets and the base path need the directories of step 17, and policies the users and the domain join of steps 13 to 15. Then qumulo_ftp_settings with qumulo.cluster.ftp_settings, after the directories and ACLs of step 17, so that a new cluster serves nothing over FTP before they are in place, and after the local users of step 13, one of which the anonymous user names.

    1. qumulo_quotas with qumulo.cluster.directory_quota, then qumulo_snapshot_policies with qumulo.cluster.snapshot_policy, on local paths only; step 2 has already refused one under a spoke root. A policy sets its lock_key; unset or null leaves the policy’s key, and "" takes it off. The user the play connects as needs PRIVILEGE_FS_KEY_MANAGEMENT_READ when a policy declares one, and step 2 needs it for its read of the key store. Under qumulo_allow_deferred_policy_lock_keys, step 2 lets a policy whose key is not in the key store through, and step 20 applies it without the key and lists it in cluster_baseline_policy_lock_key_hand_offs; a run after the key is registered sets it. qumulo.cluster.snapshot_policy refuses a disabled key there, unless the policy already holds it, so enable it before the run.

  • 20a. Each tenant declared absent in qumulo_tenants, its SMB and NFS settings returned to the global ones whether or not declared, then the tenant deleted with qumulo.cluster.tenant. Step 2 refuses the delete of a tenant that holds a network, share or export the run does not remove. Steps 3, 18 and 19 remove the networks the inventory leaves out and the shares and exports declared under the tenant or claimed for it.

    1. qumulo_replication_relationships, the relationships this cluster is the source of, with the replication_pair role, after the directories, which it may replicate. Once, before any relationship, it checks that each target is an inventory host with qumulo_cluster_uuid and qumulo_replication_address that declares the target path in its qumulo_directories, path only, with no entry inside it; no target path is /, declared twice or nested on one target host, or inside a portal root on it; no two hosts declare one replication address and port; and no host’s qumulo_previous_cluster_uuids holds its own UUID. Then it runs the removals, then the others, each so that a failure does not stop the next, and fails after the last, naming each relationship held, refused or failed. A relationship into an edge whose license and clamp do not apply yet waits, with a hand-off, and does not fail. Each relationship that is not absent reads the target’s tenants, and with two or more tenants its network document, and is refused, on every run, while the tenant serving the target’s qumulo_replication_address has replication_enabled false; the user the play connects to the target as needs PRIVILEGE_TENANT_READ, and with two or more tenants PRIVILEGE_NETWORK_READ. A check run takes that tenant’s switch from the target host’s own steps 3a and 3b when the target host is in the play.

    1. qumulo_s3_access_keys with qumulo.cluster.s3_access_key, the removals first, last of all. The cluster returns a new key’s secret only once, so the module writes it at once to a file, readable only by its owner, under cluster_baseline_artifact_dir, and the role names each new key with its file in cluster_baseline_s3_access_keys, never its secret, and hands it off (G-S3-KEY). Without an artifact directory, an entry that would make a key fails. The step fails after the last entry, naming each that failed.

  • A second run changes nothing, apart from local passwords declared with update_password=always.

  • When a step moves the connection, the role switches the play’s facts for the steps after it. qumulo_api_host_after replaces qumulo_api_host after the network step, qumulo_ssl.ca_path_after replaces qumulo_ca_path and sets qumulo_validate_certs to true after the certificate step, and the new password of the user the play connects as replaces qumulo_api_password. A check run switches none of them for a change it only predicts. In a check run a tenant that step 3a renames is still under its old name, so its shares, exports and settings show as creates, and its removals as no change.

  • A rebuild’s replay meets a factory certificate that cannot be verified (G-FACTORY-TLS), so it starts with qumulo_validate_certs=false and relies on qumulo_ssl.ca_path_after to verify the cluster from the certificate step on.

  • Connects through the play’s module_defaults for group/qumulo.cluster.qumulo, as playbooks/baseline.yml sets them.

qumulo_allow_deferred_policy_lock_keys

boolean

Apply a snapshot policy whose lock_key is not in the file system key store yet without the key, and list it in cluster_baseline_policy_lock_key_hand_offs, in place of refusing at step 2. This is the case on a rebuilt or cloned cluster before its keys are registered again with qumulo.cluster.security_key.

The role sets it false in its own vars, which outrank group_vars and host_vars, so a value in the inventory has no effect; give it as -e qumulo_allow_deferred_policy_lock_keys=true for the run that needs it.

qumulo_capacity

dictionary

The license, the capacity clamp and the eviction threshold.

clamp

any

The capacity clamp, in bytes or as a size with a unit, such as 4TB or 4TiB.

free_threshold

float

The fraction of capacity, from 0.0 to 1.0, that the cluster keeps free by evicting cached spoke data.

license

string

What the inventory expects of the license. No value makes the role wait or fail; a missing license that is expected is handed off, naming the cluster’s UUID, and the clamp waits for it.

required also sets cluster_baseline_license_missing while the cluster has no active license, so a later check of the final state can fail on it.

pending, the default, expects that the license may come after the first pass.

none is for an edge that runs without a license, within the capacity its formation gave it (G-EDGE-FLOOR). Nothing is handed off, and the clamp is written with no license. It then limits a license that arrives later, and a clamp above 1 TB provisions nothing more until a license arrives. With a license active, the step runs as pending does and warns that none is stale. It goes with a clamp, and never with qumulo_capacity.license_document, which the role refuses beside it.

Choices:

  • "pending"

  • "required"

  • "none"

license_document

any

The license document issued for the cluster’s UUID, as the document option of qumulo.cluster.license takes it, a dict or its JSON text. Encrypt it with ansible-vault.

Applied before the clamp when it is for the cluster’s UUID. One for another UUID, as after a rebuild, is not applied, and the hand-off says so.

qumulo_cluster_kind

string

What the cluster runs on, cnq, edge or baremetal. cnq is a cloud cluster, and edge and baremetal are on premises. Null counts as unset.

Step 2 refuses every tenant write to a cloud cluster. Unset, it reads the cluster’s protection type when qumulo_tenants is declared, and takes an object-backed one for a cloud cluster; a cluster on premises whose storage is object-backed declares baremetal.

Without qumulo_terraform_owned_areas, a cluster of edge or baremetal that the provider formed leaves its floating addresses to the role, and one of cnq or unset kind leaves them to Terraform.

Choices:

  • "cnq"

  • "edge"

  • "baremetal"

  • "None"

qumulo_terraform_owned_areas

list / elements=string

Areas Terraform owns, which the role refuses to manage; for this role network, network.floating_ips, dns, dns.fqdn, time, cluster, filesystem, web_ui, ssl, monitoring, audit, audit.cloudwatch, capacity, local_users, local_groups, ad, kerberos, saml, identity_mappings, roles, portal, directories, smb, nfs, tenants, s3, ftp, quotas, snapshots and replication.

identity_mappings covers both qumulo_user_defined_mappings and qumulo_identity_attributes.

A list given here is all that Terraform owns, an empty list included, and the role manages every area it leaves out, whatever qumulo_managed_by says.

Without a list it defaults to [network.floating_ips] with qumulo_managed_by=terraform_provider unless qumulo_cluster_kind is edge or baremetal, and to none otherwise.
