qumulo.cluster.replication_relationship module – Declare a replication relationship on its source cluster, or delete the source’s records of it

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_relationship.

Synopsis

  • Runs on the source cluster. A create registers the relationship on the target too, awaiting authorization there, which qumulo.cluster.replication_target gives. The replication roles pair both sides.

  • The relationship is identified by source_path, target_cluster_uuid and target_path, never by a server id or by the address. Paths compare without a trailing slash, and UUIDs without regard to case.

  • target_address and target_port are settings, like replication_enabled, map_local_ids_to_nfs_ids, source_root_read_only, blackout_windows and blackout_window_timezone. One PATCH, with If-Match from the relationship’s configuration, sends only those that differ. The server refuses an address that reaches another cluster.

  • replication_mode and snapshot_policies are never compared or sent, so an adopted relationship keeps them.

  • A create is never sent twice. A create whose answer is lost is reconciled by listing, and two records of the key fail, naming both ids.

  • After a create, the module reads the new record. When the address reached a cluster other than target_cluster_uuid, it deletes the record at once and fails, naming the address and the UUID it reached.

  • A record with the same paths and another target UUID is a changed peer when it is at the declared address and port, or when its UUID is in previous_target_cluster_uuids, at any address. With recreate_changed_peer, the module creates the new relationship first, checks the UUID it reaches, and only then deletes the changed peer; without it, it fails. A changed peer beside a record of the key is deleted with no create. A record at the declared address whose UUID is in inventory_cluster_uuids is never a changed peer; it fails, since the address reaches the wrong cluster.

  • Before any write the module evaluates the rows of the overwrite table that fall to the source, and refuses while any of them is unmet and not lifted, reporting every unmet one in unmet. O3, an ENDED record of the key with no live one, needs recreate and a release bound to that record; the real run then creates, reads the target UUID back, and deletes the ENDED record. O8, this cluster holding a target record from the declared target at a path equal to or nested with the source path, is a reversal, a failover state that nothing here lifts.

  • An ENDED record of the key beside a live one, as a prune on the target leaves after a repeated create, holds nothing; the real run deletes it.

  • A missing source directory is unmet, and in check mode pending with source_path_pending.

  • In a failover state (DISCONNECTING, DISCONNECTED, RECONNECTING, REESTABLISHING) the module changes nothing in the relationship’s state, still PATCHes its settings, and warns.

  • With state=absent, deletes on this cluster the record of the key, in any state, and every record with the same paths whose target UUID is in previous_target_cluster_uuids. The target keeps its record, and its directory its data, until qumulo.cluster.replication_target with state=absent runs there.

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Evaluates the source’s rows of the overwrite table as the real run does, and fails on the same unmet rows. It predicts a create with a null id and creates.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

The diff’s before and after each hold relationship, in the shape of relationship, and records, the records the task deletes, or in check mode would delete. After’s records is always empty.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

A create cannot be sent again; the module matches by key first and reconciles a lost create by listing (G-REPL-ONESHOT).

A target rebuilt with a new UUID leaves the old record pinned to its certificate, never ENDED (G-REPL-PEER).

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v2/replication/source-relationships/status/, GET and PATCH and DELETE /v2/replication/source-relationships/{id}, GET /v2/replication/source-relationships/{id}/status, POST /v2/replication/source-relationships/, GET /v2/replication/target-relationships/status/ for row O8, GET /v1/files/{ref}/info/attributes, GET /v1/files/{ref}/entries/, GET /v1/files/{ref}/aggregates/, GET /v4/snapshots/status/.

  • Idempotency gaps G-REPL-ONESHOT and G-REPL-PEER apply. A create to an address that reaches another cluster leaves an ENDED record there, which this module cannot reach (G-REPL-ONESHOT).

  • The source tells the target of a delete only once, so a removal deletes here and then on the target (G-REPL-NOTIFY). The target’s last recovery-point snapshot outlives the removal, owned by nothing (G-REPL-SNAPSHOT); qumulo.cluster.replication_target names it.

  • A blackout timezone cannot be cleared (G-REPL-TZ, QUIRK-019), so blackout windows without a timezone, and an empty timezone where one is set, fail before any write.

  • The source reports the target path as it was sent until it first polls the target, and then with a trailing slash (QUIRK-020); the module compares and reports paths without it.

  • Files owned by local users and groups other than the built-in ones replicate as NFS ids, so they need map_local_ids_to_nfs_ids and an NFS uid or gid on each, and come back from a replica owned by those ids, which reach the same user or group only through a matching uid or gid (G-REPL-IDMAP).

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Preview the relationship to dr01 without writing, with the refusals it would meet
  # A refusal still returns unmet, so the preview does not fail the play.
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    replication_enabled: true
    blackout_windows:
      - {start_hour: 8, start_minute: 0, end_hour: 18, end_minute: 0, on_days: [MON, TUE, WED, THU, FRI]}
    blackout_window_timezone: America/Los_Angeles
    previous_target_cluster_uuids: "{{ hostvars['dr01'].qumulo_previous_cluster_uuids | default([]) }}"
    inventory_cluster_uuids: "{{ groups['qumulo_clusters'] | map('extract', hostvars, 'qumulo_cluster_uuid') | list }}"
    recreate_changed_peer: true
  check_mode: true
  diff: true
  register: preview
  failed_when: false

- name: Show what would keep the relationship from being created
  ansible.builtin.debug:
    msg: "{{ preview.unmet | map(attribute='message') | list }}"

- name: Stop when the preview refused the relationship
  ansible.builtin.fail:
    msg: "{{ preview.msg }}"
  when: preview.msg is defined

- name: Create the relationship to dr01, or adopt one made by hand at another address of dr01 with one PATCH
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    replication_enabled: true
    blackout_windows:
      - {start_hour: 8, start_minute: 0, end_hour: 18, end_minute: 0, on_days: [MON, TUE, WED, THU, FRI]}
    blackout_window_timezone: America/Los_Angeles
    previous_target_cluster_uuids: "{{ hostvars['dr01'].qumulo_previous_cluster_uuids | default([]) }}"
    inventory_cluster_uuids: "{{ groups['qumulo_clusters'] | map('extract', hostvars, 'qumulo_cluster_uuid') | list }}"
    recreate_changed_peer: true
  register: created

- name: Show what the target's authorize needs from the source
  ansible.builtin.debug:
    msg: >-
      id {{ created.relationship.id }}, source_empty {{ created.source_empty }}, source_files {{ created.source_files }},
      source_bytes {{ created.source_bytes }}

- name: Apply the relationship, reading only the record the preview returned
  # read_by_id is null when the preview predicted a create or a delete, and the module then lists as usual.
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    relationship_id: "{{ preview.read_by_id }}"

- name: Preview a change of the blackout windows
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    blackout_windows:
      - {start_hour: 22, start_minute: 0, end_hour: 23, end_minute: 59, on_days: [EVERY_DAY]}
    blackout_window_timezone: America/Los_Angeles
  check_mode: true
  diff: true

- name: Remove all blackout windows of the relationship
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    blackout_windows: []

- name: Pause replication without deleting the relationship
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    replication_enabled: false

- name: Replicate files owned by local users as NFS ids
  # Each such local user and group needs an NFS uid or gid (G-REPL-IDMAP).
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    map_local_ids_to_nfs_ids: true

- name: Keep the source directory read-only while the relationship exists
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    source_root_read_only: true

- name: Move the relationship to a floating IP of the same target, one PATCH
  # Prefer a floating IP of the target: it stays reachable when a node of the target goes down.
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: 203.0.113.41

- name: Replace a relationship the operator ended, with the release its refusal printed
  # Pass the release with -e for this run only, never in the inventory.
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    recreate: true
    release: >-
      {{ qumulo_replication_release | default([])
         | select('match', 'dr01:/replicas/edge01-projects/?@') | list }}

- name: Delete the records of dr01's previous UUIDs that can no longer replicate, and create nothing
  # Only those at the declared address, or whose last job cannot establish a secure connection; the rest are left for a
  # create-first replacement.
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    previous_target_cluster_uuids: "{{ hostvars['dr01'].qumulo_previous_cluster_uuids }}"
    create: false

- name: Preview the relationship before the play creates the source directory
  qumulo.cluster.replication_relationship:
    source_path: /projects/new
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects-new
    target_address: "{{ hostvars['dr01'].qumulo_replication_address }}"
    source_path_pending: true
  check_mode: true
  diff: true

- name: Remove the relationship on the source, and the records of the target's previous UUIDs
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['dr01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    previous_target_cluster_uuids: "{{ hostvars['dr01'].qumulo_previous_cluster_uuids | default([]) }}"
    state: absent
