qumulo.cluster.host_vars_text module – Write variables read from a Qumulo cluster as a host_vars file Ansible never templates

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: qumulo.cluster.host_vars_text.

New in qumulo.cluster 0.1.0

Synopsis

  • Returns the text of a host_vars file holding variables, sorted, each string value tagged !unsafe. Mapping keys, mappings and sequences are not tagged.

  • Only the strings are tagged, so a template added to the file by hand, such as a reference to a vaulted secret, is still evaluated.

  • A string that would read as another type without its tag, such as 0777 or true, is written quoted without the tag. The empty string is written without the tag too.

  • The file starts with header as comments and ends with comments naming each secret to supply, from supply, and what was left out, from left_out, in the shape qumulo.cluster.capture_info and qumulo.cluster.clone_host_vars return them. Every comment line is wrapped at 112 characters of text and starts with #.

  • playbooks/capture.yml writes its files with it, and the qumulo.cluster.clone_edge playbook its file.

  • Runs on the controller and connects to nothing. It sends no request, takes no connection options, and is not in the qumulo.cluster.qumulo action group, so module_defaults for that group do not reach it.

Requirements

The below requirements are needed on the host that executes this module.

  • PyYAML, which ansible-core needs on the controller.

Parameters

Parameter

Comments

header

string

Comment text to start the file with, wrapped; a newline starts a new line.

Default: ""

left_out

list / elements=dictionary

What was left out, written as comments after the variables in the order given.

Default: []

what

string / required

What was left out.

why

string / required

Why.

supply

list / elements=dictionary

Each secret to supply, written after the variables as comments, sorted by why and then by variable.

Lines with the same why are grouped under it.

Default: []

variable

string / required

The variable that holds the secret, as qumulo.cluster.capture_info names it.

why

string / required

Why it must be supplied.

variables

dictionary / required

The variables to write. Mapping keys are written as they are.

String values are tagged !unsafe, except a string that would read as another type and the empty string, which are written without the tag.

Attributes

Attribute

Support

Description

check_mode

Support: full

This action does not modify the cluster.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: none

This action does not modify the cluster.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

This action does not modify the cluster.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Examples

# The module runs on the controller and takes no connection options.
- name: Write a cluster's captured configuration as a host_vars file
  block:
    - name: Read the cluster's configuration
      qumulo.cluster.capture_info:
      register: captured

    - name: Render it as a host_vars file whose captured strings Ansible never templates
      qumulo.cluster.host_vars_text:
        variables: "{{ captured.capture.host_vars }}"
        header: Captured from {{ inventory_hostname }}.
        supply: "{{ captured.capture.supply }}"
        left_out: "{{ captured.capture.left_out }}"
      register: rendered
      delegate_to: localhost

    - name: Write the host_vars file, readable by its owner only
      ansible.builtin.copy:
        dest: "captures/{{ inventory_hostname }}.yml"
        content: "{{ rendered.text }}"
        mode: "0600"
      delegate_to: localhost

# source is the capture_info result of the cluster to copy, read through that cluster's connection options as in
# qumulo.cluster.clone_host_vars's examples.
- name: Render a clone's derived variables as a host_vars file
  block:
    - name: Derive the new cluster's host_vars
      qumulo.cluster.clone_host_vars:
        capture: "{{ source.capture }}"
        cluster_uuid: 1b2c33f0-5c3a-4c56-9d2e-3f8c1b0a7e11
        cluster_name: edge02
      register: clone

    - name: Render them as a host_vars file
      qumulo.cluster.host_vars_text:
        variables: "{{ clone.host_vars }}"
        header: Cloned from edge01.
        supply: "{{ clone.supply }}"
        left_out: "{{ clone.left_out }}"
      register: rendered
      delegate_to: localhost

- name: Render variables with a comment header and nothing to supply
  qumulo.cluster.host_vars_text:
    variables:
      qumulo_cluster_name: edge01
      qumulo_dns: {servers: [10.0.0.2], search_domains: [corp.example.com]}
    header: |-
      Hand-written settings for edge01.
      Review before use.
  register: rendered
  delegate_to: localhost

- name: Render variables with no header or trailing comments
  qumulo.cluster.host_vars_text:
    variables:
      qumulo_cluster_name: edge01
      qumulo_time: {ntp_servers: [ntp.corp.example.com]}
  register: rendered
  delegate_to: localhost

- name: Show the rendered file
  ansible.builtin.debug:
    msg: "{{ rendered.text }}"

Key

Description

Returned: success
