qumulo.cluster.replication_restore_info module – List the restore records and restore locks left on the controller, with their age

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_restore_info.

New in qumulo.cluster 0.1.0

Synopsis

  • Lists, under one artifact directory, every <host>/restore/ directory’s restore records and restore locks, the files a restore of a rebuilt edge from its replica keeps on the controller, and the files there it cannot read. It writes nothing and sends no request.

  • A restore record is a file named by 64 hexadecimal digits and .yml that holds a restore record of format 1, whose name is the SHA-256 of the key it holds. The replication_pair role’s restore writes it before it deletes the old relationship and removes it once the relationship reads ESTABLISHED on both clusters, so a record left behind is a restore that has not finished, or one whose relationship was reconnected by hand.

  • A restore lock is the file lock, which a restore holds with holder restore and the upgrade playbook with holder upgrade. Each is read on this controller as qumulo.cluster.replication_restore_lock reads it, live, gone or expired.

  • Restore stamps, done-<digest>.yml, the guard, lock.guard, and a lock being written, lock.tmp-<token>, are left out.

  • playbooks/upgrade.yml runs it before its plan and warns of each record and live lock that names a host the run upgrades (W1).

  • It talks to no cluster, so it takes no connection options, and is not in the qumulo.cluster.qumulo action group, so module_defaults for that group do not reach it. It reads the files where the task runs, the controller under the inventory’s ansible_connection=local.

Parameters

Parameter

Comments

path

path / required

The artifact directory, a host’s edge_rebuild_artifact_dir, which holds <host>/restore/ for each host. That is artifacts beside the host’s inventory source unless the variable sets another.

A directory that does not exist holds no restore files, so nothing is listed. A directory that exists and cannot be listed fails the module with a message that starts Could not list and names the directory.

Notes

Note

  • API: none.

  • The age of a record is from its written_at, or from the file’s modification time when written_at is null or is not an ISO 8601 time. The age of a lock is from the start of the run that took it.

  • The scan cannot tell a restore that stopped from one that is still running without the clusters; a live lock says a run holds the edge now. The replication_restore playbook reads both clusters and either finishes a record’s restore or says why it cannot.

See Also

See also

qumulo.cluster.replication_restore_lock

Hold the controller’s lock on an edge’s restore, so one restore runs per edge at a time.

Examples

# Run it on its own before an upgrade or a restore: it reads files on the controller and sends nothing to a cluster.
# From a shell, the same call is
#   ansible localhost -m qumulo.cluster.replication_restore_info -a path=artifacts
# A restore reads only its host's own artifact directory, so list each directory the inventory's hosts use.
- name: List the restore files beside the inventory
  qumulo.cluster.replication_restore_info:
    path: "{{ ansible_inventory_sources | qumulo.cluster.artifact_dir(inventory_file) }}"
  register: restore_files
  run_once: true

# A record is a restore that has not finished. Finish it with ansible-playbook qumulo.cluster.replication_restore, which
# removes the record, and remove it by hand only after reconnecting the relationship by hand.
- name: Show each record left behind, with its age and the relationship it holds
  ansible.builtin.debug:
    msg: >-
      {{ item.host }}: {{ item.path }}, written {{ item.age_seconds // 3600 }} hours ago, restores {{ item.key.source_path }}
      from {{ item.key.target_host }}:{{ item.key.target_path }}
  loop: "{{ restore_files.records }}"
  loop_control:
    label: "{{ item.path }}"
  run_once: true

# A live lock is a run that holds the edge now: leave it alone. The next restore or upgrade of the host takes over a gone
# or expired lock with a warning, so remove one by hand only once the run that took it is gone.
- name: Show each lock whose run is gone or whose lease has run out
  ansible.builtin.debug:
    msg: "{{ item.host }}: {{ item.path }}, held by {{ item.holder }} since {{ item.start_time }}, is {{ item.liveness }}"
  loop: "{{ restore_files.locks | rejectattr('liveness', 'equalto', 'live') | list }}"
  loop_control:
    label: "{{ item.path }}"
  run_once: true
