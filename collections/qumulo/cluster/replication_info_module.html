qumulo.cluster.replication_info module – Read a Qumulo cluster’s replication relationships, as source, as target and to object storage

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_info.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Gathers the replication relationships of one cluster and changes nothing. A cluster reports only its own records, so a relationship’s two sides are read by running the module against each cluster.

  • Source and target relationships are reported in one shape, so a relationship’s entry on its source and its entry on its target compare key by key. Each side records only what it knows, and the rest is null.

  • Object relationships, which copy between a directory and an S3 bucket on one cluster, are reported as the cluster lists them, without their credentials. The collection does not manage them.

  • With relationship_id and side, the module reads that one record instead of the lists, as a wait polls it.

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

list / elements=string

The subsets of facts to gather. all gathers every subset.

Choices:

  • "source"

  • "target"

  • "object"

Default: ["all"]

relationship_id

string

The id of one relationship to read, from this cluster’s record of it on side, in place of the lists.

It cannot be given with a gather_subset other than all.

request_timeout

integer

Seconds to wait for one HTTP response.

Default: 60

retry_timeout

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

Which of this cluster’s records of relationship_id to read, source or target. After a reverse one cluster can hold either.

Required with relationship_id.

  • "target"

Notes

Note

  • API: source GET /v2/replication/source-relationships/status/; target GET /v2/replication/target-relationships/status/; object GET /v3/replication/object-relationships/.

  • A relationship whose target was rebuilt with a new UUID stays ESTABLISHED on the source, with the old target_cluster_uuid and an error_from_last_job of Cannot establish a secure connection.; it never reaches ENDED (G-REPL-PEER).

  • Paths are reported without a trailing slash. The source reports a target path as it was sent until it first reaches the target, and with a trailing slash afterwards (QUIRK-020).

  • API, with relationship_id: GET /v2/replication/source-relationships/{id}/status for source, GET /v2/replication/target-relationships/{id}/status for target.

Examples

# These tasks carry no connection options, except where a task names another cluster. Set them once for the play
# with module_defaults for group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: List every replication relationship of this cluster, as source, as target and to object storage
  qumulo.cluster.replication_info:
  register: replication

- name: Read the edge's relationships as a source
  qumulo.cluster.replication_info:
    gather_subset: [source]
  register: edge_replication

- name: Find the edge's relationships to dr01's address that no longer reach dr01's current UUID
  # A target rebuilt with a new UUID leaves the source's record ESTABLISHED with the old UUID, so compare each
  # record's target_cluster_uuid with the UUID the target has now.
  ansible.builtin.debug:
    msg: >-
      {{ edge_replication.replication.source_relationships | selectattr('target_address', 'equalto', dr_address)
         | rejectattr('target_cluster_uuid', 'equalto', dr_uuid) }}

- name: List the directory-to-bucket relationships of this cluster, without their credentials
  qumulo.cluster.replication_info:
    gather_subset: [object]
  register: object_replication

- name: Wait until the DR cluster holds the relationship ESTABLISHED
  qumulo.cluster.replication_info:
    gather_subset: [target]
  register: dr_replication
  until: >-
    dr_replication.replication.target_relationships | selectattr('source_path', 'equalto', '/projects')
    | selectattr('state', 'equalto', 'ESTABLISHED') | list | length == 1
  retries: 60
  delay: 5

- name: Read the edge's record of one relationship, as its source
  qumulo.cluster.replication_info:
    relationship_id: "{{ relationship_id }}"
    side: source
  register: source_record

- name: Fail unless the DR cluster holds its record of the relationship the edge reads
  # The two records share one shape, so their keys compare directly.
  qumulo.cluster.replication_info:
    relationship_id: "{{ relationship_id }}"
    side: target
  module_defaults:
    group/qumulo.cluster.qumulo: "{{ dr01_connection }}"
  register: target_record
  failed_when: target_record.replication.relationship is none

- name: Show the recovery point each side reports
  ansible.builtin.debug:
    msg: >-
      source {{ source_record.replication.relationship.recovery_point }},
      target {{ target_record.replication.relationship.recovery_point }}

- name: Wait until the edge's record of one relationship reads DISCONNECTED
  qumulo.cluster.replication_info:
    relationship_id: "{{ relationship_id }}"
    side: target
  register: edge_record
  until: edge_record.replication.relationship.state | default('') == 'DISCONNECTED'
  retries: 60
  delay: 5

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

replication

dictionary

The gathered facts. Each key is present only when its subset was gathered.

Returned: always

object_relationships

list / elements=dictionary

The relationships between a directory and an S3 bucket, from the object subset, as the cluster lists them, without access_key_id or secret_access_key.

Returned: success

relationship

dictionary

With relationship_id, this cluster’s record of it on side, in the shape of replication.source_relationships, the target’s with null for what only the source records; null when this cluster holds no record of that id on that side.

The only key gathered then.

Returned: success

source_relationships

list / elements=dictionary

The relationships this cluster is the source of, from the source subset.

Each has id, source_cluster_uuid, target_cluster_uuid, source_path, target_path, target_address, target_port, state, end_reason, job_state, job_start_time, recovery_point, recovery_point_snapshot_id, error_from_last_job, target_root_read_only, replication_enabled, map_local_ids_to_nfs_ids, source_root_read_only, blackout_windows and blackout_window_timezone.

UUIDs are in lower case, and a blackout window’s on_days lists the days from SUN to SAT.

end_reason, job_start_time, recovery_point and error_from_last_job are null when the cluster reports none; job_start_time is set only while a job runs.

blackout_window_timezone is reported as the cluster stores it, "" when none was ever set, since a timezone once set cannot be cleared (QUIRK-019).

recovery_point_snapshot_id is the id of the snapshot that holds the recovery point on this cluster, an integer, or null when the record names none.

Returned: success
