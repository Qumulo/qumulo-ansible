qumulo.cluster.snapshot_policy module – Manage a snapshot policy on a Qumulo cluster

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.snapshot_policy.

New in qumulo.cluster 0.1.0

Synopsis

  • Creates, changes or removes one snapshot policy, found by its name. The name is the key; the module looks the id up on every run and never keeps it.

  • Options left unset are not managed, so an existing policy keeps the values it has.

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

enabled

boolean

Whether the policy takes snapshots. A policy created without it is enabled.

Choices:

  • false

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

expiration_time_to_live

string

How long the policy’s snapshots are kept, such as 7days, 12hours, 90minutes, 2weeks or 6months; never or an empty string keeps them until they are deleted. A policy created without it keeps them.

Compared as written, after never becomes an empty string, as the cluster stores it.

A change applies only to snapshots taken after it; the earlier ones keep the expiration they were given (G-SNAP-TTL).

lock_key

string

The key that locks each snapshot the policy takes, by its name or id in the file system key store, as qumulo.cluster.snapshot_lock takes it. "" takes the key off. Left unset, the policy keeps its key.

Compared and returned by the key’s name. A key that is not in the key store, or that is disabled, is refused before any write, in a check run too; a policy that already holds a key disabled since is no change.

Reading a key, to set it or to name the key a policy holds, needs PRIVILEGE_FS_KEY_MANAGEMENT_READ. Without it a held key is reported by its id, with a warning.

path

string

Absolute path of the directory the policy snapshots. The directory must exist.

A policy cannot move to another directory, so a different path needs recreate=true. Required to create a policy.

The cluster refuses a policy on a directory inside a portal spoke’s root, and the module fails with that reason (G-SPOKE-PATHS).

policy_name

string / required

The policy’s name, at most 50 characters and without /. It is the key.

recreate

boolean

Delete and recreate the policy when path differs. The snapshots the policy took are kept.

The new policy keeps the lock key of the old one, unless lock_key names another or "". A recreate that would carry a disabled key, or one the API user may not read, is refused before the delete.

Choices:

  • false ← (default)

  • true

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

schedule

dictionary

When the policy takes snapshots, in the fields the cluster uses for that frequency; it refuses a field another frequency uses. Required to create a policy.

SCHEDULE_HOURLY_OR_LESS takes schedule.fire_every, schedule.fire_every_interval, the window fields, schedule.on_days and schedule.timezone. SCHEDULE_DAILY_OR_WEEKLY takes schedule.hour, schedule.minute, schedule.on_days and schedule.timezone. SCHEDULE_MONTHLY takes schedule.day_of_month, schedule.hour, schedule.minute and schedule.timezone.

Only the fields the task gives are compared, so a field the cluster filled in is not a difference.

A schedule the cluster receives restarts the policy’s timing, so the module sends the schedule only when it differs (QUIRK-006).

day_of_month

integer

The day of the month, 1 to 31; 128 is the last day of the month.

fire_every

integer

How many schedule.fire_every_interval units apart hourly snapshots are.

fire_every_interval

string

The unit of schedule.fire_every.

Choices:

  • "FIRE_IN_MINUTES"

  • "FIRE_IN_HOURS"

frequency

string / required

How often snapshots are taken.

Choices:

  • "SCHEDULE_HOURLY_OR_LESS"

  • "SCHEDULE_DAILY_OR_WEEKLY"

  • "SCHEDULE_MONTHLY"

hour

integer

The hour, 0 to 23.

minute

integer

The minute, 0 to 59.

on_days

list / elements=string

The days snapshots are taken on, compared as a set. EVERY_DAY is all seven.

Choices:

  • "SUN"

  • "MON"

  • "TUE"

  • "WED"

  • "THU"

  • "FRI"

  • "SAT"

  • "EVERY_DAY"

timezone

string

The time zone the times are in, such as UTC or America/Los_Angeles.

window_end_hour

integer

The hour the window of hourly snapshots closes.

window_end_minute

integer

The minute the window of hourly snapshots closes.

window_start_hour

integer

The hour the window of hourly snapshots opens.

window_start_minute

integer

The minute the window of hourly snapshots opens.

snapshot_name_template

string

How the policy names its snapshots, such as {ID}_{Policy}_{Directory}.

Left unset on a new policy, the cluster uses {ID}_{Policy} for / and {ID}_{Policy}_{Directory} otherwise.

state

string

Whether the policy exists. Removing a policy keeps the snapshots it took.

Choices:

  • "present" ← (default)

  • "absent"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v3/snapshots/policies/status/, GET /v1/files/{path}/info/attributes, GET /v1/file-system/security/keys/{key}, POST /v3/snapshots/policies/, GET, PATCH (If-Match) and DELETE /v3/snapshots/policies/{id}.

  • The cluster refuses to delete a policy a replication relationship uses (G-SNAP-TTL); the module fails with the cluster’s reason.

  • The DELETE carries no If-Match (QUIRK-008).

  • Registers: G-SNAP-TTL, G-SPOKE-PATHS.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Snapshot the project tree every hour on weekdays, kept for a week
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    path: /data/projects
    expiration_time_to_live: 7days
    schedule:
      frequency: SCHEDULE_HOURLY_OR_LESS
      fire_every: 1
      fire_every_interval: FIRE_IN_HOURS
      window_start_hour: 0
      window_start_minute: 0
      window_end_hour: 23
      window_end_minute: 59
      on_days: [MON, TUE, WED, THU, FRI]
      timezone: UTC

- name: Take the daily snapshots at 02:00 on weekdays
  qumulo.cluster.snapshot_policy:
    policy_name: projects-daily
    path: /data/projects
    expiration_time_to_live: 30days
    schedule:
      frequency: SCHEDULE_DAILY_OR_WEEKLY
      hour: 2
      minute: 0
      on_days: [MON, TUE, WED, THU, FRI]
      timezone: America/Los_Angeles

- name: Take a snapshot of the archive tree on the last day of each month
  qumulo.cluster.snapshot_policy:
    policy_name: archive-monthly
    path: /data/archive
    expiration_time_to_live: 6months
    schedule:
      frequency: SCHEDULE_MONTHLY
      day_of_month: 128
      hour: 1
      minute: 0
      timezone: UTC

- name: Take the hourly snapshots every day, not only on weekdays
  # The policy exists already, so path is not needed. A changed schedule restarts the policy's timing (QUIRK-006).
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    schedule:
      frequency: SCHEDULE_HOURLY_OR_LESS
      fire_every: 1
      fire_every_interval: FIRE_IN_HOURS
      window_start_hour: 0
      window_start_minute: 0
      window_end_hour: 23
      window_end_minute: 59
      on_days: [EVERY_DAY]
      timezone: UTC

- name: Keep the hourly snapshots for two weeks
  # Snapshots already taken keep the expiration they were given (G-SNAP-TTL).
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    expiration_time_to_live: 2weeks

- name: Preview a new schedule for the policy
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    path: /data/projects
    schedule: "{{ projects_snapshot_schedule }}"
  check_mode: true
  diff: true
  register: policy_preview

- name: Show the schedule change, which restarts its timing
  ansible.builtin.debug:
    msg: >-
      {{ policy_preview.diff.before.schedule | default('no policy') }}
      -> {{ policy_preview.snapshot_policy.schedule }}
  when: policy_preview.diff.before.schedule | default(none) != policy_preview.snapshot_policy.schedule

- name: Pause the policy
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    enabled: false

- name: Resume a paused policy
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    enabled: true

- name: Lock each snapshot the daily policy takes with the legal-hold key
  # Register the key first with qumulo.cluster.security_key; the task refuses a key that is not in the key store, or that
  # is disabled, before it writes. Snapshots the policy took earlier are not changed. A second run reports no change.
  qumulo.cluster.snapshot_policy:
    policy_name: projects-daily
    lock_key: legal-hold

- name: Preview taking the lock key off the daily policy
  # An empty string takes the key off. Left unset, the policy keeps the key it has.
  qumulo.cluster.snapshot_policy:
    policy_name: projects-daily
    lock_key: ""
  check_mode: true
  diff: true

- name: Take the lock key off the daily policy
  # Take the key off before you disable or remove it with qumulo.cluster.security_key; the cluster refuses either while
  # a policy uses the key. A second run reports no change.
  qumulo.cluster.snapshot_policy:
    policy_name: projects-daily
    lock_key: ""

- name: Point the policy at the archive tree, deleting and recreating it
  # A policy cannot move in place. The snapshots it took are kept, and the new policy keeps the lock key. The cluster
  # refuses a policy on a directory inside a portal spoke's root (G-SPOKE-PATHS).
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    path: /data/archive
    recreate: true

- name: Remove the policy, keeping the snapshots it took
  # The cluster refuses while a replication relationship uses the policy.
  qumulo.cluster.snapshot_policy:
    policy_name: projects-hourly
    state: absent
