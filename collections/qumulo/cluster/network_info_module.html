qumulo.cluster.network_info module – Read a Qumulo cluster’s network and name resolution settings

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.network_info.

New in qumulo.cluster 0.1.0

Synopsis

  • Gathers the cluster’s network document, its frontend interfaces and their networks, the older single-network settings, the DNS settings, the lookup overrides, the authoritative DNS settings, the network status and the network that carries api_host, and changes nothing.

  • The document, dns, dns_lookup_overrides and authoritative_dns subsets have the option shape of qumulo.cluster.network_config, qumulo.cluster.dns_settings, qumulo.cluster.dns_lookup_overrides and qumulo.cluster.authoritative_dns, so they can be fed back to those modules.

  • Each network of the document subset carries tenant, the name of its tenant, beside tenant_id. tenant is null for a network no tenant holds, on a cluster that does not offer the tenant list, and for a user without PRIVILEGE_TENANT_READ. It is also null for a network of the backend bond, which takes no tenant, though tenant_id there shows the tenant the cluster put the network in. So the subset can be given back to qumulo.cluster.network_config, which drops that tenant_id with a warning.

  • The status subset is the cluster’s answer to GET /v3/network/status as the cluster gives it, a list with one entry per node. network.status describes its shape and what 7.11.0 showed.

  • The api_host_network subset is the id, in the network document, of the network that carries api_host, which the status shows on a frontend device. It is unavailable when api_host is a name, or when the status and the network document name no one network for its address, as when the play reaches the cluster through NAT or a load balancer, when the cluster has no frontend network yet, or when the document has two networks of the type the status shows the address as.

  • With resolve_names or resolve_addresses, it also asks the cluster’s own resolver to look those up and shows what the cluster sees. A lookup runs whatever gather_subset lists, and in check mode too, since it changes nothing; with gather_subset=[] the module gathers only the lookups.

  • On a node that is not yet part of a cluster (state UNCONFIGURED) no login is possible, so every subset and lookup is listed in unavailable_subsets, and the module warns.

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

gather_subset

list / elements=string

The subsets of facts to gather. all gathers every subset.

[] gathers every subset too, unless resolve_names or resolve_addresses is given; then only the lookups run.

Choices:

  • "all" ← (default)

  • "document"

  • "interfaces"

  • "legacy_settings"

  • "dns"

  • "dns_lookup_overrides"

  • "authoritative_dns"

  • "status"

  • "api_host_network"

Default: ["all"]

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

resolve_addresses

list / elements=string

Addresses for the cluster’s resolver to look up, each answered with its name in network.resolved_addresses.

Default: []

resolve_names

list / elements=string

Names for the cluster’s resolver to look up, each answered with its addresses in network.resolved_names.

Default: []

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Notes

Note

  • API: document GET /v3/network and GET /v1/multitenancy/tenants/ for the tenants’ names; interfaces GET /v2/network/interfaces/ and, for each interface, /v2/network/interfaces/{id}/networks/; legacy_settings GET /v1/network/settings; dns GET /v1/dns/configs/system; dns_lookup_overrides GET /v1/dns/lookup-override-config; authoritative_dns GET /v1/authoritative-dns/settings; status GET /v3/network/status; api_host_network GET /v3/network/status and GET /v3/network, with the status and the document each read once for the subsets that need them; resolve_names POST /v1/dns/resolve-names-to-ips; resolve_addresses POST /v1/dns/resolve-ips-to-names.

  • The tenant list that document reads needs PRIVILEGE_TENANT_READ. A user without it, and a cluster that does not offer the list, get null for tenant in each network, and the subset is still gathered; the module warns of the missing privilege. Any other error reading the list fails the module.

  • The tenant of the document subset resolves through the multitenancy REST API, which Qumulo marks as preview; a later Qumulo Core release may change it.

  • The single-network settings of legacy_settings are deprecated, and the cluster refuses them (HTTP 501) on networking its host manages, with more than one network, or with a VLAN; the subset is then unavailable. Any other error fails the module.

  • An HTTP 500 from GET /v3/network/status, which the Qumulo Core container answers (G-NET-APPLY), and the 404, 405, 406 or 501 of a cluster that does not offer the status leave status and api_host_network listed in unavailable_subsets, with the status’s reason for both from one read, unless api_host is a name. The other subsets are still gathered. Any other error fails the module.

  • The DNS servers and search domains that interfaces shows on each network are the cluster’s one DNS setting, the same on every network; dns reads that one setting directly.

  • A cluster whose network its host manages, such as a container or a host-managed cloud cluster, lists no interfaces.

Examples

# These tasks carry no connection options, except where a task names another cluster. Set them once for the play
# with module_defaults for group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Read every subset
  qumulo.cluster.network_info:
  register: network

- name: Show the frontend networks
  ansible.builtin.debug:
    var: network.network.document.frontend_networks

# Each network carries the name of its tenant in tenant, beside the deprecated tenant_id. tenant is null for a network
# no tenant holds, on a cluster that does not offer the tenant list, and for a user without PRIVILEGE_TENANT_READ. It is
# also null for a network of the backend bond, which takes no tenant.
- name: Show the tenant that holds each frontend network
  ansible.builtin.debug:
    msg: "{{ item.name }}: {{ item.tenant }}"
  loop: "{{ network.network.document.frontend_networks }}"
  loop_control:
    label: "{{ item.id }}"

- name: Read only the DNS settings and the lookup overrides
  qumulo.cluster.network_info:
    gather_subset: [dns, dns_lookup_overrides]
  register: names

# The subsets document, dns, dns_lookup_overrides and authoritative_dns have the option shape of the modules that
# manage them. Both clusters must accept the credentials the play sets, since an api_token is bound to one cluster.
- name: Copy cluster01's lookup overrides to this cluster
  block:
    - name: Read cluster01's lookup overrides
      qumulo.cluster.network_info:
        api_host: cluster01.example.com
        gather_subset: [dns_lookup_overrides]
      register: source_network

    - name: Apply them to this cluster
      qumulo.cluster.dns_lookup_overrides:
        overrides: "{{ source_network.network.dns_lookup_overrides.overrides }}"

# When the status answers HTTP 500 (G-NET-APPLY), the subset is listed in unavailable_subsets with the reason, and the
# loop below has nothing to show.
- name: Read the network status
  qumulo.cluster.network_info:
    gather_subset: [status]
  register: network_status

- name: Show whether each interface has been applied, node by node
  ansible.builtin.debug:
    msg: "{{ item.node_name }}: {{ item.managed_interface_statuses | default([]) }}"
  loop: "{{ network_status.network.status | default([]) }}"
  loop_control:
    label: "{{ item.node_name }}"

# Pass the id, in a list, as management_network to the tenant and network_config modules.
# Behind NAT or a load balancer no network carries the address the play connects to, so the subset is unavailable
# and says so; give management_network the network that api_host is forwarded to instead.
- name: Find the network that carries the address this play connects to
  qumulo.cluster.network_info:
    gather_subset: [api_host_network]
  register: reached

- name: Show the network id
  ansible.builtin.debug:
    var: reached.network.api_host_network
  when: reached.network.api_host_network is defined

- name: Show why no network was found
  ansible.builtin.debug:
    var: reached.unavailable_subsets.api_host_network
  when: reached.unavailable_subsets.api_host_network is defined

# Before a cluster joins a domain, this shows whether it can find the domain controller.
- name: Check that the cluster resolves its domain controller, gathering nothing else
  qumulo.cluster.network_info:
    gather_subset: []
    resolve_names: [dc1.corp.example.com]
  register: lookup

- name: Stop unless the name resolved
  ansible.builtin.assert:
    that: lookup.network.resolved_names[0].result == 'OK'

- name: Look up the name the cluster gives the domain controller's address
  qumulo.cluster.network_info:
    gather_subset: []
    resolve_addresses: [10.0.0.10]
  register: reverse

- name: Show the name the address resolved to, or why it did not
  ansible.builtin.debug:
    msg: "{{ r.hostname if r.result == 'OK' else r.result }}"
  vars:
    r: "{{ reverse.network.resolved_addresses[0] }}"

- name: Read the single-network settings, which a host-managed or multi-network cluster refuses
  qumulo.cluster.network_info:
    gather_subset: [legacy_settings]
  register: legacy

- name: Show the reason, if any
  ansible.builtin.debug:
    var: legacy.unavailable_subsets | default({})

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

network

dictionary

The gathered facts. Each key is present only when its subset was gathered or its lookup asked for.

Returned: always

api_host_network

integer

The id, in the network document, of the network that carries api_host, which the status shows on a frontend device. Network id 0 is a real id.

Absent, and listed in unavailable_subsets, when api_host is a name, when the status and the network document name no one network for its address, and when the status is unavailable.

Returned: success

Sample: 1

authoritative_dns

dictionary

The authoritative DNS settings, as qumulo.cluster.authoritative_dns returns them.

Returned: success

Sample: {"enabled": true, "fqdn": "edge01.corp.example.com.", "host_restrictions": ["10.0.0.0-10.255.255.255"], "record_ttl_seconds": 0}

dns

dictionary

The DNS settings, as qumulo.cluster.dns_settings takes them.

Returned: success

Sample: {"search_domains": ["corp.example.com"], "servers": ["10.0.0.2"]}

dns_lookup_overrides

dictionary

The lookup override table, as qumulo.cluster.dns_lookup_overrides takes it.

Returned: success

Sample: {"overrides": [{"aliases": ["dc1.corp.example.com", "dc1"], "ip_address": "10.0.0.10"}]}

document

dictionary

The network document, as qumulo.cluster.network_config takes and returns it.

Each network carries tenant, the name of its tenant, beside tenant_id, which is deprecated; read tenant. tenant is null for a network no tenant holds, on a cluster that does not offer the tenant list, and for a user without PRIVILEGE_TENANT_READ. It is also null for a network of the backend bond, which takes no tenant, though tenant_id there shows the tenant the cluster put the network in.

Returned: success

Sample: {"frontend_networks": [{"default_gateway": "10.20.0.1", "floating_ip_ranges": ["10.20.0.50-10.20.0.53"], "id": 1, "ip_ranges": ["10.20.0.5-10.20.0.8"], "name": "Default", "netmask": "255.255.255.0", "tenant": "Default", "tenant_id": 1, "type": "STATIC"}], "managed_interfaces": {"frontend_bond_config": {"interface_name": "bond0", "networks": [1]}, "frontend_vlans": []}}

interfaces

list / elements=dictionary

Each frontend interface as the cluster returns it, with its networks.

Returned: success

Sample: [{"bonding_mode": "ACTIVE_BACKUP", "id": 1, "mtu": 1500, "name": "bond0", "networks": [{"assigned_by": "STATIC", "id": 1, "name": "Default"}]}]

legacy_settings

dictionary

The single-network settings, as the cluster returns them.

Returned: success

Sample: {"assigned_by": "STATIC", "floating_ip_ranges": [], "gateway": "10.20.0.1", "ip_ranges": ["10.20.0.5-6"], "netmask": "255.255.255.0"}

resolved_addresses

list / elements=dictionary

Each address of resolve_addresses with the name it resolved to and the result.

Returned: success

Sample: [{"hostname": "dc1.corp.example.com", "ip_address": "10.0.0.10", "result": "OK"}]

resolved_names

list / elements=dictionary

Each name of resolve_names with the addresses it resolved to and the result, OK, NOT_FOUND, TIMEOUT or ERROR.

Returned: success

Sample: [{"hostname": "dc1.corp.example.com", "ip_addresses": ["10.0.0.10"], "result": "OK"}]

status

list / elements=dictionary

The cluster’s answer to GET /v3/network/status, as the cluster gives it, with one entry per node.

On 7.11.0 each entry’s devices carry, under network_details, the device’s role in use_for, seen as FRONTEND_AND_BACKEND and, on the loopback, NONE; the qumulo_ip_addresses of the networks the device carries, each with its network_id, assigned_by, address, floating_addresses, netmask and gateway; and the host_routable_ip_addresses the node’s host assigns. A device of use NONE lists its addresses. On 7.11.0 hardware an entry’s network_id did not name the network in the network document; network 1 of the document showed as 0.

On the VM edge on 7.11.0 its one device lists the virtual machine’s addresses under host_routable_ip_addresses, and the loopback is a device of use_for NONE with its addresses. With no frontend network the device lists no qumulo_ip_addresses; with a HOST network declared it lists one entry assigned by HOST, with an empty address; for HOST network 0 its network_id was 0.

Each entry’s managed_interface_statuses lists each interface the cluster manages, with its name, status and details. The VM edge, whose host manages its network, listed none. On 7.11.0 hardware network_statuses was empty with a network applied; on the VM edge it mapped the declared HOST network’s id to its name, status and details.

Returned: success

Sample: [{"devices": [{"name": "bond0", "network_details": {"host_routable_ip_addresses": [], "qumulo_ip_addresses": [{"address": "10.20.0.5", "assigned_by": "STATIC", "floating_addresses": ["10.20.0.50"], "gateway": null, "netmask": "255.255.255.0", "network_id": 0}], "use_for": "FRONTEND_AND_BACKEND"}}], "managed_interface_statuses": [{"details": "", "name": "bond0", "status": "APPLIED"}], "network_statuses": {}, "node_id": 1, "node_name": "node1"}]

unavailable_subsets

dictionary

Each requested subset this cluster could not answer, with the reason.

Returned: when a subset was unavailable

Sample: {"api_host_network": "GET /v3/network/status failed: HTTP 500 ...", "legacy_settings": "GET /v1/network/settings failed: HTTP 501 ...", "status": "GET /v3/network/status failed: HTTP 500 ..."}
