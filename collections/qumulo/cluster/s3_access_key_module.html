qumulo.cluster.s3_access_key module – Manage the S3 access keys of a user on a Qumulo cluster

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.s3_access_key.

New in qumulo.cluster 0.1.0

Synopsis

  • Makes sure a user has an S3 access key, or removes the user’s keys.

  • Keys are matched by user and, when access_key_id is set, by key id.

  • The cluster makes both the id and the secret of a key, and returns the secret only in its response to the request that makes the key (G-S3-KEY). The module writes the secret at once to a file of its own in secret_destination, readable only by its owner, and returns it in secret_access_key of that run only.

  • The module refuses to make a key in a task that does not set no_log, or that has no secret_destination.

  • Without access_key_id, present means the user holds at least one key, and s3_access_key is the newest.

  • With access_key_id, present means the user holds that key. When it is gone, as after a rebuild, the module makes a new key and says so in notes, while the user holds fewer keys than the ids in declared_access_key_ids and access_key_id together name; so a rebuild restores each of a user’s declared keys. Otherwise the module fails, naming the keys the user holds.

Parameters

Parameter

Comments

access_key_id

string

The id of the key whose secret the user’s S3 clients hold, from access_key_id in s3_access_key when the key was made. Quote it, since an id of digits only would otherwise be read as a number.

With state=absent, only this key is removed.

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

declared_access_key_ids

list / elements=string

The ids of every key the inventory declares for user, as the cluster_baseline role passes them. A declared key that is gone is made again only while the user holds fewer keys than this list and access_key_id name together.

Without it, only this task’s access_key_id counts as declared.

Default: []

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

secret_destination

path

The directory on the controller where the module writes the secret of a key it makes, in s3-<user>-<access_key_id>.yml, readable only by its owner, where <user> is the user as s3_access_key names it, with each run of characters other than letters, digits, ., _ and - replaced by one _. The file holds user, access_key_id and secret_access_key. It is flushed to disk before its name appears, and never replaces another file.

Before a key is made, the module makes the directory, or makes the one there readable only by its owner, and writes a file in it and removes it; if it cannot, the task fails before any write. Through a symbolic link, the directory it points to is made readable only by its owner.

Required to make a key; a task that would make one without it fails before any write, in check mode too.

state

string

Whether the key exists. absent without access_key_id removes every key of the user.

A removed key stops working at once.

Choices:

  • "present" ← (default)

  • "absent"

user

string / required

The user that owns the keys, as a trustee such as local:svc-backup, ad:CORP\svc-backup or uid:1000. A bare name is refused, and so is a group.

The user must exist; in check mode one that does not exist yet, because an earlier task creates it, is reported as a new key.

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

A key that would be made is reported as a change, without a secret.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

The diff lists the user’s key ids before and after. In check mode, a key the run would make appears as (a new key).

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

A run that makes a key returns its secret, which no later run can return; a second run finds the key and changes nothing.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v1/s3/access-keys/ with the user, POST /v1/s3/access-keys/, DELETE /v1/s3/access-keys/{id}; POST /v1/identity/find.

  • A task that would make a key fails before any write unless it sets no_log and secret_destination (G-S3-KEY). On ansible-core 2.22 and later the module also registers the secret with Ansible’s masking of secret values.

  • A user holds at most two keys. A key cannot be replaced without its consumers losing access (G-S3-ROTATE).

  • A rebuilt cluster has none of the old keys, so the next run makes a new key for each declared one.

  • The module reads a user’s keys in one request, since the cluster refuses a page size there (QUIRK-053).

  • When the connection is lost after a key is made, or the module cannot store its secret, or the listing after the make does not show the key, the module removes that key and fails; the message says to run the task again. A key the listing cannot be read for is kept, since its secret is in its file, with a note. When the cluster refuses to remove such a key, the failure names the key, and the file that holds its secret if there is one.

Examples

# These tasks take api_host and a credential from module_defaults for group/qumulo.cluster.qumulo.
# A task that makes a key needs no_log and secret_destination, since the cluster shows the secret only once.
- name: Give the backup service an S3 key, writing a new key's secret to a file
  qumulo.cluster.s3_access_key:
    user: local:svc-backup
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  register: backup_key
  no_log: true

# Give the secret in that file to the key's consumers, then declare the key by its id (next tasks) so that
# later runs keep this key. Any task that reads backup_key.secret_access_key needs no_log too.
- name: Say where a new key's secret is
  ansible.builtin.debug:
    msg: "made S3 key {{ backup_key.s3_access_key.access_key_id }}; its secret is in {{ backup_key.secret_file }}"
  when: backup_key.secret_file is defined

- name: Keep the key the backup service holds, by its id
  qumulo.cluster.s3_access_key:
    user: local:svc-backup
    access_key_id: "{{ backup_s3_access_key_id }}"
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  no_log: true

# After a rebuild the cluster holds none of these keys, so the run makes a new key for each one; every S3 client then
# needs the new secret from its file, and the ids in backup_s3_access_key_ids must be replaced by the new ids.
- name: Keep both keys the backup service holds, making either again if it is gone
  qumulo.cluster.s3_access_key:
    user: local:svc-backup
    access_key_id: "{{ item }}"
    declared_access_key_ids: "{{ backup_s3_access_key_ids }}"
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  loop: "{{ backup_s3_access_key_ids }}"
  no_log: true

# Replace a key. Its consumers lose access until they hold the new secret. If the user holds another key, list its id
# with this one in declared_access_key_ids on the second task, or the run fails.
- name: Retire the key the backup service holds
  qumulo.cluster.s3_access_key:
    user: local:svc-backup
    access_key_id: "{{ backup_s3_access_key_id }}"
    state: absent

- name: Make the backup service's replacement key
  qumulo.cluster.s3_access_key:
    user: local:svc-backup
    access_key_id: "{{ backup_s3_access_key_id }}"
    secret_destination: "{{ inventory_dir }}/../artifacts/{{ inventory_hostname }}/secrets"
  register: replacement_key
  no_log: true

- name: Show the id to declare from now on
  ansible.builtin.debug:
    msg: "set access_key_id to {{ replacement_key.s3_access_key.access_key_id }}"
  when: replacement_key.changed

- name: Preview removing every key of a retired service
  qumulo.cluster.s3_access_key:
    user: local:svc-old
    state: absent
  check_mode: true
  diff: true
  register: retired_keys

- name: Show the keys that would go
  ansible.builtin.debug:
    msg: "{{ retired_keys.diff.before.access_key_ids }}"
  when: retired_keys.changed

- name: Remove every key of the retired service
  qumulo.cluster.s3_access_key:
    user: local:svc-old
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

maybe_applied

boolean

True when the connection was lost after a key’s removal was sent, so the key may be gone. The module fails with changed true.

Returned: on such a failure

Sample: true

notes

list / elements=string

What the module noticed, such as a declared key that was gone and the new one made in its place, a user that does not exist yet in check mode, or a new key whose listing could not be read.

Returned: when there is something to note

Sample: ["access key 00000000000003e8b5a2 of local:svc-backup does not exist, as after a rebuild; a new key would be made in its place"]

s3_access_key

dictionary

The key that meets the declaration after the task, without its secret; an empty dict after state=absent.

In check mode a key the run would make has no id or creation time yet, and both are null.

Returned: always

Sample: {"access_key_id": "00000000000003e8b5a2", "creation_time": "2026-11-02T01:58:32Z", "user": "local:svc-backup"}

access_key_id

string

The key’s id.

Returned: success

creation_time

string

When the cluster made the key.

Returned: success

user

string

The key’s owner, as a trustee.

Returned: success

secret_access_key

string

The new key’s secret, the only time the cluster returns it.

Returned: when the run made a key, outside check mode

Sample: "0123456789abcdef-example-secret"

secret_file

string

The file in secret_destination that holds the new key’s secret.

Returned: when the run made a key, outside check mode

Sample: "/srv/artifacts/hub01/secrets/s3-local_svc-backup-00000000000003e8b5a2.yml"
