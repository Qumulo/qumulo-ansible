qumulo.cluster.host_vars_duplicates filter – A host_vars file’s variables without the shares and exports the inventory already declares

Note

This filter plugin is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.host_vars_duplicates.

New in qumulo.cluster 0.1.0

Synopsis

  • Takes the variables a host_vars file is to hold and the host’s inventory variables, and returns the variables without each SMB share and NFS export entry that the inventory declares too, with a note for each. The cluster_baseline role’s tenancy step refuses a share, export or network declared twice. With captured_tenants it also adds each captured share or export that the inventory does not declare to the flat list, with tenants naming the tenant.

  • An entry is left out when the inventory declares the same share or export with the same values, and the inventory’s entry applies. Only the keys the inventory’s entry gives are compared for other values. The two entries are compared in the form the share and export modules accept, without the modules’ directory lookup, so a spelling that reads back the same is the same value, apart from trustees (below). create_fs_path, tenants, tenant_id, tenant and state are not compared. fs_path is compared without a trailing slash and a mode as 644 and 0644 alike. A share’s permissions are compared with type defaulting to ALLOWED, the rights expanded and sorted (ALL is READ, WRITE and CHANGE_PERMISSIONS, in any letter case) and each trustee as written, in the form the share module’s trustee takes, so Everyone and world:Everyone are one trustee but ad:engineering@corp and ad:Engineering@CORP are two, because the filter looks up no directory, and its network_permissions the same way. An export’s restrictions are compared with the defaults of qumulo.cluster.nfs_export filled in and require_tls false equal to unset, and its fields_to_present_as_32_bit with ALL expanded.

  • A key whose value is null, in either entry, counts as unset, as the share and export modules treat a null option as not given.

  • A key the file’s entry gives that the inventory’s entry omits is handled by cluster_holds_entries. When it is true, the entry is still left out, and its note names each such key whose value is not what a create gives, saying the cluster keeps it and no entry declares it now. When it is false, each such key refuses, “with other values of …, which the inventory’s entry leaves out”, and a key equal to its create default does not. The create defaults, as observed on Qumulo Core 7.10.3, are for an SMB share description "" with network_permissions allowing every address all rights, access_based_enumeration_enabled, require_encryption and expand_fs_path_variables false, offline_files_caching_mode NO_CACHING, default_file_create_mode 0644 and default_directory_create_mode 0755, and for an NFS export description "" and fields_to_present_as_32_bit []. A share’s permissions, an export’s restrictions and fs_path have no create default, so a missing one refuses when cluster_holds_entries is false and the file’s entry gives it.

  • An entry is also left out when the inventory removes the share or export, with state absent or with qumulo_factory_defaults smb_files_share or nfs_root_export absent, so the next baseline removes it from the cluster. A removal in the file’s own qumulo_factory_defaults of a share or export the inventory declares is left out too. A flat entry of the file that names several tenants loses only those the inventory declares it for, and one that names all is written as the list of the present tenants that remain, which does not cover a tenant added to the inventory later. When the file’s qumulo_factory_defaults is left empty by what is left out, it is left out of the variables.

  • A network that both declare, a share or export that the inventory declares with other values and, when cluster_holds_entries is false, one whose file entry gives a key the inventory’s omits with a value other than a create gives, are not left out. Each is named in _value.refusals, and playbooks/capture.yml with qumulo_adopt and playbooks/clone_edge.yml refuse to write the file for any.

  • A variable the file holds outranks the inventory’s, so the inventory’s qumulo_tenants, qumulo_smb_shares, qumulo_nfs_exports, qumulo_factory_defaults and qumulo_network count only where the file leaves them out.

  • An SMB share is the same share when its share_name matches ignoring case, and an NFS export when its export_path matches exactly, each within one tenant. A network is the same network when its id matches, whichever tenant holds it. A network under a tenant declared absent is not counted.

  • A flat entry claims the tenants it names in tenants, every declared tenant for all and, with no tenants, the only present tenant. With tenant_id 1 it claims tenant 1, which is the present entry renamed from Default, else the present entry named Default; with captured_tenants, tenant 1 is the captured one instead (below). When qumulo_tenants is unset or empty, the cluster’s one tenant is what a flat entry with no tenants, tenant_id 1 and a factory removal claim. When lacks_tenant_1 is true there is no tenant 1, so tenant_id 1 and a factory removal claim no tenant.

  • qumulo_factory_defaults with smb_files_share or nfs_root_export absent claims tenant 1’s factory Files share or / export.

  • Two declarations both in the inventory, or both in the file, are not compared. Neither is a claim the baseline refuses for a reason of its own, such as an entry with no name, or with no tenant while several are present, nor an entry with a tenant_id other than 1, which only the cluster can resolve.

  • When the inventory defines qumulo_tenants the file cannot hold the captured one, and captured_tenants gives it. The filter then reads tenant 1, the one tenant that a flat entry with no tenants names, and tenants all from the captured tenants instead of from the inventory’s list, and judges what each captured tenant holds against the inventory’s. Tenant 1 is the captured tenant renamed from Default, else the captured Default, under the name the inventory’s entry gives it. A tenant the inventory removes still counts toward the one tenant, as the baseline counts it until it deletes it. A captured tenant matches an inventory entry by previous_name only when that entry’s name is not a captured tenant’s name. name, previous_name, state, networks, smb_shares and nfs_exports are not tenant settings, and the rest are compared as written, by the keys the inventory gives. A captured network is compared by the keys the inventory gives, as written, except that under a tenant’s entry an omitted vlan_id counts as untagged; a flat qumulo_network listing takes no vlan_id. docs/reference/capture-and-clone.md says what is written, what gets a note and what is refused.

Input

This describes the input of the filter, the value before | qumulo.cluster.host_vars_duplicates.

Parameter

Comments

Input

dictionary / required

The variables the host_vars file is to hold, by name. The filter does not change them.

Keyword parameters

This describes keyword parameters of the filter. These are the values key1=value1, key2=value2 and so on in the following example: input | qumulo.cluster.host_vars_duplicates(key1=value1, key2=value2, ...)

Parameter

Comments

captured_tenants

list / elements=dictionary

The captured qumulo_tenants, when the file leaves it out because the inventory defines it.

Each share or export under a captured tenant is then written in the file’s flat list for its tenant, unless the inventory declares it, and the captured tenants and their networks are judged against the inventory’s. Tenant 1, the one tenant and tenants all are read from these tenants. A tenants all is written as these tenants only when the inventory’s present tenants differ from them after its renames and removals.

Leave it unset when the file holds qumulo_tenants, which the filter then judges by its own entries.

cluster_holds_entries

boolean

Whether the cluster the baseline runs on holds the file’s entries already, as an adopted cluster does. false for a fresh cluster, which creates each share or export from the inventory’s entry alone, so a key the file’s entry gives that the inventory’s omits refuses unless it equals its create default.

Choices:

  • false

  • true ← (default)

exclude

list / elements=string

Names of variables whose value in inventory is not the inventory’s, such as those an earlier clone’s file holds. The filter ignores each in inventory.

Default: []

inventory

dictionary / required

The host’s variables from the inventory, as hostvars[inventory_hostname] gives them.

lacks_tenant_1

boolean

Whether the cluster the baseline will run on has no tenant 1, as the capture notes it.

Choices:

  • false ← (default)

  • true

Examples

# The group's flat share and the captured tenant's share have the same name, ignoring case, so the tenant's is left
# out of the file. The result holds the file's variables without it, a note for it, and no refusal.
- name: Leave out of a host_vars file the shares the inventory already declares
  ansible.builtin.debug:
    msg: "{{ file_variables | qumulo.cluster.host_vars_duplicates(inventory_variables) }}"
  vars:
    inventory_variables:
      qumulo_smb_shares:
        - {share_name: Projects, fs_path: /projects}
    file_variables:
      qumulo_tenants:
        - name: Default
          smb_shares:
            - {share_name: Files, fs_path: /}
            - {share_name: projects, fs_path: /projects}

# For a clone, the fresh target creates each share from the inventory's entry alone. The inventory's Projects share
# leaves out the description that the source's share sets, so the result holds a refusal that names description and
# the Projects share is not left out. With cluster_holds_entries left true, as adoption does, the share is left out
# and its note says the cluster keeps the description and no entry declares it now.
- name: Refuse a clone file whose share sets a key the inventory's entry leaves out
  ansible.builtin.debug:
    msg: "{{ file_variables | qumulo.cluster.host_vars_duplicates(inventory_variables, cluster_holds_entries=false) }}"
  vars:
    inventory_variables:
      qumulo_smb_shares:
        - {share_name: Projects, fs_path: /projects}
    file_variables:
      qumulo_tenants:
        - name: Default
          smb_shares:
            - {share_name: Projects, fs_path: /projects/, description: Team projects}

# The inventory defines qumulo_tenants, so the file leaves out the captured one and passes it as captured_tenants. The
# inventory declares the Default tenant but not its Projects share, so the share is written in the file's flat
# qumulo_smb_shares for Default. The captured Archive tenant is not in the inventory, so the result holds a note
# for it, and no refusal.
- name: Keep the shares a captured tenant holds when the inventory defines qumulo_tenants
  ansible.builtin.debug:
    msg: "{{ file_variables | qumulo.cluster.host_vars_duplicates(inventory_variables, captured_tenants=captured) }}"
  vars:
    inventory_variables:
      qumulo_tenants:
        - name: Default
    file_variables:
      qumulo_smb_shares: []
    captured:
      - name: Default
        smb_shares:
          - {share_name: Projects, fs_path: /projects}
      - name: Archive

# Stops the play, before it writes anything, when the file holds a network the inventory declares too, as
# playbooks/capture.yml does for qumulo_adopt. The inventory here declares network 2 and the file network 1, so the
# play goes on. With network 1 in both, the assert fails and its message names where each declares it.
- name: Stop before writing a file that declares a network the inventory declares
  ansible.builtin.assert:
    that: kept.refusals == []
    fail_msg: "{{ kept.refusals | join('; ') }}"
  vars:
    inventory_variables:
      qumulo_network:
        frontend_networks:
          - {id: 2, name: Backup}
    file_variables:
      qumulo_tenants:
        - name: Default
          networks:
            - {id: 1, name: Default}
    kept: "{{ file_variables | qumulo.cluster.host_vars_duplicates(inventory_variables) }}"

# A fleet's group_vars remove the factory share and export. The captured Default tenant holds both, so both are left
# out of the file and the next baseline removes them from the cluster. For a cluster that has no tenant 1, set
# lacks_tenant_1 to true and the removal then claims nothing.
- name: Leave out the factory share and export that the inventory removes
  ansible.builtin.debug:
    msg: "{{ file_variables | qumulo.cluster.host_vars_duplicates(inventory_variables, lacks_tenant_1=false) }}"
  vars:
    inventory_variables:
      qumulo_factory_defaults:
        smb_files_share: absent
        nfs_root_export: absent
    file_variables:
      qumulo_tenants:
        - name: Default
          smb_shares:
            - {share_name: Files, fs_path: /}
            - {share_name: Projects, fs_path: /projects}
          nfs_exports:
            - {export_path: /, fs_path: /}

# On a second clone, hostvars already hold the first clone's file. Its qumulo_factory_defaults is that file's, not the
# inventory's, so exclude names it and the Files share stays in the new file. Without exclude, the share would be
# left out.
- name: Judge a second clone against the inventory without the earlier file's variables
  ansible.builtin.debug:
    msg: "{{ file_variables | qumulo.cluster.host_vars_duplicates(inventory_variables, exclude=earlier_file_variables) }}"
  vars:
    earlier_file_variables: [qumulo_factory_defaults]
    inventory_variables:
      qumulo_factory_defaults:
        smb_files_share: absent
    file_variables:
      qumulo_tenants:
        - name: Default
          smb_shares:
            - {share_name: Files, fs_path: /}

Return Value

Key

Description

Return value

dictionary

The variables to write, a note for each entry left out, and a sentence for each refusal.

Returned: always

left_out

list / elements=dictionary

A note for each entry left out, in the shape of left_out, with what and why.

With captured_tenants, also a note for each captured tenant that the inventory does not declare, or declares absent, or that the capture itself declares absent and the inventory does not declare, and for each captured share or export that cannot be written because the inventory defines both qumulo_tenants and the flat list, and for each flat entry with tenants all written as the captured tenants.

An empty list when nothing is left out.

Returned: success

Sample: [{"what": "the SMB share Projects of tenant Default", "why": "the inventory declares it in qumulo_smb_shares[0], and the baseline refuses an SMB share declared twice; the inventory's entry applies"}]

refusals

list / elements=string

A sentence for each network both declare and each share or export the inventory declares with other values, or, when cluster_holds_entries is false, without a key the file’s entry gives, naming where the inventory declares it and where the file does, or, for a captured tenant, the capture.

With captured_tenants, also a sentence for each captured tenant the inventory declares with other switches or settings, and for each captured network the inventory does not list for that tenant or lists with other values.

An empty list when there is none.

Returned: success

Sample: ["network 1, which the inventory declares in qumulo_network.frontend_networks[0] and the file in qumulo_tenants[Default].networks[0]"]

variables

dictionary

The given variables without the entries left out.

A smb_shares or nfs_exports of a tenant that is left empty is removed.

A qumulo_factory_defaults left empty is removed.

A flat entry with tenants all that loses a tenant is written with the list of the present tenants that remain.

With captured_tenants, each captured share or export that the inventory does not declare is added to the flat list with tenants [<tenant>], and a flat tenants all is written as the captured tenants when the inventory’s present tenants differ from them after its renames and removals.

Returned: success

Sample: {"qumulo_tenants": [{"name": "Default", "smb_shares": [{"fs_path": "/", "share_name": "Files"}]}]}
