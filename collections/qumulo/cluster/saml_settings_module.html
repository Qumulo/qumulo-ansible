qumulo.cluster.saml_settings module – Manage a Qumulo cluster’s SAML single sign-on settings

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.saml_settings.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Sets how Active Directory users sign in to the cluster’s Web UI through a SAML identity provider (IdP).

  • An option left unset keeps the cluster’s current value.

  • Every setting is read back, the IdP certificate included, which is public. The cluster stores the certificate re-encoded, without any text around it, so the module compares the certificates themselves, not the text.

  • SAML sign-in works only for users of the Active Directory domain the cluster is joined to. The cluster does not check the IdP when the settings are written, so a successful task does not show that sign-in works (G-ID-SAML).

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

cluster_dns_name

string

The name users reach the cluster’s Web UI at, which the IdP’s application for the cluster names.

enabled

boolean

Whether users may sign in through the IdP.

Sign-in needs the IdP’s certificate. The cluster turns it on without one (QUIRK-032), so the module refuses true before any write when neither the task nor the cluster has a certificate.

Turning it on without idp_certificate relies on a certificate this task did not give, which can never be removed (G-ID-SAML-CERT), and warns.

Turning it on warns when the cluster is not joined to Active Directory; in check mode it notes it instead, since an earlier task may join the domain.

Choices:

  • false

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

idp_certificate

string

The certificate the IdP signs its responses with, in PEM, or a chain of certificates. Text around the certificates is ignored, as the cluster ignores it.

Left unset, the certificate the cluster holds is kept.

A value with no PEM certificate fails before any request is sent.

The cluster keeps a certificate once one is set and refuses an empty one, so "" fails when a certificate is set (G-ID-SAML-CERT).

idp_entity_id

string

The IdP’s entity ID, as its metadata names it.

idp_sso_url

string

The IdP’s single sign-on URL, where the cluster sends users to sign in.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

require_sso

boolean

Whether Active Directory users must sign in through the IdP while enabled is true. They can then no longer sign in to the Web UI, qq or the REST API with a password, so the module warns when a task makes both true. Local users, such as admin, still can.

Choices:

  • false

  • true

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Notes

Note

  • API: GET and PATCH /v1/saml/settings, with If-Match; GET /v1/ad/status when the task turns sign-in on. PUT is never sent, since it validates the certificate even when none is given.

  • Registers: G-ID-SAML, G-ID-SAML-CERT, QUIRK-032.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# Only users of the domain the cluster has joined (qumulo.cluster.ad_domain) can sign in. Give idp_certificate, so that
# the cluster holds the IdP's own certificate. Without it, sign-in relies on whatever certificate the cluster already
# holds, which a task did not give and nobody can remove, and the module warns.
- name: Let AD users sign in to the Web UI through the IdP
  qumulo.cluster.saml_settings:
    enabled: true
    idp_sso_url: https://idp.example.com/saml2/sso
    idp_entity_id: https://idp.example.com/metadata
    idp_certificate: "{{ lookup('ansible.builtin.file', 'files/idp-signing.crt') }}"
    cluster_dns_name: qumulo.corp.example.com

- name: Preview a new signing certificate from the IdP
  qumulo.cluster.saml_settings:
    idp_certificate: "{{ lookup('ansible.builtin.file', 'files/idp-signing-2027.crt') }}"
  check_mode: true
  diff: true
  register: saml_preview

- name: Show the settings the new certificate would leave
  ansible.builtin.debug:
    var: saml_preview.saml_settings

- name: Rotate the IdP's signing certificate
  qumulo.cluster.saml_settings:
    idp_certificate: "{{ lookup('ansible.builtin.file', 'files/idp-signing-2027.crt') }}"

- name: Point the cluster at a different IdP, leaving sign-in as it is
  qumulo.cluster.saml_settings:
    idp_sso_url: https://idp2.example.com/saml2/sso
    idp_entity_id: https://idp2.example.com/metadata
    idp_certificate: "{{ lookup('ansible.builtin.file', 'files/idp2-signing.crt') }}"

# While SAML sign-in is on, AD users sign in only through the IdP. Local users, such as admin, still sign in with a
# password; keep one. require_sso has effect only while enabled is true.
- name: Require AD users to sign in through the IdP
  qumulo.cluster.saml_settings:
    enabled: true
    require_sso: true

# The cluster keeps the IdP certificate once one is set and refuses an empty one, so turn sign-in off with enabled.
- name: Turn SAML sign-in off, keeping the other settings
  qumulo.cluster.saml_settings:
    enabled: false

Return Values

Key

Description

dictionary

The values the task wrote, for the settings that did not converge.

Sample: {"require_sso": true}

maybe_applied

boolean

true when a write was sent and the connection was lost before the cluster answered, and reading the settings back did not confirm it.

Returned: on a failure after such a write

list / elements=string

What the module noticed, such as a cluster not joined to Active Directory yet in check mode when sign-in is turned on, or a write it confirmed by reading back after the connection was lost.
