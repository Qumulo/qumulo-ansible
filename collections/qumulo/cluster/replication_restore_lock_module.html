qumulo.cluster.replication_restore_lock module – Hold the controller’s lock on an edge’s restore, so one restore runs per edge at a time

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_restore_lock.

New in qumulo.cluster 0.1.0

Synopsis

  • Takes or removes the lock that keeps a second restore of an edge from starting on the same controller while one is under way. The replication_pair role’s restore.yml takes it before its first step and removes it in an always: section.

  • An action plugin that runs on the controller. It sends no request, takes no connection options, and is not in the qumulo.cluster.qumulo action group, so module_defaults for that group do not reach it.

  • The lock is a JSON file, format 1, holding holder, a random token for this run, the controller’s host name, boot id and PID namespace, the ansible-playbook process’s id, its start in clock ticks since boot and its start time, and the lease’s expiry. It is written to <path>.tmp-<token>, synced to the disk, and linked to path; then the temporary name is unlinked, and any <path>.tmp-* older than lease is removed. A lock that is empty or not JSON refuses, naming the file to remove by hand once no run is under way.

  • A lock that another run holds is taken over, with a warning, when its process is gone, if it was taken on this controller, or once its lease has run out, if it was taken on another host or on a controller without /proc, where whether its process is alive cannot be read. This controller is the same host name, the same boot id and the same PID namespace; a lock from any other controller waits for its lease. Its process is the one whose start ticks the lock records. A lock whose process is alive on this controller is never taken over, whatever its lease says. Any other lock refuses, naming its holder, its process, its controller and its lease’s end.

  • A take that passes the lock’s token, by the same holder and from the ansible-playbook process that took it, renews it, extending its lease to lease from now. The renewal is written to <path>.tmp-<token> and renamed over path under the guard, after the run reads the lock again and finds its token still there. A take by that process for another holder refuses. A renewal never takes a new lock; one whose lock is gone, or holds another token, or holds token but was taken by another process, refuses.

  • A takeover holds an exclusive flock on <path>.guard while it reads the lock again and replaces it; the removal holds it while it reads the lock again and unlinks it. The kernel drops the flock when the process dies. The guard file is kept. A run waits at most 60 seconds for the guard, then refuses.

  • state=present creates the lock’s directory and each missing one above it with mode 0700, and never changes the mode of one that exists, so a directory that cannot be written fails the take.

  • The lock is the controller’s alone. Two controllers can both restore one edge.

Note

This module has a corresponding action plugin.

Parameters

Parameter

Comments

holder

string

What holds the lock, written into it and named by the refusal of another run.

The replication_pair role’s restore takes the default.

Default: "restore"

host

string

The inventory host whose lock path is, which the refusals name.

Defaults to the task’s inventory_hostname.

lease

integer

How long, in seconds from the take, another host may not take the lock over, at least 1. Required with state=present.

path

path / required

The lock file, <edge_rebuild_artifact_dir>/<edge>/restore/lock.

state

string

present takes the lock for this run and returns its token; with token, it renews the lock that holds it.

absent removes the lock only when it holds token and this ansible-playbook process took it, so a run that found another run’s lock never removes it.

Choices:

  • "present" ← (default)

  • "absent"

token

string

The token of the lock this run holds, as the take returned it in token. Required with state=absent.

With state=present, the take renews the lock that holds it, and fails when the lock no longer does. Without it, a take never renews, so a second import of the playbook in the same process takes a lock of its own.

With state=absent, the empty string removes nothing, as after a take that failed.

Attributes

Attribute

Support

Description

check_mode

Support: full

Reports whether it would take, take over, renew or remove the lock, and refuses a lock it would refuse; it creates nothing.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: none

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

The take, the renewal and the removal report no change, so a converge’s idempotence run counts none.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Note

Examples

- name: Restore one edge at a time
  # Run on the controller. The lease is the longest the restore can take, in seconds; the always section removes the
  # lock even when a step fails, and removes nothing when the take itself failed.
  block:
    - name: Take the edge's restore lock
      qumulo.cluster.replication_restore_lock:
        path: "{{ edge_rebuild_artifact_dir }}/{{ inventory_hostname }}/restore/lock"
        lease: 90000
      register: restore_lock

    - name: Restore
      ansible.builtin.debug:
        msg: The restore's steps run here.
  always:
    - name: Remove the edge's restore lock, if this run holds it
      qumulo.cluster.replication_restore_lock:
        path: "{{ edge_rebuild_artifact_dir }}/{{ inventory_hostname }}/restore/lock"
        state: absent
        token: "{{ restore_lock.token | default('') }}"

- name: Preview taking the edge's restore lock, to see whether another run holds it
  # Check mode creates nothing; it refuses a lock it would refuse.
  qumulo.cluster.replication_restore_lock:
    path: "{{ edge_rebuild_artifact_dir }}/{{ inventory_hostname }}/restore/lock"
    lease: 90000
  check_mode: true

- name: Name a holder other than the default when taking the lock
  qumulo.cluster.replication_restore_lock:
    path: "{{ edge_rebuild_artifact_dir }}/{{ inventory_hostname }}/restore/lock"
    lease: 3600
    holder: nightly-restore
    host: edge01
  register: named_lock

- name: Extend the lease of a lock this run holds
  # Pass the token the take returned, and the same holder. The renewal fails when the lock is gone or holds another
  # token.
  qumulo.cluster.replication_restore_lock:
    path: "{{ edge_rebuild_artifact_dir }}/{{ inventory_hostname }}/restore/lock"
    lease: 3600
    holder: nightly-restore
    token: "{{ named_lock.token }}"

- name: Remove the lock this run holds
  qumulo.cluster.replication_restore_lock:
    path: "{{ edge_rebuild_artifact_dir }}/{{ inventory_hostname }}/restore/lock"
    state: absent
    token: "{{ named_lock.token }}"
