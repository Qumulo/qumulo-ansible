qumulo.cluster.ssl_certificate module – Install the TLS certificate a Qumulo cluster serves

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.ssl_certificate.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

  • Examples

  • Return Values

Synopsis

  • Installs a certificate chain and its private key as the certificate the cluster serves for its REST API, web UI and NFS over TLS.

  • The cluster offers no way to read the installed certificate or key back (G-SSL-READBACK). The module connects to each address in probe and compares the certificate it serves with the first certificate of certificate. It installs when any probed address serves another certificate, and never compares keys.

  • After installing, the module waits up to wait_timeout seconds until every probed address serves the new certificate.

  • When validate_certs=true, the module checks before installing, by serving the new chain to itself, that the chain verifies against ca_path for api_host. It refuses a chain that does not verify unless allow_management_disruption=true.

  • On Python 3.13 and later, a self-signed certificate pinned through ca_path must be a certificate authority itself, with basicConstraints CA:TRUE; the module warns about a self-signed certificate that is not.

Parameters

Parameter

Comments

allow_management_disruption

boolean

Install a chain that does not verify against ca_path for api_host although validate_certs=true.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

certificate

string / required

The certificate chain in PEM, the cluster’s own certificate first, then any intermediates. The chain must reach a root certificate authority; the cluster refuses one that does not.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

private_key

string / required

The private key of the first certificate, in PEM. A key that does not match fails before the install when validate_certs=true, unless allow_management_disruption=true; the cluster refuses it otherwise.

probe

list / elements=string

The addresses to compare, as host or host:port; a host alone uses api_port. An IPv6 address with a port is written [fd00::5]:8000.

Empty probes api_host on api_port.

Default: []

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

wait_timeout

integer

Seconds to wait, after installing, until every probed address serves the new certificate.

Default: 120

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

The diff maps each probed host:port to the SHA-256 digest it serves before the task, and to the digest of certificate after it.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

Compared by the certificate each probed address serves; an address that is not probed is not compared.

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: PUT /v2/cluster/settings/ssl/certificate; TLS connections to each probed address.

  • Registers: G-SSL-READBACK.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Serve the edge's certificate on the REST API port
  qumulo.cluster.ssl_certificate:
    certificate: "{{ lookup('ansible.builtin.file', inventory_dir ~ '/../files/edge01.pem') }}"
    private_key: "{{ vault_edge01_tls_key }}"

# Without probe, only api_host on api_port is compared. To cover a cluster of several nodes, list every node's
# address, and port 443 for the web UI.
- name: Serve the edge's certificate, and check both of its ports
  qumulo.cluster.ssl_certificate:
    certificate: "{{ lookup('ansible.builtin.file', inventory_dir ~ '/../files/edge01.pem') }}"
    private_key: "{{ vault_edge01_tls_key }}"
    probe: ["{{ qumulo_api_host }}:8000", "{{ qumulo_api_host }}:443"]

- name: Preview serving the renewed certificate
  qumulo.cluster.ssl_certificate:
    certificate: "{{ lookup('ansible.builtin.file', inventory_dir ~ '/../files/edge01-renewed.pem') }}"
    private_key: "{{ vault_edge01_tls_key_renewed }}"
    probe: ["{{ qumulo_api_host }}:8000", "{{ qumulo_api_host }}:443"]
  check_mode: true
  diff: true
  register: tls_preview

- name: Say whether any probed address would change, and to which certificate
  ansible.builtin.debug:
    msg: "{{ 'would serve ' ~ tls_preview.ssl_certificate.sha256 if tls_preview.changed else 'already served' }}"

- name: Serve the renewed certificate
  qumulo.cluster.ssl_certificate:
    certificate: "{{ lookup('ansible.builtin.file', inventory_dir ~ '/../files/edge01-renewed.pem') }}"
    private_key: "{{ vault_edge01_tls_key_renewed }}"
    probe: ["{{ qumulo_api_host }}:8000", "{{ qumulo_api_host }}:443"]

- name: Give a slow node more time to reload the renewed certificate
  qumulo.cluster.ssl_certificate:
    certificate: "{{ lookup('ansible.builtin.file', inventory_dir ~ '/../files/edge01-renewed.pem') }}"
    private_key: "{{ vault_edge01_tls_key_renewed }}"
    probe: ["{{ qumulo_api_host }}:8000", "{{ qumulo_api_host }}:443"]
    wait_timeout: 300

# A chain from another certificate authority does not verify against the current ca_path, so the module refuses it
# without allow_management_disruption. Later tasks must then connect with the new authority's certificate in ca_path.
- name: Serve a certificate from the site's new certificate authority
  qumulo.cluster.ssl_certificate:
    certificate: "{{ lookup('ansible.builtin.file', inventory_dir ~ '/../files/edge01-new-ca.pem') }}"
    private_key: "{{ vault_edge01_tls_key_new_ca }}"
    probe: ["{{ qumulo_api_host }}:8000", "{{ qumulo_api_host }}:443"]
    allow_management_disruption: true

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

served

dictionary

The digest each probed address serves, or unreachable (reason), by host:port, an IPv6 host without brackets.

Returned: when the install was sent but a probed address still served another certificate after wait_timeout

Sample: {"edge01.example.com:443": "unreachable (timed out)", "edge01.example.com:8000": "9f2a0cad..."}

ssl_certificate

dictionary

The certificate the task leaves served, or in check mode would leave served.

Returned: always

Sample: {"served": {"edge01.example.com:8000": "9f2a0cad..."}, "sha256": "9f2a0cad..."}

served

dictionary

The SHA-256 digest of the certificate each probed address serves, by host:port, an IPv6 host without brackets.

In check mode, when the task would change something, the digest each address would serve.

Returned: success

sha256

string

The SHA-256 digest of the first certificate of certificate, in DER, as hex.

Returned: success
