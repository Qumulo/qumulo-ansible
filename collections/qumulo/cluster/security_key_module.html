qumulo.cluster.security_key module – Manage a key that locks snapshots in a Qumulo cluster’s file system key store

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.security_key.

New in qumulo.cluster 0.1.0

Synopsis

  • Registers, changes, replaces or removes one key in the cluster’s file system key store. The store holds the public half of an ECDSA key, such as a P-256 key; qumulo.cluster.snapshot_lock locks a snapshot with it, and only a signature by the private half unlocks it.

  • A key is matched by its name. The cluster gives each key an id, which the module returns and never matches on.

  • The cluster takes a new key only with its name signed by the private key, so a key that does not exist yet needs private_key or verification_signature.

  • A key that holds another public key is replaced through the cluster’s replacement challenge. The cluster takes the replacement only with the challenge signed by both private keys, and the module signs it in the run that sends the replacement, so replacing a key needs the old and the new private key on the controller, a key registered with verification_signature included. The key keeps its id, comment, state and usages, so what it locked unlocks with the new private key.

Comments

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

Password of api_username.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

comment

string

The key’s comment. Left unset, an existing key keeps its comment, and a new key gets an empty one.

enabled

boolean

Whether the key can lock snapshots. A disabled key still unlocks what it locked.

Left unset, an existing key keeps its state, and a new key is enabled.

The cluster refuses to disable a key that a snapshot policy or a replication target uses, so the module refuses it before any write, in check mode too. A key that only locks snapshots can be disabled.

Choices:

  • false

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

name

string / required

The key’s name, unique in the key store. A name of digits only, or an empty one, is refused before any request; the cluster stores an empty name, which no request can then name (QUIRK-120).

The module does not rename a key. A key renamed outside the collection is not found, and a key of this name is created beside it.

old_private_key

string

The private half of the public key the key store holds now, in unencrypted PEM. Requires private_key.

Needed only when the key store holds a public key other than the one the task declares, through public_key or through private_key; the module then replaces the key. Without it the module refuses the replacement.

The module checks it against the key store’s public key, and private_key against the declared one, before it asks the cluster for a challenge.

Not used, and not checked, when the key store already holds the declared public key, so a task that replaced the key reports no change when it runs again. When no key of this name exists, the module registers the key and adds a note to notes that this option went unused.

Handled as private_key is, and never logged, returned or shown in a diff.

private_key

string

The key’s private half, in unencrypted PEM. A key encrypted with a passphrase of its own is refused.

To create the key, the module signs its name with it. To replace a key, it is the new key, which signs the replacement challenge.

The module signs with the openssl command on the controller. It writes the key to a file only the controller’s user can read, and removes the file once openssl exits. The key is never logged, returned or shown in a diff.

public_key

string

The key’s public half, in PEM or as base64 DER. Compared as the base64 DER the cluster stores.

With private_key it may be left out, and the module derives it; when both are given they must match.

To create the key, give this or private_key. On an existing key, leaving out both keeps the key’s public key.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

state

string

Whether the key is in the key store.

Choices:

  • "present" ← (default)

  • "absent"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

verification_signature

string

The key’s name signed with its private key, ECDSA over SHA-256, as base64 of the DER signature, the value qq fs_security_add_key --verification-signature takes. It creates the key without giving the module the private key.

Used only to create the key, and ignored when the key exists. It cannot replace a key, because the replacement challenge must be signed, not the name.

Give this or private_key, not both. Requires public_key.

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Checks the private keys against their public keys, and asks the cluster for no replacement challenge.

Refuses what a real run refuses before any write, such as a create without a signature, a replacement without old_private_key or a key in use.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v1/file-system/security/keys/{name}; POST /v1/file-system/security/keys/; GET, PATCH and DELETE /v1/file-system/security/keys/{id}; GET /v1/file-system/security/keys/{id}/usages; GET /v1/file-system/security/keys/{id}/key-replacement-challenge and POST /v1/file-system/security/keys/{id}/replace.

  • With private_key or old_private_key the controller needs the openssl command; the module fails before any request without it.

  • The cluster refuses to delete a key that a snapshot, a snapshot policy or a replication target uses, so the module refuses it before any write, naming each by type and id; a refusal names at most ten, then counts the rest. The refusal ends with the step that frees each kind of usage.

  • The module returns no usages. qumulo.cluster.snapshot_info reads them in its security_keys subset.

  • If the connection is lost after a write was sent, the module reads the key back to decide, and never sends it twice.

  • A replacement together with a change of comment or enabled, and a new key with enabled=false, are each two writes, since the create takes no disabled field. If the connection is lost after the first write and reading the key back shows it took, the module adds a note to notes and sends the second write. If the second write fails, the task fails with changed true, since the first took.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# Keep private keys in an ansible-vault, unencrypted inside it; the module refuses a key with a passphrase of its own.
- name: Register the legal-hold key, signing its name with the private key
  # The module derives the public key from the private one. A second run changes nothing.
  qumulo.cluster.security_key:
    name: legal-hold
    private_key: "{{ vault_legal_hold_private_key }}"
    comment: Locks the snapshots kept for legal holds

- name: Register the legal-hold key without the private key reaching the controller
  # Where the private key is kept, make the public key file and sign the name:
  #   openssl pkey -in legal-hold.pem -pubout -out keys/legal-hold.pub
  #   printf %s legal-hold | openssl dgst -sha256 -sign legal-hold.pem | openssl base64 -A
  # Put the signature in the host's vars as legal_hold_name_signature. It is not a secret and does not expire. It
  # registers the key and does nothing else: to rotate the key later, both private keys must be on the controller.
  qumulo.cluster.security_key:
    name: legal-hold
    public_key: "{{ lookup('ansible.builtin.file', 'keys/legal-hold.pub') }}"
    verification_signature: "{{ legal_hold_name_signature }}"

- name: Preview a change of the legal-hold key's comment
  # Leaving out the keys keeps the key's own. The diff shows the comment going from the old text to the new.
  qumulo.cluster.security_key:
    name: legal-hold
    comment: Locks the snapshots kept for the 2026 audit
  check_mode: true
  diff: true

- name: Change the legal-hold key's comment
  qumulo.cluster.security_key:
    name: legal-hold
    comment: Locks the snapshots kept for the 2026 audit

- name: Stop the legal-hold key from locking more snapshots
  # A disabled key still unlocks the snapshots it locked, and M(qumulo.cluster.snapshot_lock) refuses to lock with it.
  # The cluster refuses to disable a key that a snapshot policy or a replication target uses, and so does the module,
  # naming each. Set enabled: true to lock with the key again.
  qumulo.cluster.security_key:
    name: legal-hold
    enabled: false

- name: Replace the legal-hold key with a new key pair, keeping what it locks
  # Rotating a key needs both private keys on the controller, whether the key was registered with its private key
  # or with a signature of its name: the cluster takes a replacement only with its challenge signed by both.
  # The key keeps its id, so the snapshots it locks unlock with the new private key from now on, and a policy that
  # locks with it keeps locking. The old private key unlocks nothing afterwards. A second run finds the new public key
  # in place and changes nothing, so old_private_key may stay in the task.
  qumulo.cluster.security_key:
    name: legal-hold
    private_key: "{{ vault_legal_hold_private_key_2027 }}"
    old_private_key: "{{ vault_legal_hold_private_key }}"
    comment: Locks the snapshots kept for legal holds

- name: Remove the legal-hold key from the key store
  # Refused while a snapshot, a snapshot policy or a replication target uses the key, and the refusal ends with the
  # step that frees each kind of usage. Unlock the snapshots with M(qumulo.cluster.snapshot_lock), take the key off each
  # policy with lock_key: "" on M(qumulo.cluster.snapshot_policy), and take it off each replication target. The
  # collection does not manage a target's lock key, so qq does:
  # qq replication_set_target_relationship_lock --relationship-id <id> --clear-lock-key.
  # Remove a key with an empty name, which this module refuses, by its id: qq fs_security_delete_key -k <id>.
  qumulo.cluster.security_key:
    name: legal-hold
    state: absent
