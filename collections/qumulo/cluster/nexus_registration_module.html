qumulo.cluster.nexus_registration module – Register a Qumulo cluster with Qumulo’s Nexus service

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.nexus_registration.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Registers the cluster with Nexus using a single-use join key, or removes the cluster’s registration.

  • The key is join_key, or, without one, a key the module mints in Nexus with nexus_api_token.

  • A cluster whose registration status is REGISTERED is left alone, so a re-run neither spends nor mints a key.

  • The module registers synchronously and fails with Nexus’s reason when registration fails.

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

join_key

string

A single-use Nexus join key for this cluster, as the Nexus web interface creates it.

It is sent only when the cluster is not registered, and never returned.

A key spent on a failed registration cannot be used again (G-NEXUS-KEY).

nexus_account_id

integer

The Nexus organization a minted key registers the cluster to.

Needed only when nexus_api_token belongs to a user in more than one organization.

nexus_api_token

string

A Nexus user’s API token, sent to Nexus as a bearer token. It is never sent to the cluster.

What the token may do depends on the user’s role in the Nexus organization; each module says which calls it makes.

If not set, the value of the QUMULO_NEXUS_API_TOKEN environment variable is used.

nexus_api_url

string

Base URL of the Nexus API. Only https URLs are accepted, and the certificate is always verified.

If not set, the value of the QUMULO_NEXUS_API_URL environment variable is used.

Default: "https://api.nexus.qumulo.com"

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

state

string

present registers a cluster whose status is NONE or PENDING_REGISTRATION.

With PENDING_REGISTRATION and no join_key, the key the cluster already stores is tried first, then, if that fails and nexus_api_token is set, a newly minted one.

absent removes the cluster’s registration secret and any stored key. It does not retire the cluster in Nexus; qumulo.cluster.nexus_cluster does.

Choices:

  • "present" ← (default)

  • "absent"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Check mode neither mints a key nor writes, and predicts the registration.

With the Nexus connection off, check mode still predicts the registration and warns, because an earlier qumulo.cluster.nexus_connection task in the same check-mode run turned nothing on.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

Registration is decided by the cluster’s status, so a registered cluster is never sent another key.

A key spent on a failed attempt cannot be used again (G-NEXUS-KEY).

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET, PUT and DELETE /v1/nexus/registration, POST /v1/nexus/registration/rotate; PATCH /v1/support/settings to clear a stored key; with nexus_api_token, Nexus POST /api/v1/api_tokens with token type CLUSTER_OTP.

  • Registration needs the Nexus connection on (qumulo.cluster.nexus_connection). No other monitoring or Nexus setting should change while it runs.

  • Minting a key needs a Nexus role that may create API tokens in the organization.

  • A join key is single-use, and a key spent on a failed registration cannot be used again (G-NEXUS-KEY).

  • After storing the key the module POSTs rotate, which registers at once and answers with Nexus’s reason when it fails (QUIRK-011). A rotate whose answer is lost is never sent again; the registration status says whether it registered.

  • A rotate that answers HTTP 412 is sent again, up to three times in all, until the registration status reads REGISTERED (QUIRK-018).

  • A rotate that answers HTTP 400 decode_error carrying the 5xx error page of the gateway in front of Nexus is sent again while the key is still pending, backing off from two seconds to fifteen, until retry_timeout runs out (QUIRK-022).

  • A mint that the gateway in front of Nexus answers with HTTP 502, 503 or 504, or whose connection is lost, is sent again until retry_timeout runs out. A mint whose answer was lost may leave a spare join key in the Nexus organization, which nothing uses.

  • absent clears a stored key by PATCHing it empty, because DELETE /v1/nexus/registration clears only the secret (QUIRK-016). The settings are never PUT (QUIRK-010).

  • Writes to /v1/nexus/registration send no If-Match.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# Registration needs the Nexus connection on, which in turn needs cloud monitoring on.
- name: Turn on the Nexus connection and register with a key minted in Nexus
  block:
    - name: Turn on cloud monitoring
      qumulo.cluster.monitoring_settings:
        enabled: true
        wait: true

    - name: Connect the cluster to Nexus
      qumulo.cluster.nexus_connection:
        nexus_enabled: true

    - name: Register with a key minted in Nexus
      qumulo.cluster.nexus_registration:
        nexus_api_token: "{{ vault_nexus_api_token }}"

# Needed only when the token's user belongs to more than one Nexus organization.
- name: Register with a key minted in a chosen Nexus organization
  qumulo.cluster.nexus_registration:
    nexus_api_token: "{{ vault_nexus_api_token }}"
    nexus_account_id: 1234

# A join key is single-use, and one spent on a failed registration cannot be used again (G-NEXUS-KEY).
- name: Register with a key made in the Nexus web interface
  qumulo.cluster.nexus_registration:
    join_key: "{{ vault_nexus_join_key }}"

# The cluster's Nexus connection (nexus_connection's nexus_host) must name the same Nexus service.
- name: Mint the join key in a Nexus service at another URL
  qumulo.cluster.nexus_registration:
    nexus_api_token: "{{ vault_nexus_api_token }}"
    nexus_api_url: https://nexus.example.com

# Check mode neither mints a key nor writes.
- name: Preview the registration
  qumulo.cluster.nexus_registration:
    nexus_api_token: "{{ vault_nexus_api_token }}"
  check_mode: true
  diff: true
  register: registration_preview

- name: Show where the key would come from
  ansible.builtin.debug:
    msg: "{{ registration_preview.join_key_source | default('already registered') }}"

# Removing the registration does not retire the cluster's UUID in Nexus; qumulo.cluster.nexus_cluster does.
- name: Remove the cluster's registration before it is destroyed
  qumulo.cluster.nexus_registration:
    state: absent

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

join_key_source

string

Where the key that registered the cluster came from, or would come from in check mode.

given is join_key, minted a key minted in Nexus, and stored the key the cluster already stored.

Returned: when the module registers the cluster, or would in check mode

Sample: "minted"

maybe_applied

boolean

true when a write to the cluster was sent and its answer lost, so the module cannot tell whether it took effect.

After a lost rotate, the module reads the registration status first, and fails this way only when it is not REGISTERED.

The task fails with changed set.

Returned: on such a failure

Sample: true

notes

list / elements=string

What the module noticed, such as a join key the cluster stored that failed to register it, so that a newly minted key registered it instead.

Returned: when there is something to note

Sample: ["the join key the cluster stored did not register it (...); registered with a newly minted key"]

registration

dictionary

The cluster’s registration status after the task, or in check mode the status the task would leave.

Returned: always

Sample: {"nexus_enabled": true, "registration_status": "REGISTERED", "secret_created_at": "2026-10-31T02:00:00Z"}

nexus_enabled

boolean

Whether the cluster’s Nexus connection is on.

Returned: success

registration_status

string

The registration status, such as NONE, PENDING_REGISTRATION or REGISTERED.

Returned: success

secret_created_at

string

When the cluster’s Nexus secret was created; null after the registration was removed.

Returned: success
