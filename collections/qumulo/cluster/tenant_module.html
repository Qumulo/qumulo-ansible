qumulo.cluster.tenant module – Manage a Qumulo cluster’s network tenant

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.tenant.

New in qumulo.cluster 0.1.0

Synopsis

  • Creates, renames, changes or deletes a network tenant, and sets which services it allows on its networks.

  • The tenant is found by name, never by its id.

  • The network document, which qumulo.cluster.network_config manages, owns which networks a tenant holds. This module never changes them. A create sends an empty list, a change never sends networks, and tenant.networks returns them read-only.

  • A create sends one POST with every service switch, an unset one as false, no networks, and the identity configuration of tenant 1, or, once tenant 1 is gone, the one every tenant shares. When tenant 1 is gone and the tenants’ identity configurations differ, the create fails, because per-tenant identity is not supported. A POST whose answer is lost is confirmed by reading the tenant list by name.

  • A change sends one PATCH with the tenant’s current ETag as If-Match, carrying only the keys that differ.

  • Before a create, a change of rest_api_enabled or web_ui_enabled, or a delete, the module applies the continuity rule to the play’s own connection, unless allow_management_disruption is set. It judges the tenants and their networks as they will be immediately after the write. With one tenant after the write, that tenant must have REST enabled, as cluster_port defines it. With two or more, each network of the management network, which is management_network or the networks the module finds for api_host, must belong to a tenant with REST enabled, and a management network the module cannot determine is refused too. A write that fails the rule is refused before it is sent, with a message that says what to set. A rename, and a change of any other switch, are not judged.

  • With more than one tenant, each service listens only on the networks of the tenants that enable it.

Parameters

Parameter

Comments

allow_management_disruption

boolean

Skip the continuity rule, so the module sends a write that may cut this play off from the cluster.

It does not lift the refusal of a second tenant while a backend network is held, or the delete refusals at state.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

cluster_port

integer

The TCP port the cluster listens on for this play, when it differs from api_port because a load balancer or tunnel sits in between.

It decides which switch “REST enabled” means in the continuity rule. 443 means web_ui_enabled, since the web UI listener forwards /api to REST. Any other port means rest_api_enabled.

Unset, api_port is taken as the cluster port, except that at api_port=443 the module cannot tell which listener the play reaches, fails closed, and needs both web_ui_enabled and rest_api_enabled on.

content_removed

boolean

Whether the cluster_baseline role removes the tenant’s networks, shares and exports before this delete.

Used only in check mode, where true skips the refusal for a tenant that still holds a network, an SMB share or an NFS export. The refusal of the last tenant still applies. Set by the cluster_baseline role, not by a task written by hand.

Choices:

  • false ← (default)

  • true

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

management_network

list / elements=integer

The ids of the networks this play reaches the cluster on, which the continuity rule keeps in a tenant with REST enabled. Network id 0 is a real id.

Used only when two or more tenants remain after a judged write.

Given, each id must be a network on the cluster, and an empty list fails. In check mode with planned_networks, an id that planned_networks binds is accepted though the cluster lacks it, for a network that the cluster_baseline role’s network step adds. The module takes the ids as given, without checking that a HOST network among them shows on a device, and reads no network status.

Unset, the module resolves the addresses of api_host on the controller and finds the network whose ranges hold each one in the network document. For an address no range holds, or one on a HOST network, it reads the cluster’s network status, which must place the address and show a HOST network on a device.

name

string / required

The tenant’s name, compared exactly.

nfs_enabled

boolean

Whether the tenant’s networks serve NFS, on TCP 111 and 2049.

Unset is false when the tenant is created, and unchanged on an existing tenant.

Choices:

  • false

  • true

planned_networks

dictionary

Which tenant holds each network, as it will be immediately after this write. The keys are network ids and the values are tenant names.

Used only in check mode, where it also tells which networks the document will hold, so an management_network id it binds counts as a network on the cluster. Set by the cluster_baseline role, not by a task written by hand.

planned_tenants

dictionary

Whether each tenant has REST enabled, as it will be immediately after this write. The keys are tenant names and the values are booleans.

Used only in check mode. Set by the cluster_baseline role, not by a task written by hand.

previous_name

string

The tenant’s earlier name, for a rename.

When no tenant has name and one has previous_name, that tenant is renamed to name with one PATCH, which also carries any switch that differs.

When a tenant already has name, nothing is renamed.

When no tenant has either name, the module creates name.

Ignored with state=absent, which acts on name only.

replication_enabled

boolean

Whether the tenant’s networks serve replication, on TCP 3712.

Unset is false when the tenant is created, and unchanged on an existing tenant.

Choices:

  • false

  • true

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

rest_api_enabled

boolean

Whether the tenant’s networks serve the REST API, on TCP 8000.

Unset is false when the tenant is created, and unchanged on an existing tenant.

A change of it is judged by the continuity rule; cluster_port says which of the two switches REST enabled means.

Choices:

  • false

  • true

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

smb_enabled

boolean

Whether the tenant’s networks serve SMB, on TCP 445.

Unset is false when the tenant is created, and unchanged on an existing tenant.

Choices:

  • false

  • true

ssh_enabled

boolean

Whether the tenant’s networks serve SSH, on TCP 22.

Unset is false when the tenant is created, and unchanged on an existing tenant.

Choices:

  • false

  • true

state

string

Whether the tenant exists.

absent reports no change when no tenant has name.

absent fails, before any write, for the last tenant, and while the tenant holds a network, an SMB share or an NFS export. The message lists them.

Otherwise absent sends one DELETE with If-Match. A DELETE whose answer is lost is confirmed by the tenant list no longer holding name. removed_overrides names the SMB and NFS overrides the delete removed, or in check mode would remove.

Choices:

  • "present" ← (default)

  • "absent"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

web_ui_enabled

boolean

Whether the tenant’s networks serve the web UI, on TCP 80 and 443.

Unset is false when the tenant is created, and unchanged on an existing tenant.

A change of it is judged by the continuity rule; cluster_port says which of the two switches REST enabled means.

Choices:

  • false

  • true

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Predicts the change as on any cluster, including a cloud cluster that refuses the real write.

Makes the same refusals as a real run.

Warns, before a predicted create or change, when the cluster’s protection type is object-backed, because the real write would be refused.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Shows the tenant before and after, as name and the six switches, with tenant.networks the same on both sides.

A create’s before is empty and its after has no networks. A delete’s after is empty. A rename shows the old name before and the new one after.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: full

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET and POST /v1/multitenancy/tenants/; GET, PATCH (If-Match) and DELETE (If-Match) /v1/multitenancy/tenants/{tenant_id}; GET /v3/network for the second-tenant check, the continuity rule, and the network names in a delete refusal; GET /v3/network/status only for a judged write that leaves two or more tenants, without management_network, when no network’s ranges place an address of api_host or one places it on a HOST network; before a delete, GET /v3/smb/shares/, /v3/nfs/exports/, /v1/multitenancy/smb/settings/ and /v1/multitenancy/nfs/settings/; in check mode, before a predicted write, GET /v1/cluster/protection/status.

  • Qumulo marks the multitenancy REST API this module uses as preview; a later Qumulo Core release may change it.

  • A delete removes the tenant’s shares, exports and SMB and NFS overrides with it, so the module refuses it while the tenant holds any share or export (G-TENANT-CASCADE).

  • Qumulo Core refuses every tenant write on AWS, Azure, GCP and OCI, and the module maps that refusal to a message that says so (G-TENANT-CLOUD).

  • The first create of a second tenant, and the delete that leaves one tenant, rebind every listener on every node and end every NFS and replication connection. The module warns of it in the run, and in a check run that predicts it (G-TENANT-LISTEN).

  • Every create removes the static routes of every node. The module warns of it in the run, and in a check run that predicts it (G-TENANT-ROUTES).

  • A create that would make a second tenant is refused while any tenant holds a network that is not on the frontend bond, a frontend VLAN or a HOST network, such as a backend-bond network, and the message names the network (G-TENANT-BACKEND).

  • When GET /v3/network/status answers HTTP 500, as the Qumulo Core container does, a judged write that leaves two or more tenants is refused unless management_network is given (G-NET-APPLY).

Examples

# These tasks carry no connection options, except where a task sets api_port. Set them once for the play with
# module_defaults for group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
# A tenant holds no network until network_config gives it one, and a switch left unset is off on a new tenant. Every
# create removes the static routes of every node, and the first create of a second tenant also rebinds every listener on
# every node and ends NFS and replication connections; the module warns of it in the run and in a check run, so run it
# in check mode first. That create is refused while a tenant holds a backend-bond network: unbind the network first with
# a tenant PATCH of networks that leaves it out (qq multitenancy_modify_tenant --network-id), not with
# qq network_mod_network --clear-tenant-id, which puts it back in the only tenant.
- name: Create the finance tenant with NFS only
  qumulo.cluster.tenant:
    name: finance
    nfs_enabled: true

# The preview shows the tenant before and after. Check mode sends nothing, so it reports the same change until a real run
# makes it.
- name: Preview turning on SMB and SSH for the finance tenant
  qumulo.cluster.tenant:
    name: finance
    smb_enabled: true
    ssh_enabled: true
  check_mode: true
  diff: true
  register: tenant_preview

- name: Show the switches the finance tenant would have
  ansible.builtin.debug:
    var: tenant_preview.tenant

# The switches the task does not set stay as they are. A second run reports no change.
- name: Turn SMB on for the finance tenant
  qumulo.cluster.tenant:
    name: finance
    smb_enabled: true

# A run after the rename finds eng and renames nothing. When a tenant named eng already exists, the task manages eng and
# leaves engineering as it is; when neither exists, it creates eng.
- name: Rename the engineering tenant to eng
  qumulo.cluster.tenant:
    name: eng
    previous_name: engineering

# With two or more tenants, REST must stay on for a tenant that holds the network this play connects on; the module
# refuses a write that would cut the play off. Behind NAT or a load balancer it cannot see which network that is, so
# name it. Network 1 here is the network api_host is forwarded to.
- name: Create the analytics tenant from a play that reaches the cluster behind NAT
  qumulo.cluster.tenant:
    name: analytics
    rest_api_enabled: true
    ssh_enabled: true
    management_network: [1]

# The play connects to a tunnel's port 18000, which forwards to the cluster's web UI port 443. With cluster_port: 443,
# REST enabled means web_ui_enabled, so this change of rest_api_enabled passes while the tenant that holds network 2,
# the network the tunnel reaches, has web_ui_enabled on. Without cluster_port the module takes 18000 as the cluster's
# port, judges rest_api_enabled, and refuses the write if finance holds network 2.
- name: Turn off REST for the finance tenant, from a play on a tunnel to the web UI port
  qumulo.cluster.tenant:
    name: finance
    rest_api_enabled: false
    api_port: 18000
    cluster_port: 443
    management_network: [2]

# The delete is refused while the tenant holds a network, an SMB share or an NFS export, and for the last tenant.
# Move its networks to another tenant with network_config, and delete its shares and exports, first.
# The delete that leaves one tenant rebinds every listener on every node and ends NFS and replication connections, and
# the module warns of it.
# A second run reports no change.
- name: Delete the finance tenant
  qumulo.cluster.tenant:
    name: finance
    state: absent
  register: finance_removed

- name: Show the overrides the delete removed with the finance tenant
  ansible.builtin.debug:
    var: finance_removed.removed_overrides
  when: finance_removed.removed_overrides is defined
