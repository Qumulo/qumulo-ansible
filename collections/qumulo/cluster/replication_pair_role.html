qumulo.cluster.replication_pair role – Declare a replication relationship between two clusters, or remove it, refusing before any write

Note

This role is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_pair.

Entry point main – Declare a replication relationship between two clusters, or remove it, refusing before any write

New in qumulo.cluster 0.1.0

Synopsis

  • Reaches both clusters from one host, with one set of connection options for each, so it runs once per relationship. Each set is what module_defaults for group/qumulo.cluster.qumulo takes, and names its cluster’s UUID in expected_cluster_uuid. The relationship is identified by the two paths and the target’s UUID, never by a server id or the address.

  • It asserts its own inputs only. The inventory’s rules, such as a target path declared on the target host, are the cluster_baseline role’s step 21, which calls this role for each relationship a source host declares.

  • With state=present in replication_pair_relationship: 1. runs qumulo.cluster.replication_relationship on the source and qumulo.cluster.replication_target on the target in check mode, with the options their real passes take, the target check always, with source_creates when the source predicts a create; 2. joins both with qumulo.cluster.replication_pair_plan, and fails, before any write on either cluster, when a condition is unmet and not lifted, or a release entry lifts nothing in this run, reporting every unmet condition of both sides at once and the release entries that would lift the releasable ones; 3. for a target edge whose capacity the inventory declares, when a create or an authorize is due, defers the relationship unless the edge holds an active license or declares qumulo_capacity.license=none, and its declared clamp applies (the capacity gate); 4. creates the target directory’s declared ancestors, then the target directory, path only, with qumulo.cluster.directory; 5. creates the relationship on the source, or PATCHes its settings, replacing a changed peer create-first; 6. authorizes it on the target and waits until both sides are ESTABLISHED.

  • A relationship in a failover state, after a make-writable by hand, is left as it is; its settings are still PATCHed, the wait is skipped, and both modules warn.

  • While deferring, the role only deletes the source’s records of the target’s previous UUIDs that cannot be replicating to an old edge kept beside the new one, and its hand-off, from either half of the gate, names ansible-playbook qumulo.cluster.edge_license_complete. A deferral does not fail; the hand-off is in replication_pair_result, and step 21 of the cluster_baseline role prints each one after its loop.

  • With state=absent, deletes on the source, then on the target, keeping the target directory and its data, and reports the snapshots left. A release bound to a holder of the target path deletes it.

  • Never prints either side’s connection options.

  • Under --check, predicts each side’s change and waits for nothing.

  • Sets the fact replication_pair_result, with status paired, failover, deferred, held or removed, and what goes with it, such as hand_off for deferred and message, releases, holders, key and restore_form, whether the message names the restore, for held. key is the relationship’s source_path, target_host, target_cluster_uuid and target_path, the paths without their trailing slash and the UUID in lower case.

Entry point restore – Restore a rebuilt edge’s relationships from their replicas

New in qumulo.cluster 0.1.0

Synopsis

  • Runs from the edge’s host context, as tasks_from=restore.yml, for each present relationship out of the edge whose old record on the target, from one of the edge’s qumulo_previous_cluster_uuids, still holds the replica. It syncs the replica back into the edge’s source directory, turns the relationship around, and reconnects it, so that it runs from the edge’s current UUID, with its declared settings.

  • qumulo.cluster.replication_restore_step decides which relationships the run picks and, before every step, the step that runs next, from fresh reads of both clusters; the role runs only its answer. Phase 1 takes each picked relationship in turn up to the full sync’s wait, before the next one’s first step; phase 2 waits for the syncs together, in rounds, and finishes each one as it lands.

  • In a real run it holds the edge’s lock, <artifact dir>/<edge>/restore/lock, with qumulo.cluster.replication_restore_lock, so one restore runs per edge at a time on a controller, and removes it however the run ends. Check mode takes no lock, changes nothing, and reports each relationship’s predicted steps.

  • Sets the fact replication_pair_restore_outcomes, one entry per relationship with name, outcome, such as restored, done, refused, stopped, not restored, not applicable or failed, fails, whether the outcome fails the run, message, summary, note, in check mode sequence, and for a restored one snapshots_left, the replication snapshots the restore left on the target, each with host and id. A failure inside one relationship is its failed outcome, and the others go on; any other failure, such as a lock another run holds, fails the task, and the fact keeps the outcomes decided before it.

  • playbooks/replication_restore.yml and the second pass, playbooks/edge_license_complete.yml, run it.

  • Its messages and the timeouts below name the old record that holds the replica, X, the restore relationship, R, and the restore’s nine steps by number, which the Replication restore section of docs/reference/playbooks-and-roles.md lists.

Parameters

Parameter

Comments

qumulo_replication_restore

list / elements=string

The relationships to restore, each <target host>:<target path> of a present relationship out of the edge, compared without the target path’s trailing slash. Pass it with -e for one run. Without it, the restore picks every present relationship. A named relationship that is not applicable is refused.

replication_pair_artifact_dir

path

Where the restore’s files go, the restore record, the restore stamp and the lock, under <directory>/<edge>/restore/, with mode 0700 for directories and 0600 for files. replication_pair_connections

dictionary / required

The connection options of the edge and of each target host of its relationships, by inventory host, as the cluster_baseline role’s connections.yml records them in cluster_baseline_connections.

replication_pair_wait_timeout

integer

Seconds step 3’s authorize may wait until R is ESTABLISHED on the edge.

Default: 600

replication_restore_entry_point

string / required

Which entry point runs the restore, named in each way on. playbook, playbooks/replication_restore.yml, refuses its whole run before any relationship on a release, an edge with no previous UUIDs, a name that matches no present relationship, or a nested group. second_pass reports them per relationship, and fails on a stranded pair only while the relationship has a restore to do.

Choices:

  • "second_pass"

replication_restore_poll_delay

integer

Seconds between phase 2’s reads of the edge’s target list, one read for every relationship that waits.

Default: 30

replication_restore_reconnect_timeout

integer

Seconds step 8’s two polls take together, after the reconnect, until R reads ESTABLISHED on both clusters. A timeout leaves the restore record marked, so the next run only polls.

Default: 1800

replication_restore_report_claims

dictionary

The edge’s rebuild report claim the second pass read, with report, claimed and stamped. Without it, the restore reads the edge’s newest rebuild report under replication_pair_artifact_dir.

replication_restore_resume_window

integer

Seconds after its write time within which an unmarked restore record still resumes step 8, the reconnect.

replication_restore_reverse_timeout

integer

Seconds step 5 polls, after the make-writable, until R reads DISCONNECTED on the edge.

replication_restore_targets

dictionary

The target read the second pass took, by target host, each with target_relationships or error. Without it, the restore reads each target host itself.

replication_restore_wait_timeout

integer

Seconds step 4 waits for R’s first recovery point, the full sync of the replica, from the end of the relationship’s step 3 in this run, or from the end of phase 1 for one resumed at step 4. A full sync of a large replica takes hours. A run killed before the wait ends leaves the lock.
