qumulo.cluster.policy_lock_keys filter – What the cluster_baseline role applies of the snapshot policies, given the key store

Note

This filter plugin is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.policy_lock_keys.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Input

  • Keyword parameters

  • Examples

  • Return Value

Synopsis

  • A policy entry of qumulo_snapshot_policies may declare lock_key, a key in the cluster’s file system key store, which a rebuilt or cloned cluster does not hold until it is registered again with qumulo.cluster.security_key.

  • When every declared key is in the store, by name or id, the filter gives the entries unchanged.

  • Otherwise, without allow_deferred, it gives a refusal naming each policy, its key and the two remedies.

  • With allow_deferred, it gives the entries with lock_key left out of each policy whose key is missing, so the policy keeps whatever key it holds, and a hand_offs line for each.

  • An entry with state absent sets no key and is not checked.

Input

This describes the input of the filter, the value before | qumulo.cluster.policy_lock_keys.

Parameter

Comments

Input

list / elements=dictionary / required

The entries of qumulo_snapshot_policies, or null or an empty list when it is unset.

Keyword parameters

This describes keyword parameters of the filter. These are the values key1=value1, key2=value2 and so on in the following example: input | qumulo.cluster.policy_lock_keys(key1=value1, key2=value2, ...)

Parameter

Comments

allow_deferred

boolean

Apply each policy whose key is missing without its lock_key and hand it off, in place of refusing.

As qumulo_allow_deferred_policy_lock_keys gives it, an Ansible boolean; the filter refuses any other value.

Choices:

  • false ← (default)

  • true

keys

list / elements=dictionary / required

The keys, as qumulo.cluster.snapshot_info returns them in snapshots.security_keys, or null when the key store could not be read.

unreadable

string

Why the key store could not be read, as unavailable_subsets gives it, for the refusal.

Default: ""

Examples

# The read task carries no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Read the cluster's key store
  qumulo.cluster.snapshot_info:
    gather_subset: [security_keys]
  register: key_facts

- name: Plan the snapshot policies against the key store
  ansible.builtin.set_fact:
    plan: >-
      {{ qumulo_snapshot_policies | default([])
         | qumulo.cluster.policy_lock_keys(key_facts.snapshots.security_keys | default(none),
                                           qumulo_allow_deferred_policy_lock_keys | default(false),
                                           key_facts.unavailable_subsets.security_keys | default('')) }}

Return Value

Key

Description

Return value

dictionary

The plan.

Returned: always

hand_offs

list / elements=string

A line for each deferred policy, naming the key to register.

Returned: success

policies

list / elements=dictionary

The entries to apply, with lock_key left out of each policy whose key is deferred.

Returned: success

refusal

string

Why step 2 refuses, or an empty string.

Returned: success
