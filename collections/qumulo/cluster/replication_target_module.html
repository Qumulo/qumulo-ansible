qumulo.cluster.replication_target module – Authorize a replication relationship on its target cluster, or delete the target’s records of it

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_target.

Synopsis

  • Runs on the target cluster. The source’s create registers a relationship here, awaiting authorization; this module authorizes it, which makes the target directory read-only and lets the source’s content replace the directory’s. The replication roles pair both sides.

  • The relationship is identified by source_cluster_uuid, source_path and target_path, never by a server id alone. Paths compare without a trailing slash, and UUIDs without regard to case.

  • With relationship_id, the id the source’s create returned, the module reads that record before anything else, apart from the check of replication_address when that is set. An ESTABLISHED record, or one in a failover state, returns at once without listing the target’s relationships or looking at the directory.

  • Before an authorize, the module evaluates the rows of the overwrite table that fall to the target, and refuses before any write while any of them is unmet and not lifted. Every unmet row is reported at once in unmet, in this order. O7, a live relationship at a path that contains the target path or lies inside it. O9, this cluster replicating to the declared source at a path equal to or nested with the target path, a reversal. O2, a live record of another key at the target path, a holder. O6, a live record of the key that the source does not hold. O5, an ENDED record at the target path over a directory that holds files. O4, an empty source over a target directory that holds files. O1, a target directory that holds any entry.

  • A release, one release entry bound to a record’s id and naming rows, lifts only those rows of that record. O1 is lifted only by allow_non_empty_directory, or by allow_directories_only for a directory holding only directories; O6, O7 and O9 by nothing.

  • Emptiness is decided from the directory’s entries, never from its aggregates. Row O1 counts every entry, a subdirectory included. Rows O4 and O5 count only files, links and other objects at any depth.

  • Before the authorize, the real run deletes the records a release lifted, and prunes stale records of the key that hold nothing, pending ones, and ENDED ones over a directory that holds no file.

  • With state=absent, deletes every record of the key in any state, the ENDED and pending records of previous_source_cluster_uuids at the same paths, and a live holder at the target path only with a release bound to it. The target directory keeps its data, and becomes writable once no record holds it.

Parameters

Comments

allow_directories_only

boolean

For the restore of a rebuilt source from its replica. Let the source’s content replace a target directory that holds only directories, at any depth, and refuse one that holds a file, link or other object at any depth, as row O1 refuses it. The module then sends the server’s allow-non-empty-directory, and only while the directory holds entries.

The walk that decides it is the one the module takes right before every authorize, and the only one, so a file written between the walk and the authorize goes unseen. The O1 entry reports holds_objects, and the first object found as first_object.

It cannot be given with allow_non_empty_directory, which allows files too.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

planned_tenant_writes

list / elements=dictionary

The tenant writes that the target host’s own run of the qumulo.cluster.cluster_baseline role makes earlier in the play, its steps 3a and 3b, as qumulo.cluster.tenant items with name, previous_name on a rename, and the switches each sets. The qumulo.cluster.replication_pair role passes them in check mode when the target host is in the play; this option is not for direct use.

Read only in check mode, by the check of replication_address. It takes a tenant’s replication_enabled from the item that sets it, since the real run reads the tenants after those writes. An item names the tenant by its name on the cluster in previous_name on a rename, and in name otherwise.

The networks are still read as they are, so a check run that also moves the address’s network to another tenant judges the network’s tenant before the move.

Default: []

previous_source_cluster_uuids

list / elements=string

UUIDs the source cluster had before a rebuild. With state=absent, the ENDED and pending records of these UUIDs at the same paths are deleted too, since they hold nothing. A holder of one of them is reported with from_previous_source.

It must not hold source_cluster_uuid.

Default: []

relationship_id

string

The id the source’s create returned, or the id of the source’s existing record. The module authorizes only this record, and fails when this cluster does not hold it.

Give this or source_creates with state=present.

release

list / elements=string

Release entries for this relationship, each <target host>:<target path>@<record id>:<rows>. An entry lifts only the rows it names, and only while the record with its id exists.

With state=absent, an entry bound to a live holder at the target path and naming O2 deletes the holder.

An entry for another target path fails.

Default: []

replication_address

string

The IP address the source connects to, which is the target host’s qumulo_replication_address. The qumulo.cluster.replication_pair role passes it, as its replication_pair_target_address; this option is not for direct use. A value that is not an IP address fails the module.

With state=present the module checks, before it reads the record and before any write, that the tenant serving the address has replication_enabled. It reads the tenant list, which needs PRIVILEGE_TENANT_READ. With two or more tenants it also reads the network document, which needs PRIVILEGE_NETWORK_READ, and takes the tenant that holds the network whose ranges hold the address; with one tenant, that tenant. It refuses when that tenant has replication_enabled false. The message names the tenant and says to set replication_enabled true on it; with two or more tenants it also names the network, and offers moving the address to a network of a tenant that has it on.

The check runs on every run, so a relationship that is already ESTABLISHED, into a tenant with replication off, is refused each time, until replication is turned on for that tenant or the address moves to a network of a tenant that has it on.

With two or more tenants, an address that no network’s ranges hold, such as a HOST network’s host address, a DHCP network’s node address or an address behind NAT, and a network that no tenant holds, are not checked, and the module warns. With state=absent, or unset, the module reads nothing for it and checks nothing.

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Evaluates the overwrite table as the real run does, and fails on the same unmet rows and the same refusal of replication_address, with a tenant’s switch as planned_tenant_writes leaves it. With source_creates it predicts the authorize of a relationship the source has not created yet.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

The diff’s before and after each hold relationship, in the shape of relationship, and records, the records the task deletes, or in check mode would delete. After’s records is always empty.

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

An authorize cannot be resent; the module authorizes only a record awaiting authorization, and reconciles a lost answer by reading the record (G-REPL-ONESHOT).

Authorizing into a directory that holds entries replaces its content (G-REPL-OVERWRITE).

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v2/replication/target-relationships/status/, GET /v2/replication/target-relationships/{id}/status, POST /v2/replication/target-relationships/{id}/authorize, POST /v2/replication/target-relationships/{id}/delete, GET /v2/replication/source-relationships/status/, GET /v1/files/{ref}/info/attributes, GET /v1/files/{ref}/entries/, GET /v1/files/{ref}/aggregates/, GET /v4/snapshots/status/; for source_bytes, GET /v1/file-system and, on a portal spoke, GET /v1/portal/spokes/eviction-settings; for replication_address, GET /v1/multitenancy/tenants/, which needs PRIVILEGE_TENANT_READ, and, with two or more tenants, GET /v3/network, which needs PRIVILEGE_NETWORK_READ.

  • replication_address is checked through the multitenancy REST API, which Qumulo marks as preview; a later Qumulo Core release may change it.

  • Idempotency gaps G-REPL-ONESHOT and G-REPL-OVERWRITE apply. A rebuilt source’s old record holds the replica until a release (G-REPL-PEER). The source tells the target of a delete only once, so a removal deletes on the source and then here (G-REPL-NOTIFY). A deleted record leaves its recovery-point snapshot, owned by nothing, which the result names (G-REPL-SNAPSHOT).

  • On the same path, the server reports a non-empty directory before another relationship’s hold (QUIRK-021). The module looks for holders first, so it reports the holder.

  • The capacity comparison is approximate. Whether free_size_bytes leaves out a spoke’s evictable cache is inferred, not observed.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Preview the authorize before the source creates the relationship
  # Run against the target cluster. directory_pending counts a target directory that an earlier task creates.
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    source_creates: true
    directory_pending: true
  check_mode: true
  diff: true
  register: preview

- name: Show what would keep the relationship from being authorized
  ansible.builtin.debug:
    msg: "{{ preview.unmet | default([]) | map(attribute='message') | list }}"

- name: Create the target directory before the authorize
  qumulo.cluster.directory:
    path: /replicas/edge01-projects

- name: Authorize the relationship the source created, and wait until it is ESTABLISHED
  # created is the register of the source's qumulo.cluster.replication_relationship task.
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    relationship_id: "{{ created.relationship.id }}"
    source_empty: "{{ created.source_empty }}"
    source_files: "{{ created.source_files }}"
    source_bytes: "{{ created.source_bytes }}"

- name: Preview the authorize of the relationship the source created
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    relationship_id: "{{ created.relationship.id }}"
    source_empty: "{{ created.source_empty }}"
  check_mode: true
  diff: true

- name: Authorize without waiting for the first job to reach ESTABLISHED
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    relationship_id: "{{ created.relationship.id }}"
    source_empty: "{{ created.source_empty }}"
    wait: false

- name: Authorize, refusing rather than warning when the source looks larger than the space this cluster can reuse
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    relationship_id: "{{ created.relationship.id }}"
    source_empty: "{{ created.source_empty }}"
    source_bytes: "{{ created.source_bytes }}"
    strict_capacity: true

- name: Authorize into a directory that already holds a copy, letting the source's content replace it
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge02'].qumulo_cluster_uuid }}"
    source_path: /data
    target_path: /replicas/edge02-data
    relationship_id: "{{ edge02_relationship_id }}"
    source_empty: false
    allow_non_empty_directory: true

- name: Authorize into a directory that holds only directories, refusing one that holds a file
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge02'].qumulo_cluster_uuid }}"
    source_path: /data
    target_path: /replicas/edge02-data
    relationship_id: "{{ edge02_relationship_id }}"
    source_empty: false
    allow_directories_only: true

- name: After a copy back into the rebuilt source, release its old relationship and authorize the new one
  # Pass the release with -e for this run only, never in the inventory; the refusal printed it with the holder's id and
  # its rows. The module refuses entries for other target paths, so pass only this relationship's.
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    relationship_id: "{{ created.relationship.id }}"
    source_empty: false
    allow_non_empty_directory: true
    release: >-
      {{ qumulo_replication_release | default([])
         | select('match', inventory_hostname ~ ':/replicas/edge01-projects/?@') | list }}

- name: Remove the relationship on the target after the source's delete, keeping the directory and its data
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    previous_source_cluster_uuids: "{{ hostvars['edge01'].qumulo_previous_cluster_uuids | default([]) }}"
    state: absent
  register: removed

- name: Show the snapshots the removal left
  ansible.builtin.debug:
    msg: "{{ removed.snapshots | map(attribute='name') | list }}"

- name: Remove a relationship whose source cluster is gone for good
  qumulo.cluster.replication_target:
    source_cluster_uuid: 4b3c802f-8201-42b7-bb41-28f562cd8dfd
    source_path: /projects
    target_path: /replicas/old-edge-projects
    state: absent

- name: Remove the relationship from edge01 on the target, and the old relationship that holds its directory, with the release its refusal printed
  # The holder is a live record of another key at the target path, so the delete needs a release bound to its id that
  # names O2. The key's own records go too, whatever their state.
  qumulo.cluster.replication_target:
    source_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    source_path: /projects
    target_path: /replicas/edge01-projects
    release: >-
      {{ qumulo_replication_release | default([])
         | select('match', inventory_hostname ~ ':/replicas/edge01-projects/?@') | list }}
    state: absent

replaces

The target directory’s count of files, links and other objects that an authorize replaces, from its aggregates; null when the module did not evaluate the overwrite table, as with state=absent.

Returned: always, and on a refusal before any write

snapshots

list / elements=dictionary

The snapshots the records the task deleted owned, and the replication snapshots owned by nothing at the target path, each with id and name. A record’s snapshot can lose its owner at the source’s delete, before this task, so the ownerless ones count; an earlier removal at the same path may have left some of them. None expires. Empty when the task deleted nothing.

Returned: always

integer

The snapshot’s id.

Returned: success

The snapshot’s name.

Returned: success

Every condition that keeps the authorize from going ahead, lifted or not, in the reporting order. Empty when the record needed no authorize, and with state=absent. A run that fails on one still returns the list.

Returned: always
