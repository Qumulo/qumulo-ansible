qumulo.cluster.ftp_info module – Read a Qumulo cluster’s FTP settings and each node’s FTP server status

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.ftp_info.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

  • Examples

  • Return Values

Synopsis

  • Gathers the FTP configuration of one cluster and whether each node’s FTP server runs, and changes nothing.

  • The settings come back in the option shape of qumulo.cluster.ftp_settings. An anonymous user whose local user was deleted reads local:, as that module returns it.

  • The cluster has one FTP server, which answers on every network, so the module has no tenant option.

Parameters

Parameter

Comments

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

gather_subset

list / elements=string

The subsets of facts to gather. all gathers every subset.

Choices:

  • "all" ← (default)

  • "settings"

  • "status"

Default: ["all"]

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

Notes

Note

  • API: settings GET /v0/ftp/settings; status GET /v0/ftp/status.

Examples

# These tasks take api_host and a credential from module_defaults for group/qumulo.cluster.qumulo.
- name: Read the cluster's FTP settings and status
  qumulo.cluster.ftp_info:
  register: ftp

- name: Check that the FTP server runs on every node
  # Run it after turning the server on with qumulo.cluster.ftp_settings.
  qumulo.cluster.ftp_info:
    gather_subset: [status]
  register: ftp_status
  failed_when: ftp_status.ftp.status | rejectattr('status', 'equalto', 'running') | list | length > 0

- name: Read who anonymous logins act as
  qumulo.cluster.ftp_info:
    gather_subset: [settings]
  register: ftp_settings_read

- name: Print the anonymous user
  ansible.builtin.debug:
    msg: "{{ ftp_settings_read.ftp.settings.anonymous_user or 'none' }}"

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

ftp

dictionary

The gathered facts. Each key is present only when its subset was gathered.

Returned: always

Sample: {"settings": {"allow_unencrypted_connections": true, "anonymous_user": "", "check_remote_host": true, "chroot_users": false, "enabled": true, "expand_wildcards": false, "greeting": "Authorized use only.\n", "log_operations": true}, "status": [{"node_id": 1, "status": "running"}]}

settings

dictionary

The FTP settings, in the option shape of qumulo.cluster.ftp_settings.

Returned: success

allow_unencrypted_connections

boolean

Whether the cluster accepts connections that are not encrypted.

Returned: success

anonymous_user

string

The local user anonymous logins act as, as local:<name> in the cluster’s spelling, "" for none, and local: for a user since deleted. Any other identity type, which the cluster refuses to store, reads as <id_type in lower case>:<id_value>, such as local_group:Users.

Returned: success

check_remote_host

boolean

Whether all the connections of a session must come from the same host.

Returned: success

chroot_users

boolean

Whether the cluster confines FTP users with chroot.

Returned: success

enabled

boolean

Whether the cluster allows FTP connections.

Returned: success

expand_wildcards

boolean

Whether LIST and NLST expand wildcards.

Returned: success

greeting

string

The text sent with the 220 reply to a new connection.

Returned: success

log_operations

boolean

Whether the cluster logs FTP operations.

Returned: success

status

list / elements=dictionary

Each node’s FTP server, in the order the cluster lists the nodes.

Returned: success

node_id

integer

The node’s id.

Returned: success

status

string

The node’s FTP server state as the cluster names it, such as running or stopped.

Returned: success

unavailable_subsets

dictionary

Each requested subset this cluster could not answer, with the reason.

Returned: when a subset was unavailable

Sample: {"status": "GET /v0/ftp/status failed: HTTP 404 ..."}
