qumulo.cluster.replication_reverse module – Make a replication target writable, reverse a relationship, or reconnect it, by its id

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.replication_reverse.

New in qumulo.cluster 0.1.0

Synopsis

  • Sends one failover verb for the replication relationship relationship_id, on the cluster the verb goes to.

  • make_writable, on the relationship’s target, from ESTABLISHED with a recovery point. The target directory goes back to the recovery point and becomes writable, and the relationship goes DISCONNECTED on both sides.

  • reverse, on the current target, from DISCONNECTED. This cluster’s target record becomes a source record of the same id, to the current source at source_address and source_port, and the current source’s record becomes a target record. Both stay DISCONNECTED. This cluster’s directory stays writable from the make-writable. The current source’s directory keeps its read-only state: it stays read-only after the reverse while another relationship’s record holds it, until that record’s delete, and when source_root_read_only made it read-only.

  • reconnect, on the relationship’s target, from DISCONNECTED; after a reverse, that is the old source. The target directory goes back to the recovery point and becomes read-only again, and the relationship goes RECONNECTING, then ESTABLISHED once the source reaches this cluster.

  • The module reads the record first and sends the verb only from that state. A record already in the state the verb leaves is reported unchanged, and any other state is refused before any write.

  • It never waits. It reads the record once after the verb and returns it.

  • A verb whose answer is lost is reconciled by reading the record, and never sent again. When the record shows no sign of it, the module fails with maybe_applied set, and the next run reads the record and decides. A refusal from the server, or from the module, fails with nothing changed.

  • A lost answer to the comparison’s snapshot, which a reconnect without allow_data_loss takes first, fails with changed true and without maybe_applied. Only that snapshot may exist, and it expires a day after it was taken. Nothing was sent to the relationship, so the next run compares and reconnects.

Parameters

Parameter

Comments

allow_data_loss

boolean

Let make_writable or reconnect send the target directory back to the relationship’s recovery point, which discards whatever was written there after it.

make_writable fails without it, before any request.

reconnect without it first compares the target directory with the recovery point’s snapshot, through a snapshot of the directory that the module deletes once it has compared, and sends the reconnect only when nothing changed since. The snapshot is set to expire a day after the controller’s clock time, should the module stop before it deletes it.

A reconnect without it that finds changes fails with nothing changed, naming their count and the first ten, and returns all of them, up to 1000, in changes and their count in change_count. It also fails, with no change returned, when the record names no recovery point snapshot of the target directory. With allow_data_loss the reconnect is sent without comparing.

reverse takes no consent, since it moves the records and changes no data.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

relationship_id

string / required

The id of the relationship, which both sides share, and a reverse keeps.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

source_address

string

For reverse, the IP address at which this cluster reaches the current source. It becomes the target address of the new source record.

Required with verb=reverse.

source_port

integer

For reverse, the current source’s replication port.

Default: 3712

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

verb

string / required

The verb to send.

Choices:

  • "make_writable"

  • "reverse"

  • "reconnect"

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

Reads the record, refuses what the real run refuses, and returns the record the verb is predicted to leave.

A reconnect without allow_data_loss takes no snapshot, so check mode cannot compare; it notes that the real run compares.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

No verb can be resent, so each is sent only from its own state; a record already in the state the verb leaves reports no change, and a lost answer is reconciled by reading (G-REPL-ONESHOT).

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v2/replication/target-relationships/{id}/status, GET /v2/replication/source-relationships/{id}/status, POST /v2/replication/target-relationships/{id}/make-writable, POST /v2/replication/source-relationships/reverse-target-relationship, POST /v2/replication/target-relationships/{id}/reconnect; the reconnect’s comparison: GET /v2/replication/target-relationships/{id}/status for the raw record, POST /v3/snapshots/, GET /v2/snapshots/{newer_id}/changes-since/{older_id}, DELETE /v3/snapshots/{id}.

  • The verbs are one-shot, so the module reconciles a lost answer by reading the record (G-REPL-ONESHOT).

  • The reconnect’s comparison creates a snapshot of the target directory and deletes it, and reads the changes between two snapshots, so the user needs rights to create and delete snapshots and to read their differences.

  • A make-writable and a reverse leave replication snapshots owned by nothing, which never expire and which qumulo.cluster.snapshot_info lists (G-REPL-SNAPSHOT).

  • A reverse carries the id, the paths, the address and replication_enabled; the blackout windows, their timezone, map_local_ids_to_nfs_ids and source_root_read_only come back at their defaults.

  • reconnect is refused with HTTP 409 relationship_manager_target_contains_another_relationship_error while another record still holds this cluster’s directory.

  • An already reversed relationship is recognised by this cluster’s source record of the id going to source_address and source_port; a source record to another address is the current source, and refused.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Preview the make-writable, with the record before and the record it would leave
  # Run against the cluster that holds the relationship's target record.
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: make_writable
    allow_data_loss: true
  check_mode: true
  diff: true

- name: Make the edge's copy writable, discarding writes after the recovery point
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: make_writable
    allow_data_loss: true

- name: Wait until the edge's record reads DISCONNECTED
  # The module never waits, so poll the record the verb leaves.
  qumulo.cluster.replication_info:
    relationship_id: "{{ restore_id }}"
    side: target
  register: edge_record
  until: edge_record.replication.relationship.state | default('') == 'DISCONNECTED'
  retries: 60
  delay: 5

- name: Preview the reverse toward the hub's replication address
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: reverse
    source_address: "{{ hostvars['hub01'].qumulo_replication_address }}"
    source_port: "{{ hostvars['hub01'].qumulo_replication_port | default(3712) }}"
  check_mode: true
  diff: true

- name: Reverse the relationship on the edge, toward the hub's replication address
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: reverse
    source_address: "{{ hostvars['hub01'].qumulo_replication_address }}"
    source_port: "{{ hostvars['hub01'].qumulo_replication_port | default(3712) }}"

- name: Preview the reconnect that reverts the hub's directory to the recovery point
  # Run against the hub, the new target, after the record that held its directory is deleted.
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: reconnect
    allow_data_loss: true
  check_mode: true
  diff: true

- name: Reconnect, which reverts the hub's directory to the recovery point
  # Run against the hub, the new target, after the record that held its directory is deleted.
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: reconnect
    allow_data_loss: true

- name: Reconnect the edge only when nothing was written in its directory after the recovery point
  # Run against the edge, the target after a reverse on the hub. Without allow_data_loss the module compares the
  # directory with the recovery point's snapshot first, and fails, naming the changes, when it would discard any.
  qumulo.cluster.replication_reverse:
    relationship_id: "{{ restore_id }}"
    verb: reconnect

- name: Wait until the hub's record reads ESTABLISHED
  # Run against the hub, the relationship's target after the reverse.
  qumulo.cluster.replication_info:
    relationship_id: "{{ restore_id }}"
    side: target
  register: hub_record
  until: hub_record.replication.relationship.state | default('') == 'ESTABLISHED'
  retries: 60
  delay: 5

- name: Apply the declared blackout windows to the relationship the reverse returned to its defaults
  # Run against the edge, which holds the relationship's source record again.
  qumulo.cluster.replication_relationship:
    source_path: /projects
    target_cluster_uuid: "{{ hostvars['hub01'].qumulo_cluster_uuid }}"
    target_path: /replicas/edge01-projects
    target_address: "{{ hostvars['hub01'].qumulo_replication_address }}"
    blackout_windows:
      - {start_hour: 8, start_minute: 0, end_hour: 18, end_minute: 0, on_days: [MON, TUE, WED, THU, FRI]}
    blackout_window_timezone: America/Los_Angeles

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

change_count

integer

How many changes the target directory holds since the recovery point. null when there are more than 1000, which changes then lists the first 1000 of.

Returned: when a reconnect without allow_data_loss is refused because the target directory changed

Sample: 3

changes

list / elements=dictionary

Each change in the target directory since the recovery point, with op and path, as the snapshot comparison lists it.

Returned: when a reconnect without allow_data_loss is refused because the target directory changed

Sample: [{"op": "MODIFY", "path": "/projects/plan.txt"}]

maybe_applied

boolean

True when a verb was sent and the module could not confirm it, so the next run reads the record and decides. The module never resends it. A lost answer to the comparison’s snapshot does not set it, since no verb was sent.

Returned: on a failure after a lost answer

notes

list / elements=string

What the module noticed, such as a verb found already done, or a lost answer reconciled.

Returned: when there is something to note

relationship

dictionary

This cluster’s record of the relationship after the verb, read once, in the shape qumulo.cluster.replication_info reports both sides in. After reverse it is the new source record; after the other verbs, the target record, whose address and settings are null.

It may still read the state before the verb’s, since the server moves on by itself; the module does not wait.

In check mode, the record the verb is predicted to leave.

Returned: always
