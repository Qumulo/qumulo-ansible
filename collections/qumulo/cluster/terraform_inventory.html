qumulo.cluster.terraform inventory – Qumulo clusters from a Terraform root’s qumulo_ansible_inventory output

Note

This inventory plugin is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.terraform.

New in qumulo.cluster 0.1.0

Synopsis

  • Adds one host for each entry of the qumulo_ansible_inventory output of a Terraform root, with the variables the collection’s playbooks and roles read.

  • The inventory source is a YAML file whose name ends in qumulo_terraform.yml or qumulo_terraform.yaml.

  • The output maps each host name to api_host, cluster_uuid, cluster_kind (edge, cnq or baremetal), managed_by (none, terraform_provider or legacy_provisioner), owned_areas and password_ref. docs/reference/terraform-inventory.md lists the fields and the Terraform resources that fill them, and docs/how-to/terraform.md shows how to publish the output.

  • Each host gets qumulo_api_host, qumulo_cluster_uuid, qumulo_cluster_kind, qumulo_managed_by, qumulo_terraform_owned_areas and, unless the entry’s password_ref is null, qumulo_password_ref.

  • Each host joins a group for its kind, qumulo_edges, qumulo_cnq or qumulo_baremetal, and one for who formed it, qumulo_managed_by_none, qumulo_managed_by_terraform_provider or qumulo_managed_by_legacy_provisioner. All of these are children of qumulo_clusters.

  • api_host is a host name or an IP address. The modules build https://<api_host>:<api_port> themselves, so a URL, such as the endpoint the provider’s qumulo_filesystem_edge_baremetal resource exports, is refused, and so is a value with a user name in it, such as admin@10.20.0.5.

  • An IPv6 api_host is given bare, as fd00::5. A bracketed address is refused, and so is a zone id such as fe80::1%eth0.

  • owned_areas is a list of area names, such as network.floating_ips or dns. For a cnq cluster with managed_by set to terraform_provider it must list network.floating_ips.

  • password_ref is null, or a map of type, one of env, aws_ssm_parameter, aws_secrets_manager, azure_key_vault, gcp_secret_manager or hashicorp_vault, and id, a non-empty string. The output never carries the password. group_vars resolve the reference into qumulo_api_password with a lookup.

  • An entry may also give portal_hosts, the IP addresses the other side of a portal reaches the cluster at, and replication_address, the IP address a replication source reaches it at, which the replication step of the qumulo.cluster.cluster_baseline role gives the source. The host gets qumulo_portal_hosts, a list of address items on the default portal port, and qumulo_replication_address, each address in its canonical form. Null, or no field, sets neither unless load_balancer_name fills it, and host_vars outrank both.

  • The plugin publishes the addresses the output gives, or those of a load_balancer_name below, and derives none from the cluster. Each is an IP address without a host name, a port, brackets or a zone id; a URL, an unspecified, loopback or multicast address, an empty list and an address given twice are refused.

  • An entry may instead give load_balancer_name, the fully qualified DNS name of the load balancer in front of a multi-AZ cluster in AWS. The plugin resolves it on the controller each time it reads the output, a cached read included, and sets qumulo_portal_hosts to its IPv4 and IPv6 addresses, in canonical form, without repeats and sorted, IPv4 before IPv6, and qumulo_replication_address to the first, wherever the entry’s portal_hosts or replication_address is null. Addresses the entry gives win. The name itself is never published as an address. A name that resolves to no address, or to a loopback, unspecified, multicast or zoned one, fails the source, and the message names it.

  • With cache, a name whose addresses are now a strict subset of those the cache recorded fails the source, naming the missing ones. Giving the addresses in portal_hosts and replication_address, or running once with --flush-cache, ends the failure.

  • The output’s schema is strict. An entry with a missing, unknown or malformed field fails the whole source, and the message names every such entry. So do two entries with the same cluster_uuid. A field whose name looks like a secret, such as password or api_token, is refused the same way, and its value is neither read into a variable, nor cached, nor shown.

Parameters

Parameter

Comments

binary_path

string

The terraform executable that project_path runs.

A name without a directory is looked up on PATH; a relative path is relative to the directory of the inventory source.

Default: "terraform"

cache

boolean

Toggle to enable/disable the caching of the inventory’s source data, requires a cache plugin setup to work.

Choices:

  • false ← (default)

  • true

Configuration:

  • INI entry:

    [inventory]
cache = false

  • Environment variable: ANSIBLE_INVENTORY_CACHE

cache_connection

string

Cache connection data or path, read cache plugin documentation for specifics.

Configuration:

  • INI entries:

    [defaults]
fact_caching_connection = VALUE

    [inventory]
cache_connection = VALUE

  • Environment variable: ANSIBLE_CACHE_PLUGIN_CONNECTION

  • Environment variable: ANSIBLE_INVENTORY_CACHE_CONNECTION

cache_plugin

string

Cache plugin to use for the inventory’s source data.

Default: "memory"

Configuration:

  • INI entries:

    [defaults]
fact_caching = memory

    [inventory]
cache_plugin = memory

  • Environment variable: ANSIBLE_CACHE_PLUGIN

  • Environment variable: ANSIBLE_INVENTORY_CACHE_PLUGIN

string

Prefix to use for cache plugin files/tables.

Default: "ansible_inventory_"

Configuration:

  • INI entries:

  • Environment variable: ANSIBLE_CACHE_PLUGIN_PREFIX

  • Environment variable: ANSIBLE_INVENTORY_CACHE_PLUGIN_PREFIX

integer

Cache duration in seconds.

Default: 3600

Configuration:

  • INI entries:

    [defaults]
fact_caching_timeout = 3600

    [inventory]
cache_timeout = 3600

  • Environment variable: ANSIBLE_CACHE_PLUGIN_TIMEOUT

  • Environment variable: ANSIBLE_INVENTORY_CACHE_TIMEOUT

compose

dictionary

Create vars from jinja2 expressions.

Default: {}

groups

dictionary

Add hosts to group based on Jinja2 conditionals.

Default: {}

keyed_groups

list / elements=dictionary

Add hosts to group based on the values of a variable.

Default: []

default_value

string

added in ansible-core 2.12

The default value when the host variable’s value is None or an empty string.

This option is mutually exclusive with keyed_groups[].trailing_separator.

key

string

The key from input dictionary used to generate groups.

parent_group

string

parent group for keyed group.

prefix

string

A keyed group name will start with this prefix.

Default: ""

separator

string

separator used to build the keyed group name.

Default: "_"

trailing_separator

boolean

added in ansible-core 2.12

Set this option to false to omit the keyed_groups[].separator after the host variable when the value is None or an empty string.

This option is mutually exclusive with keyed_groups[].default_value.

Choices:

  • false

  • true ← (default)

leading_separator

boolean

added in ansible-core 2.11

Use in conjunction with keyed_groups.

By default, a keyed group that does not have a prefix or a separator provided will have a name that starts with an underscore.

This is because the default prefix is "" and the default separator is "_".

Set this option to false to omit the leading underscore (or other separator) if no prefix is given.

If the group name is derived from a mapping the separator is still used to concatenate the items.

To not use a separator in the group name at all, set the separator for the keyed group to an empty string instead.

Choices:

  • false

  • true ← (default)

output_file

string

A file to read the output from instead of running terraform.

It holds what terraform output -json qumulo_ansible_inventory prints. A file holding every output, as terraform output -json without a name prints them, is refused.

A relative path is relative to the directory of the inventory source.

The ansible.builtin.yaml inventory plugin reads .json files in an inventory directory as inventories of their own, so a file kept in a directory given to -i is parsed as one too.

plugin

string / required

The name of this plugin.

Choices:

  • "qumulo.cluster.terraform"

project_path

string

The Terraform root to run terraform output -json qumulo_ansible_inventory in.

A relative path is relative to the directory of the inventory source.

Set exactly one of project_path and output_file.

strict

boolean

If yes make invalid entries a fatal error, otherwise skip and continue.

Since it is possible to use facts in the expressions they might not always be available and we ignore those errors by default.

Choices:

  • false ← (default)

  • true

timeout

integer

Seconds to wait for terraform output before failing the source, as when the root’s backend does not answer.

Only with project_path.

Default: 120

use_extra_vars

boolean

added in ansible-core 2.11

Merge extra vars into the available variables for composition (highest precedence).

Choices:

  • false ← (default)

  • true

Configuration:

  • INI entry:

    [inventory_plugins]
use_extra_vars = false

  • Environment variable: ANSIBLE_INVENTORY_USE_EXTRA_VARS

workspace

string

The Terraform workspace to read, selected through TF_WORKSPACE for the one command.

Without it, TF_WORKSPACE from the environment when it is set, and otherwise the root’s selected workspace.

Only with project_path.

Note

Configuration entries listed above for each entry type (Ansible variable, environment variable, and so on) have a low to high priority order. For example, a variable that is lower in the list will override a variable that is higher up. The entry types are also ordered by precedence from low to high priority order. For example, an ansible.cfg entry (further up in the list) is overwritten by an Ansible variable (further down in the list).

Notes

Note

  • With cache, the plugin caches the hosts it read, after checking them, never the raw output. The cache key covers the source, project_path or output_file, and the workspace, from workspace or TF_WORKSPACE; a workspace switched with terraform workspace select is read once the cache times out or is refreshed.

  • The TF_LOG variables are removed from the environment terraform runs in.

  • The hosts have no ansible_connection. The collection’s modules run on the controller, with ansible_connection=local, which the group_vars example below sets.

  • Inventories are not finalized at this stage, so the auto populated all and ungrouped groups will only reflect what previous inventory sources explicitly added to them.

  • Runtime ‘magic variables’ are not available during inventory construction. For example, groups and hostvars do not exist yet.

Examples

# inventory/prod.qumulo_terraform.yml
# Add the clusters of a Terraform root, in its prod workspace, to the inventory.
plugin: qumulo.cluster.terraform
project_path: ../terraform/prod
workspace: prod

---
# inventory/ci.qumulo_terraform.yml
# Read a saved `terraform output -json qumulo_ansible_inventory` where the controller has no Terraform, pin each
# cluster's certificate authority, and group clusters by region from their host names.
# Keep the saved file outside the directory given to -i, so that no other inventory plugin reads it.
plugin: qumulo.cluster.terraform
output_file: ../terraform-output/qumulo_ansible_inventory.json
compose:
  qumulo_ca_path: "inventory_dir ~ '/../files/' ~ inventory_hostname ~ '-ca.pem'"
keyed_groups:
  - key: inventory_hostname.split('-')[0]
    prefix: region

---
# inventory/cached.qumulo_terraform.yml
# Read the output once an hour instead of on every run.
plugin: qumulo.cluster.terraform
project_path: ../terraform/prod
cache: true
cache_plugin: ansible.builtin.jsonfile
cache_connection: ~/.cache/qumulo-inventory
cache_timeout: 3600

---
# inventory/lab.qumulo_terraform.yml
# Run a Terraform binary that is not on PATH, and wait longer for a slow backend.
plugin: qumulo.cluster.terraform
project_path: ../terraform/lab
binary_path: /opt/terraform/1.11.0/terraform
timeout: 300

---
# inventory/group_vars/qumulo_clusters.yml
# Connect from the controller, and read each cluster's admin password from SSM or an environment variable,
# as its password_ref names. A host whose password_ref is null sets qumulo_api_password in its host_vars.
ansible_connection: local
ansible_python_interpreter: "{{ ansible_playbook_python }}"
qumulo_api_username: admin
qumulo_api_password: >-
  {{ lookup('amazon.aws.ssm_parameter', qumulo_password_ref.id)
     if qumulo_password_ref.type == 'aws_ssm_parameter'
     else lookup('ansible.builtin.env', qumulo_password_ref.id)
     if qumulo_password_ref.type == 'env'
     else undef(hint='no lookup for password_ref type ' ~ qumulo_password_ref.type) }}
qumulo_validate_certs: true
qumulo_ca_path: "{{ inventory_dir }}/../files/qumulo-ca.pem"
