qumulo.cluster.portal_hub module – Accept a spoke’s portal proposal on the hub, set its type and roots, or delete it

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.portal_hub.

New in qumulo.cluster 0.1.0

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Runs on the hub cluster. A spoke proposes a portal with qumulo.cluster.portal_spoke, which leaves a PENDING hub portal here; this module accepts it, authorizes its roots, and sets its type. The qumulo.cluster.portal_pair role pairs both sides in one play.

  • The portal is identified by the pair of cluster UUIDs, this cluster’s and spoke_cluster_uuid, and each root by its hub root path, never by a server id.

  • Accepting a portal or changing its type makes the hub and the spoke unavailable briefly; with wait, the module waits until the portal is ACCEPTED and ACTIVE with the requested type and roots, reading through the break.

  • Setting type=read_only on a read-write portal drains the spoke. The portal reports QUIESCING until the spoke’s outstanding writes reach the hub, and with wait, the module waits for that.

  • With state=absent, deletes the hub portal. Deleting the spoke portal with qumulo.cluster.portal_spoke removes the hub portal too; this module waits for that, or deletes the record of a spoke that no longer exists, for example after a rebuild gave the spoke a new UUID.

  • With state=present, the module fails when the hub portal is DELETING, and a real run fails when the spoke has proposed no portal. A cluster with more than one hub portal for spoke_cluster_uuid fails, naming their ids.

Parameters

Parameter

Comments

allow_data_loss

boolean

Allow deleting a hub portal whose spoke is DISCONNECTED, such as the record of a spoke that was rebuilt or destroyed. The delete is then forced, and spoke writes that the hub has not received are lost.

Without it, deleting a DISCONNECTED hub portal fails before any request that changes the cluster.

A hub portal that is DELETING and DISCONNECTED, as it reads for a few seconds after its spoke’s delete, is waited for first, with wait; only one that is still there after wait_timeout fails.

Choices:

  • false ← (default)

  • true

api_host

string / required

Address or name of the Qumulo cluster’s REST API.

An IPv6 address is given bare, as fd00::5; the URL puts it in brackets.

If not set, the value of the QUMULO_API_HOST environment variable is used.

api_password

string

Password of api_username.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_PASSWORD environment variable is used.

api_port

integer

TCP port of the REST API.

If not set, the value of the QUMULO_API_PORT environment variable is used.

Default: 8000

api_token

string

An access token, sent in place of logging in.

An access token is bound to one cluster and does not survive a rebuild.

Set exactly one of api_password and api_token. An empty string counts as unset.

If not set, the value of the QUMULO_API_TOKEN environment variable is used.

api_username

string

User that logs in with api_password.

If not set, the value of the QUMULO_API_USERNAME environment variable is used.

Default: "admin"

authorized_roots

list / elements=string

Hub root paths to authorize. Each must be a root the spoke proposed.

Roots not listed are left as they are, pending or authorized.

Default: []

ca_path

path

PEM file of the certificate authority that signed the cluster’s certificate.

On Python 3.13 and later this must be a CA certificate, with basic constraints.

A bare self-signed leaf certificate cannot be pinned here on Python 3.13 and later; such a cluster is reached only with validate_certs=false.

If not set, the value of the QUMULO_CA_PATH environment variable is used.

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

request_timeout

integer

Seconds to wait for one HTTP response.

If not set, the value of the QUMULO_REQUEST_TIMEOUT environment variable is used.

Default: 60

retry_timeout

integer

Seconds to keep retrying a request that is safe to resend, after a lost connection or an HTTP 502, 503 or 504.

If not set, the value of the QUMULO_RETRY_TIMEOUT environment variable is used.

Default: 300

spoke_cluster_uuid

string / required

UUID of the spoke cluster. To remove the record of a rebuilt spoke, give the UUID it had before the rebuild.

spoke_hosts

list / elements=dictionary

IP addresses of the spoke cluster, as this cluster reaches them on the portal port.

Needed to accept the portal. Changed in place when they differ, compared in any order.

Never an FQDN. For a cluster with floating IPs, its floating IPs; for a multi-AZ cluster in AWS, its load balancer’s IPs; otherwise its node IPs.

address

string / required

An IP address of the spoke.

port

integer

The spoke’s portal port.

Default: 3713

state

string

Whether the hub portal exists.

Choices:

  • "present" ← (default)

  • "absent"

type

string

The portal’s type. Unset keeps the type the spoke proposed or the hub last set.

Changing read_write to read_only drains the spoke first.

Choices:

  • "read_write"

  • "read_only"

validate_certs

boolean

Verify the cluster’s TLS certificate.

If not set, the value of the QUMULO_VALIDATE_CERTS environment variable is used.

Choices:

  • false

  • true ← (default)

wait

boolean

Wait until the portal is ACCEPTED and ACTIVE with the requested type and roots after a change, or until it is gone with state=absent.

A portal that needs no change but is still in a transition such as QUIESCING, or not ACTIVE, is waited for too, so a run during a drain returns once the drain is done. Its result then reports no change.

With type unset, the type is not waited for, since a drain shows the old type for a while after it starts.

With false, the module returns after its requests, and its result shows the portal as it was read just after them.

Choices:

  • false

  • true ← (default)

wait_timeout

integer

Seconds to wait, including for a delete that a portal transition blocks.

Default: 600

Attributes

Attribute

Support

Description

action_group

Action group: qumulo.cluster.qumulo

Use group/qumulo.cluster.qumulo in module_defaults to set the connection options for this module.

check_mode

Support: full

A proposal that an earlier task in check mode would make is predicted as accepted, with a note.

Can run in check mode and return a changed status prediction without modifying the cluster.

diff_mode

Support: full

Will return details on what has changed, or would change in check mode, when in diff mode.

idempotent

Support: partial

Accepting cannot be retried safely, so the module accepts only a PENDING portal (G-PORTAL-ONESHOT).

Hub portals carry no ETag, so a concurrent change between the read and a write goes undetected (G-PORTAL-ETAG).

The record of a spoke that no longer exists can only be forced away (G-PORTAL-STALE).

When run twice in a row outside check mode with the same arguments, the second run reports no change.

This assumes that nothing else changed the cluster in between.

Notes

Note

  • API: GET /v2/portal/hubs/, GET, PATCH and DELETE /v2/portal/hubs/{id}, POST /v2/portal/hubs/{id}/accept, POST /v2/portal/hubs/{id}/roots/{dir}, GET /v1/files/{ref}/info/attributes.

  • Idempotency gaps G-PORTAL-ONESHOT, G-PORTAL-ETAG and G-PORTAL-STALE apply.

  • A PATCH that repeats the stored value still rewrites the record and re-runs its connectivity checks (QUIRK-005), so the module sends type and spoke_hosts only when they differ.

  • Qumulo Core 7.10.3 offers the types read_write and read_only only.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Accept the edge's portal and authorize its root
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    spoke_hosts:
      - address: 10.0.1.20
    authorized_roots: [/data]

- name: Reach the edge at its new address
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    spoke_hosts:
      - address: 10.0.1.21

- name: Preview accepting the second edge's portal
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge02'].qumulo_cluster_uuid }}"
    spoke_hosts:
      - address: 10.0.2.20
    authorized_roots: [/data]
  check_mode: true
  diff: true
  register: edge02_preview

- name: Show the predicted portal and what the module noted
  ansible.builtin.debug:
    msg: >-
      {{ edge02_preview.portal.state | default('not proposed yet') }},
      notes: {{ edge02_preview.notes | default([]) }}

- name: Authorize a second root the edge has proposed
  # Roots not listed are left as they are, so the first root stays authorized.
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    authorized_roots: [/archive]

- name: Accept the edge's portal and return before it is ACTIVE
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    spoke_hosts:
      - address: 10.0.1.20
    authorized_roots: [/data]
    wait: false

- name: Drain the edge before deleting its portal
  # The portal reads QUIESCING until the edge's outstanding writes reach the hub; the module waits for that, so the
  # delete that follows strands no writes.
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    type: read_only

- name: Delete the drained portal
  # Deleting the spoke's portal with qumulo.cluster.portal_spoke removes this one too; the module waits for that.
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_cluster_uuid }}"
    state: absent

- name: Make the second edge's portal read-write, which pauses both clusters briefly
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge02'].qumulo_cluster_uuid }}"
    type: read_write

- name: Remove the record of the edge as it was before a rebuild
  # Forced: writes the hub had not received from the old edge are lost. After a rebuild, the last entry of the edge's
  # qumulo_previous_cluster_uuids is the UUID it had before.
  qumulo.cluster.portal_hub:
    spoke_cluster_uuid: "{{ hostvars['edge01'].qumulo_previous_cluster_uuids | last }}"
    state: absent
    allow_data_loss: true

Key

Description

maybe_applied

boolean

True when a write was sent and the read-back did not confirm that it took effect.

Returned: on such a failure

What the module noticed, such as a proposal that check mode could not see yet.

Returned: when there is something to note

dictionary

The hub portal after the task, empty after a delete. qumulo.cluster.portal_info reports hubs and spokes in this shape.
