qumulo.cluster.identity_info module – Read a Qumulo cluster’s local users and groups, roles, directory services and sign-in settings

Note

This module is part of the qumulo.cluster collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install qumulo.cluster.

To use it in a playbook, specify: qumulo.cluster.identity_info.

New in qumulo.cluster 0.1.0

  • Synopsis

  • Parameters

  • Attributes

  • Notes

Synopsis

  • Gathers the identity configuration of one Qumulo cluster and changes nothing.

  • Each subset has the shape of the options of the module that manages it. Users and groups are listed by name and role members as trustee strings, never by server ids.

  • No secret is returned. Local passwords cannot be read; the LDAP bind password and the Kerberos keytab are not read.

  • With find_trustees, expand_trustees and find_ad_objects it also looks up trustees and Active Directory objects, and returns what each term names. A lookup runs whatever gather_subset lists, and in check mode too, since it changes nothing.

  • A subset or a lookup the cluster cannot answer is listed in unavailable_subsets with the reason, and the other subsets and lookups are still gathered.

expand_trustees

list / elements=string

Trustees to expand, each answered in identity.expanded_trustees under the term as given.

A term has the grammar of find_trustees, and is found first, with the same key, miss and error rules. A term that is not found sends no expand, and its entry has false in found. A term whose find has an error has that error in its entry.

The expansion is what the cluster itself works out for the identity. type is USER, GROUP or UNKNOWN, the last for an identity that nothing maps to a POSIX identity. identity is the identity found, and nfs_identity and smb_identity are the identities the cluster uses over NFS and over SMB, each null where the cluster gives none. nfs_identity is null for UNKNOWN, and set for a USER or a GROUP from the identity’s POSIX mapping. equivalents are the identities the cluster treats as the same principal, and groups are the groups it counts the identity a member of, sorted by trustee and SID. The cluster gives the groups in no fixed order, so the sort is the collection’s.

A local user expands as USER, with its NFS uid in nfs_identity and among equivalents, and with Users and Authenticated Users among its groups. The cluster adds Authenticated Users to the groups of every identity but the guest, and groups holds nested groups, since the cluster follows each group and its equivalents (read from Qumulo Core’s source; the guest’s groups were observed).

An AD user’s equivalents hold the uid and gid from the directory’s RFC 2307 attributes when the cluster reads them, and from a user-defined mapping when mappings are on (read from the source, not observed). An AD user with neither expanded as UNKNOWN on the AD lane, with a null nfs_identity, no equivalents, and Authenticated Users its only group. None of its directory groups were in groups; find_ad_objects shows them in groups and primary_group_sid.

A 400 to the expand itself fails the task, naming the term, since the collection built its body from the find.

A mapping, a POSIX attribute or a group the directory changed just now may not show in the expansion until the caches are cleared or expire; see the notes.

Default: []

expected_cluster_uuid

string

The UUID the cluster at api_host must have.

Before the first credentials are sent, the module reads the cluster’s UUID from GET /v1/node/state, which needs no login, and fails when it differs, so that no credentials are sent to the wrong cluster. On a mismatch the task fails with live_cluster_uuid and expected_cluster_uuid in its result.

An empty value disables this identity guard, and a module that logs in warns.

If not set, the value of the QUMULO_EXPECTED_CLUSTER_UUID environment variable is used.

find_ad_objects

list / elements=string

Active Directory objects to read, each answered in identity.found_ad_objects under the term as given.

A term is dn:<distinguished name>, sid:<SID> or name:<sAMAccountName>. A DN has an = in it, and a SID is a whole SID. A name: term is a bare sAMAccountName, and searches the joined domain’s configured base DNs only, not its trusted domains (read from the source), so a term that holds \ or @ is refused. Any other term outside that grammar fails the task before any request is sent. The message names the term and the accepted forms.

A term given twice is one key and is read once.

A term that names no object is not an error. Its entry has false in found and no objects, and the task neither fails nor warns. That is a dn: or sid: read the server answers with 404 ad_not_found_error, and a name: read that answers an empty list.

A name: term can name more than one object; each object is listed once, by its SID.

A 400 distinguished_name_decode_error or ms_sid_decode_error to a term’s read is that term’s error, as for find_trustees, and the other terms are still read. Any other 400 fails the task.

A cluster that is not joined to a domain, or is joined to more than one, answers every AD read with a 409. The lookup is then unavailable. It is listed in unavailable_subsets under found_ad_objects with the server’s description, no more AD reads are sent, its key is absent from identity, and the other subsets and lookups are still gathered. Outside a domain the server’s description is “The cluster has not joined any AD domains yet.”. The answer for a cluster joined to more than one domain was read from the source, not observed.

In check mode a domain that an earlier task of the same run would join is not joined yet, so the lookup is unavailable, and an account that task would create is a miss.

Each object’s trustee is ad:<NETBIOS>\<name> for an object of the joined domain, the form that qumulo.cluster.user_defined_mappings takes in down_level_logon_name, and null for any other object. That is an object of a trusted domain, which a dn: or sid: read can answer for (read from the source, not observed), and any object when the cluster reports no NetBIOS name for the domain. A find of the trustee also makes the domain known to the cluster, as find_trustees describes for a SID.

The object’s uid and gid are the directory’s own attributes, uidNumber and gidNumber, null when the object has none. They are not what the cluster maps the object to, since the read applies no id mapping and no user-defined mapping, and ignores use_ad_posix_attributes (read from the source, not observed). The nfs_identity of expand_trustees shows the uid the cluster uses.

A read of an object the cluster has read before is answered from its directory cache, so it still answers while the domain controller is out of reach, and may be older than a change just made on the domain controller; see the notes. An object the node had not cached was not read with the domain controller away.

Default: []

find_trustees

list / elements=string

Trustees to find, each answered in identity.found_trustees under the term as given.

A term is a trustee in any form the collection’s modules take, local:<name>, ad:<DOMAIN>\<name>, ad:<name>@<domain>, ldap_user:<name>, ldap_group:<name>, qumulo_support:<name>, Everyone or world:Everyone, internal:File Owner, internal:File Group Owner, uid:<n>, gid:<n>, and a SID with the prefix sid: or without it. A bare name, a sid: term that is not a SID, a uid or gid that is not a non-negative integer, and any other term outside that grammar fails the task before any request is sent. The message names the term and the accepted forms.

A term given twice is one key and is found once. Two spellings of one identity, such as ad:CORP\alice and ad:alice@corp.example.com, are two keys holding the same identity.

A term that no identity source holds is not an error. Its entry has false in found and null in every field after it, and the task neither fails nor warns. That includes a local, AD or LDAP name nothing holds, an ad: name other than ad:NT AUTHORITY\Authenticated Users on a cluster that is not joined to a domain, and an ldap_user: name while LDAP is off.

A uid: or gid: term, and a SID of a domain the cluster knows, have true in found whether or not an account carries the number or the SID. The cluster turns the number or the SID into an identity of its own without asking a directory, so found there means that the cluster can name an identity by the term, and not that an account holds it. name is null when nothing names the identity. The find answers the same, with a null name, for the uid of a local user made with that NFS uid; it does not name the local user.

A SID of a domain the node has not found a name in since it started is not found by SID, whether or not the cluster is joined (QUIRK-100). The term’s entry has false in found and the server’s class and description in error, and the other terms are still found. A find of a name in the domain, such as ad:CORP\Domain Users, lifts it, and a later find of the SID then succeeds.

The SID of Authenticated Users, S-1-5-11, is the exception. The module looks it up by the name ad:NT AUTHORITY\Authenticated Users, which the cluster finds joined to a domain or not, so both terms are found.

An error that belongs to a term is recorded in its entry, and the task gives one warning naming the terms with an entry that has an error. A uid of 2^32 or more, a gid past 32 bits and an oversized part of a SID earn a 400 that is recorded the same way, and so does, by Qumulo Core’s source, an ldap_user: or ldap_group: name that more than one LDAP entry carries or that the LDAP search refuses (not observed, since no lane runs an LDAP server). Any other 400 fails the task.

With no Active Directory domain controller in reach, the find of an AD name fails the task. For a name the node has not found, the server answers 404 ad_domain_controller_not_found_error, which is not a miss (QUIRK-102). For a name the node has cached, the server answers 500 network_timeout_error after about a minute. The client never sends a 500 again. If that answer comes within request_timeout the task fails with it at once. With the default request_timeout of 60 seconds it usually does not, so the client sends the find again until retry_timeout is spent and the task fails with the message that the address is unreachable for retry_timeout seconds, with a reason that ends in “timed out”.

The cluster caches a miss of a local name for about a minute, and creating the name does not lift it (QUIRK-017). A local name looked up just before it is created stays unresolvable for about a minute, to every module that resolves it.

The answers for AD and LDAP names are cached too, and may be older than a change just made; see the notes.

In check mode a trustee that an earlier task of the same run would create, or that needs a join an earlier task would make, is not there yet, so its term is a miss.

A local identity’s SID is the cluster’s own, and changes when the cluster is rebuilt.

Default: []

gather_subset

list / elements=string

The subsets of facts to gather. all gathers every subset.

[] gathers every subset too, unless a lookup option is given; then only the lookups run.

local_users: the local users, as qumulo.cluster.local_user takes them.

local_groups: the local groups and their members, as qumulo.cluster.local_group takes them.

role_members: the members of every role, one entry per role, as qumulo.cluster.role_member takes them.

ad: the Active Directory membership, as qumulo.cluster.ad_domain takes it, with its join status.

ldap: the LDAP settings.

kerberos: the Kerberos settings.

roles: the custom roles, as qumulo.cluster.role takes them.

user_defined_mappings: the mappings, as qumulo.cluster.user_defined_mappings takes them.

saml: the SAML settings, as qumulo.cluster.saml_settings takes them, the IdP certificate included, which is public.

access_tokens: every access token, by its user, as qumulo.cluster.access_token returns them, never with a bearer.

Choices:

  • "all" ← (default)

  • "local_users"

  • "local_groups"

  • "role_members"

  • "ad"

  • "ldap"

  • "kerberos"

  • "roles"

  • "user_defined_mappings"

  • "saml"

  • "access_tokens"

Default: ["all"]

Notes

Note

  • API: local_users GET /v1/users/ and /v1/groups/; local_groups GET /v1/groups/ and /v1/groups/{id}/members/; role_members GET /v1/auth/roles/ and /v1/auth/roles/{role}/members (paginated); ad GET /v1/ad/status and /v1/ad/monitor; ldap GET /v2/ldap/settings; kerberos GET /v1/auth/kerberos-settings; roles GET /v1/auth/roles/; user_defined_mappings GET /v1/auth/user-defined-mappings/; saml GET /v1/saml/settings; access_tokens GET /v1/auth/access-tokens/ (paginated), which lists every user’s tokens and needs PRIVILEGE_ACCESS_TOKENS_READ.

  • API of the lookups: find_trustees POST /v1/identity/find, which needs the RBAC privilege PRIVILEGE_IDENTITY_READ; expand_trustees the same find for each term, then POST /v1/identity/expand for each term found, which needs PRIVILEGE_IDENTITY_READ too; find_ad_objects GET /v1/ad/distinguished-names/{dn}/object for a dn: term, GET /v1/ad/sids/{sid}/object for a sid: term and GET /v1/ad/usernames/{username}/objects/ for a name: term, which need PRIVILEGE_AD_USE, and GET /v1/ad/status once per task after the first object is found, unless the ad subset of the same task read it, which needs PRIVILEGE_AD_READ. A task whose user lacks a privilege fails with the server’s 403, which names it. The privileges of the expand and of the AD reads are read from Qumulo Core’s source, not observed.

  • The lookups send one request per term, one after another through one login, and keep nothing past the task. expand_trustees sends a find and then an expand for each term it finds. A hundred terms are a hundred requests, or up to two hundred for expand_trustees.

  • Leaving gather_subset unset also gathers every subset, which lists every user, group, role member and role, and reads the AD, LDAP, Kerberos, mapping and SAML settings and lists every access token, each with the privileges of its own reads. With a lookup, give [] to run only the lookups.

  • An unavailable lookup’s key is absent from identity, and is listed in unavailable_subsets.

  • The cluster caches the answers of AD and LDAP, a miss among them, per node, with a soft lifetime of 15 minutes, after which the cached answer is served stale and refreshed in the background, and a hard lifetime of 24 hours (read from Qumulo Core’s source, not observed). A change made in the domain, on an LDAP server, or by qumulo.cluster.user_defined_mappings may not show in a lookup that follows it. qumulo.cluster.auth_cache_clear clears the identity cache of the node it reaches, and emptied the directory cache of that node on the AD lane, so that an object read after it showed a group just added on the domain controller. Whether it reaches every node of a cluster was not seen.

  • The configured domain controllers are read from the monitor of the last AD operation, which a later operation replaces, so ad.domain_controllers is null when that record is not for the joined domain (G-AD-DCS).

  • Registers: G-AD-DCS, QUIRK-017, QUIRK-100, QUIRK-102.

Examples

# These tasks carry no connection options. Set them once for the play with module_defaults for
# group/qumulo.cluster.qumulo, or in the QUMULO_* environment variables.
- name: Read the identity configuration
  qumulo.cluster.identity_info:
  register: identity

- name: Read only who is in which role
  qumulo.cluster.identity_info:
    gather_subset: [role_members]
  register: roles

- name: Read the local users and the groups they belong to
  qumulo.cluster.identity_info:
    gather_subset: [local_users, local_groups]
  register: local_identities

- name: Read the Active Directory membership
  qumulo.cluster.identity_info:
    gather_subset: [ad]
  register: ad_membership

- name: Show the domain the cluster is joined to
  ansible.builtin.debug:
    msg: "{{ ad_membership.identity.ad.domain | default('not joined', true) }}"

- name: Read the custom roles and their privileges
  qumulo.cluster.identity_info:
    gather_subset: [roles]
  register: custom_roles

- name: Read the single sign-on and mapping settings
  qumulo.cluster.identity_info:
    gather_subset: [saml, user_defined_mappings]
  register: sign_in

# gather_subset: [] makes a lookup the only thing the task reads. Without it the task also reads every subset.
# Look a local name up only to check one that should exist already, never just before creating it: the cluster caches a
# miss for about a minute (QUIRK-017).
- name: Find the trustees an ACL is about to name
  qumulo.cluster.identity_info:
    gather_subset: []
    find_trustees:
      - local:svc-backup
      - 'ad:CORP\Engineering'
      - ad:alice@corp.example.com
      - uid:1001
  register: trustees

# A trustee nothing holds is a miss, not an error, so the find passes and this task stops the play. It also stops
# on a term whose entry has an error, which has found: false.
- name: Stop unless every trustee exists
  ansible.builtin.assert:
    that: trustees.identity.found_trustees | dict2items | rejectattr('value.found') | list | length == 0
    fail_msg: >-
      The cluster does not know
      {{ trustees.identity.found_trustees | dict2items | rejectattr('value.found') | map(attribute='key') | join(', ') }}

# The entry's trustee is the canonical form, which another task can name. A term is a key as given, so a name with a
# backslash is read through a variable.
- name: Find the SID of an Active Directory user
  vars:
    alice: 'ad:CORP\alice'
  qumulo.cluster.identity_info:
    gather_subset: []
    find_trustees: ["{{ alice }}"]
  register: alice_sid

- name: Show the user's SID
  vars:
    alice: 'ad:CORP\alice'
  ansible.builtin.debug:
    msg: "{{ alice_sid.identity.found_trustees[alice].sid }}"

# The SID of a domain the node has not found a name in since it started is the term's error. Finding a name of the
# domain first, in the same list, lifts it (QUIRK-100).
- name: Find an Active Directory group by its SID, after a name of its domain
  qumulo.cluster.identity_info:
    gather_subset: []
    find_trustees:
      - 'ad:CORP\Domain Users'
      - sid:S-1-5-21-1-2-3-1108
  register: group_sid

# A uid nothing carries is still found: found means the cluster can name an identity by it, and name is null.
- name: Find the identity the cluster makes of a uid
  qumulo.cluster.identity_info:
    gather_subset: []
    find_trustees: [uid:2001]
  register: by_uid

- name: Show the uid's identity, which has no name unless something names it
  ansible.builtin.debug:
    msg: "{{ by_uid.identity.found_trustees['uid:2001'] }}"

# A mapping is read through the identity cache, so clear the cache first when the mapping was just made.
- name: Clear the authentication cache before checking a mapping
  qumulo.cluster.auth_cache_clear:

- name: Expand an Active Directory user to see its NFS identity and groups
  vars:
    alice: 'ad:CORP\alice'
  qumulo.cluster.identity_info:
    gather_subset: []
    expand_trustees: ["{{ alice }}"]
  register: expansion

- name: Show the uid the cluster uses over NFS, and the groups it counts the user in
  vars:
    alice: 'ad:CORP\alice'
  ansible.builtin.debug:
    msg: "{{ expansion.identity.expanded_trustees[alice].nfs_identity.uid | default('none') }}
      {{ expansion.identity.expanded_trustees[alice].groups | map(attribute='trustee') | list }}"
  when: expansion.identity.expanded_trustees[alice].found

# The lookup is unavailable on a cluster that is not joined to a domain, or is joined to more than one. Its key is then
# absent, so read it only when it is not listed in unavailable_subsets.
- name: Look up an Active Directory account by name and by DN
  qumulo.cluster.identity_info:
    gather_subset: []
    find_ad_objects:
      - name:alice
      - dn:CN=bob,CN=Users,DC=corp,DC=example,DC=com
  register: ad_objects

- name: Show the trustee of the account found by name
  ansible.builtin.debug:
    msg: "{{ ad_objects.identity.found_ad_objects['name:alice'].objects | map(attribute='trustee') | list }}"
  when: "'found_ad_objects' not in (ad_objects.unavailable_subsets | default({}))"

# A lookup only reads, so a check run answers as a real run does. What an earlier task of the play would create is not
# there yet, so its term is a miss.
- name: Find a user in a check run
  qumulo.cluster.identity_info:
    gather_subset: []
    find_trustees: [local:svc-backup]
  check_mode: true
  register: trustees_preview

- name: Show whether the check run found the user
  ansible.builtin.debug:
    msg: "{{ trustees_preview.identity.found_trustees['local:svc-backup'].found }}"

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

identity

dictionary

The gathered facts. Each key is present only when its subset was gathered.

Returned: always

Sample: {"ad": {"domain": null, "status": "NOT_IN_DOMAIN"}, "local_groups": [{"gid": null, "members": ["admin"], "name": "Users"}], "local_users": [{"home_directory": null, "name": "admin", "primary_group": "Users", "uid": 0}], "role_members": [{"members": ["local:admin"], "role": "Administrators"}]}

access_tokens

list / elements=dictionary

Every access token, sorted by user and creation time, with user and creator as trustees, id, creation_time, expiration_time, null for never, and enabled. A token’s bearer is never read.

Returned: success

Sample: [{"creation_time": "2026-06-01T09:30:00.000000000Z", "creator": "local:admin", "enabled": true, "expiration_time": null, "id": "1000000000000000000001", "user": "local:svc-backup"}]

ad

dictionary

The AD membership, with status, domain, domain_netbios, ou, search_trusted_domains, use_ad_posix_attributes, base_dn and domain_controllers.

domain is null when the cluster is not joined.

Returned: success

Sample: {"base_dn": "CN=Users,DC=corp,DC=example,DC=com", "domain": "corp.example.com", "domain_controllers": null, "domain_netbios": "CORP", "ou": null, "search_trusted_domains": true, "status": "JOINED_TO_DOMAIN", "use_ad_posix_attributes": false}

expanded_trustees

dictionary

Each term of expand_trustees, under the term as given, with its expansion.

Each value holds the keys below, on every path. A term that is not found, or whose find has an error, has false in found, null in type and in the three identities, and empty lists.

Returned: when expand_trustees is given
